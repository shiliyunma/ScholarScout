# 第 1 章 绪论

## 1.1 研究背景与问题

### 1.1.1 背景

在"AI + 教育"的语境下，一个被反复遇到却缺少工具支撑的场景是：
**一个人要进入一个陌生方向，先把"这个方向是什么、该读什么、怎么排期"搞明白。**
这件事在本科阶段的科研训练、保研/考研后的方向选择、以及跨方向转岗中都会出现，
而当前的普遍做法是"打开搜索引擎 + 收藏夹 + 手抄笔记"，结果是资料散落、来源不可追溯、
读完记不住，且**无法回答"我这几天的调研到底靠不靠谱"**。

与此同时，大模型带来的能力跃迁使"自主调研 Agent"成为可能：模型可以自己决定检索什么、
抓取什么、如何组织结论。但它同时带来两个新问题：

1. **不可归属**：生成的结论与"哪一条真实资料支持它"之间缺少强绑定，
   于是"看起来很像那么回事"与"其实是编的"无法区分；
2. **成本不可控**：一轮调研可能触发十几次模型调用，每次都重发全部上下文，
   用户往往在账单出来之后才知道花了多少。

因此本课题的出发点是：**做一个桌面级的、全本地的学习辅助调研智能体，
并把"是否可归属""是否真的支持""花了多少"这三件事做成可复算的数字，而不是产品宣传语。**

### 1.1.2 要解决的问题

形式化地讲：给定一句方向描述作为输入，系统需要产出一份调研包，其中包含

- 一组**真实可达**的资料（学术论文 / 官方文档 / 代码仓库 / 通用网页），每条可定位到原件；
- 一组**学习化产物**：方向知识地图、学习路线、（用户要求时的）抽背卡；
- 一组**实验可复算**的运行指标：完成率、工具成功率、时延、token 消耗、
  出处覆盖率与引用语义支持度。

并满足四条约束：全本地存储（R3）、成本可控（R4）、可计量（R5）、桌面双击即用（R6）。

### 1.1.3 与传统检索的差别

| 维度 | 传统检索/文献工具 | 本系统 |
|---|---|---|
| 输入 | 关键词 | 一句方向描述 |
| 输出 | 链接列表 | 资料 + 知识地图 + 学习路线 + 卡片 |
| 归属 | 靠人工判断 | 产物每条挂真实 `source_id`，且**度量"资料是否真的支持该断言"** |
| 成本 | 不可见 | 每轮显示真实 token，会话级累计可见，省钱手段有 A/B 证据 |
| 运行 | 在线服务 | **全本地**（SQLite + 文件系统），可离线复算指标 |

### 1.2.1 四类相关工作

| 类别 | 代表形态 | 与本系统的关系 |
|---|---|---|
| **A 学术检索的 API 化** | arXiv / OpenAlex / Semantic Scholar 等开放接口 | **吸收**：作为学术层来源（第 3.4.1 节），并处理其真实工程约束（限速、robots、倒排摘要） |
| **B 本地知识库与 RAG 问答** | "文档 → 分块 → 向量库 → 检索问答" | **部分不采用**：本系统把知识库降级为次要通道，**刻意不引向量库**（第 3.3 节给出理由：召回由外部来源承担，引入向量库要新增依赖与可失败服务） |
| **C 自主调研 / 深度研究 Agent** | 多轮"检索—阅读—写作"的 Agent 范式（如数据/调研类竞赛与开源实现） | **吸收架构、放大度量**：本系统与其最大差别是**把反幻觉做成两级可计量指标**，而不是只交一份报告 |
| **D 教育智能体与学习路径生成** | 知识地图、学习路线、抽背卡等学习产物 | **吸收形态、改交互**：产物**按需生成**（用户主导），并在第 5.6 节用探针题集验证"不擅自生成" |

### 1.2.2 本系统在架构上的参照

架构参照物是**本机日常使用的桌面智能体 Hermes Agent**：复刻其"下半身"
（Python 后端 + JSON-RPC + SQLite/FTS5 + 工具注册表 + 提示词外置），
但**不搬其依赖库**（本系统要求前端无构建、可离线跑评测）。
另一参照物是 AIHOT：其摘要流水线（一次调用 + 截断 + 提示词版本=内容哈希）被直接借鉴。

## 1.4 本文的主要贡献

1. **一个可运行的桌面级学习辅助调研系统**（后端 72 个文件 11,127 行、前端 3,402 行、
   6 个模型可见工具、6 个数据库迁移、12 个来源适配器），**全本地存储、双击即用**。
2. **两级反幻觉度量体系**：把"引用真实"（可归属率）与"资料真的支持该断言"（语义支持度）
   分开定义、分开度量，并给出**按证据等级分层**的口径 —— 首次实测得到
   "覆盖率 100% vs 支持率约 91%，且落差主要来自弱证据样本"这一可复核结论。
3. **一次成本控制的可复算实验**：先解剖账单（每轮固定重发 393 + 1,558 tokens、约 10 次调用/轮），
   再逐项量化杠杆收益，并**明确记录"测量后判定不做"的那一项**。
4. **产物按需生成的设计与验证方法**：由于原题集题面全都点名要产物，导致"擅自生成"没有分母 ——
   为此**专门建立探针题集**，并把这个度量返工的教训保留在第 5.8.1 节。

## 1.5 本文的边界（先说清楚）

- 评测样本量小（E1 24 条、E2 13 条、E3 6 题、探针 3 题），**不做统计显著性主张**；
- 语义支持度是**模型判定**，不是人工金标准（需再抽 20–30 条人工标注，见第 5.8.2 节）；
- 扫描版 PDF 的正文抽取**未端到端验证成功**（外部服务当期不可用，代码与契约已就绪）；
- 只在一台 Windows 11 机器、单一模型档位上完成全部实测。
