# 第 2 章 相关技术与文献综述

> 本章文献**由本系统自己的检索链路获得**（`scripts/collect_thesis_refs.py` / `scripts/collect_thesis_refs_targeted.py`），
> 不是手工罗列：共 **22 组查询**（10 组主题 + 12 组定向），来源为 arXiv API；
> 元数据与 arXiv 编号由 `scripts/make_thesis_bib.py` 从接口返回结果直接生成（见 `docs/13-论文参考文献.md`）。
>
> 检索过程中的一个真实约束如实记录：**OpenAlex 在本机当期持续返回 429**（单次请求 + 65 秒冷却后仍失败），
> 因此本章文献**全部来自 arXiv**，每条均带 arXiv 编号可逐条核查。这不构成穷尽性的系统综述。

## 2.1 综述范围与检索方法

本章围绕四个问题组织文献：**（A）学术检索与文献计量；（B）检索增强生成与本地知识库；
（C）自主调研与工具使用智能体；（D）教育智能体与学习路径生成**；
并单列两节讨论与本文最直接相关的**（E）引用可核查与反幻觉**与**（F）上下文与成本控制**。

| 项 | 做法 |
|---|---|
| 检索入口 | 本系统的 `providers/arxiv.py`（arXiv API，查询按 `all:a AND all:b` 切词改写） |
| 查询组 | 10 组主题查询（每类 1–3 组，每组取 6 条）+ 12 组定向查询（用于钉住经典工作） |
| 时间范围 | 主题查询限 2023 年及以后；定向查询不限年份（经典工作必须能引到） |
| 去重 | 按 DOI → arXiv 编号 → 规范化标题三级去重 |
| 入选 | 与本文六个方向直接相关者共 **38 条**（其中 2025–2026 年工作 **24 条**） |

## 2.2 学术检索与文献发现

把学术检索接口化是本文调研链路的起点：**SciBERT** 一类的领域预训练模型说明学术文本需要专门的
表示与处理 [1]；而 **对计算教育类文献的引用计量研究** 指出，大模型进入写作流程后，
"看起来很像真的、其实是编造的引用"已成为可观测的完整性问题 [2]。
后者为本文的动机提供了直接证据：**引用可核查性必须被当作一项指标来做，而不是当作模型的自觉。**

本文的差别在于：不训练领域模型，而是**把公开检索接口当作可编排工具**，
并在系统内部对来源做确定性分层（第 3.4 节），使"这条资料来源是谁"永远可复算。

## 2.3 检索增强生成与本地知识库

**RAG** 确立了"检索 + 生成"的基本范式 [3]；**Self-RAG** 进一步让模型自我反思地决定检索与批判 [4]。
工程侧的研究则集中在**分块与检索的相互作用**上：面向政策文档的 RAG 架构评测 [5]、
长文档检索中分块大小的多数据集分析 [6]、面向化学领域的分段与表示权衡 [7]、
查询感知的分块压缩 [8]，以及以标签/知识图谱组织检索的 **TagRAG** [9] 与 **TOBUGraph** [10]；
面向企业异构知识库的 **W-RAG** 强调"来源感知"的检索 [11]，
面向政府监管文档的研究则系统考察了解析、分块与嵌入之间的相互作用 [12]。

**与本文的关系（刻意不采用）**：本文**不引入向量库、也不做分块检索**。
理由有二：其一，本系统的召回由**外部来源**（学术/代码/通用三层）承担，
库内检索只是可插拔的次要通道；其二，"正文不入库、只入摘要 + 路径"的设计（第 3.3 节）
使库内不存在需要分块的长文本 —— 引入嵌入模型与向量服务会新增依赖和一个可失败的服务，
而收益不对称。本文对上述文献的**借鉴**在于：它们证明了分块/检索质量的波动很大，
因此本文选择用**固定截断 + 一次调用的摘要流水线**（第 4.5 节）把这一风险移出关键路径。

## 2.4 自主调研与工具使用智能体

工具使用与推理交织是智能体的基础能力：**Chain-of-Thought** 确立了显式推理链的有效性 [13]，
**ReAct** 让推理与行动交替 [14]，**Toolformer** 让模型自学调用工具 [15]；
综述工作系统梳理了自主智能体的构成 [16]，**LLM-as-a-Judge** 提供了自动判分的常用手段 [17]。

面向"长程检索"的新近工作与本文最接近：**Laser** 指出既有 agentic search 框架
"依赖非结构化的自然语言推理、并把原始中间轨迹不断堆积进上下文"，因而提出结构化协议与
上下文登记表来治理长程搜索 [18]；**MCP-Bench** 用真实工具服务构造了复杂任务的工具使用基准 [19]；
**ToolTree** 以双反馈蒙特卡洛树搜索改进工具规划 [20]；
**AnovaX** 则以**本地**多智能体语音助手的形式给出了"规划 + 类型化执行器 + 自适应恢复"的工程样本 [21]。

**与本文的关系**：本文同样把中间轨迹堆进上下文视为成本与可靠性问题，
但处理方式更"笨"也更可核查 —— 在**喂回模型前做确定性瘦身**（去重/截断/折叠，第 4.3 节），
并把收益量化（同题输入 −15%）；同时**把轮次预算写死进提示词**，
使"用满工具预算"与"模型不收口"成为两种可区分的结束原因（`stop_reason`）。

## 2.5 教育智能体与学习路径生成

学习路径生成已有明确的问题意识：**多智能体学习路径规划**指出既有方法
"缺乏透明性、适应性与以学习者为中心的可解释性" [22]；
**IB-GRPO** 关注让路径推荐与教育目标对齐 [23]；
**面向 STEM+C 的教学智能体**强调支架式引导而不过度依赖 [24]；
**面向目标学习的多智能体框架**把智能体引入辅导系统 [25]；
**GraphMASAL** 用图结构组织自适应学习 [26]；**教育场景的智能体化工作流**给出了概念与应用梳理 [27]。

**与本文的关系**：上述工作普遍把学习产物视为**系统输出**（系统决定何时生成路径/图谱）。
本文做了一处相反的取舍 —— **产物按需生成**（第 3.5.3 节）：默认不生成知识地图与学习路线，
只在用户明确要求时生成，并把"用户未要求却擅自生成"做成可计量的比率（第 5.6 节探针题集）。
理由是本系统的定位是"用户主导的调研工具"，且生成产物是成本最高的一步。

## 2.6 引用可核查与反幻觉（与本文最直接相关）

这一方向的脉络可以概括为"从整篇文档级归因走向细粒度、可验证的归因"：

| 工作 | 核心主张 | 与本文的关系 |
|---|---|---|
| Measuring Attribution（ATTRIB）[28] | 需要评估 NLG 输出是否只包含可验证信息 | 本文的两级指标受此框架启发：**可归属率 + 语义支持度** |
| Attribute First, then Generate [31] | 现有引用常指向整篇文档/整段，用户难以核查；应先归因再生成 | 本文的产物条目**逐条挂 source_id 并单独判定支持度**，方向一致但粒度是"产物条目" |
| Learning Fine-Grained Grounded Citations [32] | 细粒度内联引用可减轻幻觉、提升可验证性 | 同上；本文把"细粒度"落到**产物条目级**而非句内引用 |
| VeriCite [29] | RAG 的内联引用需要严格验证流程 | 本文的守卫（id 存在性）+ 支持度校验对应其"验证"环节 |
| CiteGuard [30] | 仅靠 LLM-as-a-Judge **本身也不够可靠**，需检索增强的验证 | **这正是本文如实标注"模型判定非人工金标准"的依据**（第 6.3 节） |
| Deceptive Grounding [33] | 实体归因在临床 RAG 中出现"欺骗性接地"失败 | 本文据此把支持度**按证据等级分层**报告，避免弱证据被当成强证据 |
| Compound Deception [34] | 100 条伪造引用出现在 NeurIPS 2025 接收论文中 | 说明"引用真实性"仍是未解决问题 |
| AI Hallucination from Students' Perspective [35] | 从学生视角归纳幻觉问题 | 支持本文把"可核查"作为面向学习者的核心需求 |

**本文的定位与差别**（一句话）：既有工作多面向**生成文本的句内/段落级引用**，
本文面向**学习产物的条目级出处**，并且不止报告"引用是否真实"，
还给出**"被引资料是否真的支持该断言"的模型判定结果，且按证据等级分层**；
对判定的可靠性边界（模型判定 ≠ 金标准）逐处如实标注 [30]。

## 2.7 上下文与成本控制

长上下文与成本是一体两面：**Lost in the Middle** 表明模型对长上下文中间部分的信息利用显著变差 [36]；
**MemGPT** 以操作系统的内存分层类比，提出上下文的分级管理 [37]；
**TokenDance** 从服务侧用 KV 缓存共享降低多智能体推理开销 [38]。
此外，**Laser** 也把"上下文堆积"列为主要病灶 [18]。

**与本文的关系**：本文没有做缓存共享或内存分层这类系统级机制，
而是采用**可在单机复算的成本控制**：先解剖账单（每轮固定重发约 1,956 tokens、
一轮约 10 次模型调用），再逐项量化杠杆（上下文瘦身 −15%、关闭深度思考 −26% 但质量回退、
工具声明精简 <3% 且伤工具选择 → 明确不做），全部进入第 5 章的消融表。
这样做的理由是：对一个**用户自付费用**的桌面应用，
"哪一项优化值得做、哪一项不值得做"本身必须给出可复核的依据。

## 2.8 技术基础（实现选型，非学术贡献）

| 组件 | 选用 | 理由 |
|---|---|---|
| 本地存储 | SQLite + FTS5（`tokenize='trigram'`） | 单文件、免服务；中文免分词可用（短查询走 LIKE 兜底，第 3.3 节） |
| 前后端通道 | JSON-RPC 2.0 over stdio | 壳与业务解耦，评测/CLI 可在无 GUI 环境运行（第 3.2 节） |
| 桌面壳 | pywebview 5.4（WebView2） | 无构建前端 + 双击即用；坑与处理见第 4.7 节 |
| 通用搜索 | 自建 SearxNG（Docker） | 免 key；聚合引擎在本机可用者见第 3.4.1 节 |
| 学术/代码检索 | arXiv、OpenAlex、GitHub 开放接口 | 免 key 可用；各自限速与字段约束见第 4.4 节 |

## 2.9 本章小结

- 综述覆盖 A–F 六个方向共 38 篇文献，其中 2025–2026 年工作 **24 篇**，全部带 arXiv 编号可核；
- **本文与前人工作的三处明确差别**：① 反幻觉不止做"引用真实性"，还做**条目级语义支持度**并按证据等级分层；
  ② 学习产物**按需生成**且视"擅自生成"为可计量指标；③ 成本控制给出**逐项量化与"测量后不做"的记录**；
- **本文对前人工作的一处依赖与一处自我限制**：沿用"细粒度归因优于整文档归因"的结论 [31][32]；
  同时承认 CiteGuard 的发现 —— 单靠模型判分并不足够可靠 [30]，
  因此本文把语义支持度标注为**模型估计**，并给出人工标注的后续方案（第 6.4 节）。
