# 19 抓取资料的命名与放置（人类可读方案）

> 状态：**代码侧已收口（2026-10-11）**。命名（标题 slug + sha8）与「目录怎么切分」的**布局参数**已落定；
> **真库尚未按新默认布局迁移** —— 读路径一律走库里的 `raw_path` / `text_path`，所以磁盘上仍是旧布局也能正常用；
> 真迁移放到下一轮单独跑、单独验（`scripts/migrate_raw_names.py`）。
> 目标：打开 `data/` 就能看懂 —— 文件名是**资料自己的标题**，目录按**会话/格式**分桶；同时不破坏
> 既有的去重、可回溯、正文不入库等约束。

## 0. 三条不能破的前提

1. **sha256 仍是去重与不可变的锚**（`documents.sha256` 保留）；文件名可以变，**锚不能丢**。
2. **一份资料可属于多个主题/多次调研** → **不按主题放文件**；主题/会话关系走索引与资料库分组。
3. **正文不入库**：库里只有元数据+摘要+路径；全文落 `data/text/`，原件落 `data/raw/`。

## 1. 命名规则（原件与全文同名，只换后缀）

```
<标题 slug>--<sha8>.<ext>
```

- **标题来源**：优先资料真实标题（arXiv 标题 / 页面 `<title>` / PDF 元数据）；
  - 取不到标题时降级为 `<域名>--<sha8>.<ext>`（**不编标题**）。
- **slug 规则**（`paths.slugify`）：
  - 去掉 Windows 非法字符 `< > : " / \ | ? *` 与控制字符（0x00–0x1f 与 DEL）；
  - 空白与下划线 → `-`；连续 `-` 合并；首尾 `-`（以及尾随 `. `）去掉；
  - **保留中英文**（可读性优先），不做拼音化；
  - **长度上限 60 字符**（按字符计，中英一视同仁），超出则截到 59 再补 `~`（**含 `~` 仍不超过上限**）；
  - 空 slug 时回落到 `<域名>`（都空则 `untitled`）。
- **`--<sha8>` 后缀**：取 `sha256` 前 8 位 —— 保证同名不同文**不冲突**、删了索引也能回溯到唯一原件。
- 例：`data/raw/教育智能体调研/paper/pi0-A-Vision-Language-Action-Flow-Model--ac4d3d6e.pdf`

## 2. 放置（**目录怎么切分由布局参数决定**）

```text
data/raw/<布局段…>/<标题>--<sha8>.<ext>      # 原件
data/text/<布局段…>/<标题>--<sha8>.txt        # 全文（与原件同目录同名，只差后缀）
data/library/<布局段…>/index.md              # 该桶的清单
data/library/index.md                        # 全库总清单
```

### 2.1 布局参数（`library.layout`）

**默认 `<会话>/<格式>`**（`paths.DEFAULT_LAYOUT = ("session", "format")`）：

```text
data/raw/<会话>/<格式>/<标题>--<sha8>.<ext>
```

- 配置位置：`config.yaml` 的 `library.layout`（示例见 `config.example.yaml`）；取值为斜杠分隔的段名，
  也可写 YAML 序列。
- 可用段（`paths.LAYOUT_SEGMENTS`）：

| 段 | 含义 | 取值来源 | 缺失时落 |
|---|---|---|---|
| `session` | 会话目录名 | 会话标题 slug（同名会话带短 id） | `unknown` |
| `format` | 格式 | `paths.doc_type_for(sources.source_type)` | `other` |
| `collected` | 收录年月 | `documents.fetched_at` | `unknown` |
| `published` | 发表年月 | 资料自己的时间戳（arXiv 号 / meta 日期） | `unknown` |
| `type` | `format` 的旧称（等价） | 同 `format` | 同 `format` |

- **为什么做成参数**：这是用户会反复改的**显示约定**，原来被写死在三处（`paths` / `tools` / 迁移脚本），
  改一次要三处同时改对、还容易漏。现在三处都读这一个值。
- **未知段直接报错**（`paths.normalize_layout`）—— 静默回默认 = 用户以为改了、其实还在老位置写文件。

### 2.2 各段口径

- **会话目录名**（`library.naming.session_dir_name`）：标题 slug；**两个会话标题同名时都追加 `--<短会话 id>`**
  （取 id 里字母数字的末 4 位）。为什么"同名的都加"而不是"第一个用裸名、后面的加"：后者依赖遍历顺序，
  换个入口就算出不同目录，迁移就不幂等；「撞车 → 撞车的每个都带短 id」**与顺序无关**。
  标题取不到 → `unknown`（不编一个看着像会话名的字符串）。
- **一份资料被多个会话带出**：**目录取最早收录它的那次**（`source_mentions` 按 `rowid` 的先后；
  与 `state/archive.py::list_documents` 的分组口径同一套，未另造关系），**索引「关联会话」列全部列出**。
- **格式**取自 `sources.source_type`，由 `paths.doc_type_for` 映射：`arxiv`/`openalex`/`semantic_scholar`/`doi`
  → `paper`、`github` → `code`、`official`/`web` → `doc`、`video` → `video`；认不出来 → `other`（**不编格式**）。
- **收录年月**（`library.naming.collected_month`）= `documents.fetched_at`（"我什么时候采到它"）→ `YYYY-MM`。
  **发表年月**（`library.naming.year_month_for`）= 资料自己的时间戳：优先 arXiv 号自带的 `YYMM`
  （`2410.24164` → `2024-10`）、再看 meta 里的发表/更新日期。
  **两个都取不到就各写各的 `unknown`**，绝不用抓取日期冒充发表日期，也绝不用发表日期冒充收录时间
  （与 `docs/05`「未知年份不编」同口径）。

### 2.3 索引（`data/library/**/index.md`）

每行**七列**：`标题 ｜ 收录年月 ｜ 发表年月 ｜ 格式 ｜ 来源域 ｜ 关联会话 ｜ 相对路径`。

「关联会话」列填**会话目录名**（与 `data/raw` 下的目录一一对应；同名会话带短 id），所以这一列能直接当下钻路径用；
多个用 `、` 分隔 —— 这样"一份资料被好几次调研带出来"既看得见、又不必搬文件。

索引由 `library.index.render_index`（**纯函数**）渲染，界面 `archive.reindex` 与迁移脚本共用同一份，逐字节一致。

## 3. 迁移历史文件（一次性；**代码就绪，真库尚未按新布局跑**）

`scripts/migrate_raw_names.py`（**布局是参数**：不给 `--layout` 就读 `config.yaml` 的 `library.layout`，
默认 `<会话>/<格式>`；未知段直接报错）：

1. `--dry-run` 先打印"旧路径 → 新路径"清单与冲突数，**不动任何文件**；
2. 正式跑：按 `documents` 表逐条 `rename`（原件与全文各一次），**在同一个事务里**更新
   `raw_path` / `text_path`；库更新失败就把文件改回去并如实报告（不留"库里说在这、盘上在别处"的错位）；
3. **幂等**：新名与库里现有路径逐字符一致就 `skip`（重跑 = 全部跳过）；
4. 冲突（目标已被别的文件占用、且不是同一个文件）：给新名追加 `--2`、`--3`…，在报告里单列；
5. **全部迁移**：不区分新旧，库里每条 `documents` 都按**当前布局**重算一遍路径；
6. 结束打印：布局 + 改名数 / 跳过数 / 冲突数 / 失败数（失败逐条给原因，不静默）。

**为什么不用枚举"旧布局"**：入库时写下的 `documents.raw_path` / `text_path` 就是"旧路径"，
迁移只做一件事 —— 把文件从它现在的位置搬到按当前布局算出来的位置 —— 所以任意已知旧布局都能迁到任意新布局。

**旧目录清理与 `_orphan/` 策略**（`library.migrate._cleanup_old_dirs`）：

- 把 `data/raw` / `data/text` 下**未被库引用的**历史文件移进 `data/raw/_orphan/`、`data/text/_orphan/`
  （**隔离而非删除** —— 那些文件已无元数据、编不出人类可读的名字，删了就是数据丢失）；
- 计划涉及的任何路径（含失败后留在原地的旧路径）都受保护，不会被误当孤儿；
- **扫描范围只限"旧布局形状"**（`<sha 前 2 位>/`、`<类型>/<年-月>/`、`<类型>/unknown/`）：新布局是
  `<会话>/<格式>/`（文件在第三层），资料一多整棵 `data/raw` 走一遍纯属浪费，而新布局下的文件都是
  本轮/上次迁移的产物、必然被库引用 —— 跳过新布局的会话目录就是省下来的时间；
- 空掉的旧桶目录（`<类型>/<年-月>/`、`<2位>/`）随即自底向上删除。

## 5. 测试（全桩测）

- `slugify`：非法字符、空白/下划线、连续 `-`、中英混排、超长截断、空标题回落；
- **布局**：默认 `会话/格式`、段序可变（`type` 是 `format` 的旧称）、未知段报错、目录段不许越出 `data/`、
  会话/格式/年月缺失各自的回落、同名不同 sha 不冲突、超长路径不触发 Windows 260 限制；
- **命名**：收录年月取 `fetched_at` / 取不到落 `unknown`、会话短 id、**同名会话都带短 id 且顺序无关**；
- **索引**：七列都真写出来、收录年月与发表年月分开、多会话时目录取最早而列全部、空库不报错；
- **迁移**：`--dry-run` 不落盘、正式跑后 DB 路径与磁盘一致、重跑幂等、冲突追加 `--2` 并报告、
  布局参数改目标目录、清理只扫旧布局形状。

## 6. 明确不改的

- 不按主题移动文件；不做拼音化；不引入新依赖；不改 `sha256` 去重逻辑；
- 不把摘要/正文塞进文件名以外的任何新地方（正文照旧不入库）。

## 8. 抓取格式与大文件策略（2026-10-11）

### 8.1 能吃哪些格式（全部标准库，零新增运行期依赖）

| 格式 | 抽取方式 | 落盘后缀 | `extract_engine` |
|---|---|---|---|
| `.pdf` | pymupdf 本地抽字；无文字层走 MinerU | `pdf` | `local` / `mineru` |
| `.docx/.xlsx/.pptx` | `fetch/office.py`（zip + XML） | `docx/xlsx/pptx` | `local-office` |
| **`.epub`** | `fetch/formats.py`（zip + XHTML，按章抽字） | `epub` | `local-ebook` |
| **`.rtf`** | 控制字剥离成纯文本 | `rtf` | `local` |
| **`.zip/.tar/.tar.gz/.tgz/.tar.bz2/.tar.xz`** | **只列目录**（名字 + 大小），不解内容 | `archive` | `local-archive` |
| `.svg/.xml/.rss/.atom` + `.md/.py/.json/.csv/.yaml/.ipynb/.sql/…` | 原样解码 | 原后缀 | `local` |
| HTML（其余） | `fetch/html_text.py` | `html` | `local` |
| 音视频 | **不抽正文**，只登记大小/类型/URL | 原后缀 | `none` |

- **扩展名判定先看 URL 后缀再看 media type**（`fetch/formats.py::guess_extension`）：
  很多站点把 `.md`/`.py` 用 `text/plain` 甚至 `application/octet-stream` 发出来，只看 media type 会一律认成 txt。
- 文本类**不过 HTML 提取器**：那是洗正文用的，会把缩进与代码结构洗没。

### 8.2 优先抓真文件、不抓落地页

有明确文件入口的来源先取文件：`arxiv.org/abs/<id>` → `arxiv.org/pdf/<id>`；**拿不到再回落到原 URL**。
抓的哪一种如实记在 `source.fetch` 返回的 `requested_url` / `fetched_url` / `used_landing_page`。
**`sources.url` 始终是用户/检索给的那个地址**（它就是"去原站"的入口），**去重逻辑一字不改**。

> 背景：磁盘上曾 100% 是 `.html` —— 因为抓的是落地页（如 `arxiv.org/abs/…` 的摘要页，不是 PDF）。

### 8.3 大文件阈值（`fetch.large_file_mb`）

- **阈值可配**：`fetch.large_file_mb`（默认 **20**，单位 MB；内部 `large_file_bytes = int(mb * 1_000_000)`）。
- **超过阈值不抽正文**：只登记元数据（大小 / mime / 源地址），标 `extract_status="skipped_large"`，
  `extract_engine="none"`，`extract_detail` 写明「文件 N 字节超过阈值 M 字节（xMB）」。原件照常落盘。
- 音视频 → `skipped_media`；源码包/大压缩包 → `skipped_large`；两者在界面上都标「需到原站看 / 需手动下载」。
- **与 `fetch.max_bytes`（硬上限，默认 20MB）的分工**：`max_bytes` 是出网层**直接拒收**的红线
  （超过它连字节都拿不到，RPC 会回 `too_large`）；`large_file_mb` 是**落盘后要不要抽正文**的阈值。
  想抓更大的文件就把 `max_bytes` 调大；只想登记不想抽正文就把 `large_file_mb` 调小。

### 8.4 按需下载（`archive.download`，RPC 见 `docs/01 §3.3`）

- 界面详情里给两个入口：**「去原站」**（用 `sources.url`）+ **「下载」**（调 `archive.download`）。
- **默认关**：`features.enable_download=false` 时**不动网**，回 `{ok:false, reason}`。
- **面板在哪开**：设置 → **功能 → 「允许按需下载」**（写回 `config.yaml` 的
  `features.enable_download`，保存即生效，不必重启）。地图详情里「获取正文」失败时给的
  「去设置」按钮会**直接定位到这一行**（切到「模型与生成」分类、滚进视口并高亮）；
  资料库那边的「下载」同样受这一个开关控制 —— 关着时两处都只会说"未开启"，不会出网。
- 真去下载走 `fetch/http.py`（限速/退避/缓存/robots/体积上限都在这一层），落 `data/raw/`，
  返回**人类可读路径**（按本文件的布局）+ 字节数。失败（非零状态 / 网络异常 / 超硬上限）**如实回原因**，不假装成功。
