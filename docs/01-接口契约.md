## 1. 分层与调用方向（单向，不许反向）

```
┌──────────────────────────────────────────────────────────────┐
│ 桌面壳  pywebview (Edge WebView2)                             │
│   ui/index.html + app.js  —— 只发 JSON-RPC，不读库、不发外网   │
└───────────────────────────┬──────────────────────────────────┘
                            │ JSON-RPC 2.0 over stdio (UTF-8, 一行一消息)
┌───────────────────────────▼──────────────────────────────────┐
│ rpc/server.py  —— 方法表 + 参数校验 + 流式通知                 │
└───────────────────────────┬──────────────────────────────────┘
                            │ 进程内函数调用
┌───────────────────────────▼──────────────────────────────────┐
│ runtime/  单轮 loop：组装上下文 → 调模型 → 执行工具 → 落 trace │
│   registry.py（工具注册表） context.py（会话上下文）           │
└───────────┬───────────────────────────────┬──────────────────┘
            │ 模型可见工具                   │ 读写
┌───────────▼──────────────┐    ┌───────────▼──────────────────┐
│ tools/*.py（6 主线 + 1 降级）│    │ state/db.py（SQLite + FTS5） │
└───────────┬──────────────┘    └──────────────────────────────┘
            │ 只经此层出网
┌───────────▼──────────────────────────────────────────────────┐
│ providers/*（arxiv/openalex/s2/web/github/llm）               │
│ fetch/http.py —— 统一限速 / 退避 / 缓存 / UA / 超时           │
│ data/raw/ 原件 ｜ data/text/ 纯文本 ｜ data/cache/ 抓取缓存    │
└──────────────────────────────────────────────────────────────┘
```

三条硬规则：

1. **前端只调 RPC**：不直接读 SQLite、不直接发 HTTP。单入口才可能把每次调用记进 `tool_traces`，指标才是真数。
2. **模型只看得见 `tools/`**：加能力 = 加一个工具或一个 provider，不许在 loop 里塞特例分支。
3. **出网只走 `fetch/http.py`**：限速、退避、缓存、UA 全在这一处；绕过它的请求在 review 里直接打回。

## 2. JSON-RPC 2.0 传输层

- **传输实现有两种，方法表与语义完全相同**（分发逻辑只有一份，在 `rpc/methods.py`）：
  1. **stdio**：一行一个 JSON 对象，UTF-8 无 BOM —— 桌面壳拉起的后端进程、CLI 冒烟测试、自动化测试都用它
  2. **桌面壳**：pywebview 窗口 + **同样的 `python -m scholarscout --rpc` 子进程**（`desktop/rpc_client.py` 管进程与帧，`desktop/bridge.py` 只做转发）。壳里**不 import 任何业务模块**，理由：
     - 分发只有一份：桌面与 CLI 走的是同一条必经之路，测试覆盖的就是用户跑的那条
     - 后端崩了窗口还在，界面能把错误显示给人看，而不是整个应用消失
     - 中文路径与编码坑（`docs/03 §9`）被挡在子进程里：子进程强制 `PYTHONUTF8=1` / `PYTHONIOENCODING=utf-8`
     - 界面要做到"点了就有反应"，后端只要保证"回了就是真的"

壳暴露给 JS 的只有四个方法（都在 `desktop/bridge.py`，返回值统一 JSON 字符串）：
`info()` / `rpc(method, params_json)` / `reveal(path)` / `shutdown()`；
事件反向推给 `window.scoutEvent({method, params})`，窗口未就绪时先缓冲再补发（避免开窗瞬间丢事件）。
  选择依据：壳与后端同机时用桥更简单；后端需要独立进程/远程时用 stdio。**客户端看到的方法与事件一致**。
- 版本：JSON-RPC 2.0；**通知**（无 `id`）用于流式事件
- 启动顺序：壳启动 → 装配上下文（`app.build_context`）→ 调 `system.health` 自检 → 调 `session.list` 渲染侧栏
- 错误码：

| code | 含义 |
|---|---|
| -32700 / -32600 / -32601 / -32602 / -32603 | JSON-RPC 标准（解析/请求/方法不存在/参数非法/内部错误） |
| -32000 | 未登录或未配置模型（缺 API key） |
| -32001 | 外部服务不可用（arXiv/S2 挂了或限速中） |
| -32002 | 资源不存在（source_id / doc_id 查不到） |
| -32003 | 抓取被拒（403/429/robots） |
| -32004 | 超时 |
| -32005 | 取消（用户点了停止） |

## 4. 流式事件（notification）

| 事件 | 载荷 |
|---|---|
| `chat.delta` | `{turn_id, seq, kind:"text"\|"thinking", text}` |
| `chat.tool_call` | `{turn_id, seq, call_id, tool, args_digest, args_preview}` |
| `chat.tool_result` | `{turn_id, seq, call_id, ok, digest, latency_ms, refs}` |
| `chat.done` | `{turn_id, stop_reason, usage:{prompt_tokens, completion_tokens}}` |

`stop_reason` 取值固定：`completed` | `tool_limit` | `cancelled` | `error` | `refused`。
（`tool_limit` 必须存在：小模型不调工具与死循环都要能区分，这是踩过的坑。）

## 5. 工具契约（模型可见）

### 5.0 通用约定

- 命名：`namespace.action`，namespace ∈ `{research, source, topic, route, note, kb}`
- 每个工具 = `ToolSpec{name, description, parameters(JSON Schema), handler, toolset}`
- JSON Schema 一律 `additionalProperties: false`，参数校验失败 → `-32602`
- **返回统一包络**（这是可追溯性的根）：

```json
{
  "ok": true,
  "data": { },
  "error": null,
  "refs": {"source_ids": [], "doc_ids": [], "chunk_ids": [], "note_ids": [], "route_ids": []}
}
```

> 规则：**任何进入回答的 id 必须回填 `refs`**。回答里写了没回填的 id，等于假引用 —— 评测里算错，答辩时算失信。

- 所有工具调用落 `tool_traces`（名字、args 摘要、结果摘要、时延、成败）
- `toolset` 取值：`research`（默认开）｜ `kb`（默认关，消融开关）

**工具名的两副面孔（真机跑出来才知道的硬约束）**：

| 场景 | 形式 | 例 |
|---|---|---|
| 注册名 / 文档 / 事件 / `tool_traces` / 论文 | 点号命名空间（**规范名**，唯一真相） | `research.search` |
| 发给模型的 `tools[].function.name` 与模型回传的 `tool_calls[].name` | 点换成双下划线（**线上名**） | `research__search` |

原因：OpenAI 兼容 API（DeepSeek 实测）校验 `^[a-zA-Z0-9_-]+$`，**带点直接 400**，
整个工具层会整体不可用。转发由 `runtime/registry.py` 的 `wire_name()` / `canonical_name()` 双向映射，
调用进来时 `get_spec()` 两种名字都认；注册名禁止包含 `__`（否则映射有歧义，注册即报错）。

### 5.1 `research.search`

```
input : {query: str, sources?: ["arxiv","bing","duckduckgo","searxng",
                                "tavily","serper","brave","google_cse","auto"],
         limit?: int = 10, year_from?: int, sort?: "relevance"|"date", lang?: "zh"|"en"}
output: {items: [source_card], provider_status: [{provider, ok, n, interval_s?, error?}]}
```

**来源分三层**（`providers/settings.py` 是唯一真相）：

| 层 | 来源 | 要不要 key | 本机实测 |
|---|---|---|---|
| 学术 | `arxiv` | 免 | ✅ 可用（≥3s 限速；只索引英文） |
| 代码/教程 | `github` | 免（可选 token 提额） | ✅ 可用（0.9s 返回真仓库；未认证 Search API 10 次/分钟 → 间隔 6s） |
| 通用 | `searxng` | 免（自建实例） | 需 `search.searxng_base_url`；容器没起时 provider 会直接告诉你怎么修 |
| 通用 | `bing` / `duckduckgo` | 免（抓结果页） | ⚠️ robots 禁止搜索页 / 国内需梯子 → **默认关**，要抓得开 `search.allow_searchpage_scraping` |
| 商用 | `tavily` / `serper` / `brave` | 要（`.env`） | 未配 key 时如实报 `missing_api_key` |
| 商用 | `google_cse` | 要（`GOOGLE_CSE_KEY` + `search.google_cse_cx`） | 每天 100 次免费额度 |

- `sources` 省略或写 `["auto"]` → 用 `search.providers`（默认 `auto`）：**只带现在真能用的来源**
  （arxiv + 已配实例的 searxng + 已配 key 的商用来源）；抓取类来源不会被 auto 带上，
  避免每次检索都去撞超时/被拒
- **缺 key、缺配置、被 robots 拦**都写进 `provider_status.error`（`missing_api_key` /
  `missing_config` / `blocked_by_robots` / `not_implemented` / `unknown_provider`）——
  "没搜到"与"这层没配"必须能分开，否则模型会拿旧结果硬凑（真机实测过）
- 真机自检：`.venv/Scripts/python.exe scripts/check_search_sources.py --all`

`source_card`：

```json
{"source_id":"src_xxx","title":"…","url":"…","domain":"arxiv.org","authors":["…"],
 "year":2025,"venue":"NeurIPS","source_type":"arxiv","tier":1,"tier_label":"一手权威",
 "score":0.82,"snippet":"…","has_full_text":true}
```

- **必须落库后才返回 `source_id`**；同一 URL 复用既有 id（`sources.url_canonical` 唯一约束保证）
- 每个 provider 独立限速；某个 provider 失败**不阻塞**其他，只在 `provider_status` 里标红
- 网页来源统一 `source_type="web"` → 判权默认落到 tier 4；但**域名规则优先**，
  所以 bing/商用检索命中的 `nature.com`、`.edu.cn` 等仍按域名判到 tier 1–2

### 5.2 `source.fetch`

```
input : {url?: str, source_id?: str, want?: ["text","html","pdf"], force?: bool = false}
output: {doc_id, source_id, mime, chars, lang, raw_path, text_path,
         extract_status, extract_engine, extract_detail, truncated,
         summary: {summary_id, title_zh, summary_short, points, prompt_version, degraded, guard_failed}}
```

- **这一步同时完成"取资料"与"出摘要"**（流水线见 `04-摘要提取方案.md` §4）：正文抽取 → 清洗 → 截断 → 提示词 → 模型 → 解析 → 守卫 → 落 `summaries`
- 原件落 `data/raw/<sha256[:2]>/<sha256>.<ext>`；**全文纯文本**落 `data/text/<doc_id>.txt`（**库里只放摘要，不放正文**）
- 去重顺序：`sha256` → `ETag`/`Last-Modified` → 命中即回，不重抓（摘要已存在则一并返回，不重复调模型）
- `extract_status` ∈ `ok` | `mineru_ok` | `no_text_layer` | `mineru_failed` | `too_large` | `blocked` | `empty`
- **`extract_detail` 记"为什么"**（如 `没有文字层（多为扫描版）→ 交给 MinerU；failed: model service is temporarily unavailable`）。
  只有状态没有原因的话，"扫描版走 MinerU"在论文里就是黑盒：
  分不清"这份文档确实没有文字层"与"解析服务当时没干活"
- PDF 抽取顺序：**pymupdf 本地抽取 → 抽不到文字层才走 MinerU**（`features.enable_mineru` 控制开关）；
  MinerU 优先用精准接口（配了 `MINERU_API_TOKEN`），401/额度不足自动退回免 token 的 Agent 轻量接口
- `extract_engine` ∈ `local`（pymupdf / HTML 解析）| `mineru`（走了官方接口，具体是 agent 还是 precise 记在 `extract_detail`）| `none`
- 扫描件或抽不出文字 → **走 MinerU 官方接口**（决议 8），失败也不阻塞：`degraded=1`，用元数据出摘要
- 全文超限（默认 6 万字符）→ 只保留前 N 字符并记 `truncated=1`，**摘要照出**（决议 9）
- 摘要用便宜档模型；正文不入库、不进 FTS（决议 5/6）

### 5.3 `source.grade`（"判断权威性 / 判断相关性"的落点）

```
input : {source_ids?: [str], urls?: [str], topic?: str,
         use_model?: bool = true, limit?: int = 20}
output: {items: [{grade_id, source_id, tier, tier_label, authority, relevance,
                  relevance_source, verdict, matched_rule, reason, signals, guard_failed}],
         skipped: [{source_id|url, reason}],
         counts: {核心: n, 相关: n, 外围: n, 排除: n},
         topic, relevance_engine}
```

- `verdict` ∈ `核心` | `相关` | `外围` | `排除`；阈值写在 `grading/relevance.py:verdict_for`（docs/02 §3.1）
- **authority 由规则表 `source_tier_rules` 判定，不由模型拍脑袋** —— 可解释、可复现，论文里能算一致率
- **relevance 才交给模型**（给了 `topic` 且 `use_model=true` 时），且必须给 `signals` 与 `reason`；解析失败**退回本地确定性打分**并标 `guard_failed=1`
- 没给 `topic` 时只判权威性，`relevance=null`、`relevance_source="none"`
- **三个参数都不给**时，顺手判最近入库、`tier` 还为空的前 20 条（`limit` 可调）
- 结果写入 `source_grades`（**只追加**）并把 `tier/authority` 反范式化回 `sources`

### 5.4 `topic.build_map`

```
input : {topic: str, source_ids?: [str], max_nodes?: int = 20, use_model?: bool = true}
output: {topic_id, topic, mode, source_count,
         nodes: [{nid, label, kind, source_ids, dropped_source_ids}],
         edges: [{src, dst, rel}],
         stats: {nodes, edges, ungrounded_nodes, dropped_edges, ungrounded_labels}}
```

- `kind` ∈ `concept` | `method` | `dataset` | `tool` | `venue` | `source`
- `rel` ∈ `prerequisite` | `variant` | `uses` | `evaluates`（模型给了别的词就落 `uses`）
- **候选来源三级取**：给了 `source_ids` 就用它 → 否则取该主题下判权为「核心/相关」的来源 → 否则取最近入库的 25 条
- **每个 node 至少挂 1 个真实 source_id**；挂不上的节点保留但 `label` 前缀 `[无出处]` 并计入 `stats.ungrounded_nodes`，白名单外的 id 进 `dropped_source_ids`
- 端点不存在的边一律丢弃（计入 `stats.dropped_edges`）
- `mode` ∈ `model`（模型梳理）| `flat`（没有模型或输出不可解析时的**兜底扁平图**：每个来源一个节点、无边）
- 结果落 `topic_maps`（`graph_json`），`topic.get` 可取回

### 5.5 `route.plan`

```
input : {topic, level?: "入门"|"进阶"|"研究", weeks?: int = 4, weekly_hours?: int = 6,
         source_ids?: [str], use_model?: bool = true}
output: {route_id, topic, level, mode,
         weeks: [{idx, goal, checkpoint, items: [{kind, title, source_id?, why, est_minutes}]}],
         stats: {weeks, items, resource_items, grounded_resource_items, exercise_items,
                 ungrounded_items, ungrounded_titles, dropped_duplicates, sources_used}}
```

- `kind` ∈ `paper` | `doc` | `video` | `code` | `exercise`（模型给别的词就落 `doc`）
- **条目分两类，出处要求不同**（口径见 docs/05 §3.2）：
  - **资料类**（`paper`/`doc`/`video`/`code`）声称"这里有一份资料" → 必须挂库里已有的 `source_id`，
    否则 `source_id = null` 并计入 `ungrounded_items`（`why` 里要说明是补充项）
  - **行动类**（`exercise`）是"你要动手做的事/产出" → 来源列写 `-`，**不计入** `ungrounded_items`
    （练习本来就没有出处；把它算成"无出处"既误报，又会反向逼模型硬挂一个来源 = 真幻觉）
- 同一来源在一条路线里只出现一次（重复条目丢弃并计入 `dropped_duplicates`）
- `est_minutes` 卡在 10–600；`weeks` 卡在 1–24
- `mode` ∈ `model` | `skeleton`（没模型时的兜底：按 tier 与年份把已有资料均匀排进各周，不做内容推断）
- 结果落 `learning_routes`（`plan_json`）；`route.export` 导出成带 `why` 与来源的 Markdown

### 5.6 `note.save`

```
input : {kind: "summary"|"note"|"card", title?: str, content?: str,
         cards?: [{front, back}], refs?: {source_ids?, doc_ids?, summary_ids?}, tags?: [str]}
output: {note_id, kind, title, path, card_count, cards}
```

- `kind=card` 走**抽背卡**：批量给 `cards`，或给一对 `title`（问题）/`content`（答案）；每张必须是正反面齐全
- `kind=note` / `summary` 必须有 `content`
- 同时导出 Markdown 到 `data/notes/<note_id>.md`（库里 `content` 也是 Markdown，两边一致）
- 抽背卡的写卡标准（`tools/note_save.py:QUALITY_RULES`）：一道题只考一个点、背面带数字与来源、按「1 道原题 + 2 道延伸题」组织

### 5.7 `source.reprofile`（重跑摘要）

```
input : {doc_id: str, force?: bool = false}
output: {summary_id, prompt_version, degraded, guard_failed}
```

- 首次摘要由 `source.fetch` 内部生成（流水线见 `04-摘要提取方案.md` §4）；本工具用于**换提示词版本后显式重跑**，或首次没取到正文、事后补出更好的摘要
- `summaries` 表有 `UNIQUE(doc_id, prompt_version)`：同一版本重复调用幂等，不产生重复行
- 重跑**不删除旧版本**（论文要能说清"这批数字出自哪版提示词"）
- `prompt_version` = 拼装后提示词的 `sha256[:12]`

### 5.8 `kb.search`（**降级通道 / 消融开关，默认关**）

```
input : {query: str, k?: int = 5}
output: {items: [{chunk_id, text, score}]}
```

- 只在 `toolsets` 含 `kb` 时注册；`config.ENABLE_KB=0` 整批关掉
- 用途：论文消融对照（回答"开放世界方案为什么不需要自建知识库"），不是主线功能

## 8. 决议记录（2026-10-05，9 项全部拍板）

| # | 问题 | 决议 |
|---|---|---|
| 1 | 「辅助学习」形态 | **会话内讲解 + 抽背卡**（`note.save(kind='card')` 产正反面卡片，可从资料库反查）。讲义生成不做 |
| 2 | 通用搜索 provider | **先只做免 key 的源**（arXiv / OpenAlex / Semantic Scholar / 官方文档直抓 / GitHub）；通用搜索只留 `providers/web.py` 接口不实现 |
| 3 | 是否允许多轮澄清 | **允许，每轮最多反问一次**，trace 记 `clarify` 事件（可统计澄清次数） |
| 4 | PDF 抽取库 | **`pymupdf`**（已批准，许可证 AGPL-3.0，毕设不分发无碍） |
| 5 | 正文入库粒度 | **库里只放摘要**；正文全文落 `data/text/`，原件落 `data/raw/`。分块留给以后的 RAG |
| 6 | 中文检索方案 | **`tokenize='trigram'`**；检索范围**仅摘要 + 会话记录**。代价：2 字查询走 LIKE 兜底（见 `02 §4.1` 实测） |
| 7 | 纯文本是否另存 | **另存** `data/text/<doc_id>.txt` |
| 8 | 扫描版 PDF | **不自己造轮子**，走 **MinerU 官方 API**（免登录轻量接口优先，大文件用需 token 的精准接口），见 `04-摘要提取方案.md` §7 |
| 9 | 超长文档 | **只存原件，摘要照出**，`documents.truncated=1` 标记 |
