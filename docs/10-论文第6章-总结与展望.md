# 第 6 章 总结与展望

## 6.1 工作总结

本文完成了一个**桌面级、全本地的学习辅助调研智能体 ScholarScout**：
输入一句方向描述，系统在开放世界检索真实资料、抓取正文并摘要、生成知识地图与学习路线
（抽背卡按用户要求才生成），全部数据落在本机 SQLite 与文件系统中，双击即用。

实现规模与验证状态如下（数字取自本机 `git` / `pytest` / `wc` 的真实输出）：

| 项 | 数量 |
|---|---|
| 后端源码 | 75 个文件，12,314 行 |
| 前端（无构建） | 3,842 行 |
| 测试 | 85 个文件，11,245 行，**830 项**（全离线） |
| 数据库迁移 / schema 版本 | 8 个 / v8 |

| 来源适配器 | 12 个（免 key 4 个：arXiv / OpenAlex / GitHub / 自建 SearxNG） |

## 6.2 主要结论

1. **判权分层可以做到确定性且保守**：规则表驱动的层级判定在 E1 上一致率 100%（κ=1.000）、
   误升率 0%；而语义相关性**不交给它**（本地打分一致率 58.3%，κ=0.444），
   这条边界划定让"为什么这条资料排前面"始终可解释（第 5 章 §5.3、§5.9）。
2. **反幻觉必须有两级证据，且要分层报**：守卫把"虚高的出处覆盖率"从 92.6% 校正到 76.9%
   （差值是守卫的价值）；端到端覆盖率 100%，但**引用语义支持度约 91%**
   （知识地图 91.7%、学习路线 90.9%），分层后**强证据 8/8=100%、弱证据 93.3%** ——
   即"覆盖率 100%"只能读作**可归属率**，真正的落差来自弱证据样本（第 5 章 §5.7.4、§5.8.2）。
3. **成本控制的关键是"先解剖账单，再砍有量级的那条"**：每轮固定重发约 1,956 tokens、
   一轮对话约 10 次模型调用；上下文瘦身使同题输入下降 15%（默认开）；
   关闭深度思考可省 26% token 但质量回退明显（默认不开）；
   **工具声明精简经测量收益不足 3% 且会伤工具选择，明确判定不做**（第 5 章 §5.7.2、§5.7.3）。
4. **产物按需生成既省成本又更贴合用户主导**：探针集实测"题面没要却仍出产物 0%（0/3）"、
   结尾主动询问 100%、点单后成功率 100%（第 5 章 §5.6）。
5. **在"人定接口、AI 填实现"的协作方式下，工程门槛是正确性前提而非形式**：
   lint/类型检查/测试/构建/依赖白名单/防漂移测试六项门槛在本轮开发中实际拦下了
   类型标注错误、嵌套分支、前端复选框默认值反向等真错（第 4 章 §4.10）。

## 6.3 局限性

本节收敛第 5 章 §5.8 的已知局限，并说明其影响范围：

| 局限 | 影响 |
|---|---|
| **样本量小**（E1 24、E2 13、E3 6、探针 3） | 只能作方向性结论，**不做统计显著性主张** |
| **语义支持度是模型判定**，非人工金标准 | 该数字应读作"模型估计"；要作结论需补 20–30 条人工标注 |
| 本地相关性打分较弱（κ=0.444） | 只影响离线路径；端到端以模型路径为准 |
| **扫描版 PDF 未端到端验证成功** | 外部解析服务当期不可用，属环境限制；降级链与 `degraded` 标记已实现 |
| 单一模型档位、单一机器（Windows 11） | 结论不外推到其他模型与平台 |
| **没有用户研究** | 本文的"可用性"指标是**运行指标**（完成率/时延/token），不是主观满意度；`asked_rate` 一类的措辞启发式指标已在口径上标注其边界 |

## 6.4 未来工作

按"补强论文证据 → 提升可用性 → 扩展能力"三层排序：

**（1）补强证据**

1. **人工标注金标准**：抽 20–30 条（断言，来源）对做人工判定并报一致性（κ），
   把语义支持度从"模型估计"升格为有金标准对照的结论 —— 这是优先级最高的一项。
2. **扩大评测集**：E3 扩到 20 题以上、纳入多语言与跨方向，并补"同一题多次运行"的稳定性度量。
3. **成本-质量曲线**：在 2–3 个模型档位上重跑 E3，给出"每元产出"的对比，
   把"省钱"从单点实验变成曲线。

**（2）提升可用性**

4. **扫描版 PDF 端到端打通**（含 MinerU 服务可用性回退策略与离线 OCR 兜底）。
5. **产物增量修改**：当前"把第 3 周改成 6 周"会整条重生成（贵且可能前后不一致），
   应改为基于既有路线打补丁。
6. **抽背卡的"练"模式**：现在只生成卡片，缺少翻面/自评/计分 ——
   与"1 道原题 + 2 道延伸题、答完先判分再讲透"的学习习惯直接对接。
7. **答辩/演示友好模式**：预热资料库 + 短链路演示题 + 网络不可用时的兜底展示路径。

**（3）扩展能力**

8. **来源时效性与多样性指标**：在报告里加入年份分布与来源类型分布，作为调研质量的辅助信号。
9. **长会话记忆管理**：当前用"历史字符预算 + 保头保尾"防膨胀，可进一步做摘要式记忆。
10. **分享与协作**：现在分享=可复制的 Markdown，可扩展为只读打包（资料 + 产物 + 可复算报告）。
11. **跨平台打包**：当前 exe 只是启动器（依赖本机 Python 环境），可做真正的自包含分发。

## 6.5 工程与协作层面的经验

本课题的推进方式本身是一个可复用的经验样本（"人定接口、AI 填实现"）：

| 经验 | 具体做法 | 为什么重要 |
|---|---|---|
| 接口先定、实现后填 | `docs/01`–`docs/04` 冻结后再写代码 | 避免同一概念出现两套命名 |
| 一次只改一个文件或函数 | 56 次小提交，每次可回滚 | 回归能定位到唯一改动 |
| 门槛全绿才合 | `scripts/check.sh` 六项 | 把"本地能跑"变成"可交付" |
| 新增依赖要审批 | 白名单 + 检查脚本 | 拦住"随手 import 不存在的包" |
| **提示词分档即实验条件** | 两档提示词用内容哈希钉住（`f68b1b7abb03` / `af6f1b33e12c`） | 改一个字就是换了实验条件，必须显式承认 |
| **指标口径优先于数字好坏** | 发现 `ungrounded` 与 `auto_artifact_rate` 两个口径都错过并返工（第 5.8.1 节） | 口径错的代价远大于数字难看 |
| 失败与返工照实录 | 第 5.8 节专列返工与局限 | 论文的可信度来自"敢写自己错过" |

## 6.6 结语

本文的工作可以概括成一句话：**把"一个 Agent 说它调研了一个方向"变成"一套能复算的数字"** ——
哪些资料是真的、哪些引用真的支持结论、以及这一切花了多少钱。
在这三件事上，本文给出的不是宣称而是可复核的实验与代码：
覆盖率 100% 与支持率约 91% 同时成立、守卫把虚高覆盖率校正掉 15.7 个百分点、
上下文瘦身带来 15% 的输入下降、以及一项"测量后决定不做"的优化。

系统仍有明确边界（样本量、模型判定、扫描版、单一平台），
这些边界与结论一并写在正文中 —— 因为对这类系统而言，**知道自己在哪里不成立，比多一个功能更重要**。
