# 02 数据模型（SQLite + FTS5）

> 状态：**v0.1 待冻结** ｜ 2026-10-05 ｜ 本文件是 DDL 的唯一权威来源
> 任何代码若与本文件不一致，改代码；要改模型，先改本文件并说明理由。
> 分工：`src/scholarscout/state/schema.sql` 由本文件生成，`state/migrations/NNNN_*.sql` 只做增量。

## 0. 设计原则

1. **元数据进表，正文进 FTS，原件进磁盘**（用户决议 #5）
   - `data/raw/` 放原件（PDF / HTML），路径记在 `documents.raw_path`
   - `data/text/` 放抽取出的纯文本副本（人可读、可 grep、可备份）
   - SQLite 里放：出处、简介、会话关联、检索索引
2. **可追溯性是第一约束**：任何进入回答的 `source_id` / `doc_id` 都必须能在库里找到，且能反查"它是在哪次会话、哪一轮被用到的"（`source_mentions` 表）
3. **索引由触发器维护**，不在应用层手动同步（照抄 Hermes `state.db` 的做法，少一类 bug）
4. **分层规则数据化**：来源权威性来自 `source_tier_rules` 表，不由模型自由心证 —— 否则论文指标不可复现
5. **迁移幂等 + 版本化**：`schema_version` + 编号迁移文件，重复执行不报错

## 1. 命名与类型约定

| 约定 | 规则 |
|---|---|
| 主键 | `TEXT`，前缀化短 id：`src_` / `doc_` / `chk_` / `ses_` / `msg_` / `trc_` / `sum_` / `tpm_` / `rte_` / `not_` |
| 时间 | `TEXT`，ISO-8601 带时区，如 `2026-10-05T10:46:00+08:00`（**不用** `datetime('now')` 默认值，由应用层统一生成） |
| 布尔 | `INTEGER` 0/1 |
| 结构化字段 | `*_json` = `TEXT`，应用层负责序列化；**不建 JSON 列**（保持 sqlite3 stdlib 兼容） |
| 外键 | 必须显式声明；连接时 `PRAGMA foreign_keys=ON` |
| 检索 | 所有面向用户的检索走 FTS5，不允许 `LIKE '%…%'` 全表扫（例外：<3 字兜底，见 §6） |

## 3. 来源与分层（决策 #3：全来源按层打分）

```sql
-- 权威性分层规则：数据驱动、可解释、可复现（评测里"权威性判定"的分母就在这里）
CREATE TABLE IF NOT EXISTS source_tier_rules (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  match_type TEXT NOT NULL CHECK (match_type IN ('domain','domain_suffix','url_regex','source_type')),
  pattern    TEXT NOT NULL,                     -- 例：'arxiv.org' / 'docs.python.org' / 'github.com'
  tier       INTEGER NOT NULL CHECK (tier BETWEEN 1 AND 4),
  weight     REAL NOT NULL DEFAULT 1.0,
  note       TEXT,
  enabled    INTEGER NOT NULL DEFAULT 1,
  UNIQUE (match_type, pattern)
);
-- tier 语义（写死进论文第 3 章）：
--   1 = 一手权威：官方文档 / 规范 / RFC / 顶会论文 / 预印本源站（arxiv、OpenReview）
--   2 = 学术索引与同行评议：OpenAlex、Semantic Scholar、期刊页、DOI 落地页
--   3 = 社区与教程：GitHub 仓库、官方博客、技术博客、问答站
--   4 = 未知 / 低质 / 聚合转载 / 内容农场
-- 打分：authority = f(tier) 由规则表决定；relevance 才交给模型（见 01 契约 source.grade）

CREATE TABLE IF NOT EXISTS sources (
  id            TEXT PRIMARY KEY,
  url           TEXT NOT NULL,
  url_canonical TEXT NOT NULL UNIQUE,   -- 去 utm_*、去锚点、排序 query、统一小写 host
  domain        TEXT NOT NULL,
  title         TEXT,
  authors_json  TEXT,
  year          INTEGER,
  venue         TEXT,
  doi           TEXT,
  source_type   TEXT NOT NULL,          -- arxiv | openalex | semantic_scholar | web | github | official
  tier          INTEGER,                -- 由 source.grade 写入，可空
  authority     REAL,                   -- 0..5
  first_seen_at TEXT NOT NULL,          -- 首次入库 = "发现时间"
  last_seen_at  TEXT NOT NULL,
  meta_json     TEXT
);
CREATE INDEX IF NOT EXISTS idx_sources_domain ON sources(domain);
CREATE INDEX IF NOT EXISTS idx_sources_tier   ON sources(tier);
CREATE INDEX IF NOT EXISTS idx_sources_year   ON sources(year);
CREATE INDEX IF NOT EXISTS idx_sources_type   ON sources(source_type);
```

## 4. 文档、正文分块与检索索引

```sql
CREATE TABLE IF NOT EXISTS documents (
  id          TEXT PRIMARY KEY,
  source_id   TEXT NOT NULL REFERENCES sources(id) ON DELETE CASCADE,
  title       TEXT,                     -- 从 sources 反范式化，供 FTS 用
  title_seg   TEXT NOT NULL DEFAULT '', -- 标题的二元组切分（写入时由 state/cjk.py 生成，触发器只能搬列）
  abstract    TEXT,
  abstract_seg TEXT NOT NULL DEFAULT '',-- 摘要的二元组切分
  sha256      TEXT NOT NULL,            -- 原件内容哈希 = 去重键
  mime        TEXT,
  lang        TEXT,                     -- 'zh' / 'en' / 'unknown'
  chars       INTEGER NOT NULL DEFAULT 0,
  raw_path    TEXT,                     -- 相对 data/ 的原件路径
  text_path   TEXT,                     -- 相对 data/ 的纯文本副本路径
  fetched_at  TEXT NOT NULL,
  http_status INTEGER,
  ok          INTEGER NOT NULL DEFAULT 1,
  error       TEXT,
  UNIQUE (source_id, sha256)
);
CREATE INDEX IF NOT EXISTS idx_documents_source ON documents(source_id);
CREATE INDEX IF NOT EXISTS idx_documents_sha    ON documents(sha256);

-- 正文分块：长文档不整篇塞 FTS（引用要能定位到"第几节"，中文 trigram 对长文召回也差）
CREATE TABLE IF NOT EXISTS doc_chunks (
  id       TEXT PRIMARY KEY,            -- chk_*
  doc_id   TEXT NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
  seq      INTEGER NOT NULL,
  section  TEXT,                        -- '3.2' / 'Introduction' / NULL
  text     TEXT NOT NULL,
  text_seg TEXT NOT NULL DEFAULT '',    -- 二元组切分结果（中文检索用，写入时由 state/cjk.py 生成）
  chars    INTEGER NOT NULL DEFAULT 0,
  UNIQUE (doc_id, seq)
);
CREATE INDEX IF NOT EXISTS idx_chunks_doc ON doc_chunks(doc_id, seq);
```

### 4.1 FTS5 索引（两张：文档级 + 块级）

```sql
CREATE VIRTUAL TABLE IF NOT EXISTS documents_fts USING fts5(
  title, title_seg, abstract, abstract_seg,
  content='documents', content_rowid='rowid',
  tokenize='unicode61 remove_diacritics 2'
);

CREATE VIRTUAL TABLE IF NOT EXISTS doc_chunks_fts USING fts5(
  text, text_seg,
  content='doc_chunks', content_rowid='rowid',
  tokenize='unicode61 remove_diacritics 2'
);
```

**为什么索引里有 `*_seg` 列**（本项目的关键决策，答辩必须能讲）：

| 方案 | 中文行为 | 结论 |
|---|---|---|
| `tokenize='unicode61'` 直接索引正文 | 一串汉字被当成**一个 token**，搜"智能"命不中 | 不能用 |
| `tokenize='trigram'` | 支持子串检索，但**查询短于 3 字无法命中**（"教育"两字就废了） | 不够用 |
| **二元组切分后索引（本方案）** | "教育智能体" → `教育 育智 智能 能体`，查"智能"直接命中 | **采用** |

Hermes 的 `state.db` 用的是 `messages_fts`(unicode61) + `messages_fts_trigram` **双索引**，因为它是英文为主、中文靠 trigram 兜。本项目**中文为主**，所以用"原文列 + 二元组列"双列方案，一个 MATCH 同时覆盖中英文：

```sql
-- 中文查询：python state/cjk.py 切二元组 → 匹配 *_seg 列
-- 英文查询：直接在原文列上匹配
-- 组合（推荐）：(text : "bigram1 bigram2" OR text : "raw words")
```

切分规则见 `state/cjk.py`，单测必须覆盖：
`bigrams("教育智能体") == ["教育","育智","智能","能体"]`、`bigrams("AI") == []`、标点与空白不产生二元组。

### 4.2 触发器（索引自动同步）

```sql
-- documents → documents_fts
CREATE TRIGGER IF NOT EXISTS documents_fts_ai AFTER INSERT ON documents BEGIN
  INSERT INTO documents_fts(rowid, title, title_seg, abstract, abstract_seg)
  VALUES (new.rowid, new.title, new.title_seg, new.abstract, new.abstract_seg);
END;
CREATE TRIGGER IF NOT EXISTS documents_fts_ad AFTER DELETE ON documents BEGIN
  INSERT INTO documents_fts(documents_fts, rowid, title, title_seg, abstract, abstract_seg)
  VALUES ('delete', old.rowid, old.title, old.title_seg, old.abstract, old.abstract_seg);
END;
CREATE TRIGGER IF NOT EXISTS documents_fts_au AFTER UPDATE ON documents BEGIN
  INSERT INTO documents_fts(documents_fts, rowid, title, title_seg, abstract, abstract_seg)
  VALUES ('delete', old.rowid, old.title, old.title_seg, old.abstract, old.abstract_seg);
  INSERT INTO documents_fts(rowid, title, title_seg, abstract, abstract_seg)
  VALUES (new.rowid, new.title, new.title_seg, new.abstract, new.abstract_seg);
END;

CREATE TRIGGER IF NOT EXISTS doc_chunks_fts_ai AFTER INSERT ON doc_chunks BEGIN
  INSERT INTO doc_chunks_fts(rowid, text, text_seg) VALUES (new.rowid, new.text, new.text_seg);
END;
CREATE TRIGGER IF NOT EXISTS doc_chunks_fts_ad AFTER DELETE ON doc_chunks BEGIN
  INSERT INTO doc_chunks_fts(doc_chunks_fts, rowid, text, text_seg)
  VALUES ('delete', old.rowid, old.text, old.text_seg);
END;
CREATE TRIGGER IF NOT EXISTS doc_chunks_fts_au AFTER UPDATE ON doc_chunks BEGIN
  INSERT INTO doc_chunks_fts(doc_chunks_fts, rowid, text, text_seg)
  VALUES ('delete', old.rowid, old.text, old.text_seg);
  INSERT INTO doc_chunks_fts(rowid, text, text_seg) VALUES (new.rowid, new.text, new.text_seg);
END;
```

> **触发器只能搬列，不能调用 Python**。所以 `*_seg` 全部是表上的实列，由应用层写入时算好 —— 这是刻意的设计，不要试图在触发器里做切词。

## 5. 会话、消息与工具轨迹

```sql
CREATE TABLE IF NOT EXISTS sessions (
  id                 TEXT PRIMARY KEY,
  session_key        TEXT UNIQUE,          -- 前端可指定，用于恢复
  title              TEXT,
  source             TEXT NOT NULL DEFAULT 'desktop',   -- desktop | cli | eval
  model              TEXT,
  system_prompt_hash TEXT,                 -- 改了系统提示词导致的历史不可比，标记出来
  created_at         TEXT NOT NULL,
  updated_at         TEXT NOT NULL,
  ended_at           TEXT,
  meta_json          TEXT
);
CREATE INDEX IF NOT EXISTS idx_sessions_updated ON sessions(updated_at DESC);

CREATE TABLE IF NOT EXISTS messages (
  id              TEXT PRIMARY KEY,
  session_id      TEXT NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
  idx             INTEGER NOT NULL,        -- 会话内顺序号，从 0 开始
  role            TEXT NOT NULL CHECK (role IN ('system','user','assistant','tool')),
  content         TEXT NOT NULL DEFAULT '',
  tool_calls_json TEXT,                    -- assistant 的 tool_calls 原样存
  tool_call_id    TEXT,                    -- role=tool 时对应
  name            TEXT,                    -- role=tool 时的工具名
  active          INTEGER NOT NULL DEFAULT 1,   -- 压缩/重写后旧消息置 0，不物理删
  token_in        INTEGER,
  token_out       INTEGER,
  created_at      TEXT NOT NULL,
  UNIQUE (session_id, idx)
);
CREATE INDEX IF NOT EXISTS idx_messages_session ON messages(session_id, idx);

CREATE VIRTUAL TABLE IF NOT EXISTS messages_fts USING fts5(
  content, tokenize='trigram',             -- 会话内检索；中文短词兜底走 LIKE（见 §6）
  content='messages', content_rowid='rowid'
);

-- 每次工具调用一行 = 论文里所有"调用次数/成功率/时延"指标的取数入口
CREATE TABLE IF NOT EXISTS tool_traces (
  id            TEXT PRIMARY KEY,
  session_id    TEXT NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
  message_id    TEXT,
  turn_id       TEXT NOT NULL,
  step          INTEGER NOT NULL,          -- 本轮第几次调用
  tool_name     TEXT NOT NULL,             -- 'research.search'
  args_json     TEXT,
  args_digest   TEXT,
  result_digest TEXT,
  result_path   TEXT,                      -- 大结果外置到 run/traces/ 时记路径
  ok            INTEGER NOT NULL,
  error         TEXT,
  latency_ms    INTEGER,
  created_at    TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_traces_session ON tool_traces(session_id, created_at);
CREATE INDEX IF NOT EXISTS idx_traces_tool    ON tool_traces(tool_name);
CREATE INDEX IF NOT EXISTS idx_traces_turn    ON tool_traces(turn_id, step);

CREATE TABLE IF NOT EXISTS usage_records (
  id                TEXT PRIMARY KEY,
  session_id        TEXT,
  turn_id           TEXT,
  model             TEXT NOT NULL,
  prompt_tokens     INTEGER,
  completion_tokens INTEGER,
  est_cost          REAL,
  created_at        TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS provider_status (
  id          TEXT PRIMARY KEY,
  provider    TEXT NOT NULL,               -- arxiv | openalex | s2 | web | github | llm
  at          TEXT NOT NULL,
  ok          INTEGER NOT NULL,
  http_status INTEGER,
  latency_ms  INTEGER,
  note        TEXT
);
CREATE INDEX IF NOT EXISTS idx_provider_status ON provider_status(provider, at DESC);
```

## 6. 出处关联表（回答"这条资料是哪次会话、哪一轮带出来的"）

```sql
CREATE TABLE IF NOT EXISTS source_mentions (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  source_id  TEXT NOT NULL REFERENCES sources(id) ON DELETE CASCADE,
  doc_id     TEXT REFERENCES documents(id) ON DELETE SET NULL,
  chunk_id   TEXT REFERENCES doc_chunks(id) ON DELETE SET NULL,
  session_id TEXT NOT NULL,
  message_id TEXT,
  turn_id    TEXT,
  role       TEXT,                          -- 谁引用的：assistant 回答 / user 追问
  created_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_mentions_source  ON source_mentions(source_id);
CREATE INDEX IF NOT EXISTS idx_mentions_session ON source_mentions(session_id, created_at);
```

## 7. 简介、主题地图、学习路线、笔记

```sql
-- 简介（用户决议原话："原始资料的简介而非全部内容放 SQLite"）
CREATE TABLE IF NOT EXISTS summaries (
  id         TEXT PRIMARY KEY,
  doc_id     TEXT REFERENCES documents(id) ON DELETE CASCADE,
  source_id  TEXT REFERENCES sources(id) ON DELETE CASCADE,
  session_id TEXT,
  kind       TEXT NOT NULL CHECK (kind IN ('short','key_points','why_relevant','critique')),
  text       TEXT NOT NULL,                 -- kind=key_points 时为 JSON 数组
  model      TEXT,
  created_at TEXT NOT NULL,
  UNIQUE (doc_id, kind)
);

CREATE TABLE IF NOT EXISTS topic_maps (
  id         TEXT PRIMARY KEY,
  session_id TEXT,
  topic      TEXT NOT NULL,
  graph_json TEXT NOT NULL,                 -- {nodes:[],edges:[]}，结构见 01 契约 topic.build_map
  created_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_topic_maps_topic ON topic_maps(topic);

CREATE TABLE IF NOT EXISTS learning_routes (
  id           TEXT PRIMARY KEY,
  session_id   TEXT,
  topic_map_id TEXT REFERENCES topic_maps(id) ON DELETE SET NULL,
  topic        TEXT NOT NULL,
  level        TEXT,                        -- 入门 | 进阶 | 研究
  weeks        INTEGER,
  plan_json    TEXT NOT NULL,               -- 结构见 01 契约 route.plan
  created_at   TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_routes_topic ON learning_routes(topic, created_at DESC);

CREATE TABLE IF NOT EXISTS notes (
  id         TEXT PRIMARY KEY,
  session_id TEXT,
  kind       TEXT NOT NULL CHECK (kind IN ('summary','note','card')),
  title      TEXT,
  content    TEXT NOT NULL,
  refs_json  TEXT,                          -- {source_ids:[],doc_ids:[],chunk_ids:[]}
  tags_json  TEXT,
  path       TEXT,                          -- 同时导出到 data/notes/ 的路径
  created_at TEXT NOT NULL,
  updated_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_notes_kind ON notes(kind, created_at DESC);
```

## 8. 待确认项（v0.1 → v0.2 冻结前必须定）

| # | 待确认 | 我的建议 | 影响 |
|---|---|---|---|
| 1 | 正文是否分块入 FTS（`doc_chunks`）而不是整篇入 | **分块**：引用能定位到节，中文召回质量高，单库不会因长 PDF 膨胀 | 若选整篇，删 `doc_chunks`/`doc_chunks_fts`，`documents` 加 `text` 列 |
| 2 | 中文检索用二元组列（本方案）还是 `tokenize='trigram'` | **二元组**：trigram 查询短于 3 字失效，而中文双字词最常见 | 若选 trigram，删所有 `*_seg` 列 |
| 3 | 抽取的纯文本是否在 `data/text/` 另存一份 | **另存**：DB 坏了还能 grep，且可整目录备份 | 只影响 `documents.text_path` 是否留空 |
| 4 | 图片/扫描版 PDF 要不要 OCR | 先不做，`documents.ok=0` + `error='no_text_layer'` 显式记录 | 影响 `documents` 是否需要 `ocr` 列 |
| 5 | 超长文档（>50 万字符）是否限制入块数量 | 限 `max_chunks` 并记 `truncated=1` | 影响 `documents` 是否加列 |

## 10. 验收（这些不过就不合）
