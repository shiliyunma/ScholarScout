> 建立 2026-10-21 ｜ 状态：**滚动更新**
> 关联：目录与落盘归属见 `03-目录结构与规则文件.md` §1.1；门槛见 `03` §4。

**为什么要单独一份**：修缺陷的过程（怎么发现、证据长什么样、改法与验证方式）在提交信息里只能写几行、
在代码注释里又只覆盖一个文件。缺陷会重复出现 —— 下次撞上同一个坑时，先看这张表能不能直接复用
证据与改法，比重新翻提交历史快得多。

**记录纪律**：

1. 一条缺陷一行，**证据必须是可复现的命令或真实输出**（`文件:行` 也行），不写"感觉像"；
2. 「怎么验的」写**具体测试/命令**，不写"已测试"；
3. 只记**已修完并进门禁**的条目；未修的写进 `docs/00-总索引.md` 的「没做完」段落。

**注 ①（自指 SHA 的写法）**：一笔提交无法在自己的正文里写下自己的 SHA —— 改动内容会变，SHA 随之变，
永远差一步。所以本表「提交」列写**唯一可检索的主题**；要取哈希：

```bash
git log --grep "feat(logging): 日志落盘" -1 --format="%H %s"
```

（若这条约束以后可放宽，改成"修复提交 + 一次 docs 回填提交"两笔即可直接内嵌 SHA，但那与
"一笔提交"的项目规矩冲突，故如实记录取舍。）
