## ① Hermes 的完整引导时序（八步，每步带证据）

用户原话顺序：**终端设置 → 自动弹出链接 → 点链接创建机器人 → 回终端继续 → 完成配置 → 飞书获得 DM 码 → 终端运行 → 打通**。

### 步骤 1　终端入口：`hermes gateway setup` → 编号菜单选 `12. Feishu / Lark`

- **实测**：入口命令是 **`hermes gateway setup`**（**不是** `hermes setup`）；界面是**编号选择菜单**，Feishu 是 **`12. Feishu / Lark`**。
- **源码锚点**：平台 setup 由 `_configure_platform(platform)` 分发（`hermes_cli/gateway.py:5578`）；它取插件的 `setup_fn`（`:5582`），飞书插件的 `register()` 把它登记为 `setup_fn=interactive_setup`（`plugins/platforms/feishu/adapter.py:4303`）；`interactive_setup()` 定义在 `adapter.py:4162`，进入即 `print_header("Feishu / Lark")`（`:4169`）。
- **`12.` 这个序号**：来自 `hermes gateway setup` 的编号菜单（实测记录）。菜单本体的拼装代码本机**未读**，故此处只认「编号菜单 + 第 12 项是 Feishu / Lark」这一实测事实，不给行号 —— **unknown**。

### 步骤 2　创建方式二选一（弹链接即在此步）

- **实测菜单**：
  - `1. Scan QR code to create a new bot automatically (recommended)`
  - `2. Enter existing App ID and App Secret manually`
- **源码锚点**：`prompt_choice("How would you like to set up Feishu / Lark?", [...], 0)`（`adapter.py:4173-4177`）；选 1 走 `qr_register()`（`:4181`）。
- **选 1 后的终端原文**：
  ```
  Connecting to Feishu / Lark... done.
  Open this URL in Feishu / Lark on your phone:

  https://open.feishu.cn/page/launcher?user_code=Z2BC-3GAP&from=hermes&tp=hermes
  ```
  另有提示：`Tip: pip install qrcode  to display a scannable QR code here next time`。
- **这个链接是怎么拼出来的**（源码）：
  1. `qr_register()` → `_qr_register_inner()`（`adapter.py:4074 / :4086`）先 `_init_registration()`（`:3918/3920`）POST `{action:"init"}` 到 `{accounts_base}/oauth/v1/app/registration`（路径常量 `_REGISTRATION_PATH = "/oauth/v1/app/registration"`，`:203`；accounts 基址 `_ONBOARD_ACCOUNTS_URLS = {"feishu": "https://accounts.feishu.cn", "lark": "https://accounts.larksuite.com"}`，`:198-201`）。
  2. `_begin_registration()`（`:3929`）POST `{action:"begin", archetype:"PersonalAgent", auth_method:"client_secret", request_user_info:"open_id"}`（`:3931-3933`），取回 `device_code` 与 `verification_uri_complete` 当作 `qr_url`（`:3934-3937`），再**追加** `&from=hermes&tp=hermes`（`:3937-3938`）。
  3. 打印：`_render_qr(qr_url)` 成功则 `Scan the QR code above, or open this URL directly:`（`:4095`）；失败（没装 `qrcode`）则 `Open this URL in Feishu / Lark on your phone:`（`:4097`）+ 上面那条 pip 提示（`:4098`）。**实测命中的是没有 `qrcode` 的那条分支。**
  4. `_render_qr` 定义 `:3999`，`import qrcode as _qrcode_mod` 失败即返回 False（`:3993-3996`）——**QR 只是可选增强，不是必需依赖**（实测也印证）。
- **链接模板与参数**（把实测与源码合起来）：
  - 基址：`https://open.feishu.cn/page/launcher`（实测原文）。
  - 参数：`user_code=<用户码>`、`from=hermes`、`tp=hermes`（实测原文）。
  - `user_code` 格式：**4 位大写字母数字 + `-` + 4 位**（实测 `Z2BC-3GAP`）；源码里它是 `verification_uri_complete` 带回的**设备码**（`_begin_registration`，`:3937`），由飞书服务端签发。
  - `from=` / `tp=` 的**具体语义**本机**未在源码/文档读到**，只有实测取值 `hermes` —— **unknown（我推断）**：像是"来源标识/渠道标识"，用来让飞书侧识别这次创建来自哪个客户端。**不得当成事实使用**，本地实现把它们做成**可配置**即可。
- **`hermes gateway setup` 的"自动弹出链接"≠ API 造 URL**：链接是**飞书注册接口返回**的（`verification_uri_complete`），Hermes 只负责**打印**（并可选渲染 QR）。**这也是 P0 不能本地"造"链接的原因**（见 §③、§④）。

### 步骤 3　点链接创建机器人 → 回终端轮询拿结果

- **实测**：点链接在飞书里完成创建后，终端打印 `Fetching configuration results....`（省略号随轮询增加），成功后 **`✓ Bot created: 大浩`**。
- **源码锚点**：`_poll_registration()`（`adapter.py:3945`）循环 POST `{action:"poll", device_code, tp:"ob_app"}`（`:3954`，`tp` 实测未直接打印，源码原文如此），打印 `Fetching configuration results...`（`:3962`）并按每 6 次补 `.`（`:3963-3964`）；拿到 `client_id` + `client_secret` 即返回 `{app_id, app_secret, domain, open_id}`（`:3971-3977`）。域名自动探测：`user_info.tenant_brand == "lark"` 时切到 lark（`:3967-3970`）。
- **Bot 名**：`_qr_register_inner` 里 `probe_bot(app_id, app_secret, domain)`（`:4106`）→ `GET /open-apis/bot/v3/info`（`_probe_bot_sdk` `:4042` / `_probe_bot_http` `:4067`）取 `bot.app_name`（`_parse_bot_response` `:4034`）。`✓ Bot created: <name>` 由 `print_success(f"Bot created: {bot_name}")` 打印（`:4239`）——**实测文案完全一致**。
- **结论**：**是"轮询等待飞书侧完成创建"，不是让用户回终端再输凭据**（与用户描述一致）。

### 步骤 4　回终端完成配置（连接模式 / 凭据落盘）

- **密钥去向**：`save_env_value` → 写 `~/.hermes/.env`（`hermes_cli/config.py` 的 `save_env_value`，本机未逐行读，**unknown**，但与本项目"密钥只进 .env"同规矩）。**完成摘要不打印 App Secret**（实测印证，见步骤 7）。

### 步骤 8　飞书获得 DM 码 → 终端 `hermes pairing approve` 打通

- **实测**：未知用户私聊机器人 → 机器人回一条 **8 位大写字母数字的配对码**（如 `KMHSZQXF`）→ 在终端跑
  `hermes pairing approve feishu KMHSZQXF`
  → 打印 `Approved! User ou_aa206fb174402ae72345a7fe39a51ae2 on feishu can now use the bot~`
  → **写进白名单的身份就是飞书 openid（`ou_` 开头）**。
- **源码锚点（配对码生成，飞书侧）**：未知用户发私信 → 网关入站处 `_hm_offer_pairing_code`（`gateway/run_inbound.py:78-110`）：`pairing_store.generate_code(platform, user_id, user_name)`（`:88`），回复文本
  ```
  Hi~ I don't recognize you yet!

  Here's your pairing code: `{code}`

  Ask the bot owner to run:
  `hermes {profile_arg}pairing approve {platform} {code}`
  ```
  （`:97-103`）；`source.chat_type == "dm"` 且未授权才给码（`:199-204`）。
- **源码锚点（配对码规格与存储）**（`gateway/pairing.py`）：
  - 字母表 `ALPHABET = "ABCDEFGHJKLMNPQRSTUVWXYZ23456789"`（**32 字符，剔掉 0/O/1/I 防混淆**，`:28-29`）；
  - 长度 `CODE_LENGTH = 8`（`:30`）—— **与实测 `KMHSZQXF`（8 位大写）一致**；
  - 有效期 `CODE_TTL_SECONDS = 3600`（1 小时，`:32`）；
  - 同平台最多 `MAX_PENDING_PER_PLATFORM = 3` 个待批（`:35`）；失败 `MAX_FAILED_ATTEMPTS = 5` 次后锁定 `LOCKOUT_SECONDS = 3600`（`:34/:36`）；每用户每 `RATE_LIMIT_SECONDS = 600` 分钟最多请一次（`:33`）；
  - 存储目录 `~/.hermes/platforms/pairing/`（`_default_pairing_dir()`，`:57-58`），每平台三份文件：`{platform}-pending.json` / `{platform}-approved.json` / 共享 `_rate_limits.json`（`:343-350`）；文件权限 `0o600`（`:280-281`）；
  - **只存哈希**：`_hash_code = sha256(salt + code)`（`:412-414`），条目按**随机 `entry_id`（`secrets.token_hex(8)`）** 索引、存 `{hash, salt, user_id, user_name, created_at}`（`:444-447`）——码本身不落盘；
  - 生成：`generate_code()`（`:427-450`）先 `_cleanup_expired()`（`:352-362`，过期即清）、判限速/锁定/满额，再 `secrets.choice` 逐位生成（`:441`）。
- **源码锚点（终端校验并写白名单）**：
  - CLI：`hermes pairing approve <platform> <code>` → 子命令 `pairing`（`hermes_cli/console_engine.py:297-298`）→ `pairing_command`/`_cmd_approve`（`hermes_cli/pairing.py:3 / :56`）；
  - 校验：`PairingStore.approve_code(platform, code)`（`pairing.py:452`）——**大写去空格 → 清过期 → 判锁定 → 逐条 `secrets.compare_digest(hash)`**（`:461-479`），命中即 `_finish_approval()`（`:416`）；
  - **写白名单**：`_finish_approval`（`:416-425`）→ `_approve_user(platform, user_id, user_name)`（`:384-393`）写 `{platform}-approved.json`，并**顺带 `_sync_allowlist_add`（`:393`）把 openid 写进已配置的 allowlist 环境变量**（`_PLATFORM_ALLOWLIST_ENV["feishu"] = "FEISHU_ALLOWED_USERS"`，`:72`；写入见 `:157-172`）；
  - **成功文案**：`Approved! User {name} ({uid}) on {platform} can now use the bot~`（`hermes_cli/pairing.py:68`）—— **与实测 `Approved! User ou_... on feishu can now use the bot~` 一致**（实测无 name 时只显示 uid，源码 `:67` 的 `display` 正是这个分支）；
  - **失败文案**：码错/过期 → `Pairing request or code '{code}' not found or expired for platform '{platform}'.`（`hermes_cli/pairing.py:80`）；锁定 → `Platform '{platform}' is locked out after too many failed approval attempts.`（`:76`）。

### 3.3 配对机制的方向差异（本项目有意为之，且**可做得更好**）

- **Hermes**：未知用户私信 → **机器人**生成绑定该 openid 的码 → 用户把码**抄回终端** → 终端 `approve`。
- **ScholarScout（向导场景）**：尚无任何私信 → **向导**先生成码（不带 openid）→ 用户**把码发给机器人** → **渠道层收到这条私信时捕获发送者 openid 并绑到该码上**（`feishu.pairing.claim`）→ 向导 `verify` 完成批准。
- **这就是"可做得更好"的第一条：自动获取并落库 openid** —— Hermes 要用户手抄码、终端敲 `hermes pairing approve feishu <code>`；我们把"身份获取"放进渠道层，用户只做一件事（发一条私信），**openid 自动落库**。P0 无渠道时退化为"手工粘贴 openid"（向导明确说明）。
- **可做得更好的第二条：设置页可视化**：Hermes 的配对只能 `hermes pairing list/approve` 命令行看；我们给 `feishu.status` / `feishu.pairing.list`，设置面板/看板能直接看到"待配对 / 已白名单 / 临时放行状态"。
- **可做得更好的第三条：自检清单**：向导末尾用 `feishu.status` + `probe_listener` 打印一张勾选表（凭据/模式/监听端口/白名单/临时放行），Hermes 只打印一段摘要，不给"哪一项没成就去查哪"。

### 3.4 关于"设置只进 config.yaml"的一处**有意例外**（必须写清楚）

本项目**设置面板的白名单**（`settings_io.FIELDS`，落 `config.yaml`）管的是**模型 / 检索 / 预算 / 生成策略**。
飞书的**渠道层运行期开关**（连接模式、群聊策略、DM 策略、home channel）与**签名密钥**都跟**渠道本身**走 `.env`：

- 理由 1：`channels/` 是**入口层**，它的配置天然属于渠道（与 `desktop/` 的窗口偏好互不干涉）；
- 理由 2：键名与 Hermes **逐字一致**（`FEISHU_CONNECTION_MODE` = `adapter.py:1311`、`FEISHU_GROUP_POLICY`、`FEISHU_ALLOWED_USERS`），照抄不带来新词汇；
- 理由 3：**密钥**本就只进 `.env`（`FEISHU_APP_SECRET` / `FEISHU_VERIFICATION_TOKEN` / `FEISHU_ENCRYPT_KEY`）。

> **结论**：`.env` 在本项目里不只放密钥，还放**渠道层运行期开关**；`config.yaml` 只放**应用设置**。
> 这条边界写进 `docs/03`，免得以后误以为飞书设置"漏登记"。
