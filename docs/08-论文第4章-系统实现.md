# 第 4 章 系统实现

> 本章讲**实现层面的真问题**：哪些地方不是"照着设计写就行"，而是撞了墙才写对。
> 每个小节都尽量给出：做法 → 实测证据 → 被放弃的做法。
> 代码规模与测试数取自本机 `git`/`pytest`/`wc` 的真实输出（2026-10-06）。

|---|---|---|
| 后端源码 | **75 个 `.py`，12,314 行** | `src/scholarscout/` |

**实现顺序**：M1 库与迁移 → M2 传输层与循环 → M3 检索 → M4 判权 → M5 生成 → M6 界面 →
M7 摘要与扫描件 → M8 评测与成本。每个里程碑收尾**必须跑一次真接口**（真联网 + 真模型），
不允许"单元测试过了就算完成" —— 这条规则在 M3/M5 各抓出一批只有真机才暴露的问题。

## 4.2 传输层：JSON-RPC over stdio 与流式事件

**做法**：壳层以子进程方式拉起 `python -m scholarscout --rpc`，双向 JSON-RPC 2.0；
请求-响应之外还有**单向通知（notification）** 承载流式事件（`chat.delta`、工具轨迹、`chat.done`）。

**三个实现要点**：

1. **事件先于结果**：`chat.send` 是阻塞调用，但过程性事件在它返回前就推给前端 ——
   否则一轮 3–12 分钟里界面一片死寂。
2. **错误码分层**：`-32001` 参数、`-32004` 未找到、`-32005` 取消…前端据此决定"提示还是重试"，
   而不是把异常文本直接抛给用户。
3. **前端无构建**：直接 `<script src>` 加载，不引入打包器 —— 目标机器上"双击能用"是第一约束，
   构建链是**多一个会失败的环节**。代价是前端不能享受 npm 生态，所以只搬设计决策不搬库。

## 4.3 单轮工具循环

**循环结构**（`runtime/loop.py`）：轮次预算 = **工具预算 + 1**，
最后一轮**不给工具**、要求模型必须收口。这样"用满工具预算"和"模型还想继续调"能区分开：
前者是设计内的收敛，后者才记 `tool_limit`。`stop_reason ∈ {completed, tool_limit, cancelled, error}`。

**三条实现细节**：

1. **取消是步间检查**：`is_cancelled(turn_id)` 在每轮开头检查，正在跑的模型/工具调用不会被打断。
   界面上必须如实写"当前这一步结束后生效"，否则用户会以为点了立刻停。
2. **界面按会话取消**：整轮结束前前端拿不到 `turn_id`（它随 `chat.done` 才回来），
   所以后端维护 `session_id -> turn_id` 的注册表（`ctx.running`），轮次结束（含异常路径）
   在 `finally` 里摘除。**这是"没有停止按钮"的真正原因**：不是忘了加按钮，是原接口不可调用。
3. **喂回模型前瘦身**（`runtime/context_budget.py`）：同一批来源第二次出现不再重发摘要、
   单条片段截断到 200 字符、字段折叠。实测同题输入 token **39,808 → 33,808（−15%）**，
   工具调用次数与 `stop_reason` 不变。

## 4.4 检索来源的实现难点

每个适配器都有"文档没写、撞了才知道"的地方：

| 来源 | 实现难点 | 处理 |
|---|---|---|
| arXiv | `robots.txt` 禁止 `/api/query`；必须带 `Accept` 头；≥3s 限速；`all:"精确短语"` 恒返 0 | 加 `robots_exempt_hosts`；补头；节流；**切词改写为 `all:a AND all:b`** |
| OpenAlex | 摘要字段是 `abstract_inverted_index`（**词 → 位置数组**） | 按位置还原成连续文本（不做等于拿到一袋词） |
| GitHub | 未认证 10 次/分钟 | 全局限速表 6s；**但**这个键曾被更粗的全局表覆盖 → 删掉默认项修好 |
| SearxNG | `keep_only` ≠ 启用（`/config` 报启用 0）；重启后加载引擎要十几秒 | 显式写 `engines:[{name,disabled:false}]`；脚本轮询就绪 |
| Semantic Scholar | 无 key 恒 429 | 不进 `auto`（不进"现在能用的"集合） |
| 抓结果页 | 违 robots、国内不通、质量差 | **默认关**，需显式开启 |

**统一失败语义**：全部来源失败 → `ok=false` + 原因（不是"成功但空列表"）；
来源不可用 → `provider_status` 区分 `missing_api_key` / `missing_config` / `blocked_by_robots`。

## 4.5 摘要流水线与扫描版 PDF

**摘要**照"一次调用 + 截断"的方案（参照 AIHOT 的实测做法）：不切块、截断 6,000 字符、
一次调用产出 `title_zh / summary_short / points / why_relevant`；
**提示词版本 = 内容哈希**（改一个字版本就变，可追溯"这份摘要出自哪版提示词"）。
字段分三档（完整/精简/空），扫描版走降级。

**扫描版 PDF**接 MinerU，两级降级：

- 精准解析接口（带 token）→ 401 时**自动退回免 token 的 Agent 接口**，且**轮询 URL 同步切换**
  （这里曾出过 bug：回退后仍轮询旧地址，被单元测试抓到）；
- 抽取失败则 `degraded=1` 且 `extract_detail` 记原因，**不假装成功**。

**如实记录的现状**：MinerU 免 token 的 Agent 服务在本机实测期间返回
`model service is temporarily unavailable`，"扫描版能抽出正文"**尚未端到端成功过**，
因此在第 5 章作为局限写明（代码与接口契约已就绪）。

## 4.6 反幻觉守卫与引用语义支持度校验

**守卫（写库前，确定性）**：校验产物里每个 `source_id` 是否存在、是否属于本次允许集合、
是否越权；不通过则剔除，并把被剔除的 id 记进 `dropped_source_ids`（便于事后解释）。

**语义支持度校验（离线审计，模型判定）**：`grading/support.py` + `eval/verify_support.py`：

1. **配对**：只审资料类条目（`paper/doc/video/code`）；行动类（`exercise`）不声称出处，
   不进入分母 —— 与反幻觉指标口径一致。
2. **分层证据**：抓过原文的来源给"标题+中文摘要+要点"（强证据），否则只给"标题+年份+域名"（弱证据）。
3. **严格输出**：要求 `{"verdict","reason"}`；解析不出即 `unknown`，**不计入分子分母**。
4. **落库可复算**：结果写 `support_checks`（`UNIQUE(artifact_id,item_id)` + upsert），
   重复审同一批产物**不重复计费**，弱支持清单可直接交人工复核。

**实现中抓到两个会直接让指标虚高的 bug**（都写了钉子用例）：

- 关键词兜底里 `"supported"` 是 `"unsupported"` 的子串 → **"不支持"会被读成"支持"**；
  改成从长到短匹配；
- 解析失败必须落 `unknown` —— 默认成 `supported` 是最坏的错法。

首次真机结果（23 条判定，37 秒，解析失败 0）：知识地图 91.7%、学习路线 90.9%；
**按证据等级分层后：强证据 8/8 = 100%，弱证据 15 条 = 93.3%** ——
即"覆盖率 100%"与"支持率约 91%"的落差**主要来自弱证据样本**（详见第 5 章 §5.7.4）。

## 4.7 桌面壳实现

pywebview 5.4 + WebView2，**问题都出在"看起来能用、实际不生效"**：

| 问题 | 现象 | 处理 |
|---|---|---|
| 图标 | `webview.start(icon=...)` 在 Windows **不生效** | ctypes 发 `WM_SETICON` + 设 AUMID（任务栏） |
| 图标句柄 | 64 位下 `LoadImageW` 不声明 `restype=c_void_p` → HICON 被截断成 32 位，`SendMessage` **静默失败** | 显式声明 + 测试钉住 |
| 窗口几何 | `window.width/height` 是**物理像素**，`create_window(width=…)` 是**逻辑像素** | 存盘前除以 DPI 缩放 |
| "是否最大化" | 用"窗口≈屏幕"判断 → 单位不一致把 2400×1400 误判成最大化，**结果尺寸干脆不记**（功能整个失效） | **不猜**，一律存几何 |
| URL 片段 | `index.html#settings` 让窗口**全白**（加载失败） | 页面起来后再 `evaluate_js` 调函数 |
| exe | 打包后改代码要重编 | exe 只做**启动器**（拉起项目/解释器），改代码永不用重编 |

## 4.8 成本控制的实现

| 手段 | 实现 | 诚实边界 |
|---|---|---|
| 深度思考开关 | 请求体带 `thinking={"type":"disabled"}` | `reasoning_effort` 该模型**不认**（实测 162→154/160 无差别），只有这个字段有效（162→36） |
| 响应缓存 | key = **整个请求体哈希**（模型名/消息/工具声明/参数） | 交互命中率≈0，**只有评测复跑/调试重跑有用**，默认关 |
| 历史预算 | 保头保尾（用户首句定义任务必须留），丢弃中间时**显式留一句说明** | 当前会话历史仅约 1,000 tokens，它不是主要省钱手段，作用是**防长会话线性膨胀** |
| 用量可见 | `usage_records` 落库 → 每轮显示真实 token + `session.usage` 汇总 | **单价未配置就不折算金额**（报 0 会让人以为免费） |
| 每轮真实 token | 界面显示 `token 输入 12.3k／输出 0.4k` | — |

## 4.9 Windows 与中文路径适配

本机环境（Windows 11 + 中文路径 `D:\AI+教育毕设毕设\`）逼出的适配：

| 坑 | 现象 | 处理 |
|---|---|---|
| `pip install -e .` | 中文路径下解释器**启动即崩**（site.py 用 GBK 读 editable 写的 UTF-8 `.pth`；`PYTHONUTF8=1` 无效） | **不做 editable 安装**，改用启动脚本把 `src` 插进 `sys.path` |
| 截图/导出 | GDI+ `Bitmap.Save` 遇中文绝对路径抛 `ExternalException` | 用相对路径 |
| GUI 子系统输出 | 中文 GBK 乱码 | `Console.OutputEncoding = UTF-8` |
| 进程管理 | 按名字批量杀 `python` 会**误杀别的进程** | 先看命令行再杀（只匹配 `scout.py`） |
| 容器 | Docker Hub 不可达；`restart: unless-stopped` 关机后不自愈 | 走 `docker.m.daocloud.io`；`searxng_up.py` 自动起守护进程并轮询（实测 29s 恢复） |

## 4.10 测试与工程门槛

**门槛**（`scripts/check.sh`，6 项，任一不过就不合）：ruff lint/format、mypy（`src` + `eval`）、
pytest、规则文件同步检查、依赖白名单检查、前端资源检查。

**测试策略的三条**：

1. **桩模型端到端**：`StubLlm` 按脚本返回回复，`tests/rpc/` 直接走 `chat.send` 的完整链路 ——
   验证"多轮工具循环/取消/守卫/落库"而不联网、不花钱；
2. **防漂移测试**：前端 `SETTINGS_SPEC` ↔ 后端 `settings_io.FIELDS` 必须一一对应；
   提示词两档用**内容哈希**钉住；schema 版本与迁移数一致；UI 里引用的元素 id 必须在 HTML 里存在；
3. **度量测试**：指标的分母口径单独测（例如"只算资料类条目""解析不出不计入"），
   因为**口径写错的代价比代码写错的代价大**（第 5 章 §5.8.1 是一次真实的度量返工）。

**门槛实际拦下的真错（举例）**：ruff 的嵌套 `if`；mypy 对 `data_usage` 的标注
（`dict[str,int]` 里塞了 `str` 路径）；前端复选框"值缺失时勾上"与"默认关"相反；
MinerU 回退后轮询旧 URL；导出件混进 `role=tool` 原始 JSON（一条 4 千多字符）。

## 4.11 本章小结

- 实现层面的主要工作量不在"写功能"，而在**适配真实世界**：来源方的限速与 robots、
  模型接口的字段怪癖（倒排摘要、工具名正则、不认的推理强度参数）、
  GUI 框架的"看起来生效其实没生效"、以及中文路径下解释器与 GDI+ 的坑；
- 反幻觉与成本这两条主线都靠**可复算的落库数据**支撑，而不是靠"我们做了缓存"这类说法；
- 工程门槛与防漂移测试是**在无人工逐行读全部代码的前提下**保持一致性的手段，
  它们的价值已经被实际拦下的三类真错证明。
