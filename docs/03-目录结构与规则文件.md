## 2. 模块边界（谁可以 import 谁）

```
desktop/  →  rpc/  →  runtime/  →  tools/  →  {providers/, fetch/, grading/, state/}
                                        ↑
                                    state/ 不被 providers 反向依赖
```

| 规则 | 说明 |
|---|---|
| `tools/*` 不许 import `rpc/*` | 工具是模型可见层，不知道自己被谁调 |
| `providers/*` 不许 import `state/*` | provider 只负责取数据，落库是 tools 的事 |
| `desktop/*` 只经 `rpc/server.py` 通信 | 壳里不许出现 sqlite3 或 httpx |
| `state/*` 是唯一碰 SQL 的地方 | 其他模块不许出现 `execute(` |
| `fetch/*` 是唯一出网的地方 | 其他模块不许 import httpx（除了 providers 的 base 抽象） |

**新增一个能力时的落点（按顺序问自己）**：
1. 是"取数据"吗 → 加 `providers/` 里的一个 provider，或复用现有
2. 是"模型要能主动做的一件事"吗 → 加 `tools/` 里一个工具 + 在 `docs/01` 里加 schema
3. 是"前端要展示的界面"吗 → 加一个 RPC 方法 + `ui/` 一页
4. 都不是 → **先别写**，回 `docs/01` 讨论（铁律 #1）

## 3. 规则文件

- **规则正文的唯一权威副本是 `docs/项目规则.md`**（`<!-- RULES:BEGIN -->` 与 `<!-- RULES:END -->` 之间）
- **`AGENTS.md` 是必须存在的分发副本**（Hermes 与各类 AI 助手读它）
- **`CLAUDE.md` 是可选副本**：2026-10-05 项目所有者决定不创建（本机不用 Claude Code）。要启用时 `cp AGENTS.md CLAUDE.md` 再改开头两行注释即可，正文必须逐字一致
- 校验：`scripts/check_rules_sync.py` —— 必需副本缺失或不一致 = 门槛不过 = 不合；可选副本不存在只提示
- 为什么不各自维护：规则漂移比重复更危险（AI 会按旧规则写代码）
- 规则正文包含七节：协作铁律 / 技术栈 / 命名 / 错误处理 / 依赖政策 / 门槛与关键路径 / 提交与 PR

## 4. 门槛（对应铁律 #4）

```bash
bash scripts/check.sh          # 全跑；任何一个不过，退出码非 0
bash scripts/check.sh --fast   # 只跑 lint + rules_sync + deps（提交前快速自检）
```

门槛组成：

| 步骤 | 命令 | 不过的后果 |
|---|---|---|
| lint | `ruff check src tests` | 不合 |
| 格式 | `ruff format --check src tests` | 不合 |
| 类型 | `mypy src` | 不合 |
| 测试 | `pytest -q` | 不合 |
| 规则同步 | `python scripts/check_rules_sync.py` | 不合 |
| 依赖审批 | `python scripts/check_new_deps.py` | 不合 |
| 前端资源 | `python scripts/scout.py --check-ui` | 不合 |

## 5. 依赖审批机制（对应铁律 #6）

1. 运行期依赖写在 `pyproject.toml` 的 `dependencies`，同时必须列进 `deps-allowlist.txt`
2. `scripts/check_new_deps.py` 逐条比对；**出现未列入白名单的依赖，退出码 1**
3. 申请新增时在本文件 §6 追加一行，写清：用途 / stdlib 为何不行 / 体积 / 许可证
4. `dev` 组（pytest/ruff/mypy）与构建后端不进运行期白名单，但也要在 §6 登记

## 6. 依赖登记表

| 依赖 | 用途 | stdlib 为何不行 | 状态 |
|---|---|---|---|
| `httpx` | 出网（超时/重定向/HTTP2 控制好） | `urllib` 无连接池、超时语义差、重试要手写 | 已批准 |
| `PyYAML` | 读 `config.yaml` | 无内置 YAML | 已批准 |
| `pywebview` | 桌面壳（Edge WebView2） | 无内置 | 已批准 |
| `pymupdf` | PDF 文字层抽取（PDF/HTML/Doc 等） | 无内置 PDF 解析 | **已批准** 2026-10-05（AGPL-3.0，约 20 MB） |
| MinerU 官方 API | 扫描版 / 复杂版式解析（**非 Python 依赖，走 HTTP**） | 不自己写 OCR | 已批准（免登录轻量接口 + 需 token 的精准接口） |
| SearxNG（Docker 容器，**非 Python 依赖**） | 通用网页检索（免 key、返回 JSON） | 抓结果页违约且质量差（docs/03 §7） | 已批准（`deploy/searxng/`，本机自用，一条 `docker compose up -d`） |
| `pytest` / `ruff` / `mypy` / `hatchling` | dev + 构建 | — | 已批准（非运行期） |

**通用/商用检索没有新增任何 Python 依赖**：六个来源全用已批准的 `httpx` 手写（`providers/{bing,duckduckgo,searxng,tavily,serper,brave,google_cse}.py`），
所以 `deps-allowlist.txt` 不用动。

## 7. 真机跑出来的坑（写代码前先看这一节，能省一轮调试）

| 现象 | 根因 | 修法 |
|---|---|---|
| 模型报 `Invalid 'tools[0].function.name'` / 400 | API 只接受 `^[a-zA-Z0-9_-]+$`，我们的工具名带点 | 线上名用 `__`，注册名不变（docs/01 §5.0） |
| 检索恒返回 0 条且 provider 报 `forbidden` | `robots.txt` 被套用到 **官方 API**：arXiv 明确禁 `/api/query` | API 主机进 `robots_exempt_hosts` 白名单（`fetch/http.py`） |
| 检索 `ok` 但恒 0 条（provider 报 ok） | 查询被整句加引号 → 变成精确短语匹配 | 按空格切词，`all:a AND all:b` 组合（`providers/arxiv.py`） |
| 中文关键词检索恒 0 条 | arXiv 只索引英文（**事实，不是缺陷**） | 检索用英文关键词，中文只用于主题与摘要 |
| 模型反复重试同一检索直到烧光预算、开始输出 DSML 伪工具调用 | 工具把「全失败」当「没结果」返回（`items: []`） | 全部来源失败时回 `ok=false` + 原因，模型才会停下来如实告知 |
| 模型刚好用满工具预算时最终答案丢失 | 轮次预算 = 工具预算 | 轮次 = 工具预算 + 1，最后一轮 `tools=None` |
| 通用检索：`cn.bing.com` 返回 200 却报 `forbidden` | **搜索页也在 robots 里被禁**（Bing 禁 `/search`），我们只豁免官方 API 主机 | 默认不抓；要抓就显式开 `search.allow_searchpage_scraping`（把该主机加进豁免名单，是用户的决定） |
| 通用检索：DuckDuckGo / 公共 SearxNG 一律 ConnectTimeout | 国内网络不可达（**事实，不是缺陷**） | 免 key 通用检索走 **自建 SearxNG**；或商用 API 免费额度（Brave/Google CSE） |
| `provider_status` 只看得到 `missing_api_key` 却不知道要配哪个 | 缺 key 与缺配置混在一个错误里 | 错误码分三类：`missing_api_key: <ENV>` / `missing_config: <配置键>` / `blocked_by_robots` |
| 产物 100% 走兜底（`flat`/`skeleton`），报告只显示一个"降级率 100%" | 推理模型的 `reasoning_content` 吃掉全部 `max_tokens`，`content` 空着回来 | 限额提到 16384/4096；`ChatReply.truncated` 可判定；产物写 `mode_reason` 并在报告里列出 |
| 自检脚本报"默认路径全绿"，其实一个来源都没跑 | 脚本把 `providers: ["auto"]` 当成一个叫 auto 的来源名 → 查不到 key → 跳过 → 退出码 0 | 自检脚本必须复用工具的 `resolve_wanted` 解析 auto；未知来源名与"一个都没解析出来"都算硬失败 |
| SearxNG 单引擎查询有结果，聚合查询恒 0 条 | `use_default_settings.engines.keep_only` **只负责保留，不负责启用**；这两个引擎在默认表里就是 `disabled`，而查询里显式写 `engines=x` 会强制运行 | 再补一段 `engines: [{name: x, disabled: false}]`；用 `/config` 核对"启用引擎数"而不是猜 |
| 容器 `/search?format=json` 直接 curl 有 16 条，我们的 provider 恒 0 条 | **缓存把一次瞬时状态钉死了**：容器刚起、引擎未加载完时返回 `200 + results: []`，被缓存 6 小时 | 出网层只缓存"200 且有内容"的响应；**检索类请求一律 `cache=False`**（检索是时点查询，内容抓取才吃缓存） |
| `docker compose up -d` 报 `dial tcp registry-1.docker.io` 超时 | Docker Hub 在境内不可达（**事实，不是缺陷**） | `docker pull docker.m.daocloud.io/<repo>:latest` 再 `docker tag` 回官方名；`docker.1ms.run` / `docker.1panel.live` 实测也可达 |

## 9. Windows 中文路径下的已知坑（必读，能省一小时）

**现象**（2026-10-05 本机实测）：`uv pip install -e .` 之后，`.venv` 里的解释器**启动即崩**，连 `print(1)` 都跑不了：

```
Fatal Python error: init_import_site: Failed to import the site module
UnicodeDecodeError: 'gbk' codec can't decode byte 0xae in position 16: illegal multibyte sequence
```

**原因链**：

1. 项目路径是 `D:\AI+教育毕设毕设\ScholarScout`（**含中文**）
2. editable 安装会写 `.venv/Lib/site-packages/_editable_impl_scholarscout.pth`，内容是 **UTF-8** 的 `D:\AI+教育毕设毕设\ScholarScout\src`
3. CPython 3.11 的 `site.py` 读 `.pth` 用的是 **locale 编码**（zh-CN Windows = GBK）→ 解码失败 → 解释器起不来
4. **`PYTHONUTF8=1` 也救不了**（已实测），因为它不影响 `site.py` 读 `.pth` 的那次解码

**规则（本项目自定）**：

1. **禁止 `uv pip install -e .` / `pip install -e .`**（比铁律 #6 更硬：这条直接让环境不可用）
2. 装依赖用 `python scripts/install_deps.py`（读 pyproject 装依赖，**不装本包**）
3. 跑 CLI 用 `python scripts/scout.py ...` —— 启动器把 `src` 显式插进 `sys.path`，路径由文件系统 API 取得，不经过 `.pth`
4. 跑测试不需要装包：`pyproject.toml` 里 `[tool.pytest.ini_options] pythonpath = ["src"]` 已处理
5. 换机器/换到纯英文路径后本条依然成立（少一个可变因素）
