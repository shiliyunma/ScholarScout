## 2. 模块边界（谁可以 import 谁）

```
desktop/  →  rpc/  →  runtime/  →  tools/  →  {providers/, fetch/, grading/, state/}
                                        ↑
                                    state/ 不被 providers 反向依赖
```

| 规则 | 说明 |
|---|---|
| `tools/*` 不许 import `rpc/*` | 工具是模型可见层，不知道自己被谁调 |
| `providers/*` 不许 import `state/*` | provider 只负责取数据，落库是 tools 的事 |
| `desktop/*` 只经 `rpc/server.py` 通信 | 壳里不许出现 sqlite3 或 httpx |
| `state/*` 是唯一碰 SQL 的地方 | 其他模块不许出现 `execute(` |
| `fetch/*` 是唯一出网的地方 | 其他模块不许 import httpx（除了 providers 的 base 抽象） |

**新增一个能力时的落点（按顺序问自己）**：
1. 是"取数据"吗 → 加 `providers/` 里的一个 provider，或复用现有
2. 是"模型要能主动做的一件事"吗 → 加 `tools/` 里一个工具 + 在 `docs/01` 里加 schema
3. 是"前端要展示的界面"吗 → 加一个 RPC 方法 + `ui/` 一页
4. 都不是 → **先别写**，回 `docs/01` 讨论（铁律 #1）

## 3. 规则文件

- **规则正文的唯一权威副本是 `docs/项目规则.md`**（`<!-- RULES:BEGIN -->` 与 `<!-- RULES:END -->` 之间）
- **`AGENTS.md` 是必须存在的分发副本**（Hermes 与各类 AI 助手读它）
- **`CLAUDE.md` 是可选副本**：2026-10-05 项目所有者决定不创建（本机不用 Claude Code）。要启用时 `cp AGENTS.md CLAUDE.md` 再改开头两行注释即可，正文必须逐字一致
- 校验：`scripts/check_rules_sync.py` —— 必需副本缺失或不一致 = 门槛不过 = 不合；可选副本不存在只提示
- 为什么不各自维护：规则漂移比重复更危险（AI 会按旧规则写代码）
- 规则正文包含七节：协作铁律 / 技术栈 / 命名 / 错误处理 / 依赖政策 / 门槛与关键路径 / 提交与 PR

## 4. 门槛（对应铁律 #4）

```bash
bash scripts/check.sh          # 全跑；任何一个不过，退出码非 0
bash scripts/check.sh --fast   # 只跑 lint + rules_sync + deps（提交前快速自检）
```

门槛组成：

| 步骤 | 命令 | 不过的后果 |
|---|---|---|
| lint | `ruff check src tests` | 不合 |
| 格式 | `ruff format --check src tests` | 不合 |
| 类型 | `mypy src` | 不合 |
| 测试 | `pytest -q` | 不合 |
| 规则同步 | `python scripts/check_rules_sync.py` | 不合 |
| 依赖审批 | `python scripts/check_new_deps.py` | 不合 |
| 前端资源 | `python -m scholarscout.desktop.assets --check` | 不合（W2 起） |

## 5. 依赖审批机制（对应铁律 #6）

1. 运行期依赖写在 `pyproject.toml` 的 `dependencies`，同时必须列进 `deps-allowlist.txt`
2. `scripts/check_new_deps.py` 逐条比对；**出现未列入白名单的依赖，退出码 1**
3. 申请新增时在本文件 §6 追加一行，写清：用途 / stdlib 为何不行 / 体积 / 许可证
4. `dev` 组（pytest/ruff/mypy）与构建后端不进运行期白名单，但也要在 §6 登记

## 6. 依赖登记表

| 依赖 | 用途 | stdlib 为何不行 | 状态 |

| `httpx` | 出网（超时/重定向/HTTP2 控制好） | `urllib` 无连接池、超时语义差、重试要手写 | 已批准 |
| `PyYAML` | 读 `config.yaml` | 无内置 YAML | 已批准 |

## 9. Windows 中文路径下的已知坑（必读，能省一小时）

**现象**（2026-10-05 本机实测）：`uv pip install -e .` 之后，`.venv` 里的解释器**启动即崩**，连 `print(1)` 都跑不了：

```
Fatal Python error: init_import_site: Failed to import the site module
UnicodeDecodeError: 'gbk' codec can't decode byte 0xae in position 16: illegal multibyte sequence
```

**原因链**：

1. 项目路径是 `D:\AI+教育毕设毕设\ScholarScout`（**含中文**）
2. editable 安装会写 `.venv/Lib/site-packages/_editable_impl_scholarscout.pth`，内容是 **UTF-8** 的 `D:\AI+教育毕设毕设\ScholarScout\src`
3. CPython 3.11 的 `site.py` 读 `.pth` 用的是 **locale 编码**（zh-CN Windows = GBK）→ 解码失败 → 解释器起不来
4. **`PYTHONUTF8=1` 也救不了**（已实测），因为它不影响 `site.py` 读 `.pth` 的那次解码

**规则（本项目自定）**：

1. **禁止 `uv pip install -e .` / `pip install -e .`**（比铁律 #6 更硬：这条直接让环境不可用）
2. 装依赖用 `python scripts/install_deps.py`（读 pyproject 装依赖，**不装本包**）
3. 跑 CLI 用 `python scripts/scout.py ...` —— 启动器把 `src` 显式插进 `sys.path`，路径由文件系统 API 取得，不经过 `.pth`
4. 跑测试不需要装包：`pyproject.toml` 里 `[tool.pytest.ini_options] pythonpath = ["src"]` 已处理
5. 换机器/换到纯英文路径后本条依然成立（少一个可变因素）

**已中招怎么救**：

```bash
rm .venv/Lib/site-packages/_editable_impl_scholarscout.pth
uv pip uninstall --python .venv/Scripts/python.exe scholarscout
```
