# 25 检索源候选清单（GitHub 清单调研 + 官方文档逐项核实）

> 建立 2026-10-24 ｜ 状态：**调研稿（只出文档，未改生产代码）**
> 关联：`src/scholarscout/providers/`（现有 11 源）、`docs/03-目录结构与规则文件.md` §6/§7；
> 结论口径：**只认官方文档原文**，清单/博客/二手转述一律不作为依据；查不到就写「未核实」。

**一句话**：现有 11 个源里真正"免费 + 无 key + JSON + 稳定"的只有 arXiv/OpenAlex 两个，
学术侧最该补的是 **Europe PMC / Crossref / DataCite / DOAJ / CORE / Zenodo / PubMed** 这一组
（全部免费、多数连 key 都不要），通用搜索侧只值得再补 **LangSearch** 一个，
其余"免费搜索 API"清单里躺着的名字大半已退役、停服、或本来就是抓别人结果页。

## 1. 调研方法，以及为什么不能只信清单

三步：

1. **先看清单**：GitHub 上 5 个仓库（下方 §2），取它们列的搜索类 API 作为候选池；
2. **再去官方文档**：每个候选逐个打官方文档/官方 API，记录 key、额度、速率、格式、中文、合规；
3. **最后实测**：能直接打的接口发一次真实请求（含中文关键词），拿到 HTTP 状态与返回体才算数。

两个必须先说清的限制（影响结论的置信度）：

- **本机网络对部分站点不可达**：`www.mojeek.com`、`base-search.net`、`searx.space`、
  `api.stackexchange.com`、`www.reddit.com`、`developers.google.com` 在本机 curl/urllib 均超时；
  `www.ncbi.nlm.nih.gov`（文档站）被 reCAPTCHA 拦截，`europepmc.org` 文档站返回 403。
  这些**不是"不存在"，是"我这边读不到"**，因此相关字段一律标「未核实」，不按记忆补数字。
- **PubMed 的速率数字不是从 books 文档拿的**：官方 books 页打不开，改从 NLM 支持库
  KA-05317 与 NCBI Insights 官方博客拿到同样的 3/10 rps 原文（见 [S1][S2]）。

**这一节的结论本身就值得写下来**：中文互联网上流传的"免费搜索 API 大全"基本是这三种货色——
① 早就重构掉了搜索分类（public-apis）；② 五年没更（n0shake）；③ 由某家 SERP 转售商维护（awesome-seo-tools）。
所以本清单的**每一条都回到官方文档**，而不是抄清单。清单里出现、官方文档里查不到的（Mojeek 的免费额度、
Zenserp 的速率），本文一律写「未核实」。

## 4. 中文支持：实测，不猜

同一个中文查询词「人工智能教育」，直接打各家公开接口：

| 源 | 结果 | 结论 |
|---|---|---|
| Europe PMC | `hitCount: 1115` | 可召回中文（其索引含中文题录/摘要） |
| DOAJ | `total: 36`，`query` 原样回显 | 可 |
| Crossref | `total-results: 454569` | 可（但 fuzzy 匹配，数字含义弱） |
| DataCite | 返回正常 JSON | 可 |
| Zenodo | 返回正常 JSON | 可 |
| HAL | `numFound: 0` | **不可**（法语/英语索引） |
| PubMed | `count: "0"`（英文同义词查询 49,630） | **不可**，与 arXiv 同类问题：检索要用英文关键词 |
| CORE | SSL handshake 超时 | 未核实 |

**给接入的规则**（和 `providers/README.md` 里 arXiv 那条一致）：**检索词用英文，中文只用于主题与摘要**。
中文项目不等于中文检索——这条要在 `research.search` 的提示词里写死，否则用户拿中文问，
一半源直接 0 条，看起来像"坏了"。

## 5. 分组推荐

### ① 优先接入（免费 / 无 key / JSON / 有官方文档 / 实测通）

1. **Europe PMC** — 无 key，生命科学 + 预印本，中文也能召回；唯一短板是速率数字没读到 [S3]
2. **Crossref** — 全学科 DOI 元数据底座，无 key，`mailto` 进 polite pool [S6]
3. **DataCite** — 数据集/软件 DOI，速率分档写得最清楚（500/1000/3000 每 5 分钟）[S7]
4. **DOAJ** — OA 期刊，2 rps 明确，元数据干净 [S5]
5. **CORE** — OA 全文，无 key 可用（5 单条/10 秒）[S4]
6. **Zenodo** — 数据/软件/预印本，搜索 30/分钟 [S8]
7. **PubMed** — 医学权威源；中文 0 命中，必须英文检索 [S1][S2]
8. **HN Algolia** — 无 key，补"工程舆情"这一层 [S27]

### ② 次选（有免费额度但要 key，或额度会变）

1. **LangSearch** — $0 全功能 + 5 RPS + 50 条/请求，通用侧最划算；风险是"每日 token 额度"没写数字 [S21]
2. **Brave Search API** — 自己的索引、50 QPS、可商用；$5/月免费额度只够演示 [S14]
3. **Exa** — $10/月额度、10 QPS，语义检索质量好，长期用要付费 [S20]
4. **Marginalia** — 非商用免费，冷门站点覆盖独一份；许可证 NC [S17]
5. **Serper / Tavily（已有）** — 已有 key，作为兜底保留，不再扩 [S25][S26]
6. **Stack Exchange / dev.to / Lobsters** — 都能用，但"没速率承诺"或"网络不通"，只适合做可选源 [S29][S30][S31]

### ③ 不推荐（付费 / 不稳 / 合规风险 / 已停）

| 源 | 一句理由 |

| Stract | 仓库 2026-04-02 已归档，站点域名易主 [S18] |
| Yandex Search API | 文档 307 死循环、需俄罗斯云账号、条款读不到 [S19] |
| Mojeek | 官网本机不可达，额度/条款/速率全部未核实，不能凭印象接 [S16] |
| BASE | 要注册 + IP 白名单，域名本机不可达 [S10] |

| 3 | **DataCite** | 数据集/软件 DOI 是现有源完全空的一块，速率分档官方写死，好实现 | ~150 行，`min_interval_s=1.0`（按未标识档 500/5min 留余量） |
| 4 | **DOAJ** | OA 期刊元数据干净，2 rps 明确，中文可查 | ~140 行，`min_interval_s=0.6` |
| 5 | **CORE** | 唯一能拿 OA **全文**的免费源；5 单条/10 秒 → 间隔 2s | ~170 行，`min_interval_s=2.0` |
| 6 | **PubMed** | 医学权威，3 rps 无 key 起步，配 key 升 10 rps；与 Europe PMC 互为补充 | ~150 行，`min_interval_s=0.4` |
| 7 | **Zenodo** | 数据/软件/预印本，搜索 30/分钟；补"非论文成果"这一类 | ~140 行，`min_interval_s=2.0` |
| 8 | **LangSearch** | 通用侧唯一"$0 全功能 + 5 RPS + 50 条"，用来替代抓页类通用源 | ~160 行 + key 配置，`min_interval_s=0.3` |
| 9 | **HN Algolia** | 免 key、零成本，补技术社区舆情；实现量最小 | ~110 行，`min_interval_s=0.5` |
| 10 | **HAL** | 法语/欧洲 OA 覆盖独一份，实现简单；中文 0 命中要在 status 里说明 | ~130 行，`min_interval_s=1.0` |

**为什么不再多**：每个源不是"一个 URL"，而是 `provider 文件 + 限速常量 + 解析纯函数 + fixture 测试 +
`provider_statuses` 的一条诊断分支 + README 的一段坑`，实测一项 ~110–170 行；10 个就是 ~1,500 行。
更贵的代价在运行时：`auto` 模式的并发扇出、去重、摘要预算都随源数线性涨，
而**给模型的来源清单每长一截，"选哪个源"的判断准确率就掉一截**——用户看到的是"检索变慢了、结果变杂了"。
建议**硬上限 18～20 个**：现有 11 个 + 本节 10 个 = 21，已经到顶，再加必须先下线（见 §8）。

## 7. 一条没进主表但值得记的路：自建 SERP

`karust/openserp`（1,499★，2026-10-19）用浏览器渲染自建 Google/Bing/Yandex 检索接口。
它解决的是"想要 Google 结果又没有合规 API"的需求，但**自己渲染 Google 结果页依然是抓取**，
robots/ToS 风险只是从"别人家的服务"转移到"你自己的 IP"。毕设开源项目不建议引入（要跑浏览器、要代理池）。
记在这里是为了说明：**这条路看起来能解决合规问题，实际上没有**。

## 9. 三条接入前必须知道的事（从这次核实里掉出来的）

1. **"免费搜索 API"清单基本不可信**：public-apis 已经把 Search 分类删了，n0shake 五年没更，
   awesome-seo-tools 是 SerpApi 自家的。这类清单只能当候选池，不能当依据。
2. **额度口径会变，且同一家官网自相矛盾**：Brave 落地页写"最高 $20/月免费"，定价表写"每月 $5 免费额度"。
   写代码时**按小的那个算**，并在配置里留可调项。
3. **Zenodo 的文档和实测不一致**：文档说"所有 API 访问都要 access token"，实测搜索接口免 token 就返回 JSON。
   这类情况以**实测为准 + 代码注释写明"文档与实测不一致，见 docs/25"**，别默默按文档写死。
