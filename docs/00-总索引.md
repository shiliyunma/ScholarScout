- **传输层并发（修一个真 bug）**（2026-10-06）：`serve()` 原本是"读一行 → 分发 → 写回"的
  单线程循环，一轮 `chat.send` 阻塞 3–12 分钟，后面的请求根本读不到 → 生成中点资料库条目
  **没有任何反应**；同样原因，**「停止」其实从来没生效过**（它排在队尾）。
  桌面桥 `RpcClient` 也把锁握到整个等待结束、并且会丢弃别的 `id` 的响应 → 并发必然串台。
  改法：服务端 daemon 工作线程 + 带锁写回；桥改成 per-id 信箱（锁只管"分配 id + 写请求"）；
  `Database` 放开 `check_same_thread`（WAL + 每语句 autocommit → 一写多读）。
  真机核对：生成过程中点资料库条目，右栏立刻切到文档预览，同时工具调用继续推进。
- **已修：用量记账不再漏记**（2026-10-07）。原缺口是记账在**整轮结束时**才落库（`traces.record_usage` 在

  改法：**每次模型调用后立即记**（`purpose="chat"`，不再在轮尾重复记一次）；标题总结那次调用也记
  （`purpose="title"`）——这样"关掉标题总结能省多少"才有数可答。
  测试钉住三件事：正常轮＝调用几次记几条、**取消的轮次已花的部分必须记**、失败的轮次同样记。
