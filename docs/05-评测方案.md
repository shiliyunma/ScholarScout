## 1. 要回答的三个问题（评测不为凑数字，为目标服务）

| # | 问题 | 为什么必须回答 | 对应指标组 |
|---|---|---|---|
| Q1 | **判权规则可靠吗？** 查表得出的层级/结论与人工判断差多少 | "判断权威性"是本课题的核心主张，拿不出一致率就只是形容词 | E1 |
| Q2 | **生成物真的挂在资料上吗？** 路线/地图里有多少条目你能指回真实来源 | 开放世界生成最容易被问"这不就是编的"，必须有**可计量的反幻觉证据** | E2 / E3 |

## 2. 三套评测集

| 集 | 文件 | 规模 | 需要模型 | 原子/判定 |
|---|---|---|---|---|
| **E1 判权集** | `eval/sets/e1_grade.jsonl` | 24 条 | 否（本地确定性打分） | URL + 主题 → 期望 `tier` 与 `verdict` |
| **E2 守卫集** | `eval/sets/e2_guard.jsonl` | 12 条 | 否（模型输出写死在题里） | 构造的模型原始输出 → 期望"开/关守卫"后的差异 |
| **E3 任务集** | `eval/sets/e3_tasks.jsonl` | 6 条 | **是**（真联网真模型） | 主题请求 → 产物是否挂真实来源 + 调用指标 |

### 2.1 E1 判权集：怎么标出来的（论文要写清楚，别假装是专家标注）

1. 题面从 `source_tier_rules` 的 40 条种子规则覆盖到的域名里取（含**一条都不命中**的兜底域名）；
2. 期望 `tier` 由规则表推出后**逐条人工复核**（看域名是不是真的属于该层：例如 `blog.csdn.net` 判 tier 4、`docs.python.org` 判 tier 1）；
3. 期望 `verdict` 用**本地确定性打分**（`use_model=false`）跑出后人工复核，凡不符合直觉的（例如主题词命中却判"外围"）当场改题面或记录为"已知分歧"；
4. 标注口径写进题里（`label_note` 字段），争议题保留而不删除 —— 论文里"分歧样本分析"比"成绩好看"更有说服力。

**如实声明**：标注由作者按上述规则整理，非多人独立标注，因此**只报告与规则的一致性，不外推为"人类共识"**。

### 2.2 E2 守卫集：不靠模型，靠写死的输出

每条题给一段**模型原始输出**（含真实 ID 与伪造 ID 混合、缺出处节点、乱格式行）+ 一个真实资料清单，比较两条路径：

- `raw = parse_*()` —— **不开守卫**（等于"信模型）
- `guarded = apply_guards(raw, allowed_ids=...)` —— **开守卫**（生产路径）

判定：`guarded.stats.ungrounded_*` 是否把伪造内容全部标出、`dropped_edges` 是否丢掉了悬空边、两种路径的差异是否与题面期望一致。

### 2.3 E3 任务集：现场可演示的六条

每条是一个真实用户请求（如"帮我找教育智能体方向的入门资料并排 4 周路线"），跑法：真模型 + 真出网（arXiv，遵守 3 秒限速）。产物落库后按 §3 取数。

**E3 不进门槛**（要网络与密钥，结果不可复现），只在论文与答辩现场跑，报告里标注运行时间与模型名。

## 3. 指标定义（分子/分母/取数口径，逐条可复算）

### 3.1 判权类（E1，数据源 `source_grades` + 规则表）

| 指标 | 定义 | 口径 |
|---|---|---|
| `tier 一致率` | 与标注相同的条数 / 总条数 | 直接比较 `source_grades.tier` 与题面 `expect_tier` |
| `verdict 一致率` | 同上，比 `verdict` | 四分类：核心/相关/外围/排除 |
| `Cohen's κ` | `(Po - Pe) / (1 - Pe)` | 四分类混淆矩阵算，`Pe` 用边缘分布 |
| `兜底命中率` | 无规则命中而落 tier 4 的条数 / 无规则命中的条数 | `matched_rule_id IS NULL` 且 `tier = 4` |
| `误升率` | 标注为 tier ≥ 3 却被判 tier ≤ 2 的条数 / tier ≥ 3 的条数 | 低质来源被抬高的代价 |

### 3.2 反幻觉类（E2/E3，数据源 `topic_maps.graph_json` / `learning_routes.plan_json`）

| 指标 | 定义 | 口径 |
|---|---|---|
| `出处覆盖率` | 挂了真实 source_id 的**资料类**条目数 / 资料类条目数 | 地图节点 + 路线资料类条目合并统计（分母见下方"条目分两类"） |
| `伪造引用率` | 被守卫标出的伪造引用数 / 模型给出的引用总数 | 守卫前分母、守卫后分子 |
| `ungrounded 比例` | `stats.ungrounded_nodes` 与 `ungrounded_items` 之和 / **资料类**条目数 | 越低越好，**但 0 不等于好**：模型没引用任何来源时该值也为 0，必须同时看出处覆盖率 |
| `行动类条目数` | `stats.exercise_items` | 练习/产出的条数；**不进上面两个比率的分母**（见下） |
| `每题不同来源数` | 一件产物里出现过的**不同** `source_id` 个数（地图节点引用 ∪ 路线资料类条目） | 防退化：全挂同一个 id 时覆盖率仍是 100%（真机抽样：e3-04 = 14 节点 30 次引用 8 个来源、路线 7 条 7 个来源） |
| `悬空边剔除数` | `stats.dropped_edges` | 端点不存在的边数 |
| `降级率` | `mode ∈ {flat, skeleton}` 的产物数 / 全部产物数 | 反应模型不可用/输出不可解析时是否如实降级 |
| `产物完整率` | 同时产出主题图与路线的任务数 / 任务数 | 只看 `stop_reason=completed` 会漏掉"对话完成但少出一件产物"（真机第三轮 2/6 只出了路线） |

**条目分两类 —— 这决定了分母（e3-04 真机踩出来的口径修正）**：

| 类别 | kind | 是否声称有出处 | 计入 ungrounded / 覆盖率分母 |
|---|---|---|---|
| 资料类 | `paper` / `doc` / `video` / `code` | 是（"这里有一份资料"） | **计入**：挂不上真实 id 就是 ungrounded |
| 行动类 | `exercise` | 否（"你要动手做的事/产出"） | **不计入**，单独报条数 |

为什么必须分开：第一次真机跑 e3-04 时路线 18 条里 11 条被判"无出处"，逐条看完全是
`在小型 KT 数据集上跑通训练`、`构造新学生冷启动评估划分`、`写一份端到端复现报告` 这类**练习与产出** ——
它们本来就没有、也不该有出处。把练习算成"无出处"是**度量的错**，而且会反向逼模型给练习硬挂一个来源
（那才是真幻觉：为了让指标好看而编引用）。修正后同一题的无出处条目从 11 条降到个位数，
剩下的才是真实缺口（模型指名了库里没有的资料）。

### 3.3 稳定性与成本（E3，数据源 `tool_traces` + `usage_records`）

**生成策略：两档对照**（2026-10-05 起，默认按需）

| 档位 | 提示词 | 期望 |
|---|---|---|
| **按需档（默认）** | `ON_DEMAND_PIPELINE_PROMPT` | 首轮**不出产物**，结尾用一句话问用户要不要；用户点单后才生成 |
| **自动档（对照臂）** | `PIPELINE_PROMPT`（= 2026-10-05 E3 第四轮那版，逐字未改） | 每轮自动出"主题图 + 路线" |

跑法：`run_eval.py --set e3 --live`（按需档）/ `--live --auto-artifacts`（对照臂）/
再加 `--ask-artifacts` 会在首轮后追发一条"请生成"的消息，量**按需生成成功率**。

两个档位各加三个指标，一起看才有结论：

| 指标 | 口径 | 按需档期望 | 自动档期望 |
|---|---|---|---|
| `auto_artifact_rate` | 首轮就出产物的任务占比（确定性，查库）。**含题面点名要产物的情形** | 取决于题面 | ≈ 1 |
| `unrequested_artifact_rate` | **题面没要、模型却出产物**的比例（确定性）。分母只算"题面没点名要产物"的题 | ≈ 0 | — |
| `asked_rate` | 结尾主动询问要不要生成（**措辞启发式，不精确**） | 高 | 不适用 |
| `on_demand_success_rate` | 用户点单后真出产物的比例（**确定性**） | 高 | 不适用 |

### 3.4 一次真实的度量返工（写进论文的"教训"节）

2026-10-05 第一次跑按需档，`auto_artifact_rate` 报 **83.3%**，看上去像"模型不听指令、照样自动出产物"。
查证后是**我的指标错了**：`eval/sets/e3_tasks.jsonl` 六道题的题面**全部点名要了产物**
（"再排一条 4 周学习路线""给我一条路线""怎么安排四周"…），所以在按需档下"用户明确要了 → 模型直接做"
是**正确**行为；照 `auto_artifact_rate` 的口径算，正确行为被记成了违规。

修法：把"擅自生成"单独拆成 `unrequested_artifact_rate`，**分母只算题面没要产物的题**；
并新增探针题集 `eval/sets/e3_probe_tasks.jsonl`（3 道只要回答、不要产物的题）——
那个数据集的题面都不点名要产物，才有分母可算。

> 教训：**指标的名字与分母必须写清楚**。"首轮出了产物"与"用户没要却出了产物"是两件事；
> 用一个数同时表示它们，就会把正确行为读成失败。报告里这两条现在分列，且分母随行标注。
>
> 口径边界：`asked_rate` 只是"有没有出现「要不要…生成…」这类措辞"，**不是**语义判断、
> 更不是用户满意度；要拿它下结论必须同时给出 `on_demand_success_rate`。
> `report.py` 的 `arm.system_prompt_hash` 会记录本档用的是哪版提示词，
> 保证"这两组数字分别来自哪版提示词"可追溯。


| 指标 | 定义 | 口径 |
|---|---|---|
| `工具成功率` | `ok = 1` 的行数 / 全部行数 | **唯一取数入口 `tool_traces`**（docs/01 §5 硬规则），失败行同样计入分母 |
| `工具时延 P50/P95` | `latency_ms` 的分位数 | 仅成功调用；**最近秩法**（`eval/metrics.py:percentile`，`ceil(p/100×n)` 个），口径与代码一致 |
| `单请求工具次数` | 每条任务的 trace 行数 / 任务数 | 直接反映"打转" |
| `token 消耗` | `usage_records` 的 prompt/completion 累加 | 按用途（chat / summary）分开报 |
| `端到端时延` | 任务开始到产物入库的墙钟时间 | 报告里给中位数，注明机器与网络环境 |

### 3.5 E1 第一次跑出来的真问题（记录在案，别让它悄悄消失）

第一次跑 E1 的原始成绩：**tier 一致率 87.5%（κ 0.834）、verdict 一致率 50.0%（κ 0.342）**。三个不一致全部是**系统侧的真缺陷**，不是标注错：

| 现象 | 根因 | 修法 |
|---|---|---|
| `www.nature.com` 判成 tier 4 | 域名规则是**等值**匹配，规则写 `nature.com` 命中不了任何子域 | 改匹配逻辑：域名规则同时认子域（`grading/tiers.py`） |
| `zhuanlan.zhihu.com` 判成 tier 4 | 同上 | 同上 |
| `www.gov.cn` 判成 tier 4 | `.gov` 后缀匹配不到 `gov.cn`，中国政务站点整类漏判 | 迁移 `0003` 补 `.gov.cn` / `.org.cn` / `.ac.uk` / `.edu.hk` |

verdict 一致率低则是另一回事，**属于已知局限而非缺陷**：本地确定性打分只认字面重合（含中文二元组的部分credit），语义相邻的题（如"对话式教学系统"与"教育智能体"）它判不出来 —— 这正是"判权分级 + 模型判相关"两段式设计的依据，语义相关性交给 E3 的模型路径。

修完后 tier 一致率回到 100%（回归护栏在 `tests/eval/test_eval_sets.py::test_e1_tier_matches_rule_table_exactly`）；verdict 一致率与分歧样本照旧如实报告。

### 3.6 E3 第一次真机运行暴露的三个致命缺陷（比 E1/E2 更有价值的一组发现）

离线两套集全绿（E1 tier 100%、E2 守卫 12/12）之后，**第一次真机跑 E3：六个任务全部 `error`、0 次工具调用、0.1 秒返回**。三层根因，每一层单独都足以让系统在真实环境下完全不可用：

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 模型立即返回 400：`Invalid 'tools[0].function.name'` | OpenAI 兼容 API 只接受 `^[a-zA-Z0-9_-]+$`，而工具名是 `research.search` | 引入**线上名**（点→`__`）与规范名的双向映射（`runtime/registry.py`）；事件、轨迹、对外结果仍用规范名 |
| 2 | 检索恒 0 条，provider 报 `forbidden` | `robots.txt` 被套用到**官方 API**：arXiv 明确 `Disallow /api/query` | API 主机进 `robots_exempt_hosts` 白名单（`fetch/http.py`），只豁免指定主机 |
| 3 | 检索 `ok=true` 但恒 0 条 | 查询被整句加引号 → 变成精确短语匹配 | 按空格切词，`all:a AND all:b` 组合（`providers/arxiv.py`） |

**附带修掉一个"误导模型"的回包设计**：所有来源都失败时，`research.search` 原本回 `ok=true` + `items: []`，模型据此判断"这个方向没资料"，于是反复换关键词重试直到烧光工具预算，最后开始输出伪造的工具调用标记（DSML）。现在全失败回 `ok=false` + 明确原因，模型才会停下来如实告知用户；混合情况（部分来源失败）仍算成功，失败不阻塞。

> **这组发现的方法论意义（论文第 6 章可以引用）**：E1/E2 是**打桩**评测，只能证明"逻辑自洽"，证明不了"能跟真实 API 对上话"。
> 三个缺陷全部藏在接口边界（工具声明格式、robots 适用范围、第三方查询语法），任何离线用例都触碰不到。
> 结论：**每个里程碑收尾都必须跑一次真接口冒烟**，否则"全绿"是假绿。

另有一条**事实性约束**（不是缺陷）：**arXiv 只索引英文**，中文关键词（如「教育智能体」）恒 0 条。
因此检索用英文关键词，中文只用于主题、摘要与产物 —— 这条已写进 `docs/03 §7` 坑清单。

## 4. 对照臂（ablation）——用同一份数据做差，而不是另起一套流程

| 臂 | 做法 | 期望结论 |
|---|---|---|
| **A_full** | 生产路径（规则表判权 + 模型相关性 + 守卫 + 白名单来源） | 基线 |
| **A_no_guard** | 同一份模型输出，跳过 `apply_guards` | 伪造引用率上升、出处覆盖率虚高（假 ID 也算"有出处"）→ 证明守卫不是装饰 |
| **A_no_rules** | 判权退化为"全 tier 4" | verdict 一致率下降，用来量化规则表的价值 |
| **A_tier_in_relevance** | 相关性打分把 tier 计入（违背设计的那条） | 主题词命中但低质来源被抬高，标注一致率下降 → 支撑"分级只调门槛不参与打分"的设计决定 |

**A_no_guard / A_no_rules 在 E2 与 E1 上离线可跑**（无需模型），A_tier_in_relevance 只在 E3 上跑（需模型）。所有臂的差异都从**同一份**模型输出/同一份题面算出，避免"换题换结论"。

## 5. 判分规则（写死，避免事后调松）

1. 出处标识只认库内真实 ID：`src_`（资料）/ `rte_`（路线）/ `tpm_`（主题图）/ `not_`（卡片）。
   回答里出现形如 `src_xxx` 但库里查不到 → 记**幻觉引用**，不因"看起来像"而放过。
2. 数字类断言（如"准确率 42% → 58%"）必须能在该 source 的摘要里找到同样的数字串，否则记**不可溯源数字**。
3. 判定不一致时**保留原判**并在报告里列出分歧样本，不许回头改题面让分数好看。

产物：`eval/reports/<时间戳>.json`（原始数字，供复算）与 `<时间戳>.md`（可直接贴进论文的表格）。
`eval/reports/` 不入库（见 `.gitignore`），论文只引用其中的数字并注明报告文件名。

## 7. 已知局限（论文第 6 章要写全，别藏）

1. **样本量小**：E1 24 条、E2 12 条、E3 6 条 —— 结论是"方向性"的，不是统计显著性的。
2. **规则表是人工种子**：tier 分布由作者维护的 40 条规则决定，换一批域名会变；规则表本身可被审阅与替换，这是设计选择而非缺陷。
3. **本地打分非语义**：`use_model=false` 时的相关性是词覆盖+时效的近似（中文主题词按二元组给部分credit），**不能代表语义相关**。修完规则缺口后 E1 的成绩是：tier 一致率 100%（κ 1.000）、verdict 一致率 58.3%（κ 0.444），分歧 10 条全部保留在报告里。
   两个方向不同的偏差值得写进论文：**漏判**（语义相邻但不含主题词，如「对话式教学系统」被判"排除"）与**高估**（社区层标题含"智能体"二元组而被抬到"相关"，如掘金/知乎教程）。前者要靠模型路径补，后者提示"部分命中在低权重来源上应当打折"是明确的 future work。
4. **模型非确定性**：`temperature=0` 也只降低而非消除波动，E3 数字标注运行时间与模型版本，不承诺逐次复现。
