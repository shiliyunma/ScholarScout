# 指标完整性：自检、注入验证与跑批后复核

这一层比"指标选得好不好"更容易翻车：**指标静默算错，没人会发现**。

## 一、为什么必须有自检

读错记录字段名（例如读 `tool_calls` 而实际字段叫 `tools_called`）会让指标
**恒为 0 且不抛任何异常**——面板上看起来像"系统完全不会调工具"。
真数据跑不出这个 bug：你要么信了那个 0，要么根本注意不到。

结论：**指标代码的可靠性不能靠跑真数据验证，只能靠"给已知输入、断言已知输出"。**

## 二、自检怎么写

1. 建一个 `selftest_metrics.py`，**不联网、不需要模型**，秒级跑完（否则没人会在每次改动后跑）。
2. 覆盖四个层面：
   - 检索指标：金标准排第 1 / 第 2 / 没命中 / **无金标准（应返回"不适用"而不是 0）**
   - 引用解析：直接写 id / 按序号 `[1]` / 序号越界 / 只写出处标记没标 id / 同 id 重复出现只记一次
   - 三档判分：内容对且引到金标准=1 / 内容对但没引到=0.5 / 该答却拒答=0 / 不可答且拒答=1 /
       纠正错误前提=1 / 附和错误前提=0
   - 聚合与统计：**聚合层是否读对了字段**（用构造记录跑一遍 E6 等），Wilson 边界不出 0–1，
     McNemar 与 kappa 的已知值
3. **构造的记录必须与真实记录同形**：多塞一个字段（例如顺手给个 `tool_calls`）会刚好绕过
   要测的那个 bug。
4. 容差要匹配指标的舍入（指标值统一 round 到 4 位就用 1e-3；用 1e-6 会把舍入当失败）。
5. 失败时 `sys.exit(1)`，能接进任何检查流程。

## 三、注入验证（不做这步，自检等于没写）

写完自检后，**故意把要测的条件改错**（字段名改回错的、严格判定改成并集、分母改错），跑一遍，确认：

- 自检**报失败**（而不是因为别的原因崩溃）
- 退出码非 0
- 还原后重新全过

只看到"全过"不算验证——断言本身写错了也会全过。
注意：管道（`| tail`）会吞掉退出码，验证退出码时别接管道。

## 四、跑批之后的复核清单（汇报之前必做）

1. **扫一遍所有指标，专找异常值**：恒 0 / 恒 1 / 分母为 0 的都要查。
   （恒 0 是最典型的"读错字段"信号。）
2. **抽查 2–3 条原始记录**，人工核对分数是否合理；汇总表看不出判分逻辑错在哪。
3. **逐题对"期望 vs 实际"**：期望的工具链 vs 实际调用、期望的引用 vs 实际引用。
   结果分与工序指标分开看——"结果满分但工序只跑一半"就靠这一步发现。
4. **改了判分规则 → 重算不重跑**：写一个 rescore 入口重新应用规则、模型输出一字不动，
   两次结果才可比；重跑模型会引入随机性。
5. **汇报时说清哪些数变了、哪些还站得住**：前面的结论若因此变化，主动纠正，不要默默改口。

## 五、其他会静默出错的地方

| 风险 | 机理 | 处理 |
|---|---|---|
| 引用解析不全 | 模型会写"根据资料[1]"（序号）而不写 id | 把序号映射回检索结果的第 n 条；越界要留痕 |
| 假引用不计分 | 只扫 id/序号会漏掉"写了出处标记却说不出是哪一条" | 加一个哨兵值进分母，让"假装引用了"也扣分 |
| 不可答题拉低检索指标 | 无金标准时返回 0 而不是"不适用" | 返回 -1 并在聚合时跳过 |
| 跨臂比较混入不同题 | 两臂跑的题集不完全重叠 | 按题号对齐，只对交集做配对检验 |
| 报告渲染失败没被发现 | 内联 SVG 可能因 NaN/None 变成空白 | 生成后校验：SVG 可解析、无 NaN/None、关键数字确实在页面里 |
| 离线兜底被当成真实效果 | 检索源限速时落回 fixture，数字看起来一样漂亮 | 报告里显式标注；只声称"流水线能跑通" |
| mock/小模型数字被引用 | 没 key 时自动降级到假模型 | 报告顶部自动打警示条，并把模型名写进报告 |
