# 用评测驱动地改进 prompt / 工具描述 / 判据文本

适用：你要改的不是代码，而是**一段文本**（系统提示词、工具描述、意图判据、技能文件），
并且想知道"改完到底好了没有"。做法是把它当成一个**有对照臂的优化循环**，不是一次编辑。

## 一、先分三份数据，否则会"背答案"

| 集 | 谁用 | 目的 |
|---|---|---|
| **train** | 优化时每轮都看 | 收 feedback，决定往哪改 |
| **val** | 用来选版本 | 防过拟合 train |
| **holdout** | **只在最后看一次**，优化过程中从不使用 | 真正的考试 |

只用一份数据的话，优化器会针对这几道题越调越好，换个新任务就不行了。
分层抽样（按金标类别分层），固定随机种子保证可复现。
样本量小时（几十条）**val/holdout 每条 = 好几个百分点**，要把这句话写进局限，
必要时改成"多次重复分层划分，报均值与范围"。

## 二、循环四步

```
在 train 上评估 → 收 feedback（为什么差、该改哪句话）
  → 按 feedback 定向改写文本
    → 在 val 上评估
      → 更好就留，否则回退到上一版
        → 重复 N 轮（连续 2~3 轮无改进就早停）
```

**feedback 驱动 ≠ 随机变异**：把文本交给模型说"改改"，它不知道该改什么，大概率越改越差；
先拿到具体反馈（"这一类答错是因为判据里没写清 `other` 的边界"），再定向改，命中率高得多。
所以错例列表**必须逐条带"期望 / 实际 / 置信度 / top3 / 备注"**——这就是 feedback 的原料。

**回退是硬规则**：每轮只在 val 上真变好才保留。这条规则的价值在于它**会否决你自己的改动**：
实测过一轮定向改写后 train 反而更差、val/holdout 完全持平，按其规则直接回退 ——
没有这条规则，人就会用"感觉这次改得有道理"把退化版留下来。

## 三、约束门控：硬门控，且放在评估**之前**

改写后的文本必须先过四条硬检查，**任何一条不过就直接拒，不管分数多高**：

| 约束 | 规则 | 为什么 |
|---|---|---|
| `size_limit` | 总字符数 ≤ 上限 | 防膨胀 |
| `growth_limit` | ≤ 原始大小的 120% | 模型倾向于"多加点说明"来提分 |
| `non_empty` | 不能为空 | 变异可能产出空文本 |
| 结构合法 | 必需字段齐全、枚举值合法、段落结构未破 | 保持可解析 |

**放在评估之前**：先跑完评估（贵）再发现超限，白花一轮的调用。
**两条独立规则同时否决同一个候选，比单看分数可靠得多**（实测：一轮改写既被 growth 门控
拦下、又在 val 上无改进，两个不相关的判据给出一致结论）。

## 四、人审与部署

自动生成的文本改动**必须过人工 review 才能进主线**。配套：改动前备份原版（或开分支），
带时间戳，可一键回滚。教学/实验环境可以直接覆盖，但要在产物里留痕。

## 五、能套用这套循环的对象

同一套"打分 → 理解为什么差 → 定向改写 → 择优"换个对象就能用，变的只是"评什么"和"约束多严"：

| 对象 | 评估方式 | 典型约束 |
|---|---|---|
| 技能 / 提示词段落 | LLM 判 + 行为测试 | 不能比原版大 20%（提示词缓存） |
| **工具描述 / 意图判据文本** | **工具选择准确率 / 分类准确率** | 每个 ≤ 几百字符 |
| 工具源码 | 全量测试通过 + benchmark 不回归 | 函数签名不能改 |

## 六、常见坑

- **只看 train 分数就宣布成功**：train 是优化器看过的，必须有 holdout。holdout 比 baseline 差就不部署。
- **迭代次数越多越好**：不一定。观察 improvement 曲线，连续 2~3 轮无改进就停，后面都是白花钱。
- **改了文本不重跑全量**：train 好了但 val 崩，是最典型的过拟合信号，必须两个都看。
- **把"改详细了"当成"改好了"**：加例句、加说明会让文本变长，**实测多数情况下反而变差**（见 SKILL.md 同名条目）。
- **约束不过也硬上**："分数涨了 0.15 但大小超了 20%"——分数诱人，但膨胀会影响所有使用它的对话。
