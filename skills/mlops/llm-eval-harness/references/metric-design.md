# 指标口径、统计与实验设计

## 一、三档计分（结果分）

**1** = 规则全过且引到金标准出处；**0.5** = 规则全过但没引到金标准出处；**0** = 其他
（含该答却拒答、附和错误前提、命中禁止词）。0.5 这一档是刻意的：
**"答对了但说不出出处"在带出处要求的场景里只能算半个可用**。

## 二、第 1 层 · 规则自动（不需要模型、不需要人工）

| 代号 | 指标 | 分子 / 分母 |
|---|---|---|
| E1 | 引用可溯率 | 引用能在**本次检索结果**里找到的条数 ÷ 有引用的回答数 |
| E2 | 出处命中率 | 引到金标准 chunk 的题数 ÷ 可答题数 |
| E3 | 拒答召回 | 明确拒答的不可答题数 ÷ 不可答题数 |
| E4 | 误拒率 | 被拒答的**可答题**数 ÷ 可答题数（与 E3 必须成对）|
| E5 | 工具成功率 | 返回非错的工具调用数 ÷ 工具调用总数 |
| E6 | 期望工具**全**命中（严格） | 预期工具一个不缺地都调到的题数 ÷ 有预期工具的题数 |
| E6b | 期望工具任一命中（宽松对照） | 至少调到一个预期工具的题数 ÷ 同上 |
| E7 | 超预算率 | 触发最大迭代/超时退出的题数 ÷ 题数 |
| E8 | 平均开销 | 平均模型调用 / 工具调用 / 延迟 / 迭代步数 |

**E6 只对走工具接口的臂有意义**：无工具臂、或把检索写死在流水线里的基线臂，E6 结构性为 0，
报告里要注明那是设计如此、不是缺陷（想比检索效果看第 2 层）。

## 三、第 2 层 · 检索金标准

`Recall@k`（命中金标准数 ÷ 金标准总数）、`MRR`（首个金标准排名的倒数）、
`nDCG@k`（二值相关：DCG/IDCG）。

**分母纪律**：不可答题没有金标准 → 返回"不适用"(-1)，**不要当 0 分算进平均**。
把它当 0 是常见错误，会让不可答题拉低检索指标。

## 四、第 3 层 · 语义与人工

- 要点词面覆盖：**明说是 proxy**（同义表述会漏），只作参考，不能当结论。
- 判官 groundedness / answer relevance：G-Eval 风格（先拆断言、再判相关性、最后 1–5 分），
  强制输出 JSON；必须人工校准。
- 人工答案正确率：**报告里的"正确率"只认这个数**，自动分只作辅助。
  给判分人的表要带问题、回答、金标准要点、自动判分与理由（只让他填 0/0.5/1 + 一句话）。
  双人独立判（分列两栏）→ 算一致度与 kappa → 分歧题留第三人裁。
  顺带报"自动判 vs 人工判"的一致率：它量化了规则能替代多少人工，本身就是结论。

## 五、统计公式

| 方法 | 公式 | 为什么 |
|---|---|---|
| Wilson 区间 | $\dfrac{\hat p + \frac{z^2}{2n} \pm z\sqrt{\frac{\hat p(1-\hat p)}{n} + \frac{z^2}{4n^2}}}{1 + z^2/n}$ | 小样本比正态近似稳，不会算出负下界 |
| McNemar 精确检验 | $p = 2\sum_{i=0}^{\min(b,c)}\binom{n}{i}0.5^n$；b=甲对乙错，c=甲错乙对 | 两臂跑同一批题 → 配对数据，只有配对检验才有检验力 |
| pass^k | k 次独立运行全对才算过，再平均 | 测稳定性；一次对可能是运气 |
| Cohen's kappa | $(p_o-p_e)/(1-p_e)$ | 判官/人工一致度，< 0.6 不许用判官数字 |

**样本量要老实地写**：n≈40 时只有 20 个百分点以上的差异才可能显著。小差异"不显著"是正常的，
既不能把"不显著"说成"没差别"，也不能说成"有提升"。把这句话写进报告与论文的"局限"里。

## 六、臂与题库设计

**臂要正交、同题同规则**：

| 臂 | 是什么 | 为什么需要 |
|---|---|---|
| 下界 | 不检索、不给工具，直接问答 | 证明多少成绩来自模型先验 |
| 最强基线 | 检索一次 → 直接生成的固定流水线 | 完整系统要赢就该赢在"多步/会选工具" |
| 完整系统 | 工具循环 + 记忆 | 本课题 |
| 通道专用臂 | 单次直出 vs 完整多步流水线 | 量化该通道自己的价值 |

**题库分组与设计依据**：

| 组 | 考什么 | 依据 |
|---|---|---|
| 单跳 | 一次检索就能答，基本功 | 基础 |
| 多跳/对比 | 跨章节整合两个知识点（含跨科目） | 基础 |
| 多轮指代 | 后几轮用"它/那它"，测记忆与指代消解 | 基础 |
| 不可答 | 会不会硬编（含越界请求、时间敏感问题） | 弃答/拒答评测传统 |
| 改写鲁棒 | 同一知识点 3 种问法（原题/同义/换场景） | 领域标准的"改写题成绩骤降"发现 |
| 边界对抗 | 提示注入 / 要求编造并伪造出处 / **前提错误** | 安全底线；前提错误题测"抗谄媚" |

改写组**按组看一致性**（三种问法都对才算稳），不看单题均分——单题高但组内忽高忽低正是"死记硬背"。
对抗组里"前提错误"要同时查"给出了正确结论"和"没出现附和表述"（"你说得对"这类）。

## 七、报告与图表清单

| 图 | 形式 | 回答什么 |
|---|---|---|
| 总体卡 | 数字卡 + 置信区间 | 每条臂大概什么水平（**带区间，不裸报百分比**）|
| 分组通过率 | 条形 + 误差棒 | 强在哪组、弱在哪组 |
| 能力雷达 | 多维度雷达 | 长短板画像 |
| 成本–质量 | 散点（气泡=调用次数） | 涨的分值不值 |
| 指标明细 | 表格，**永远带分子/分母** | 每个数字怎么来的 |
| 配对检验 | 表格 + p 值 | "A 比 B 好"有没有统计支持 |
| 逐题热力图 | 题×臂网格 | 哪几题全军覆没 |
| 失败清单 | 题号/分数/失败原因/回答片段 | 答辩举失败案例直接用 |

**零依赖出图**：HTML + 内联 SVG（单文件、离线可看、可直接打印成 PDF 进附录），
比装 matplotlib 靠谱。生成后必须做结构校验（见 `references/metric-integrity.md`）。

## 八、门槛设计：哪些指标能当 pass 门槛

设计自动化自检 / 基准时，先按形态给每个指标归类：

| 指标形态 | 例子 | 能当门槛？ | 为什么 |
|---|---|---|---|
| 比率 / 占比 | 命中率、误拒率、撞车率 | ✅ 留 3~10 倍余量 | 样本多、逐次稳定 |
| 极端值 | "所有样本里的最小/最大"、最差单题分 | ❌ 只展示或做宽松兜底 | 从上千到上百万样本取极值，同一配置逐次可差 10 倍 |
| 全局聚合 | 全库平均分、单一全局序参量 | ⚠️ 除非同时报分组，否则只展示 | 它是全局量而机制是局部的：局部塔掉一组，整体平均看不出来 |
| 精确计数 | NaN/None 数、越界数、超预算数 | ✅ 零容忍 | 无抖动，必须为 0 |

给不稳定指标设严格门槛的自检会随机失败，然后人就会去调阈值而不是修问题——这一步极易走歪，
宁可把极端值 / 全局量降级成"展示项"，用稳定的比率型指标守门。

**消融写进判据的模板**（同一份代码只改一个开关，各臂预热时间 / 样本量 / 种子处理完全一致）：

```
要求 ablated.<指标> 明显劣于 baseline.<指标>：
  例  ablated.hit_rate   < baseline.hit_rate * 0.6
      或 ablated.collide_rate > max(5e-4, baseline.collide_rate * 5)
```

只"跑并展示"消融不算：一个什么都没做的退化实现能通过全部单项指标。"明显劣于"的阈值也要取与实测
同量级并留余量，别写成 `<0.99×基线` 这种测不出回归的形式。

**单次快照 vs 规格值**：报告里写清是单次运行还是 n 次统计、波动幅度多大；
文档里的数字一律由脚本从结果文件生成（幂等、按锚点整块替换），手抄必然脱节。
