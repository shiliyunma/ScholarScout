# 跨轮研究状态（ledger）：字段、缺口类别与验证脚本

配套 SKILL.md 的「多轮有效性」一节。适用于“调研型 agent 第 2 轮开始原地打转”的落地。

## 状态该存什么（一个会话一行）

| 字段 | 谁写 | 口径 |
|---|---|---|
| `goal` | 循环（开局） | 用户首条目标，截断到 ~200 字符 |
| `questions[] {text, status, evidence[]}` | 循环（开局拆 + 每轮回填） | `status ∈ open\|covered`；**解析不到模型回填就保持 open，绝不猜** |
| `used_queries[]` | 循环（每次检索**成功后**） | 判重的**唯一**数据源；失败不写 |
| `seen_sources[]` | 循环（每次工具返回后） | 用来判“这一轮有没有新证据” |
| `empty_rounds` | 循环 | **轮内**计数，每轮开头清零 |
| `plan_error` | 循环（拆分失败时） | 子问题清单缺失的原因，要在注入文本里显形 |

存储：`(session_id PRIMARY KEY, payload_json TEXT, updated_at TEXT)` 一张表；
读出来坏 JSON 一律回 None 按新台账重来 —— 一条脏记录不能把整个会话打死。

**写者只有循环一个**（见 SKILL.md 的硬规则）；工具只读。

## 缺口类别（只做能从库里确定性判定的）

| kind | 判据 | 建议方向 |
|---|---|---|
| `open_questions` | 子问题里 status≠covered | 针对该子问题换关键词/来源/语种 |
| `weak_evidence` | 有来源但没有摘要 | 先取正文再决定是否引用 |
| `year_gap` | 全部来源的最新年份 < 当前年 − 1 | 加年份限定再搜一轮 |
| `kind_gap` | 来源全是论文，没有代码/文档/网页 | 换 GitHub / 官方文档方向 |
| `not_fetched` | 有来源但没取过正文 | 先取 1–2 条 |
| `source_concentration` | 单一域名占比 ≥ 80% 且来源数 ≥ 4 | 换来源族 |

取不到的字段一律不写进缺口（未知年份**不进**“近两年占比”的分母）。
每条缺口给「现象 → 建议方向」，别只报现象。

## 注入文本的形状

放在**本轮消息的最后**（缓存前缀稳定），内容：目标 / 子问题（带「缺口·已覆盖」标记）/
已搜过的查询（明写“不要换词重搜，会被工具拒绝”）/ 缺口清单 / 一句“本轮若无新增来源就如实说明并停止”。
整体控制在几条以内 —— 注入本身也按 token 计费。

## 开局拆子问题

一次小调用，输出 JSON `{"goal", "questions": [3~6 条可独立检索的问句]}`；
要求覆盖不同角度（是什么 / 怎么做 / 对比或争议 / 近期进展），每条要能直接拿去检索，别写“深入了解 X”这种空话。

- 失败就**退化**（不阻塞这一轮），但要把原因写进状态并在注入文本里显形。
- 这类“多一次模型调用”的开关**默认关**，由配置文件显式打开 —— 否则每个既有测试的桩回复都会被它吃掉一次
  （表现是十几个循环用例集体失败，很容易误判成实现错了）。

## 停止条件

「连续 N 次（建议 3）检索都没有新增来源」→ 注入“停止检索、如实总结还缺什么”的说明并**收走工具**
（下一轮 `tools=None`），`stop_reason` 单列一档。多花一次调用换一句诚实的话，
比让它继续换词重搜（每轮约 10 次调用）便宜得多。

## 验证脚本该报什么（每次改进都用同一个脚本复测）

跑一个**真实两轮**会话（真实模型 + 真实检索），从库里取真值，逐条打印判据：

1. 第 2 轮**新增来源数**（改进前基线通常是 0）；
2. 第 2 轮**无重复查询** —— 判据调**产品代码里那个相似度函数**（同一把尺子），
   并单独报“被判重门拦下 M 次”；
3. 服务端**缓存命中 token > 0**；
4. 结束原因是“有意义的停”（`completed` / `no_new_evidence`），不是烧完预算；
5. 开局**真的拆出了子问题清单**（验证那条小调用跑通了）。

取数口径：新增来源从**库里的来源关联表**取（不是从模型自述）；查询从工具轨迹表取，
**必须带上成功标志**，否则被拦下的那次会被误报成重复。
