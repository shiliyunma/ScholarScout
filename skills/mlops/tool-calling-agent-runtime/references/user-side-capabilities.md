# 用户侧能力：画像、跨会话记忆、间隔重复

配套 SKILL.md 的「用户侧能力」与「花钱的功能」两节。适用于“agent 要按**这个人的**水平说话、
并且记住他”的落地。三件事都不需要新依赖，全部落在既有的本地库里。

## 学习者画像：确定性分档

能从库里算出来的量一律本地算（零调用、可复算、可核对）。掌握度分档示例：

| 档 | 条件 |
|---|---|
| 熟 | 连续答对 ≥2 次，**或**间隔已排到 ≥6 天（排到一周后说明连着答对过） |
| 复习中 | 连续答对 1 次；**以及“评过但还没有排期”的老数据** |
| 薄弱 | 答错过 ≥1 次，或最近一次评价是“不会” |
| 未练 | 没有任何记录 |

**分母**：`掌握度 = 熟 / 有记录的`，未练的不进分母。
**主题维度**只能取产物自带的 topic；卡片没有 topic 字段就按“卡片组标题”单列，**别硬凑主题**
（编出来的主题比没有主题更坏）。
**注入文本**只放能改变行为的几行：主题数/掌握度/近期活跃/最薄的三块/已做过的主题（“不要从零讲起”）。
没有原料时整段为空 —— 不注入空话。

## 间隔重复（SM-2 这一档就够）

三档评价映射到 SM-2 的 q 值：会=5 / 模糊=3 / 不会=1（**q<3 视为没记住**，模糊恰好落在“通过”上）。

- EF 每次评都更新：`EF' = EF + (0.1 − (5−q)×(0.08 + (5−q)×0.02))`，**下限 1.3**；
- 答对：第 1 次 1 天、第 2 次 6 天、之后 `round(上次 × EF')`；
- 答错：连续成功清零、间隔回到 1 天、答错计数 +1。**不要沿用旧间隔**（沿用会越攒越长，最后干脆想不起来）；
- `due_at` 为空**算到期**（宁可多练一次，也不让没有排期的记录永远沉底）；
- 时间**一律靠传入的 `now`**，不在函数里读钟 —— 否则测试钉不住口径；
- 排期挂在复习记录上（扩列），**不另开表**：排期是“最近一次复习结果”的派生值，
  分两张表会出现不一致且没法自证的中间态；
- `limit` **只截断返回条数，不改变计数**（踩过：界面上的“今天该练 N 张”随 limit 变）。

算法期望值按原论文**手算**当 oracle；跑一遍抄输出等于什么都没钉住。

## 跨会话记忆

表：`(id, text, kind ∈ preference|fact|goal, source_session, created_at, updated_at)`。

抽取提示词要**正反两面都写**：

- 要：身份与背景、长期偏好与禁忌、持续目标、硬约束；
- 不要：一次性任务细节、能随时重读的百科信息、任何推测、助手自己说过的话；
- **“没有值得记的就回空表”是正确输出**，并明说不要凑数（上限 4–5 条）。

素材口径：只喂**用户说过的话** + 这次会话产出的主题。助手的回答又长又贵，塞进去只稀释信号。

判重：本地只兜近似文本（包含关系，短句设一个最小长度；或高相似度），语义判重交给模型
（把已有记忆一起放进提示词，让它自己别重复写）。注入有字符预算，超了只发最新几条。

## 历史压缩

三层，前两层不花钱、第三层花钱：

| 层 | 做什么 |
|---|---|
| 工具结果瘦身 | 同来源只回锚点、截断、旧工具结果折叠成一行 |
| 保头保尾裁剪 | 超字符预算时裁掉中段 |
| **模型摘要式压缩** | 把未被摘要覆盖的那段压成「目标／已确认结论（**带来源 id**）／未决问题／用户偏好」 |

- 摘要是**续写**：把上一版摘要一起喂进去，只压新增部分；
- 注入位置固定（system 之后、历史之前），每次压缩只让缓存冷一次；
- 提要里**只认带来源 id 的结论**，提示词与注入文本两头都写死
  （压缩最危险的是把没证据的转述固化下来）；
- 摘要存进业务状态（与研究台账同一行），不另开表，也不冲掉台账已有字段。

## 人工核对的验证脚本该报什么

跑一遍真库，把真值打印出来（**不靠模型自述**）：画像每个分档的计数、到期队列条数、
记忆列表与注入文本、压缩前后的“已覆盖条数”。

两条卫生规则：

- 拿真库当输入前先跑迁移（应用在**启动时**迁移，你的脚本不是）；
- **核对完把自己插进真库的数据删掉** —— 那是用户的开发库，不是你的夹具。
