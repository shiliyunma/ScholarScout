# 工具调用型 Agent 运行时（自建 loop + OpenAI 兼容 API）

适用：自己写 agent loop（工具注册表 / 提示词 / 轮次预算 / trace）对着 OpenAI 兼容端点跑。
本 skill 只没收“离线打桩永远碰不到、真机一跑就露”的那类缺陷。
配套：评测口径与指标见 `llm-eval-harness`（离线集只能证明逻辑自洽）。

## 开工顺序

1. **先定接口与数据模型**（工具签名、消息/事件帧、trace 表），再填实现。一次只改一个文件/函数。
2. 工具层 → 循环 → 提示词 → 出网层，每层写完先跑离线用例。
3. **每个里程碑收尾跑一次真接口**（真 key + 真出网）。离线全绿时下面这些全是零信号——实测一次真机跑
   同时暴露过：工具名被拒、robots 拦官方 API、查询语法恒 0 条、空结果被当没资料、额度不够。

## 工具名：注册名与线上名分离

- **OpenAI 兼容 API 只接受 `^[a-zA-Z0-9_-]+$`**，带点（`research.search`）直接 400
  （`Invalid 'tools[0].function.name'`）。报错在请求层，肉眼看回包很容易误读成“模型不会调工具”。
- 做法：注册名保留人类可读的**规范名**（文档 / trace / 事件 / 论文都用它），发给模型与模型回传的用
  **线上名**（点换双下划线：`research__search`），双向映射集中在一个地方（`wire_name` / `canonical_name`）。
- **注册时禁止名字里含 `__`**，否则映射歧义、静默取错工具。
- `get_spec` 两个名字都要认（模型回传的是线上名）。

## 工具返回值必须诚实

- **“全部来源失败”必须回 `ok=false` + 具体原因**，不能回 `ok=true` + 空列表。模型拿到“空结果”会认为
  “没资料”，反复换关键词重试到烧光预算，最后自己编造工具调用（输出 `DSML` 这类伪标签）。
- **“确实没命?”与“请求失败”是两个状态**：分开表达，否则上游不能分别处理（重试 vs 换词）。
- 失败也要落 trace（每个调用一行，带时延与成功标志）——**调用次数/成功率/时延只能从 trace 取数**，不另造埋点，
  否则报告里的数对不上库。

## 循环与预算

- **轮次预算 = 工具预算 + 1**，**最后一轮传 `tools=None` 逼模型收口**。否则模型恰好用满工具预算的那一轮
  会被判 `tool_limit`，最终答案直接丢掉。
- `stop_reason` 要有分类（`completed` / `tool_limit` / `cancelled` / `error`），**`error` 要带上游原因字符串**：
  只写 `error` 的话，六个任务全挂只能看到六个 `error`。
- 用满预算≠失败：先把“预算耗尽但已出产物”与“预算耗尽且无产物”分开统计。

## 提示词要写死流程与预算

- 模型会把全部预算花在同一个检索工具上反复调用，一件产物不出。这不是“不会用工具”，是**没人告诉它何时停**。
  系统提示词一定要写：每阶段最多几次、什么时候必须转下一步、**用户要的最终产物是什么形状**
  （“要的是路线和地图，不是一长串链接”这类句子直接改变行为，实测有效）。
- 提示词进哈希（`system_prompt_hash`）存进会话：改了提示词历史会话不可比，这是设计。

## 出网层

- **第三方文档解析/OCR 服务**（扫描件、复杂版式）的集成契约：端点、预签名上传、认证形式与四个实测坑
  （`PUT` 预签名地址不能带 `Content-Type`；OCR 开关默认是关的；优先直传本地字节而不是交 URL；
  控制台给的 AK/SK 未必是接口凭证）见 `references/mineru-cloud-api.md`。
- **robots.txt 只约束爬虫，不约束官方 API 客户端**：把官方 API 主机放进豁免白名单，否则合规逻辑会把
  官方端点自己拦掉（表现：检索恒 0 条，provider 报 forbidden，很像是网络问题）。其余主机照旧遵守。
- 限速 / 指数退避 / 缓存三件套，按主机的实际容忍度设（如学术 API ≥3 秒/次）。
- 某些 API 必须显式带 `Accept` 头，否则一律 406；另一些只索引英文——**中文关键词恒 0 条是事实不是 bug**，
  要能区分“没收录”和“请求错了”。
- 查询语法别整句加引号：`all:"educational agent LLM"`（精确短语）几乎恒 0 条，按空格切词 `all:a AND all:b`。

## 模型侧硬约束（踩过才知道）

- **推理模型把 reasoning token 也算进 completion**。`max_tokens` 给小了，表现是 `content` 为空、
  `finish_reason=length`，而日志里只有“解析失败 → 走兜底”：很容易错怪解析器。
  实测过“5379 个 reasoning token 只写出 490 字符正文”——**额度按实测留 3 倍余量**，
  并把 `finish_reason=length` 当作可判定事实上报，不要静默返回空串。
- **弱模型不会发结构化 `tool_call`，而是把调用写进正文文本**（`【出处】搜索课程知识库得到：{...}`）。
  诊断入口：看该轮的 `tools_called` 是不是空。这是模型能力问题，不是架构问题——据此否掉自己的架构是错的。
- 模型输出不可解析时要有**确定性兜底**（退化产物），但**必须同时写降级原因**（截断/空输出/解析失败/未用模型），
  存进产物本身；否则报告里只看到一个“降级率 100%”而无从诊断。
- 生成类工具挂不上出处时用哨兵占位（`[无出处]` / `null`）并计数（`ungrounded_*`）——这是可计量的反幻觉指标，
  比“模型应该不会编”可靠。

### 模型与思考档位：从接口取，不要写死

- **能力探测优先于文档**：OpenAI 兼容端点不一定接受 `reasoning_effort`。先 `GET /models`；
  有的服务（实测 DeepSeek）会在每个模型上返回 `effort.supported_levels` 与 `default_level`。
  没有这组字段就回落配置里的模型 + 当前值，并如实标 `source="fallback"`，不要假装探到了。
- **档位是 UI 概念，接口值是枚举**：五档（最小/低/中/高/最高）映射到接口声明的 `low/high/max`，
  「关」不发 `reasoning_effort` 而发 `thinking:{"type":"disabled"}`；默认档要能逐字节等于原先不带参数的行为。
- **判“这一档支不支持”要用映射后的源值**：拿降级后的 effort 去判，降级必然落回支持集 →
  每档都判“支持”、置灰形同虚设（真 bug）。
- **不支持就降级一次并标注**：请求 400 且正文提到 reasoning/thinking → 摘掉该字段重试一次，
  回包标 `reasoning_degraded` / `reasoning_note`；不要因为一个可选参数让整轮对话报错。流式路径同口径。
- **没有 key 就不要探测**：必然 401。`if key: probe() else: fallback(note="未配置 …")` —
  这同时是类型收窄的正解，比强转或 `type: ignore` 干净。探测失败不缓存（下次还试），成功才缓存。

## 多轮有效性：第 2 轮必须带来“新信息”

用户体感“只有第一轮有用、不满意也只能说继续搜索”时，**别凭感觉改提示词**——先量。

**固定一把尺子**（写成脚本，每次改进用同一口径复测）：

- 第 2 轮起的**重复查询率**：把查询归一化（去空格/标点、小写）后按**字符组 Jaccard ≥ 0.6** 判“换词不换靶”
  （中文里“同一个靶”常常字面完全不同，完全相等判不出来）；
- 第 2 轮起的**新增证据数**（新来源/新摘要），趋近 0 即“这一轮白花钱”；
- 每轮**工具构成**：第 1 轮 search→fetch→grade，第 2 轮若只剩 search，说明它没有换策略的能力。
- **尺子自己也要有测试**：判重阈值与归一化规则写进用例，否则改了判据会把“没改进”读成“改进了”。
- **“被拦下”与“重复执行”要分开算**：判重门拒掉的那次**不是**“又重复搜了一遍”——那是门生效的表现。
  统计脚本要把每次调用的成功标志带出来，分开报“实际执行 N 次 / 被拦下 M 次”，
  否则一条正确的改进会被自己的指标读成退步。

**四个结构性缺口**（缺了任何一个，“继续搜索”就必然变成原地打转）：

1. **没有跨轮研究状态**：每轮只带消息历史重新现推意图 → 要有显式的「目标 / 已确认结论 / 待解子问题 / 已用证据」，
   每轮更新并注入（比重发全部历史更省 token）；
2. **没有覆盖缺口概念**：本地能算出“缺哪一年/哪类来源/哪个子问题没有摘要”，把缺口当成**必须回答的清单**塞进下一轮；
3. **没有把模糊反馈结构化的入口**：用户说“不满意”时，界面/提示词要把它变成可点选的维度（缺深度/缺来源/缺对比/想换角度），
   自由文本只能被理解成“再搜一次”；
4. **固定顺序提示词**：把流程写死成 search→fetch→grade→产物，模型到第 2 轮自然回到同一步。

**配套**：查询去重门（工具层拒掉与本会话高度相似的查询并回一句提示，零模型成本）；
给模型**读回自己产物**的只读工具（否则它不知道自己上轮产出了什么，容易前后重复）。

### 落地这四件事时的硬规则（真机踩出来的，照着做省一轮）

- **台账只有一个写者**。工具在判重时写一次、循环在轮末再写一次时，循环会用它在轮初加载的内存快照
  **整表覆盖**，工具刚写进去的记录当场丢失 → 判重门永远判不出重复，功能**静默失效**
  （没有报错，只有“改进了但指标不动”）。做法：写者固定为循环（工具**只读**），
  循环每次工具调用后记账并立即落库；用例钉住“工具不写台账”，再加一条端到端（循环记账 → 下一轮换词重搜被拒）。
- **台账注入放在消息的最后，不要放头部**。服务端上下文缓存按**从头的最长公共前缀**命中，
  而台账每轮都在变（已用查询、缺口都在增长）——放头部等于每轮主动让缓存失效。同理：
  裁剪历史时把“中间已省略”的说明追加到**末尾**，并把**首条用户消息固定在 system 之后**，前缀才是常量。
- **把缓存命中记下来**，否则“省了多少”只能靠猜：解析服务端的缓存字段
  （DeepSeek `prompt_cache_hit_tokens`、OpenAI 兼容 `prompt_tokens_details.cached_tokens`）写进用量表，
  界面按命中/未命中分开显示；**服务端没报就存 NULL，不写 0**（0 会被读成“缓存全没命中”）。
- **“连续 N 次没有新证据”是轮内计数**。持久化会让它在下一轮开头就满格，用户换话题再问时
  **第一轮就被叫停**（连工具都不给）。每轮开头清零。叫停时给一句“停止检索、如实总结还缺什么”
  并收走工具，`stop_reason` 单列一档（`no_new_evidence`）——停在“没有新信息”上比停在“预算用满”上省钱且诚实。
- **判重门要在发请求之前拦**，拒绝信息必须带“往哪走”（先前那条重复查询 + 缺口清单的第一条建议）；
  没有会话上下文的调用（评测脚本直调工具）不做判重。
- **记账只认成功**：检索全失败或抛异常都不写入“已搜查询”，否则一次网络抖动就把这个方向永久锁死。

**具体状态字段、缺口类别、注入文本形状与验证脚本该报什么**：`references/multi-turn-research-state.md`。

## 多会话并行：按会话分槽，而不是加一把全局锁

“一个会话在跑时切到另一个会话就出错”通常是三处叠加，缺一处都不能真正并行：

1. **界面只有一个全局在跑标记 + 唯一进行中槽**：`state.sending` 这类布尔会把第二个会话挡在门外。
   改成 `state.turns[session_id]` / `state.streams[session_id]`，闸门问的是 `sessionRunning(id)`。
2. **事件不带 `session_id`**：只有标题/完成类事件带，增量事件不带 → 客户端无法归位，
   两个会话的 token 会交叉落进同一个气泡。事件信封统一带 `{session_id, turn_id?, seq, …}`，
   前端按 `session_id` 落槽；**取不到 `session_id` 就丢弃，不要兜到“当前会话”**。
3. **共享可变状态无锁**：单连接 + 显式事务的库在第二个轮次里直接
   `cannot start a transaction within a transaction`。

做法（比“加一把大锁”好得多）：

- **一个会话 = 一个工作单元**，`submit_turn(session_id, …) -> {ok, turn_id}` 立刻返回；
  后台用**有界线程池**（3 个就够），满员时明确回 `at_capacity` + 当前运行数，不排队也不假装接受。
- **`send` 立即回 `turn_id`**（异步模式），另给 `status(session_id?)` / `result(turn_id)` /
  `cancel({session_id|turn_id})`；界面收到 `done` 事件再收尾。顺带治好“长轮次被界面超时丢弃”。
- **存储选“一写多读 + 应用层写锁”**：同一条连接上的 `BEGIN IMMEDIATE` 重入直接报错，
  每会话一条连接也绕不开 WAL 的单写者。
- **关窗/退出前先看有没有轮次在跑**：worker 还在写库时关库/关 HTTP 客户端 →
  Windows 上直接进程级崩溃（`0xC0000005`，栈停在写库那一行）。
- **并发测试用屏障，不用时间戳**：每轮模型调用前都设 `Barrier`；只同步第一轮时，收口轮的顺序靠调度运气，
  会偶发红（先分清是“测试同步问题”还是“产品串行”，再改）。断言用“三会话墙钟区间有交集”，不用“总耗时变短”。

## 提示词模板的占位符：delimiter 写错是静默失效

模板引擎用 `{{var}}` 这类双分隔符时，写成单花括号 `{var}` **不会报错**（正则匹配不上而已），
于是带着字面 `{route}` 的提示词直接发给模型——模型只能看到一个叫“route”的花括号。

- 先找到引擎的正则再写提示词；有的引擎仅在**缺变量**时抛错，**格式不对时不抛**。
- 加一条仓库级守卫用例：扫所有提示词文件，出现 `(?<!\{)\{[a-z][a-z0-9_]{1,}\}(?!\})` 即失败
  （JSON 示例 `{"ops": ...}` 不会误报，`{` 后面是引号）。
- 同一个文件夹里有十几份提示词时，这类错只会在**模型输出莫名其妙**时才被发现——守卫用例是唯一的出路。

## 用户侧能力：画像 / 跨会话记忆 / 人格档

“继续搜索不好用”解决之后，下一层是“它对不对**这个人**说”。硬规则：

- **画像要算，不要问模型**：掌握度/水平这类能从库里确定性推出的量（复习排期、练习次数、产出）
  一律本地算（零调用、可复算、可核对）；让模型“感觉用户水平”会随措辞漂移。
- **未练过的东西不进分母**：`掌握度 = 熟 / 有记录的`。把没练过的算成不会，画像必然难看，
  用户会以为系统在打击他（与“记住率只算评过的”同口径）。
- **后来才加的字段，老行要单独兜一档**：老数据只有评级、没有排期，那种行不能落进“从未练过”档
  —— 用户明明练过，画像说他没练过就是造谣。按已有的字段（评级）落档。
- **跨会话记忆必须有出口**：列表 / 修改 / 删除三个入口都要有。**没有出口的自动记忆＝污染源**——
  一次误抽会污染之后每一轮，用户还找不到地方改。
- **判重分工**：本地只兜**近似文本**（包含关系或高相似度），**语义判重交给模型**
  （抽取时把已有记忆一起塞进提示词）。不要用“字符集重合度”去抓乱序改写：
  它会把“偏好中文”和“不喜欢中文”判成同一条 —— 误合并比漏合并危险。
- **注入里写死冲突规则**：“与用户当前说法冲突时以当前说法为准”——记忆是背景，不是命令。
- **抽取要有触发条件与上限**：每会话最多一次，且要有“值得记”的迹象（多轮用户发言或产出过产物）；
  注入有字符预算，超了只发最新几条（老的留在库里不删）。
- **人格/风格档：默认档必须逐字节等于没这功能时的提示词**（默认档 = 空串），否则实验臂被顺手
  改掉、历史数字不可比。改风格应当是有意识的行为，报告里必须写明用了哪一档。
- **取值不认识就报错，不许静默回默认**：两层都拦 —— 设置在**面板里**拦（当场报错），
  读取器在**启动时**拦（不认识的值直接抛）。静默回默认＝“用户以为改了、其实没改”。

字段、分档表与注入形状：`references/user-side-capabilities.md`。

## 花钱的功能：成本闸门

给 agent 加“用模型做某件事”的功能（记忆抽取、历史压缩、起标题、画像描述）时，五条一起做，
少一条它就会变成看不见的暗开销：

1. **有触发条件**：只在跨过阈值时触发（未处理部分 ≥ N 字符、每会话一次），低价值场景走确定性路径；
2. **记“处理到哪”**：把摘要/已处理指针与业务状态存在一起，下次只处理**新增**部分 ——
   **这是底线**：不记的话“省 token”的功能会变成每轮多花一次调用（同一段反复压）；
3. **单独记账**：用量表给它独立 `purpose` 并在界面可见；混进“对话”里等于没记；
4. **失败软着陆**：模型失败或空输出时退回确定性路径，本轮照常完成（省钱手段不能弄挂一轮）；
5. **提示词位置固定**：注入的摘要类内容放**固定位置**（如 system 之后、历史之前），
   服务端缓存才能在两次处理之间稳定命中；每次处理只让缓存冷一次，而不是每轮都冷。

“同一段只处理一次、第二次不产生调用”要有用例钉住 —— 否则功能上线即烧钱。

## 测试 Loop：别按“总调用次数”断言

一轮里除了回答还可能有后台调用（起标题、记忆抽取、历史压缩），用 `len(llm.calls)` 断言会把
正确的用例变成假红。改成按**内容/身份**认（这次调用的提示词里有没有那句特征话），
并补一条**正向对照**（第一轮确实认得出 1 次）—— 否则过滤器写错时空过的断言等于没断言。

同理：**写小数阈值的断言之前先把那个值算出来**（相似度、覆盖率）。凭感觉写 0.75，
实测可能只有 0.5：要么改成真值并写清为什么，要么改实现，别留一条“看着在管其实不管”的用例。

## 流式输出：只有“最终回答”那一轮能流

把“模型输出一次性蹦出来”改成真流式（用户要求主窗口与侧边问答都流式）时，三条判断：

- **只给最终回答那一轮开流**：工具调用轮模型输出的是 `tool_calls`，不是给人读的正文。循环的硬规则是
  **最后一轮 `tools=None`**（见「循环与预算」）—— 正好就是生成最终回答那一轮，所以流式接口只在这一轮用，
  工具轮照旧走一次性请求，进度由既有的工具调用事件体现。
- **回调发「累计文本」而不是增量**：前端收到 `chat.delta` 一类事件时若是**替换**正文（不是追加），
  发累计值就**前端一行都不用改**，中途断线也不会留半句话；要发增量就得同时改前端渲染语义，收益为零。
- **收完拼成与一次性路径同形状的响应体，交给同一个解析函数**：
  `tool_calls` / usage / `finish_reason` 的解析只有一处实现，两条路径不会漂移。
  SSE 里非 JSON 行（心跳）直接跳过 —— 一行坏数据不该中断整段输出。

**必须主动告知用户的取舍**：取消通常是**步间检查**，所以流式期间点“停止”不会立刻断流，要等这一轮 HTTP 流结束才生效；
想“点了立刻断”得在流式读取循环里接取消标志。**别让用户以为点了就停。**

## 给 Agent 加“代码执行 / 改文件”能力：执行器与审批门

用户会说“固定工具只能处理某几种格式，限制了多样性，改成能跑 Python”，同时要求“能沙箱就沙箱”。
这两句必须同时满足：**开放的执行能力 + 一道不依赖模型自觉的闸**。

### 先分清三层，不要一步到位

1. **常用编辑走对象模型 API**（docx/xlsx/pdf 的读/写/改），零代码执行、不弹审批；
2. **API 覆盖不到的才走 `py.exec`**，完整审批；
3. **纯读取/抽取仍用标准库解析**（zipfile+ElementTree），不为读而引库。

只有第 2 层才有安全问题。把第 1 层也塞进 `py.exec`，等于让“改个标题”也走审批——用户三次之后就会点“永久允许”，闸自己废掉。

### Windows 上的隔离现实（实测，写进文档给用户看）

- **Job Object 只限资源，不是隔离**：64MB 上限真的生效（`bytearray(400MB)` → `MemoryError`），但同一个 Job 里
  **文件照写、socket 照连、子进程照起**。把它当沙箱是常见误解。
- **AppContainer** 默认拒文件/网络，但实现代价高（ctypes 全套 + ACL + 打包后 `_MEIPASS` 与用户目录都要逐个授权）；
  **Windows Sandbox** 家庭版没有；**Docker** 不能要求终端用户安装（且容器内挂载写盘要额外设计）；
  **低权用户** 需管理员；**RestrictedPython / AST 白名单** 挡不住 `().__class__.__base__.__subclasses__()`、
  `getattr(__builtins__,'open')`、`ctypes.CDLL` —— **不能当安全边界**。
- 可用组合：**独立子进程 + Job Object（内存/CPU/进程数上限）+ 超时杀进程树 + `sys.addaudithook` 限 open 到工作区
  + 运行前人工确认**。审计钩子是 stdlib、零依赖，能挡“无意越界”，**挡不住刻意调 ctypes 走原生 API**——
  这句必须原样告诉用户，不要宣称“用户机器上有绝对安全沙箱”。
- 写前快照（备份原文件到 `.bak`/临时目录）+ 只回传文本结果，比“事后道歉”便宜。

### 审批模型（这六条是从成熟实现里提炼的，照做）

1. **模式，不是布尔**：`manual / smart / off` 三档；布尔开关最后一定变成“用户关掉它”。
2. **硬底线先于一切**：写系统目录、删项目根、改 `.env`/密钥、改可执行文件、外发数据 —— 无论用户选过什么都不能放行。
   实现上把这条放在 allowlist **之前**判，否则“永久允许”迟早把底线一起放过去。
3. **按“操作类别”记忆，不按代码字符串**：记“允许在工作区内写 docx”，不是记“允许这段 40 行的代码”。
   代码字符串一定不会重复，按它记忆等于每次都要问。
4. **session / always 两级，内容级风险强制 session**：凡“看到内容才能判断”的（某条新命令、某段新代码）只许本次会话；
   可永久化的只有**类别 × 路径范围**，且必须能在设置里**看到并撤销**。
5. **拒绝是硬拒绝**：回给模型的文本必须写明“不许重试、不许换种写法、不许换条路达成同一结果”，
   并**连续 N 次（3 次）触发熔断**直接中止本轮 —— 不写这句，模型会换个函数名再来一遍。
6. **审批器自身要防注入**：代码里可能有注释/字符串在指挥审批者。剥注释、把待审内容当数据（包裹标记）、
   只允许 `APPROVE/DENY/ESCALATE` 三种输出；**任何不确定 → 升级给人**。失败方向必须是“交给人”，不是“放行”。

### 展示与交互（用户明确要求过的形状）

- 代码**完整显示**，但装进**固定高度、内部可滚动**的框，不占满对话框；默认折叠。
- 摘要写“**可能修改的地方**”，到位但凝练：要读/写的路径、是否联网、是否起子进程、是否删除；
  风险行高亮，不要只给一句“将执行 Python 代码”。
- 四个选项：**允许一次 / 本会话允许 / 永久允许（按类别）/ 拒绝**；选完立即回显“这次记住的是什么类别”，
  否则用户不知道未来会被自动放行什么。
- 审计要能追：每条审批记录带 `turn_id / tool_call_id / session_id`，落库可查；不靠聊天记录考古。

## 把技能库接进 Agent（渐进式披露）

用户要求“`/` 能引用仓库里的 skill”时，**交付的是一个目录约定 + 一个索引器**，不是把技能正文拼进提示词。

- **一个技能 = 一个目录**：`SKILL.md` + 与它**同级**的资源目录 `scripts/`（可直接跑）/ `references/`（按需读的深度）/
  `templates/`、`assets/`。脚本不要内嵌在 SKILL.md 里 —— 内嵌就无法单独跑、也无法被复用。
- **frontmatter 的 `name` + `description` 是索引，不是正文**：启动时只扫所有 SKILL.md 的 frontmatter 建一张表
  （名称 / 描述 / 相对路径），**不读正文**。这是渐进式披露的第一层。
- **三段式加载**：① 索引命中 → 读 SKILL.md 正文；② 正文里明确指到 `references/x.md` / `scripts/y.py` 才读那一份；
  ③ 一次只加载一个技能的正文。把十份正文一起塞进上下文既贵又会让两套流程互相打架。
- **`/` 的匹配**：先按 name/description 子串，再按中文二元组（中文没有空格，按空格切词永远匹配不上）；
  返回**带描述的候选列表**让用户选，选中后才注入正文。没有 `description` 的技能应当被索引器拒收 ——
  否则它永远匹配不到，却看起来“已经装好了”。
- **技能库要签入仓库**（`<repo>/skills/`），运行时优先读仓库内那份，外部安装目录只当来源。
  否则换机器/换版本就跑不起来，也不能复现“当时用的是哪版技能”。
- 加一条守卫：索引里每个技能的资源引用都必须真实存在（扫 SKILL.md 里的 `references/...`、`scripts/...` 路径逐个 `exists`）。

## 反例清单（真机跑一次就能全部暴露）

| 症状 | 真因 |
|---|---|
| 所有任务 `error`、0 次工具调用、秒回 | 工具名带点被 API 400 拒收 |
| 检索恒 0 条、provider 报 forbidden | robots 把官方 API 拦了 |
| 检索几乎恒 0 条、报错是对的 | 查询被整句加引号（精确短语） |
| 模型反复重试到烧光预算并编造工具调用 | 全失败回了 `ok=true` + 空列表 |
| 产物全走兜底、`content` 为空 | `max_tokens` 对推理模型不够 |
| 工具调用成功但零产物 | 提示词没写流程与预算 |
| 最终答案丢失、`stop_reason=tool_limit` | 轮次预算没给总结轮 |
| 多轮改进“做了但指标不动”、判重门从不触发 | 台账有两个写者，循环轮末覆盖了工具的记账 |
| 配置里写了开关却不生效 | 读取器是手写字段列表，新字段没接进去（静默忽略，无报错） |
| 后端能改但用户在界面上找不到入口 | 加了白名单字段却没接界面面板（守卫用例可当场抓） |
| 面板里填了不支持的值，下次启动才炸 | 取值范围只在校验读取处做了，面板没有取值约束 |
| “省 token”的压缩功能反而每轮多花钱 | 没记“已经处理到哪”，同一段内容反复压 |
| 流式“做了”但界面还是一次性蹦出来 | 根本身未开流（请求体里 `stream:false`）或增量事件只在轮末发了一次 |
| 改了风格/口径后历史数字突然不可比 | 新功能的默认档没有逐字节等于旧提示词（默认档应当是空串） |
| 用户明明练过，画像却显示“未练” | 字段是后加的，老行只有评级没有排期，被落进了“未练”档 |

排查手法：**抓包看原始响应**。上层只告诉你“解析失败”，原始响应里才有 `finish_reason` 与 usage
（reasoning / completion 分开看），一次就能定性。

**临时脚本写成 `.py` 文件再跑**：`python -c` 和 heredoc（`python - <<'PY'`）都会被 shell 吃掉里边的
引号/反引号，表现是语法错而**整段脚本一行没执行**（文档没补上、数据没写进去，很容易误判成
“改了但没生效”，多花一轮）。在 Windows 上真实路径也要按原生程序习惯写（`D:/x` 而不是 `/d/x`）。

## 静默失败是这类系统最大的敌人（两个通用修法）

- **配置读取器漏接一行 = 键被静默忽略**：手写字段列表的读取器（`load_config` 那类）加了新字段
  却忘了接到读取处，配置里写什么都被忽略，表现只是“功能没生效”，一句报错都没有。
  加**枚举式守卫用例**：拿 `dataclasses.fields(Profile)` 与“全非默认值”的映射比对，
  再逐字段断言真被读到 —— 以后加字段忘了接线，用例当场失败。
- **加一个可调值 = 接三处**：① dataclass 字段；② 读取器；③ 设置白名单 **+ 界面面板入口**。
  漏第三处的表现是“后端能改、用户在界面上找不到”。守卫用例：白名单里的键必须出现在面板分组里
  （枚举两侧集合比对）。这类守卫的价值在真机之前就显现 —— 加字段后忘了接线会被当场抓住。
- **有取值范围的键要自带取值校验**：面板上写错一个值，会在**下次启动读配置时**才炸，
  那是最糟的时机。给字段加取值白名单，让错误在面板里当场出现；读取器再兜一层（见下条）。
- **`except Exception: return []` 会吃掉根因**：兜底可以吞异常，但必须把原因**带出来**
  （写进状态/产物/日志）。做法：兜底函数返回 `(结果, 原因|None)`，调用方把原因落进状态并在界面显形；
  否则只剩“结果不对”，排查只能靠猜（真机上为此多花了一轮）。
