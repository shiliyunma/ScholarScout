# 开源项目学习工作台（六件套）

大浩要学一个开源项目时，不要只丢链接，也不要只写一份"学习建议"。**产出固定是 6 个文件的目录**，与他已有的 `hermes-learn` / `aihot-learn` 同构。

## 触发

- "帮我安装 X 项目，然后用与 hermes 同样的方式对学习这个项目进行规划"
- 要读新的开源仓库、要"像读 Hermes 那样"读它

## 落地位置与目录结构

```
<项目根>\<项目名小写>-learn\
├── 00-总索引.md        一句话组成原理 + ASCII 架构图 + 3 个关键洞察 + 文件导航 + 三层阅读法 + 实测规模
├── 01-学习路线.md      阶段 0..N，每讲四段：读物 / 源码锚点 / 动手验证 / 自测；★ 标必读；末尾专题"搬进我自己的项目"
├── 02-源码地图.md      目录 → 职责 → 关键文件 → **实测行数**；最大文件榜；测试/迁移/脚本清单
├── 03-核心机制速查.md  8 条机制 × 〔解决什么 / 怎么实现（带锚点）/ 一句话讲法〕+ 面试话术包 + 数字校准表
├── 04-自测题库.md      每阶段 1 原题 + 2 延伸题，答案带锚点；每题 3 分（结论/机制/锚点）；末尾抽背记录表
└── 学习进度.md         前置条件表 + 打卡表 + 实证笔记（必须带 文件:行号）+ 待解决问题 + 产出物清单
```

## Procedure

1. **先核对当前日期**（`date`）。会话可能跨天，别拿旧上下文里的日期当今天写进文档。
2. **下载**：`curl -sSL -o X.zip https://codeload.github.com/<owner>/<repo>/zip/refs/heads/main`（先试 main、再 master）；解压后校验：用 Python `zipfile` 列 zip 内文件、逐个 `os.path.exists`，**报告"缺失 0"才算装上**。
3. **实测（这一步不能跳）**：用 Python `os.walk` 统计各目录 `.ts/.py` 文件数与行数。
   - ⚠️ **不要用 `find | xargs wc -l | tail -1` 拿总数** —— xargs 会分批，tail 只看到最后一批，本次据此得到 5923 行，真实值是 52501 行。要么用 Python 累加，要么逐目录 `wc -l` 后相加。
4. **读权威材料**：仓库自带 `docs/`、`README`、`AGENTS.md`、`.env.example`、`docker-compose.yml`、以及**提示词/配置类文件**（这类项目的 KnowHow 往往不在代码里）。
5. **抓锚点**：对每个要引用的文件跑 `grep -nE "^export (async )?(function|const|class|interface|type)|^export const [A-Z_]+ ="`，拿真实行号；常量类用 `grep -n "NAME ="`。
6. **写 6 个文件**。
7. **写完必做一轮"引用复核"**：把文档里所有自己写的行数/行号再查一遍，用脚本 `assert t.count(old)>=1` 批量改。
8. **索引挂接**：把工作台写进项目所在域的 `00-总索引.md`（如 `毕设规划\00-总索引.md`），否则下次找不到。

## 铁律（写进 01 的正文，让它成为约定）

1. **数字与结论必须现查本副本。** 网上的技术描述一律不采信，凡写进笔记的都要 grep 出代码。
2. **不整文件通读**，只读被调用的函数；**一次只带读一个函数**。
3. **笔记必须带 `文件:行号` 锚点**，否则不算数。
4. **他说"不会"就停**，不许猜，猜对也算错。
5. 每讲结束要有一句"**如果我来做，我会/不会照抄它**"。

## 变体：没有现成教材时（自写讲义型 —— claude-learn 那次的打法）

当目标仓库**没有可下载的第三方中文讲义**（典型：闭源项目的 source map 还原版，如 Claude Code），六件套升级为「路线 + 我写的讲义 + 脚本生成的索引/题库」。**不要一次性把 N 讲全塞进自己的上下文**，按下面两阶段走。

### 阶段 1（自己做，约 6 件产物）

1. `讲义写作规范.md` —— 把讲义骨架写成**硬约束**，这是后面所有质量的基础：
   一句话总结 → 先看一个场景 → 它其实是这样（**比喻**）→ 本讲要记住的几个词（表格 3–6 个，每个一句人话）→ 关键代码长什么样（伪代码 ≤20 行，中文注释）→ 源码锚点表（5–10 条）→ **和已学项目的对照**（他学过 Hermes：同步循环/finish_reason、工具自注册、上下文压缩、MEMORY.md 快照、skill、delegate_task、cron、MCP、hooks）→ 必答三问 + 延伸两问 → 下一讲预告。
   语言纪律：正文 150–250 行；**纯文本段落 ≤5 行**；术语首现必须紧跟人话解释；不用「顾名思义/众所周知」。
2. `01-学习路线.md` —— 阶段 → 讲次表，每行给：讲义文件名 / **已初步 grep 过的锚点线索** / 动手项。末尾加「与已学项目逐条对照」专题（**最大杠杆，面试直接用**）+「面试怎么说」专题。
3. `00-总索引.md`（一页速览 + 文件导航 + 三条铁律）、`02-源码地图.md`、`03-核心机制速查.md`（机制 ↔ 已学项目对照 + 实测数字清单 + 十个「为什么」）。
4. **亲手写 2 份样板讲义**（最核心那一讲 + 第一讲），后面所有讲义照它写。
5. 起目录骨架 + 把仓库自带的 `docs/*.md` 按主题复制进对应讲文件夹当 `②材料`（md5 逐字节校验）。

### 阶段 2（并行子智能体批量写）

- 每批 **3 个**（上限），每个 3–6 讲；每个子智能体的 context 必须给全：源码根绝对路径、规范路径、样板路径、路线里它那几讲的行、输出路径清单、**已知坑**。
- 要求它：每个 `文件:行号` 自己 grep/sed 验证过，验证不了写「约 XX 行附近，搜 xxx 可定位」，**绝不许编**；只创建列出的文件。
- 让它回报「亲手验证过的锚点 + 遇到的空壳/残缺 + 哪一讲材料最薄」。

### 阶段 3（必做，别省）

- **索引与题库用脚本生成**：`build_讲义索引.py`（PLAN 表为唯一事实来源，算讲数/文件数/缺失清单，`--check` 可当门禁）、`build_自测题库.py`（正则抽每讲的「自己检查一下」汇总成 `04-自测题库.md`）。**手写索引必然漂**。
- **合规检查器**：章节齐全数（如 9/9）、行数区间、最长纯文本段、最长代码块；**撞迭代上限的子智能体不会自查**，必须补。
- **抽验锚点**：子智能体报的锚点是自述。抓过的实例：`replLauncher.tsx:11→:12`、`client.ts:1746→:1743`、`bun:bundle` 文件数 197→196。**grep 计数类结论亲自重数一遍**（注意命令与结论要自洽：它给的命令算出来是 196，却写 197）。

## Pitfalls

- **还原版/闭源源码必查空壳**（`grep -rln "return \[\]\|return false" src/`、或按字节数找可疑小文件）：常见 `workerAgent.ts` 37 字节、`useProactive.ts` 88 字节、文件被 require 但根本不存在。讲义里要**逐句区分**「官方文档这么说」与「源码里真能看到」；「门在房间没了」本身就是最好的教学材料，如实写，别替它圆。
- **不要相信目录名**：`src/context/` 可能是 React 界面 context（和提示词无关）、`src/hooks/` 可能是 React 钩子（事件钩子在 `utils/hooks.ts`）。每个结论都要打开文件看一眼。
- **"N 个策略"这类数字要数两遍**：文件目录里的 15 个文件，有触发时机的可能只有 6 个。分不清"文件数/目录数/条目数"会写错（`ls src/tools | wc -l` = 54 = 53 目录 + 1 散装文件）。
- **交给子智能体之前，自己别把路线里的"已知坑"漏掉**：前一批踩到的坑（空壳、目录名骗人、行号要到行）要转告给后一批，否则同一批错各犯一遍。
- **和已有的同类工作台做交叉对照**：写第二份源码讲义时，"与第一份逐条对照"这一专题是最大增值点，也最容易变成面试话术。
- **资料副本要覆盖两类来源**：仓库源码 + **官方文档站**。文档站通常有 `llms.txt`（全站索引）与每页 `.md` 端点，用 `ThreadPoolExecutor(8)` + urllib 抓，91 篇约 50 秒；web_extract 在本机取不到正文，别指望它。把每篇来源 URL 写进文件头，再生成一份 `00-来源清单.md` 供引用/答辩。
- **复现脚本里 `ast.literal_eval` 解析不了含拼接的任务表**（如 `DOCS + "a.md"` 是 BinOp）。要么把任务表改成纯字面量，要么 `eval(compile(ast.Expression(node), ...), {"DOCS": ...})` 给命名空间。
- **锚点复核脚本要按出现位置排序**：先收集 `path.py:NNN` 与省略路径的 `:NNN` 两类 token，按 `match.start()` 排序后再走，省略路径的锚点用"它之前最近一次解析成功的文件"补全；否则同一行里后面的文件会把前面的省略锚点算错。文件名冲突（仓库里有多个 `server.py`/`context.py`）要人工维护一张 ALIAS 表钉死指向，并按 basename 冲突排序优先级（优先 `src/` 下的那个）。正则还要排除 `'limit':999` 这类字面量里的冒号。
- **别忘了索引挂接**：新工作台要写进上级域的总索引（如 `毕设规划\00-总索引.md` 的文件导航表）。
- **别把 README 的流程图当代码结构**。本次：README 说"六步流水线"，代码实际是 `analyze.ts` 5 个 stage + `group.ts` 归组 + `reports/compose.ts` 成刊。要在 03 里做一张**数字校准表**，列出"网上说法 vs 本副本实测"。
- **`wc -l` 对无尾换行的单行文件返回 0**。本次 `group-method.md` 是 311 字节的**一整段**（无换行），`wc -l` = 0。描述这类文件用**字节数**，不要写"0 行"。
- **`wc -l` 数出来的是换行符数，不是"段落数"**：一份 6 个换行的 prompt md 可能是 6 段长文本，别写成"只有 6 行的短文件"。
- **阶段划分要按"可迁移的机制"分，不按目录分**。业务模块（如排行榜、动画页）单独成"选读"，不要在 ★ 讲里占位。
- **必须有一讲是"搬进他自己的项目"**（本次是专题 B + 阶段 6），否则这份工作台就只是读书笔记，他会问"所以呢"。
- **时间盒要给三档**（速通/精读/面试前抱佛脚），并标 ★ 必读讲次 —— 他在秋招期，不可能按 14 天满配走。
- **"安装"要交代前置条件**：本次 AIHOT 需要 Node ≥24.11（本机 22.23.2）、Docker 守护进程在跑、一个 OpenAI 兼容的模型 Key。**报告现状 + 给出确切命令**，不要含糊说"需要 Docker"。
