# 学习工作台的补录与维护

适用：**工作台已经存在**，用户说"某几讲的讲义没了 / 内容缺了 / 帮我加上"，要补官方文档，或要改阶段划分。
（建新工作台不归本技能管：那是 `repo-learning-workbench` 的范围 —— 本技能只管"已有工作台的增量与修复"。）

这类活儿触发时通常只给一个模糊的缺口描述，真正的工作量在**定位缺口**与**对齐既有约定**，不在复制文件。

## 工作顺序

1. **先把实际缺口算出来，不要照用户给的范围办事。**
   拿「上游章节清单」减掉「生成脚本映射表里收录过的」与「路线文档里引用过的」，差集才是真缺口。
   实测用户说"s17 到 s22 没了"，实际 s20–s22 都在、真缺的是 s17–s19。
   **汇报时必须一并说清"你说的哪些其实有"**，否则他会去找不存在的东西。
2. **把源树列全再找源。** 上游仓库的"官方文档"与"教材"往往是两棵甚至三棵树，中文又是单独的 i18n 目录：
   只翻一棵树就下"没有官方材料"的结论，是本类任务最典型的错。`找不到` ≠ `不存在`。
3. **先 `ls` 两个已建好的目标文件夹，照实际排法命名与编号**，不要自创格式
   （命名与排序约定、源树布局、选材料判断、验证脚本见 `references/naming-conventions.md`）。
4. **复制用逐字节副本 + 当场断言**，并按既有约定重排编号（新加入的材料会把原有编号往后顶）。
5. **在新增目录里留一份 `00-说明.md`**：为什么缺、补了什么、哪几处没同步、怎么用。
6. **两边都同步**：材料目录与路线文档是同一件事的两面，只补一边就是新的不一致。
7. **跑验证**（见 Verification），再汇报。

## 硬规矩

- **用户说"尽量不修改其他文件"时，就只改他点名的那个文件 + 新增文件。**
  索引、生成脚本、进度打卡表这些"顺带该同步的"先不动，在汇报里列出来让他点头；
  擅自同步会被当作没听要求。
- **生成脚本是唯一真相，产物永不手改**：`00-索引.md` 与所有副本都由脚本的映射表生成 ——
  要改索引就**加映射表记录再重跑**，手改索引下次重跑就没了。（脚本只写不删，重跑安全。）
- **新增一讲要同步四处**：路线文档的讲表、进度打卡表 + 阶段完成标志、生成脚本的映射表、总索引里的讲数。
  **讲数、生成日期这类数字要由脚本算**（数映射表 + 取当天日期），写死就会一补讲就全库不一致。
- **新阶段用加后缀编号**（`阶段 4B`），不要重排后续阶段号：重排要改全文几十行，
  与"尽量少改"直接冲突。插完要同步四处：总览表加一行、总学时数字、路径约定、新阶段自身小节。
- **被教材/官方自己排除的主题不要收。** 选材料前先读它自己的"教学边界 / 不讲的"清单；
  被明确排除的内容收进来只会造成与正文冲突。宁缺勿乱。
- **“官方文档”只收讲设计思路的那一类**（用户口径：要“介绍 hermes 在该方面设计思路的文档，即为了学习了解 Hermes 写的文档”）—— 使用手册 / 配置参考不收。
  **判据看二级标题**：`Architecture` / `Non-goals` / `How it works` / `Shape` / `Why this matters` → 收；
  `Overview` / `Setup` / `Available Tools` / `Limitations` / `Practical Examples` → 不收。
  挑材料去三处：`developer-guide\*.md`、**各子目录的 `<子目录>\AGENTS.md`**（仓库级约定，归“仓库级约定”类，优先收）、仓库根 `AGENTS.md`；`user-guide\`、`reference\` 默认是手册。
- **“教材排除”的判据落到小节、不是整篇**：一篇里常既有要讲的设计（如“CLI 的形状”）又有教材写明不讲的（更新流水线、皮肤引擎），
  因为个别小节把整篇排除，会丢掉真正该读的设计文档。
- **行号锚点写进文档前必须用脚本断言**：该行必须包含预期符号（函数名/`name=` 键），
  不能只肉眼看"像"。逐条断言的成本是秒级，写错一行的代价是用户照锚点去找找不到。
- **脚本只写不删**：手建的文件夹重跑不会被删，但也不会自动进索引 —— 要么进映射表，要么在说明文件与索引里写明“未同步”。

## 常见坑

- **别用"最近修改时间"扫描证明改动了哪些文件。** `copy2` / `copystat` 会保留源时间戳，
  副本根本不出现在 `find -newermt` 结果里；既有工作台正是这么做的。扫描结果还会带上用户在 IDE 里的
  操作痕迹。要证明"只动了 X"：列预期改动清单逐项核对，或比内容哈希。
- **JSON 化的 schema 里 `"name": ...` 与 `"description": ...` 只差几行**，引错一行内容依旧"看着像"。
  实测一批锚点里当场抓到引到 description 行的。
- **CRLF 文档**：用 patch 工具编辑会保留原行尾，改完断言 `count(b"\r\n") == count(b"\n")`，别留混行。
- **同名主题会在文件名里出现两次**（`s19-...-s19-....md`），这是既有约定，别"修正"它。
- **别整份重写目标目录**：清掉自己刚建的、重拷一遍是可以的，但不要顺手格式化或重命名别人的既有文件。
- **工作台路径别照抄旧笔记**：工作台搬过家（`D:\找工作找工作\hermes-learn` → `D:\AI+教育毕设毕设\hermes-learn`），
  更早的笔记里还是旧路径，照抄会 `ls` 到一个不存在的目录、然后误判“讲义没了”。开工第一步 `ls` 候选路径确认。

## 材料来源的深挖

- `references/naming-conventions.md` —— 命名与排序约定、源树布局、选材料判断、验证脚本。
- `references/官方文档站抓取.md` —— 把官方文档站**抓成本地可引用的 `.md`**：先找 `/llms.txt` 与每页
  `.md` 端点（优于扒 HTML）、Mintlify 内联组件 JS 的「按花括号配对」清洗、资料目录三层分层
  （清洗件 / `_原始抓取件/` / `_HTML版备件/`），以及中文实体检索（公众号文章垂直）。要补给工作台补官方文档时先看这份。

## Verification

- 副本一致：按文件名反查源路径 → `md5` 比对，全部一致才算复制成功。
- 编号连续：抽 `①..⑩` 的数字，断言等于 `1..N` 且无重号。
- 锚点正确：逐条读 `文件:行号` 所在行，断言包含预期符号。
- 行尾一致：无混行。
- 改动范围：能说清"改了哪 1 个既有文件 + 新增了哪些文件"，并给出核对依据（不是 mtime）。
- 重跑幂等：再跑一次生成脚本，文件名与文件数不变（证明脚本命名规则与手工添加的写法一致、没产生重复件）。
- 数字口径一致：总索引 / 索引 / 路线三处的讲数一致。
- 旧说法零残留：`grep` 上一版的讲数与生成日期，确认没留在任何文档里。
