# 命名与排序约定（讲义汇总类目录）

先 `ls` 两个已建好的文件夹照抄，本文件只是把实际约定写下来，供无法 `ls` 时参考。

## 文件名

```
<讲号>-<①…>-<类别>-<主题>-<版本>-<原文件名>
类别：官方文档 | 仓库级约定 | 教材 | 教材代码
版本：中文版 | 英文原版        （仓库级约定 / 教材 / 教材代码没有这一节）
```

## 排序（顺序编号，不重号）

```
4B.1-①官方文档-browser-supervisor-中文版-browser-supervisor.md
4B.1-②官方文档-browser-supervisor-英文原版-browser-supervisor.md
4B.1-⑤仓库级约定-tools-AGENTS-英文原版-AGENTS.md
4B.1-⑥教材-s17-browser-automation-s17-browser-automation.md
4B.1-⑦教材代码-s17_browser_automation-s17_browser_automation.py
```

- 顺序固定：**官方文档（中文版紧挨英文原版）→ 仓库级约定 → 教材 → 教材代码**。
- **仓库级约定 = 各目录的 `AGENTS.md`**：主题名写目录名（`tools-AGENTS` / `gateway-AGENTS` / `hermes_cli-AGENTS` /
  `tui_gateway-AGENTS` / `web-AGENTS`），原文件名就是 `AGENTS.md`。
- 无中文版只放英文原版，编号继续往下走（既有目录里见过单语的情形，索引会标注 ⚠）。
- 教材条目的主题名重复两次，是既有约定。
- 既有目录里有个别编号重号的瑕疵，不要学；新写的按 `1..N` 严格连续。

## 两棵树的分工

| 文件 | 单位 | 内容 |
|---|---|---|
| `01-学习路线.md` | **讲**（如 4B.1） | 每讲四段：读什么 / 源码锚点 / 动手 / 必答问题 |
| `讲义汇总\<阶段>\<讲号>-<主题>\` | **讲** = 一个文件夹 | 四件套（官方设计文档 + 教材章节 + 可运行代码） |

路线里“读什么”列引的材料，应与讲义文件夹里的文件一一对应；**补录时两边都要改**。

## 源树常见布局（上游仓库）

| 材料 | 路径（相对上游仓库根） |
|---|---|
| 官方文档英文 | `<仓库>\website\docs\` |
| 官方文档中文 | `<仓库>\website\i18n\zh-Hans\docusaurus-plugin-content-docs\current\`（相对路径与英文树一致） |
| 仓库级约定 | `<仓库>\<子目录>\AGENTS.md`（**不在** `website\docs\` 下，最容易漏找） |
| 教材章节 | `参考资料\<教材目录>\docs\zh\sNN-*.md` |
| 教材可运行代码 | `参考资料\<教材目录>\agents\sNN_*.py` |

中文是否存在：用同名文件去中文树里试读，拿不到就只放英文并在索引标注。

## 生成脚本（`build_*.py`）的角色

一张映射表（阶段 / 讲号 / 主题 / [(标签, 源路径)] / 源码锚点说明）+ 逐条复制（保留时间戳）
+ 重建 `00-索引.md`（含“已复制 N / 缺失 M”统计）。

- **只写不删**：先前生成的文件夹不会因重跑消失，索引里也不会自动出现新文件夹。
- **索引与副本全部由映射表生成 → 产物永不手改**。要改索引：加映射表记录 → 重跑脚本；
  手改索引在下次重跑时整段丢失（“索引悬着不同步”就该走这条路解决）。
- **脚本里的标签直接决定文件名**（规则 `{num}-{label}-{basename}`）：标签写对了，文件名才和手工添加的写法一致。
- **加了记录就重跑，并确认幂等**：文件名与文件数不变，才算脚本命名规则与既有文件没冲突。
- 路径变量用脚本里已有的（官档中/英、教材 md、教材 py 各一个），别新造。
- **映射表可能有缺口**：实测某阶段在 `s16` 之后直接跳到 `s20`，中间的 `s17–s19` 从未收录。
- **缺口检测（正解）**：把上游章节清单，与「映射表里出现过的」∪「路线里引用过的」做**差集**。
  顺带能查出路线里的**漏引**（实测某讲的“读什么”列漏引了一章教材）。
- **讲数、生成日期要由脚本算出来**（数映射表 + 取当天日期），写死就会一补讲就全库不一致。

## 选材料的判断

**判据是二级标题，不是标题 —— 用户要的是“讲设计思路”的文档，不是使用手册。**

| 二级标题长这样 | 性质 | 收不收 |
|---|---|---|
| `Architecture` / `Non-goals` / `How it works` / `Shape` / `Why this matters` | 讲设计取舍 | ✅ |
| `AGENTS.md`（规则 + 为什么 + 反例） | 讲设计规则 | ✅（类别写 `仓库级约定`） |
| `Overview` / `Setup` / `Available Tools` / `Practical Examples` / `Limitations` | 使用手册 | ❌ |

- **挑材料的去处**：`developer-guide\*.md`、各子目录的 `<子目录>\AGENTS.md`、仓库根 `AGENTS.md`。
  `user-guide\` 与 `reference\`（斜杠命令等）基本都是手册，默认不收。
- **手册不是删，只是不收**：说明文件里留一句“要查用法看 `website\docs\`”即可。
- **“教材排除”的判据落到小节，不是整篇**：`cli-internals.md` 曾被当成“教材写明不讲的（更新流水线、皮肤引擎）”整篇排除，
  但它同时讲 `hermes_cli` 的形状 —— 那正是该讲要的设计文档。一篇里混着两类内容时，取它对应该讲设计思路的小节。
- 优先选与章内各小节**一一对应**的页面；同一能力在别的形态上的实现（如浏览器那套语义定位用在桌面）是很好的对照材料，值得收。

## 验证脚本要点

| 检查 | 做法 |
|---|---|
| 副本一致性 | 按文件名反查源路径 → `md5` 比对（不要靠 mtime） |
| 编号连续 | 正则 `^\S+-([①②③④⑤⑥⑦⑧⑨⑩])` 抽数字，断言 == `1..N` 且无重号 |
| 行号锚点 | 逐条读 `文件:行号` 所在行，断言包含预期符号 |
| 行尾一致 | `count(b"\r\n") == count(b"\n")` |
| 重跑幂等 | 再跑一次生成脚本，文件名与文件数不变 |
| 数字口径一致 | 总索引 / 索引 / 路线三处的讲数一致 |
| 旧说法零残留 | `grep` 上一版讲数与生成日期，确认没留在任何文档里 |
