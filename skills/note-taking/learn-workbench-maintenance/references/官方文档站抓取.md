# 官方文档站抓取：把网站变成可引用的本地 `.md`

用于把上游官方文档站抓成本地「讲义 / 参考资料」——要能引用、能离线翻、能证明没漏页。

## 1. 先找站点自己给 LLM 准备的索引

- **先 `curl` 首页，把 `href` 全列出来**（`re.findall(r'href=["\']([^"\']+)["\']', html)`）：
  一次拿到导航全集，比猜路径快，也避免「一次 404 就断定该页不存在」。
- **Mintlify 系站点**（页脚写 "built and hosted on Mintlify"）额外提供两件好东西：
  - **`/llms.txt`** —— 全站页面表：标题 + URL + 一句话摘要。先抓它当**导航与覆盖面凭证**。
  - **每页的 `.md` 端点**（`https://docs.<host>/<path>.md`）—— 直接返回 Markdown 正文。
  - 非 Mintlify 站用 `/sitemap.xml` 当备用地图。
- 抓 **`.md` 端点优于扒 HTML**：无导航/无样式残余，正文边界干净。

## 2. `.md` 里嵌着编译后的组件 JS —— 必须按花括号配对删

Mintlify 会把文档里的交互示例组件编译成**一大段内联 JS**（`export function <Name>(…)`，内含 lz-string 压缩器；
特征串 `keyStrUriSafe` / `compressToEncodedURIComponent` / `_compress`）。它落在**正文最前面**，
不清洗就等于在读 JS。

- ❌ 不要靠逐行正则删：花括号跨行，且里层还冒同名片段，删不干净。
- ✅ **按花括号配对整体切掉**：从匹配处起找第一个 `{`，逐字符计深度直到配平，把整块丢掉
  （写成可复用的 `drop_brace_block(text, pattern)`）。
- 再按行过滤残余：含 JS 特征串的行、特长且 `;`/`{` 密度异常的行、JSX 标签行。
- **自检**：`grep -c "keyStrUriSafe\|compressToEncoded\|context_dictionary" <file>` 必须为 0，
  且行数落在合理量级（几 KB 的页 → 约 100–200 行）。

## 3. 目录分层：主目录只放能直接读的

```
参考资料/
├── *.md                 ← 清洗后的正文（可直接读、可引用）
│   └── <站点>__llms.txt  ← 官方全站索引，单独留一份
├── _原始抓取件/         ← 清洗前的备份（含 JS），用于回查「是不是删多了」
└── _HTML版备件/         ← 同页的 HTML 抓取版，`.md` 版缺内容时对照
```

抓取与清洗脚本放 `_tools/`，**做成可重跑**，并在总索引里写一句「官方文档更新后一条命令 refresh」。

## 4. 中文实体检索（产品名 / 人名 / 公司名）

通用搜索引擎经常拿不到：DDG 超时、百度弹安全验证、必应把未加引号的中文词拆成单字返回词典页。
**实测可用的是微信文章垂直**：

```
https://weixin.sogou.com/weixin?type=2&query=<URL编码的词>
```

- 对**中文人名 / 公司名 / 头衔 / 公司沿革**效果最好：文章标题与摘要直接进文本层，不登录、不撞验证码。
- **多篇独立公众号交叉印证**再说；官方站（`/about/` 系列）常常只有公司简介、**没有管理层名单**，
  别在官网里反复翻找「老板是谁」。
- 🔴 **引用要标时点**：「头衔出自某年至某年的公开报道，**是否仍在任未核实**」——履历类信息会过时，
  写成现在时是硬伤。

## 5. 分清官方站与 SEO 仿站

同一产品常有一堆仿站（`<产品>ai.com` / `<产品>-ai.dev` / `freeapihub` 之流）。判据：

- **官方** = 域名与文档站一致（`docs.<主域名>` / `console.<主域名>` / `api.<主域名>`）；
- 仿站往往自称「独立 app / 非官方」，**信息可以看，引用必须标来源**；
- **价格、限额、上下文上限这类会变的一手数字，只认官方文档页**，并标抓取日期。
