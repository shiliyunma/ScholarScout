# 源码讲义体系配方（有源码可读的仓库，自写一整套讲义）

适用：「参照 <已学项目> 的完整讲义，给 X 也设计一套」——主题是**一个能读源码的仓库**，
上游没有现成中文教材（多数仓库都没有），所以要自己写。
（只是收官方文档 / 补漏 / 修索引 → 那是 `learn-workbench-maintenance` 的范围；
建六件套 → `repo-learning-workbench`（用户自有资产，不能直接改），本文件是它可写的姊妹篇。）

## 0. 一句话流程

立规范 → 自己写 2 份样板 → 并行子Agent 批量产 → 父逐条复核 → 生成索引 → 挂总索引。

## 1. 先立《讲义写作规范.md》，再写任何一份讲义

规范里写死五件事：

1. **读者画像**：谁会读、他已经会什么。本类任务通常是「第二份源码」——读者已经读过第一份（如 Hermes），
   凡两边对应的机制，直接说「这和 X 的 Y 是同一件事」，省掉一半篇幅。
2. **每讲固定八段骨架**（见 SKILL.md 变体小节）。
3. **语言纪律**：英文术语第一次出现必须紧跟一句人话解释；段落 ≤5 行；禁「顾名思义 / 众所周知」；
   比喻落到日常物件；少量伪代码，不要成段贴真代码。
4. **长度**：正文 150–250 行。
5. **禁止编造**：所有 `文件:行号` 写前必须 grep 验证过；验证不了写「约 N 行附近，搜 X 可定位」。

规范是批量生产时唯一的质量闸门——没有它，5 个子Agent 会写出 5 种风格。

## 2. 样板讲义先自己写 2 份

挑「定位那一讲」（这是份什么样的源码 / 怎么跑起来）与「核心机制那一讲」（如主循环）各写一份。
这两份定调，其余照抄结构。写完给用户过目再批量。

## 3. 讲次怎么分

- 按**可迁移的机制**分阶段，不按目录分。
- 阶段 0 固定是「建立地图」：3 讲（这是什么源码 + 三个入口/怎么跑起来 + 一次操作的全局流水线）。
- 每阶段 3–6 讲；总量 20–30 讲够用。
- 非官方源码必有一讲讲「门控与被裁剪的功能」（编译开关 / 内部用户标记 / 远程开关这类三层门控）。
- 最后两个专题最出彩：**与已学项目的逐条对照表**（一个维度一行，含「谁更好 / 差异的根因」列）
  与 **面试怎么说**（问题 → 权衡 → 实现 → 数字）。
- 路线里每讲要带四项：讲义文件路径 + 已核实锚点 + 动手项 + 必答三问；末尾给一档速通路径。

## 4. 并行派活模板（一次 5–6 讲）

一个子Agent 包 5–6 讲，**写集不重叠**（一人一个阶段目录最省心）。brief 必带五件，缺一件风格就漂：

1. 规范的绝对路径（写明「逐条遵守」）
2. 样板讲义的绝对路径（写明「风格与结构照它」）
3. 路线文件路径（里面有父已初步 grep 过的锚点线索，写明「当起点，但必须自己去源码验证并补充」）
4. 每讲的主题 + 输出绝对路径（逐条列出）
5. 硬要求：八段骨架、长度、**每个 `文件:行号` 必须自己 grep/sed 验证过、验证不了不许编**、
   只创建列出的文件、结尾报告「亲自验证过的锚点 + 哪一讲材料最少」

再加两条：

- **不许子Agent 改父的产出**（路线、总索引、规范、进度表）——它只写自己那几讲的讲义。
- **最多 3 个并行**（平台上限）；一轮回来再派下一轮，别把新批叠在还在跑的兄弟上。

## 5. 父的复核（不许省）

子Agent 的「我验证过锚点」是自述，父要自己跑一遍：

- 抓出所有讲义里的 `文件:行号` 与 `文件（N 行）`，逐条读该行、断言含预期符号（函数名 / `name=` 键）。
- 讲义存在性与行数（落 150–250 区间）。
- 抽读 1–2 份非样板讲义，看是否真照骨架写（最常见的漂法：退回「先贴代码再解释」）。
- 讲数口径四处一致：总索引 / 路线 / 讲义索引 / 进度打卡表。

## 6. ②材料：把仓库自带的一手文档分发进讲目录

仓库自带的 `docs/*.md`、各目录 `AGENTS.md` 是一手材料。按主题复制进对应讲文件夹：
`<讲号>-②材料-<主题>.md`（`copy2` 保留 mtime + md5 逐字节断言），并在路线对应讲里加一句
「本仓库自带说明，已复制到本讲文件夹」。比在讲义里转述强得多。

## 7. 索引与进度表

- `讲义汇总/00-索引.md` 由脚本生成（讲数由映射表算，不写死）；手建目录也要进映射表，否则不进索引。
- `学习进度.md` 打卡表列到每一讲，留「实证笔记」栏（强制 `文件:行号 + 我搞懂了什么`）——
  这是用户以后简历 / 面试的素材库。另加「阶段完成标志」自检清单。
- 讲义文件夹的阶段名与路线里的阶段同名同号，方便对号入座。

## 8. 坑

- **引用计数分清文件数与目录数**：`find X -type f | wc -l` vs `ls -d X/*/ | wc -l`。
- **校验脚本两个分支都要累加**：只累加失败分支，全过时会打印 `0/0`。
- **源码出处要写清**：还原版 / 非官方 = 架构真、细节可能是补丁、官方版裁剪过功能。
- **别按常识解释目录名**：先 grep 实际用法（实测某仓库 `hooks/` 是 React 钩子，不是事件钩子）。
- **量大时先写规范与样板再派活**，不要边派边定风格。
