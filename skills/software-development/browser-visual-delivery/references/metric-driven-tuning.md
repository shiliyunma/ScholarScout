# 指标驱动的调参：把“看起来怎么样／跑得多快”变成能扫的量

适用：涌现类仿真与可视化的参数选择（群体/粒子/元胞/风格化流体），以及任何“用户给的是感觉、
你必须自己造判据”的场合。

## 1. 先把含糊要求量化成代理指标

| 用户的话 | 代理指标 | 算法 |
|---|---|---|
| “形状一直在变，不要老是个球” | 形态谱 `[λ1,λ2,λ3]/tr`、主轴比 `elong=√(λ1/λ3)`、变化率 churn | 位置协方差矩阵（3×3 对称，Jacobi 迭代十几次即可）→ 特征值排序归一化；churn = 相邻采样间**归一化**协方差的 Frobenius 距离（球形恒 0） |
| “别掉队／要成一群” | 聚拢度 = 到群心的均方根距离 ÷ 世界边长（均匀分布 ≈ 0.5） | 一阶矩即可 |
| “跟上／方向一致” | 局部对齐 = 每个体的邻居速度单位向量平均长度 | 邻域内累加 |
| “别撞” | 撞车率（成对采样中重叠比例）+ 最小间距（兜底） | 随机成对采样，避免 O(N²) |
| “跑得动” | 每步 CPU 毫秒（**只算仿真**，渲染另算） | 无头真实时钟 |

把指标实现进仿真类内部（如 `shapeStats()`），扫描器只当调用者——不要在扫描脚本里重算。

## 2. 扫描骨架（页面端 + 驱动器）

页面端：`?sweep=1` / `?shapesweep=1` 触发一个同步函数，逐配置跑完，把**每个用例的完整指标**
POST 回本地服务；驱动器（python）起 HTTP 服务、开无头 Chrome、等 POST 落 `docs/*sweep.json`、再打印成表。

- 用例表用数据描述（`{id, n, mode, start, steps, 各权重}`），不要一条条写死代码。
- 每个用例前先 `applyBaseParams()` 再覆盖该用例的字段——否则上一个用例改过的权重会**泄漏**到下一个
  （实测对撞专项继承了前一用例的 `wSep=0`，结论完全反过来）。
- **步数要显式写出来**并在注释里说明为什么（测平衡态需要多少步），别让不同用例悄悄跑不同步数。
- 想在时间上观察某个量，就按固定间隔采样（每 30–60 步），把整个序列一起回传。
- 每轮扫 6–8 组、每组几秒，比来回改十次代码快得多，还能看出参数之间是否耦合。

## 3. 记录哪些字段（少一个就要重跑）

`id / n / mode / start / steps / msStep / avgNeighbors / 各质量指标 / 各形状指标 / pass`，
外加**分项计时**（网格重建 vs 邻居+积分）与**采样计数**（候选测试次数）——
“平均邻居数是否等于 k”这类断言是你确认“上限真的生效”的唯一证据。

## 4. 判读规则（比指标本身更容易错）

1. **受控比较同条件**：起始分布、模式、步数全一致，只差被研究的那个权重。
2. **在平衡态上比**：先 warm 几百步再采样。短窗口量到的是初始松弛（实测变化率 0.103 → 平衡态 0.0195）。
3. **按起始分布分别设阈值**：“从散开收敛”（0.5 → <0.3）比“本来就紧、别散开”严格得多；
   紧起始的用例放宽（<0.4），否则会把“参数放松后平衡尺寸本来就更大”误判为失败。
4. **噪声判断**：同一配置重复跑 ≥2 次；若某指标的跑动幅度 **≥ 配置之间的差异**，它**只允许用来筛掉
   明显坏的**，最终选择换用直接观察（抓图/时序图）。
5. **消融要能在正确的起始条件下杀掉退化实现**：同一份代码只把一个权重设 0，要求对应指标显著变差；
   并且要在**能暴露差异的起始分布**上做——凝聚消融要从“散开”起始衡量“能不能收成一群”，
   从紧球起始时硬球的非弹性接触会把群卡住，掩盖“没有凝聚”（实测 0.33 贴着阈值 0.335）。
6. **极端值只做兜底**：最小间距这类全局最小量能跳一个数量级，只当“求解器没崩”的下限（>0.1）。

## 5. 时间序列抓图（审美要求的最终判据）

条件：**同一机位、同一距离**（不要每帧重新取景，否则几张图不可比），只改 warm 步数（如 240/480/720/960），
走和普通抓图同一个 POST 通道，文件名带 tag（`render-ts1..4.png`）。
判读：四张要能看出**不同的形状或朝向**，而不是同一个团换个位置。

## 6. 性能基准卫生

- **一次只跑一个浏览器实例**：并发跑会抢 CPU，把同一份代码的每步耗时测高 50%+（实测 12000 实体
  10.1ms → 16ms），据此得出“跑不动”是错的。
- 报“每步毫秒”这类与显卡无关的数；无头下渲染是软件光栅，帧率无意义。
- 明确区分：面板上的“时间倍率”只改 `dt`（运动快慢），**不降低每步成本**，不能用它救大 N 的流畅度。
- 同一份代码重复跑波动 ±10~30%：结论写区间，不要写单次值。

## 7. “要一直变”= 要有持续驱动

保守的局部规则系统会松弛到准平衡（形状冻住）。可用的持续驱动：

- **小幅随机转向（“温度”）**：每步加 `noise × maxForce` 大小的随机方向力；方向用**预生成的单位向量
  查表**（`idx = (个体×大质数 + 步数×小质数) & 255`），热点路径里零三角函数。实测 0.6 仍保持聚拢 0.20、
  对齐 0.98；再大就散。面板给它一个滑块（0 = 纯规则，方便对照）。
- **捕食者/移动吸引点**：外来刺激是真实群体形变的主要来源，也天然是一个“对抗用例”。
- 两者都会轻微降低平均邻居数（结构变松），属预期，不要当回归。

## 8. 调参杠杆的实测效果（群体类）

| 杠杆 | 调整 | 效果 |
|---|---|---|
| 长程归群“绳长” | 0.24 → 0.32×世界边长 | 群从近球形团 → 可变形团块，主轴比 1.66 → 2.4~3.4 |
| 对齐权重 | 1.05 → 1.8 | 长程耦合变强，更容易拉成片/带 |
| 随机扰动“温度” | 0 → 0.6 | 形状从“冻住的准平衡” → 持续起伏 |

三个都是相对量（比例/权重），与 N 和世界尺寸解耦后才可复现。
