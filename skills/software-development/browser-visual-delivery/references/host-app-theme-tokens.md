# 界面配色：取自宿主应用的令牌，不要自创

用户的要求是**自建界面与他正在用的应用同体系**（他明确否掉过深蓝色调，只接受“跟你现在的主题框架与颜色相似”）。
所以开工顺序是：**先读宿主应用的样式文件 → 抄它的令牌结构 → 再画自己的组件**。

## 权威来源（先读，再动手）

- `C:/Users/Lenovo/AppData/Local/hermes/hermes-agent/apps/desktop/src/styles.css` —— `:root` / `.dark` 下的令牌定义。
- 同目录 `themes/` 下的主题预设文件（若存在）：多主题时每个预设只改几个种子色，其余全靠派生。

找不到桌面端源码时，退化也有一条：他当前用的界面本身（截图取色）——但优先读源码，色值才准。

## 令牌分层（照抄结构，不要只抄某几个颜色）

| 层 | 内容 |
|---|---|
| 种子 | 背景 / 前景 / 强调（accent）/ chrome（顶栏与侧栏底） |
| 表面 | 卡片、悬浮、选中态：`color-mix(in oklab, <前景> X%, <背景>)` 逐级推开 |
| 文字阶梯 | 前景按透明度分主 / 次 / 弱 / 禁用（如 100% / 70% / 55% / 40%），不要另调文字色 |
| 描边 | hairline：前景 8–12% 透明 + 1px，不要用灰色写死 |
| 圆角 | 单一系数乘基准尺寸（本项目 0.2），**不要每个组件各写一个值** |

**浅色为默认**：前景 `#17171a`、强调 `#0053fd`、chrome `#f3f3f3`、卡片 `#ffffff`。
**深色用中性近黑**：`#000` / `#0d0d0e` / `#161618` —— **严禁蓝调深色**。

## 必须有的交互

- 顶栏三态切换：跟随系统 / 浅色 / 深色；选择存 localStorage，首次读 `prefers-color-scheme`。
- 主题只切一个 class（如 `<html class="dark">`），**颜色全部来自 CSS 变量**；JS 里不许出现颜色字面量。
- 主题入口写成一个函数（如 `applyTheme(mode)`），启动时调一次——这样截图脚本能拿它直接切状态。

## 自检

- 静态资源校验进门槛：文件齐全 + 界面只调真实存在的后端方法 + 无外链（离线可用）。
- 改完自己拓图看：浅色、深色各一张 + `vision_analyze`（配方与坑见 `headless-chrome-verification.md`）。
- 若界面靠 `class` 开关主题，**截图时绝不能注入 class**：启动会重新 apply，注入会被覆盖。

## 反例（重做过的代价）

第一版自创了一套深蓝配色，交付后被要求整段重做。**自创配色的返工成本远大于先花五分钟读令牌文件**。
