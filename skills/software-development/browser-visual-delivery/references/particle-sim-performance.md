# 粒子/群体仿真的性能与力设计（万级实体实时）

适用于：boids 类群体、n-body、粒子系统——任何“每个实体要按邻近关系算力”的实时仿真。

## 数据结构与循环

- 每个分量一个 `Float32Array`（`px, py, pz, vx, vy, vz`），比交错数组对 CPU 遍历更友好；
  GPU 需要交错时再在每帧拼一份实例缓冲。
- 循环外一次性把对象属性读进局部变量（`const {px, py, wSep, kMax} = ...`）；循环里出现 `this.xxx` 就是白花开销。
- **热点路径禁用 `Math.hypot`**：`Math.sqrt(x*x + y*y + z*z)` 快一个量级。
- 不在每帧循环里 `new` 任何东西；复用一个 3 元素暂存向量传结果（`steer(out, ...)`）。
- 需要一个每步重建的索引（网格）时，用**计数排序**：`counts.fill(0)` → 记数 → 前缀和 → 散射，全程复用同一批 `Int32Array`。
- 把 `step()` 拆成 `_buildGrid()` + `_integrate(dt)`：既能分项计时，也方便单测。
- ⚠️ 往热点函数里插新的力项时，先确认它引用的每个 `const` 在插入位置**之前**已声明：同一个函数块里
  后声明的 `const` 在前面被使用会抛 TDZ `ReferenceError`（表现是整页白跑，不是“力算错了”）。
  插入后按声明顺序核对一遍，或干脆把新块放到所有 `const` 声明之后；页面挂了 `window.onerror` 时
  跑一次无头就能暴露。

## 均匀网格空间哈希（从 O(N²) 到 ~O(N·k)）

1. 单元边长 ≈ 最大的相互作用半径；网格维度取整 `g = round(world / cell)`，单元边长取 `world / g`（整除，环形世界必须这样）。
2. 邻域扫描 `(2r+1)³` 格，`r = ceil(radius / cellSize)`，“跨边界回绕”用一次加减就够
   （`v >= g ? v-g : (v<0 ? v+g : v)`）。
   ⚠️ **不要为了省循环把窗口裁成 `floor(g/2)`**：当世界相对交互半径很小、窗口跨满整条轴时，
   裁剪会在 g 为奇数时**漏掉真邻居**、g 为偶数时把同一个邻居**重复计入**（偏移式最小镜像因此完全失效，
   而且聚拢/对齐指标会静默失真）。正解是**跨满整轴时改为扫遍该轴的全部格子**（`_fullAxis`/`_nAx`），
   保证每格恰好出现一次。
   ⚠️ 2D 模式下 z 轴循环只应跑**一次**：写成 `2r+1` 次会让每个邻居被算 3 遍。
3. 网格单轴维度**设上限**（如 ≤64³）：每步 `counts.fill(0)` 的开销随格子数线性增长，别让极端参数把它顶爆。
4. **每格算一次世界平移量**，候选循环里零分支：
   `raw = ci + d; wrapped = 回绕(raw); off = (raw - wrapped) * cellSize;`
   然后 `ddx = px[j] + offX - xi`。比每个候选做 3 次“最小镜像”比较快得多，也是让每候选只剩十几条指令的关键。
   改了方向约定（自己-别人 ↔ 别人-自己）后，分离/凝聚/视野判据的符号要**一起**翻。

## 两个“只做一半就没用”的优化

- **限制采纳邻居数 ≠ 限制开销**。稠密区域里每只实体仍会把 27 格里的所有候选走一遍。
  必须另设**候选测试预算** `kCand`（如 `max(24, 4*kMax)`），到预算就跳出。实测：12000 实体从 63ms/步降到 ~10ms/步
  （**独占机器**测得；同时开两个 Chrome 会把它测成 16ms）。
- **截断顺序决定质量**。预算/上限截断时，先扫自己格再一圈圈向外（近的先来），
  同时用实体下标做个哈希随机化每只的扫描方向，避免“总是先看 -x 一侧”造成系统性的方向偏置。

## 转向力的设计（三条规则类）

- 分离/对齐/凝聚都用 Reynolds 式 steer：`期望速度 = normalize(目标方向)*maxSpeed`，`力 = 期望-当前`，
  截断到 `maxForce`，再乘权重。三者量级相同，群才收得住。
- **归一化会吃掉距离权重**。把“越近越猛”的分离力送进 normalize 型 steer，紧迫度信息就没了。
  正确做法是拆两层：① 软分离（归一化 steer，负责形状）② **硬核**（幅度按紧迫度/接近速度放大、
  上限远高于 maxForce，且只在“贴脸 或 径向接近”时才有值，负责别撞）。
- 单个未归一化的强分离力（幅值是对齐/凝聚的十几倍）会把整体撑散——表现是“群永远聚不起来”，
  而每帧都不报错，很容易误判成聚合权重太小。
- **硬球（位置投影）是“别撞”的硬保证，但只有位置投影不够**：投影发生在积分之前，`pos += v·dt`
  每步最多又能把两者合拢 ~0.43 单位（实测残留穿插 0.055、对撞专项 0.019）。必须**同时抹掉径向接近
  速度**（接近时两只各消掉一半），补上后最小间距 0.39–1.37、对撞专项 2.37。
  ⚠️ 别靠“把碰撞半径调大”来救：约束数 ∝ r³、成对投影不可交换，半径 0.55→0.8 反而更差（最小间距 0.24→0.08）。
- 限速：`sp > maxSpeed` 缩放、`sp < minSpeed` 缩放（保底不静止）、`sp ≈ 0` 时给个固定方向，避免 NaN。

## 环形世界（toroidal）的真实后果

- **纯局部规则在环形空间里的平衡态是均匀分布**（平移对称下的精确平衡点），不是一个大团。
  实测表现：一团起始会先被分离力炸开，然后稳定在“很多个小团”（聚拢度指标 ≈ 均匀分布的理论值 0.5）。
  这不是 bug，是物理；不要为了“看起来像一群”去乱调分离权重。
- 要一个大团，加一个**长程吸引项**（goal seeking / arrival），并且**作用半径随世界边长缩放**
  （这样 N 变化时群内密度恒定，不会 N 越大挤得越死）。把它做成可关闭的滑块，并说明“调到 0 = 纯局部规则”。
  ⚠️ 这一项的强度直接决定“群的形状能不能变”：太强/绳长太短会把所有实体压成一个近球形团
  （实测主轴比 1.66、形状基本冻住）；放松到 ~0.3、绳长 ~0.32×世界边长之后变成可变形团块
  （主轴比 2.4–3.4）而聚拢度仍 <0.25。想让形状一直变，另需持续驱动——见 `metric-driven-tuning.md`。
- **自动居中**：每若干步把全体位置平移回盒子中心（用最短镜像增量）。在环形空间里这是精确对称，
  不改变任何相对运动，但能让群体永远在取景框里，并让“算术质心”类的度量不会因为跨越边界而失真。
- 圆均值（`atan2(Σsin, Σcos)`）求群心只在单峰分布下有意义；分成两群/对称分布时会指向无意义的点——
  用它当相机目标或长程吸引目标时要知道这个前提。

## 渲染（WebGL2 实例化）

- 朝向不要在 CPU 建矩阵：顶点着色器里用“实例位置 + 速度”现场构造正交基
  （`f = normalize(v)`，`up = |f.y|>0.97 ? x : y`，`s = normalize(cross(f,up))`，`u = cross(s,f)`），
  局部几何按 `s*x + u*y + f*z` 变换。一次 `drawArraysInstanced` 画完 N 个实例。
- ⚠️ **WebGL2 没有 `baseInstance`**：把“额外一个对象”（捕食者、鼠标标记）写进主实例缓冲的尾部空槽位
  是**读不到的**，它会被画成第 0 个实体的复制体（常见的“多了个红色大鸟”现象）。额外对象必须用
  **独立 VBO+VAO** 自己画一次。
- 拖尾/残影：累积纹理 + 每帧先画一层低 alpha 黑幕（`SRC_ALPHA, ONE_MINUS_SRC_ALPHA`）再加法画实体；
  渲染前把该纹理从采样单元解绑，否则触发 feedback loop 报错。
- 2D 模式（约束在 xy 平面）下，构基用的“上”参考向量要换成 `(0,0,1)`：固定用 `(0,1,0)` 会让机翼轴
  落到正对相机的方向，实体被压成约 1 像素薄片。
- 实体显示大小随世界边长缩放，否则大世界/大 N 时实体小到看不见。

## 度量指标（自检用，能被证伪）

| 指标 | 定义 | 参考值 |
|---|---|---|
| 序参量 φ | `\|Σ v̂\| / N` | 随机 ≈ 0.01，成群 > 0.35 |
| 局部一致性 | 每个实体的 `\|Σ 邻居v̂\| / n` 的均值 | 随机 ≈ 0，局部对齐良好 > 0.6 |
| 聚拢度 | 到群心的 RMS 距离 ÷ 世界边长 | 均匀分布 ≈ 0.5，成型的一团 0.13–0.27 |
| 撞车率 | 距离 < 0.3×分离半径 的邻居对占比 | < 1e-3（阈值取与实测同量级） |
| 对撞专项 | 两个实体正面对飞，测最小间距 | 应 > 体长的一半；穿模说明“别撞”没实现 |
| **形态谱** | 位置协方差矩阵的三个特征值（归一化） | 球 ≈ 0.33/0.33/0.33；像片/带时 λ1 明显更大 |
| **主轴比 elong** | `√(λ1/λ3)` | 1 = 球；2–3.4 = 明显非球形 |
| **形状变化率 churn** | 相邻采样间“归一化协方差”的 Frobenius 距离 | 球形恒 0；>0 说明在伸缩/转动 |

再加 NaN 计数、越界计数、速度是否严格在 `[minSpeed, maxSpeed]` 内，以及**分项计时**
（网格重建 vs 邻居遍历+积分）——后者是唯一能告诉你“该优化哪里”的东西。

指标本身的坑（和算法一样容易错，详见 `metric-driven-tuning.md`）：

- **在平衡态上量**：先 warm 几百步再采样。短窗口量到的是初始松弛（实测变化率 0.103 → 平衡态 0.0195）。
- **指标噪声 ≥ 配置差异时只当筛选**：churn 同一配置能 0.014–0.082（形变是慢速“转动+伸缩”，会撞上不同相位），
  比配置之间的差异还大。最终选择用**同机位时间序列抓图**肉眼定。
- **按起始分布分别设阈值**：“从散开收敛”（0.5 → <0.3）比“本来就紧、别散开”严格得多；
  紧起始的用例放宽到 <0.4，否则会把“参数放松后平衡尺寸本来就更大”判为失败。
- **消融要在能暴露差异的起始条件上做**：凝聚消融要从“散开”起始衡量“能不能收成一群”；
  从紧球起始时硬球的非弹性接触会把群卡住，掩盖“没有凝聚”（实测 0.33 贴着阈值 0.335）。
