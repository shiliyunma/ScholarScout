# 偶发红、假绿、守卫误报：先分类再收口

用于：并发/时序用例偶发红、无头探针报"通过"但实际没发生、守卫把注释当代码拦、绝对几何断言随窗口尺寸失效、
以及第三方接口只有真打才能暴露的问题。

**核心原则：假绿比红危险**。红会拦住提交；假绿会静默关掉一道检查，并让"已修复"变成口头承诺。

## 流程

1. **先分类，再动代码**。用一次放大条件判断属于哪类（产品竞态 / 测试同步手法 / 探针共享状态）。
   禁止"先改产品再看"或"先放宽断言再看"。
2. **修完必须给出可证伪的证据**：正常 N/30 绿 + 放大条件下 N/30 绿 + **旧写法在同一放大条件下必须红**。
   没有第三条，就证明不了你修的是那个 flake。
3. **如实标注构造条件**："注入 10.5s 卡顿"是构造的可证伪条件，不是当初那次红的现场——要说出来。
4. **守卫要更精确，不是更松**：剥注释后再判；每放宽一条规则配一条反例用例。
5. **绝对几何断言必须钉死视口**，探针第一步校验视口，不等就报错、不出数。
6. **外部接口能力判定读元数据**（如 `/models` 的 `supported_levels`），降级要留痕、只重试一次。

## 硬规则（每条都踩过）

- **并发用例的同步只用屏障**，墙钟超时只当死锁哨兵。桩里 `wait(timeout=10)` 会把机器卡顿变成红，
  而且红在与产品无关的断言上（超时后该轮以 `error` 收尾并被摘出池）。**每一轮/每个阶段都要过屏障**，收口轮也算。
- **探针用例不许并发共享 spy**：`Promise.all` + 共用 `sent` 数组时，后一例的 reset 抹掉前一例记录，
  同时产生假红（实际 `[]`）与假绿（"再点没发"其实从未发过）。串行 await + 每例 reset + 调用序日志。
- **`patch` 的 old_string 撞多处 = 文件没改**。改 JS/HTML 重复结构时带上上一行+下一行做唯一锚点；
  改完用 `git status` / `git diff --stat` 看该文件是否真的 `M`，不要信"已改"的汇报。
- **对 `object` 形参做 `int()`/`float()` 前必须 `isinstance` 收窄并排除 `bool`**（`bool` 是 `int` 子类）；
  禁 `type: ignore`、禁 `Any` 掩写、禁改签名迎合检查器。
- **派生判据不能用降级后的值**：用降级结果判"该档是否支持"，降级必然落回支持集 → 每档都判支持、置灰形同虚设。
- **并行写者下重新应用而非覆盖**：旧 stash 只读设计意图，改动重新加到当前文件；
  `git diff --numstat` 对别人改过的文件应当 0 删除行，有删除要逐行说明。
- **新增配置字段必须同步示例配置**：有"每个字段都要能在 YAML 里读到"的守卫时，漏加即为红。
- **第三方身份 id 按应用隔离**：只有真打一次才能发现"跨应用"，桩测永远绿。
