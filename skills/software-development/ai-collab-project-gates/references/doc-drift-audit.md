# 文档与代码一致性审计（清单 + 检测命令）

用于：有人问“文档和代码一致吗 / 帮我核对文档”，或需要给一个文档多的仓库做体检。
目标不是读遍文档，而是**用命令把不对的地方揪出来**。以下六类，按“最容易漏”排序。

## 1. 目录树里列了不存在的文件

```bash
grep -n "\.py\b" docs/0*-*.md | head -40      # 文档点名的文件
ls src/<pkg>/<dir>/                           # 与之对照
```

典型：目录树里留着“规划中”的文件，除注释外没有任何标记指出它不存在。
修法是**在文档里标明它尚不存在**（而不是把文件补出来）。

## 2. 计数漂移（最隐蔽的一类）

```bash
grep -c "register()" src/<pkg>/tools/__init__.py   # 注册了几个工具
wc -l eval/sets/*.jsonl                            # 题集实际条数
```

典型：文档写“只注册 7 个”而代码是 8 个。
**历史陈述不要改**（“当时是 7 个”是真的），只改描述**当前**状态的数字，并在同一句里说清增量从哪来。

## 3. 门禁命令的范围

```bash
grep -n "ruff check\|ruff format\|mypy" scripts/check.sh
grep -rn "ruff check \|mypy src" docs/ AGENTS.md
```

脚本扩大扫描范围而文档没跟，是最不容易发现的一类 —— 文档看起来对，只是不全。
改范围时**三处一起改**，且规则文件的命令块必须逐字一致（否则同步校验红）。

## 4. docstring 里的章节号 / 路径引用

```bash
grep -rn "docs/0[0-9] §" src/            # 代码引用的文档章节
grep -n "^### 5\." docs/01-*.md          # 文档实际的章节号
```

典型：docstring 写 `docs/01 §5.5` 而正文里它在 `§5.9`。这类错**只会误导读者，不会让任何测试红**。
注意：改了 docstring 的**首句**会让生成物（符号清单）失效 → 同一轮重跑生成物。

## 5. 示例配置 vs 代码默认值

```python
import yaml, pathlib
d = yaml.safe_load(pathlib.Path("config.example.yaml").read_text(encoding="utf-8"))
print(d["search"]["min_interval_s"])      # 解析出来的才是**生效值**
```

- **重复键**：YAML 后者覆盖前者，肉眼看不出来。检重复键要**读原文文本**逐行数同名键；
  `Counter(dict)` 会把 dict 的**值**当计数 —— 那不是重复键检测，别拿它下结论。
- **代码明令禁止的键被示例写回去**：代码注释写着“故意不写 X”（X 由 provider 动态算），示例却写了 `X: 1.0`，
  照示例拄的人会踩上代码注释里预言的那个坑。**示例配置是要被人复制的文件**，它写错的代价比普通文档高。

## 6. 字段名漂移

```bash
grep -rn "key_points" src/                 # 文档里的字段名
```

只在文档里命中、代码里叫别的名字时：**以代码为准**，并在文档里并列写出“文档名 vs 代码名”，不要二选一猜。

## 收尾纪律

结论按三类分，不要混报：

| 类别 | 处置 |
|---|---|
| 文档落后代码 | 改文档，同一轮提交 |
| 代码笔误（如 docstring 章节号） | 改代码，**并重跑生成物** |
| 历史陈述 / 参照外部文件 | **不改**（如“反幻觉 12 条”指的是它参考的行业版文件，本项目自己的是 9 条） |

改完跑一次生成物 `--check` + 项目门禁，并把“哪几条是文档落后、哪几条是代码笔误”逐条写进回复 ——
用户要的是可核对的清单，不是“已核对”三个字。
