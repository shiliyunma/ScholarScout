# 大文件拆分（按职责、可验证、能回滚）

适用：一个文件长到没人愿意读（几百到几千行），要拆成多个模块；或大规模把代码从 A 文件搬到 B 文件。

## 拆不拆：判据是「职责」，不是行数

- 拆的理由 = **文件里混了两类以上互不相关的职责**（一个文件里既有「会话」又有「抽背卡」就是混了）。
- **只是长、但都关于同一件事 → 不拆**。用户的标准原话："如果拆分不符合真实业务实际则不必拆分"。
- 别为了行数好看拆。拆完读起来更绕是净亏。

## 拆法：机制一处、实现按域、入口只留注册

**后端/库代码**
- 机制与基础设施单独成模块（上下文对象、注册表、参数校验、分发函数）。
- 实现按域分文件，每个域一个模块，文件名就是域的名字。
- 原入口文件只留**注册入口 + 再导出**，并保留外部依赖的那几个名字：
  `from pkg.entry import Context, dispatch, names` 在调用方、CLI、测试里**一个字都不用改**。
- 已验证的量级：单个模块 972 行 → 18 行，实现按域分成 5 个 100–280 行的模块，注册项数不变。

**前端（无构建的项目）**
- 多个纯 `.js`，由 `index.html` 分别引入 —— **不需要打包器、不需要 import**。
- 跨文件调用靠全局函数声明；**顶层状态与常量留在入口文件**，其余文件只放函数声明
  → 加载顺序不影响运行时（但既有的顺序约束，例如「渲染器必须在入口之前」，继续保留）。
- 加了新文件后，资源校验脚本要能发现「拆出来的文件没被引入」这种死文件。

## 拆巨型函数：按职责切，一次一刀

另一种形状：文件不算离奇，但**一个函数几百行**（实测：一个函数 475 行、文件 868 行）。这时拆文件没用，要拆函数。

- **位移而非改写**：提取出的每个函数只搬代码。条件、异常分支、事件名与载荷、日志语义一律不动。
  搬完的判据是：**原来那些测试一行不改也全绿**。如果你得改测试才能绿，那就不是纯重构 —— 停下来先弄清为什么。
- **一刀一跑**：每提一个职责就跑一次**全量**测试（不是只跑那个文件），绿了再进下一个；红了就回滚这一刀，
  不要"先继续、最后一起修"（到那时已经分不清是哪一刀弄坏的）。
- **切的是职责，不是行数**：能一句话说清"它负责什么"的才是一个切口（压缩 / 记忆抽取 / 台账 / 预算闸 /
  一轮工具调用 / 产物收尾）。切完的编排函数只应剩下顺序、条件和返回值。
- **总量会变大，先说清楚**：提取会新增函数头、docstring、参数传递，**文件行数常常上升**（典型：函数 475→300，
  文件 868→987）。所以"文件小于 N 行"的门禁**不会**因为拆函数而满足：如果真正的问题是文件混了多类职责，
  那要拆文件；如果问题只是单个函数难读，拆函数就够了。绝不允许拿"函数短了"去声称"文件门禁达标了"。
- **有些不可能是逐字搬移**：把 `if 开关 and llm:` 改成提前 return 是等价但**非搬移**；把闭包的 `nonlocal`
  改成参数传入传出，是跨函数边界的**必要**改动。这类改动允许，但要在提交信息里**点名**（"这两处不是纯搬运，
  理由如下"）—— 否则整笔提交的"零行为变化"就是假声明，reviewer 会把它们当搬移跳过。
- **中断的提取会留下不导入的树**：调用点改完、函数定义还没写 → `NameError`。接手时先
  `git restore --source=HEAD -- <file>` 丢掉那个半成品，确认能 import，再重新切一刀。
- **提交粒度**：每个提取一笔提交（回滚故事才完整）；每笔前至少跑全量测试，
  **push 前**在最终树上跑**完整门禁** —— `lint`/`format`/`types` 往往到那一刻才第一次被跑。
- **派给子 Agent 时一次只派一刀**：一个任务里塞 N 刀，它几乎总在最后一刀被迭代上限截断，
  留下"调用点改了、函数定义还没写"的 `NameError` 树。做完一刀 → 提交 → 再派下一刀；宁可多派几次。

## 拆出独立模块（而不是同一文件里加方法）

文件超标时，"在同一个文件里把大函数拆成私有方法"只是把债换了位置：实测函数 475→300，文件反而 868→987。
要让**文件**变小，必须搬到新模块。四条补充：

- **先算这一刀能带走多少行**：带走后仍超限的接缝不是这一刀的接缝（提议的 123 行块搬走还剩 659，改搬 243 行那块才过线）。
- **要搬两块才能过线 → 说明它们不是一个接缝**：两块一起搬就不得不改调用方的内部流程时，那已不是纯位移；
  宁可换一个自带契约的块（类型 / 错误 / 结果对象那一组：零状态、被多个模块依赖、只依赖标准库）。
- **新模块自己也超限时，按"原语 vs 步骤"再切一层**：先搬上下文 / 结果 / 发射器原语到 `*_context.py`，
  步骤函数留在 `*_steps.py`（实测 617 → 155 + 522，两个都达标）。
- **新建顶层模块可能撞上分层元测试**：项目常有一条"每个顶层模块都必须登记在规则表里"的测试，
  新文件会逼着改测试。更省事的落点是**已有的层**（把数据维护放进 `state/`，而不是新建顶层 `data_maintenance.py`）。

另外：**"0 处可搬"是合法结论**。全量 AST 扫过、没有残留的手写形状时，如实报 0 并修正你给过用户的数字，
不要为了凑数量硬迁。

## 拆前必须做的两件准备

1. **先抽共享读取器**。若 N 个契约测试各自定义「读哪个文件」（`APP_JS = ...`），先抽成一个共享模块
   （如 `tests/desktop/_ui.py` 里定义「整个前端 = 所有 js 的合并文本」），测试改成从它导入。
   **先做这一步再拆** —— 否则就是在 N 个文件里同时打补丁，越补越乱（本项目就是这么撤回去的）。
2. **先提交或先备份**。`git commit` 或 `cp -r` 一份目标目录，拆崩了 `git checkout -- <目录>` 一键回绿。

## 验证：靠不变量，不靠感觉

- **先写下一个拆分前后的不变量**，拆完量它：注册项数不变、导出的名字集合不变、
  对外接口的返回结构不变。数字对不上就是搬漏了。
- **最强的"纯位移"证据是 AST 切片哈希**（比"测试绿"强得多）：对搬运前后的每个顶层对象取
  `ast.get_source_segment` 算 sha256，与 HEAD 逐个比对 —— 搬走的那批和留下的那批都要比，数量也要对得上。
  实测口径：24/24、12/12 全同 + "新增定义仅 `__all__`"，这才是能写进提交正文的证据。
  配套两条命令：`git diff HEAD -- tests | wc -l` 为 0、`git status --porcelain tests | wc -l` 为 0。
- 每个新文件过语言级检查（`node --check` / `ast.parse` / 编译器），再跑完整门禁。
- 只允许**搬家**，不允许顺手改逻辑；要改逻辑另开一次提交。

## 守卫/契约测试会抓什么（这是敢拆的底气）

- 契约测试常**直接读源码文本**（在入口文件里 grep `id="..."`、调用字符串、常量名）：代码一搬就失效。
  它们不是障碍，是「这次搬对了没有」的探测器 —— 被它们抓到就改它们的目标路径，别绕过。
- **monkeypatch / mock 的目标字符串随代码搬家而失效**（`pkg.entry._helper` → `pkg.domain._helper`）。
  更狠的一种：被 `monkeypatch.setattr(module, "_x")` 钉住的函数**不能搬**。搬走不会报错，
  而是桩静默失效、那条测试变成**无效通过**（假时钟不再生效）。判据：动手前在测试树里 grep 该名字，
  看它是否被 setattr 钉住；被钉住就换一个接缝，别为了让文件变小去动它。
- **校验脚本只扫一个文件会在拆分后假通过**：资源/方法名校验必须让它扫**全部**源码文件，否则拆出去的代码出问题也查不出来。
- **同名定义会互相盖住**：搬运后若原文件里还留着同名函数，它会盖住新加的共享版本，
  症状是「读到的还是旧内容」，而且失败项会随修补**漂移**。

## 什么时候撤（重要）

失败项在连续几次修补中**不断换位置** = 已经失控。此时立刻回滚：
`git checkout -- <目录>` → 删掉新产生的散件 → 确认工作区干净、门禁回绿。
**不要**提交红色门禁，也不要把烂摊子留给下一次会话。回滚不是失败；留下红门禁才是。

## 用临时脚本批量搬迁的四个硬坑

- **每个替换命中后再打印**：`assert old in t`，或检查 `subn()` 的计数。未命中却打印「已改」
  会让你以为改好了（会很贵：验证和排查都要重来）。
- **heredoc 会吃掉一层反斜杠转义**：要往文件里写 `\n` 这两个字符（不是真换行），用 `chr(92) + "n"` 拼。
- **CRLF 文件**：多行字面量匹配不上，正则行尾写 `\r?$`；读文件用 `io.open(..., newline="")` 保持原样。
- **`git restore` 之后文件仍显示 ` M`**：`core.autocrlf=true` 下这是纯行尾差异。判据是
  `git diff --stat -- <file>` 与 `git diff --ignore-all-space --stat -- <file>` **两次都为空**。
  处理：接受格式化器的结果（它会写成 LF）并在提交里说明"该文件行尾归一"；
  **不要**顺手改 `.gitattributes` 去全局换行尾 —— 影响面太大，要单独决定。
- **结构性删除用行号 + 花括号/缩进配平**比正则稳；每改完一个文件立刻做语法检查。

## 交付纪律

- 门禁全绿才提交，串成一条命令：`check.sh && git commit`（失败就不会走到提交）。
- 提交信息写清：哪个文件去哪、对外契约有没有变、被守卫测试抓到了什么。
- 临时搬迁脚本用完即删。
