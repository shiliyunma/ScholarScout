# 选购调研：把口语指标翻译成料件

用户给「预算 + 优先级指标」（耐用、响应、静音、轻、续航、防水……）要一个买哪款的结论。
这类任务的成败不在搜到多少型号，而在**指标是否落到了可查的件料上**，以及**缺点有没有如实写**。

不适用：盯价告警 → `product-price-monitor`；只查一次现价 → 直接搜；纯参数抄录 → 用户没这个需求。

## Procedure

1. **先写「这东西通常坏在哪」，再找料。** 把品类拆成 3–5 个易损件，然后逐个把指标翻译成可查规格：
   - 耐用 → 易损件的**型号与标称寿命**（例：鼠标 = 左右键微动、滚轮编码器、内置电池；机械键盘 = 轴体/热插拔座、稳定器）
   - 响应 → 上报率/延迟/传感器或芯片等级
   - 完成后自检：每个指标都能指到一个具体型号或数字，指不到就再拆一层。没拆到件料的推荐＝在替营销词背书。

2. **候选走三路检索，写盘累积。** ① `型号 + 拆解/评测`（拿件料和实测）② `型号 + 到手价/促销`（拿价格）③ `品类 + 价位 + 横评`（发现漏掉的选手）。
   目标 3–5 个，覆盖三档：**低价新牌的硬件最强款 / 件料扎实的均衡款 / 大厂保守款**。一次并发 2–3 个查询，失败重试一次；不要一条路走到超时。

3. **核实「分档」，而不是核实「型号」。** 同型号常按版本换料（标准版 / Pro / Max / Ultra 的传感器、微动、回报率都不同）。
   任何参数进表前，先确认它属于用户真会买的那个版本；搜到的参数互相冲突，通常不是有人写错，而是两个版本被混着说。

4. **价格写区间 + 检索时点。** 标「约 X 元」「近期到手 X」，并注明价格随促销波动。不要给一个精确数字当承诺，也不要把官方指导价当成交价。

5. **交付结构固定**（用户要的是结论，不是资料汇编）：
   一句话结论（首选 + 一句为什么）→ 对比表（**列按易损件排，不按营销参数排**）→ 逐款优缺点（**缺点必须写**，含最大风险）→ 避坑清单（为什么不买那几个热门款）→ 「买哪个」编号决策清单 → 来源（可点开的真实 URL）。

6. **落盘 + 短回复。** 完整调研写 Markdown 到桌面，聊天里只给结论、对比表、决策清单和 `MEDIA:` 路径；用户常单字回复，决策项给编号。

## 规矩（每次都要满足）

- **每条推荐至少一条可核实的来源**；核实不了的参数写「未核实」，不写「大概」。
- **大牌 ≠ 耐用**：入门大牌经常压最低档易损件（鼠标 1000 万次微动＝双击通病）。耐用结论必须落在件料型号上，落在品牌上就是错的。
- **标称寿命不是实测寿命**；「结构上不会坏」的方案（如无触点光微动）要同时说明它的手感/不可维修代价。
- **把「省下的钱该花在哪」写出来**：这个价位该加钱买件料，不该加钱买 DPI/灯效/回报率这类用不上的数字。

## Pitfalls

- **AI 聚合页当一手证据。** 什么值得买的「AIGC 文章」、搜索引擎的 AI 摘要只能当线索源，用来发现型号和价格；参数要回拆解文/官网/产品页交叉核对。
- **只写型号不写版本** → 用户下单买到降配版，推荐即失效。商品页常同时挂多个档位。
- **无线设备的电池是最短的板**（内置锂电约 500 次循环 / 3–5 年）。「支持插线当有线用」能把这条降级，写进卖点。
- **电商搜索页对脚本不友好**（302 / 验证页）。别硬刚：用文章站与搜索快照拿型号和价格区间，成交价让用户在自己账号里确认。
- **给了一堆并列候选没有结论** = 把决策成本退回给用户。必须有首选，并说明首选和次选差在哪。
