## Procedure

1. **先读既有文件**（`search_files target='files'` 列 `面试准备\`，读同名主题的那一份）。同一主题已有文件 → **patch 扩展**，不要另起一份；两份记录分叉是最贵的错误（曾差点在 `D:\找工作找工作\` 下另建平行台账目录）。
2. **题库按册写**，单册 500–700 行量级：Java 语言/集合/并发/JVM 一册，Spring/MySQL/Redis/网络/场景题一册。册间用相对路径交叉链接，不抄二遍。
3. **每题固定格式**（他认这个）：编号带模块前缀（J-/S-/M-/R-/N-/D-）+ ⭐必问/🔥高频/🎁加分标记 → **先说这题在考什么、为什么是分水岭** → 口述版答案（30–60 秒，粗体标必须说出口的关键词）→ `⚠️ 坑` / `🔥 追问` / `🎁 加分`。
4. **取舍：语法题可以简，实战题必须厚**——事务失效场景、索引失效、MVCC、synchronized 锁升级、缓存一致性、秒杀/幂等，这些才是拉开差距的地方。
5. **每册末尾放自检清单**（能一口气念出来才算过关），他会拿它复习。
6. **方向类文档**先画分层图（模型层/平台层/应用层/业务层/支撑角色），每个方向固定五栏：做什么 / **典型岗位名（能直接拿去搜索的关键词）** / 技术栈 / 与他的匹配度 / 对应他手上哪个作品；结尾必须给"这份地图怎么用"（怎么搜岗位、按公司类型分流、面试自我定位的一句话模板）。
7. **回执**：文件路径清单（代码块）→ 最关键的分水岭条目（表格）→ 抽样一段实际内容 → 怎么用（3–4 条）→ 结尾给**具体**的下一步选项（抽背模式 / 按公司出专项卷 / 深挖某方向的 JD 差距清单），不要泛泛问"还需要什么"。

## 校招笔试准备（情报 → 全覆盖题库）

**触发**：“去搜索 X 公司笔试的相关信息，放到 `<目录>`，然后总结提炼，寻找类似题型，尽可能覆盖全面”。

完整流程（抓取命令、目录形状、汇总必有的四块、题库标记规则、时间分配表）见 `references/bishi-intel-and-question-bank.md`。三条最容易错的：

- **一手源优先抓牛客**：`nowcoder.com` 搜索页是 SSR，`curl` + Chrome UA 能直接拿到**考生原话**（题型、题量、难度、面试原题）；而搜索引擎查中文短词会把公司名拆成单字、返回字典页，费时且无用。
- **题库每题标 `🔴 真题`（带出处）/ `⚪ 同类题`（自拟补齐）**，混在一起会让他把自拟题当真题背。
- **公司特色题型单独成节**（如“代码填空 + 高精度”“ACM 模式自己处理输入输出”）—— 这类题型推不出来，只能从面经里抄；官方设备硬要求（双机位、页面跳出限制、**选卷＝选岗**）另存 `02-官方要求摘要` 并在回执里只报最容易临时缺的那一两件。

## 技术概念答疑（他问"XX 是什么，帮我快速了解一下"）

按五段骨架答，别写成长篇教程：

1. **一句话定义**，尽量引官方定位原话（如 LangGraph 是"low-level orchestration framework for long-running, stateful agents"）
2. **核心概念表**（3–5 个术语，每个一行说人话）
3. **跟他已有经历对照**——这​段他最买账：把新框架映射到他手写过的东西上（手写过的 ReAct 循环 ≈ LangGraph 的图；RAGLearn ≈ RAG 全链路；KDD Cup 源码精读 ≈ Agent 工程）
4. **学习成本 + 值不值得学**的判断（"你概念都有，换 API 而已，3–4 个晚上"）
5. **一个坑/提醒**（如偏锁现状、网络/DNS 拉不到官方文档时改用 PyPI 页面与 GitHub raw）

## 决策类问题的答法

- **先给一条明确推荐 + 理由**，再给备选。他是照"我建议 X"直接拍板的，列一堆选项反而增加负担。
- 涉及**工作地点、是否要考军校/军队路线、校区距离**这类硬取舍，必须显式摆出来让他拍板，不要默默录入台账。
- **他说"暂时不要"就跳过**，别在下一条回复里换个说法再推一次。
- 未验证的比较别当事实讲：写方向文档时标清"这是行业通用分类框架，不是岗位数量统计"。

## 网申表单材料（项目简述/职责/自我评价/爱好/毕设）

网申表单的栏目是分开的，**别交一段混合文本**：

- **项目简述**＝项目本身：背景/要解决的问题 → 做了什么 → 技术栈 → 规模或成果。**不出现“我”**。
- **项目职责**＝我做了什么：逐条编号，动词开头（独立设计／实现／负责）。两栏各自能独立成立，不重复。
- 每个项目再备一个**合并版**（简述 + 职责连起来），表单只有一个“项目描述”栏时直接粘。
- 每段 150–250 字；另备**一句话版**（约 40 字）应对限字数。
- 同一份材料里同时保留**可阅读版（带符号）与可粘贴版（纯字符）**两份，别只留一份。

### 字符限制（他明确提过“下划线是不可以的”）

粘进表单前必须转成简字符，否则可能判非法或乱码：

| 禁 | 换成 |
|---|---|
| `_`（下划线） | `-` 或直接去掉（`task_11` → `task-11`） |
| `①②③④⑤⑥` | `(1)(2)(3)` |
| `·`（间隔号） | `、` |
| `→`（箭头） | `到` / `，` |
| `｜`（全角竖线） | 换行或 `、` |
| `「」`、`【】` | 去掉，或半角 `[]` |
| `～`、`–`、`—` | `-` |
| `⭐` 等 emoji、`+` 连接词 | 去掉 / 改“配合” |

中文标点（，。；：、）保留。`C++`、`ReActAgent.run()`、`512/128`、GitHub 地址这类技术名词必须留 —— 每个项目**只保留一个可查证的链接/仓库名**。
写完用一个字符白名单脚本自查（只允许：汉字 + 英数 + `，。；：、()/-`），报告剩余非白名单字符再交付。

### 自我评价 / 个人爱好 / 毕设简介

- **自我评价**：成绩（GPA、排名、核心课分）→ 两条能力线（传统工程交付 / AI 应用落地）→ 一句习惯（读源码）→ 一句工作作风。备 260 字完整版 + 120 字精简版。
- **个人爱好**：**不能代编** —— 编了必被追问（“跑了多久？什么水平？”）。只给模板 + 结构示例（运动类=能坚持 / 团队类=能配合 / 技术类=自驱），要求他给真实项 + 具体的量。模板里写清“别直接抄”。
- **毕设简介**：先查他毕设目录里的学校通知（如 `D:\AI+教育毕设毕设\关于开展…毕业设计（论文）工作的通知.doc`）拿真实时间线（申请汇总表截止、**课题汇总表截止**、开题–完成区间）。毕设未开工时只写“方向为…/拟开展…/具体课题正在与导师确认”，**绝不写“已完成/已实现”**；备三版（通用方向 / 带场景 / 最保守），让他选一个字母定稿。

### 三栏材料的两条红线

- **量化数字必须有评测集支撑**才能写（检索命中率、提升百分比这类）；没有就只写**动作**（“把切分参数做成可配置”“逐块排查”），不写百分比。
- **不是他写的代码不能说成他写的**：读源码/复现官方 baseline ≠ 开发；统一口径“通读并复现官方 baseline，正在独立实现最小 Agent”。同理实习经历里没发生的 bug 不编，只讲真实摩擦点（接口契约、分页 SQL、导出字段映射）。
- 材料落 `2-简历\项目与经历-详细简介.md`（**只存本机、不随简历投**）：顶部放“可直接复制”的分栏版，后面接面试准备细节（链路、可深挖点、高频追问、不要说的话、三档表达、待补清单）。

## 官方表格（就业推荐表 / 认定采集表）——先抽规则，未知留空

网申自由文本框之外，还有一类是**官方模板表**（就业推荐表、家庭经济困难认定采集表、奖助学金申请表、三方）。
他本人进系统录入，你交的是**可草写的底稿**。流程：

1. **先看他刚放进目录的原件**（`search_files(target=files, path=<目录>)`）：通知 PDF、官方截图、去年已填副本。**不要凭记忆写字段**。
2. **从官方原文里抄「填写规则」**（不是抄正文）：字数上限、排序方向、时间格式、「没有就填无」、哪些栏是学生填（带 `*`）、哪些是辅导员填（评语/推荐意见）。
   - PDF 有文字层直接 `read_file`；报 OCR 失败就用 PyMuPDF 逐页 `get_text()` + `get_pixmap(dpi=160)` 渲成图再读（脚本交给 `terminal` 跑，`fitz` 不在沙箱解释器里）。
3. **字段从权威源抽**（优先级）：成绩单 PDF → 简历 docx → 已填过的政府/学校表格（身份证号、出生日期、民族、生源地、家庭住址、家长电话）→ 综测测评表（班级、学院全称、体育成绩、有无不及格、**各项加分**）。
   - ⭐ **加分项能反推事实**：「社会工作能力 0 分」= 没有班委/学生会职务 → 职务欄直接填「无」；「大学英语国家考试 18 分」= 四级六级全过；「计算机能力 5 分」= 有计算机等级证。
4. **输出两份 md**：`<表名>-填写信息-<姓名>.md`（已知项按官方格式填好、**未知项留空**并旁附格式提示）+ `<表名>-说明.md`（时间线（谁在哪天做什么）/ 系统菜单路径 / 规则原文摘录 / 避坑 / 签约与解约条款）。
5. **回执只报三件**：还差哪几个空（最多 2–3 个）、每个空一句提示、最硬的截止时间。

### 官方格式里最容易填错的几栏

- **在校职务**：`时间段+职务`、时间**倒序**、**不超过 5 条**、没有就填「无」（不能留空）。
- **奖惩**：`时间+奖项名`、按**国家级→省级→校级→院级**倒序、不超过 5 条、没有填「无」、**有违纪要如实填**。
- **外语/计算机水平**：写「**截至目前已取得证书的等级**」，不是学时或课分。
- **特长爱好**：带等级/名次（“游泳，校级比赛第二名”）；**这栏不能代编**，只给结构与示例让他自己给。

### 三条提交提醒（每次都讲）

① 盖章原件通常**只有 1 份**，先交彩色扫描/复印；② **填错/涂改会作废**，先电子版确认再草写；③ **就业推荐表 ≠ 三方协议**（推荐表只证明应届身份，三方才有法律效力），**网签点「接受」即生效**、多数学校本学期**不受理解约审批**。

## 台账跨文件一致性（改一处漏三处是最常见的错）

三本台账 + 总入口是同一批事实的四个落点，任何一次安排变动都要同步这四处：
已投本主表的**状态与时间列** → 已投本「四、笔面进展」对应行（**每轮面试单独一行**：面种/线上或线下/时长/携带材料）
→ 总入口「八、待办决策」的 ⏰ 行 → 总入口「九、日程」的当日行（连同当日其他场次一起重排冲突）。
改完**回读四处**，确认没留上一次的说法（“一早去”“13:40 现场”这类旧文本最容易残留）。

- 计数：主表**条数按岗位**、**家数按公司**；同一集团的省公司/子公司**按 1 家计**并在计数行括号里注明含哪几个岗位
  （例：中国移动集团含镇江 / 上海 / 浙江 3 个岗位）。改完主表必须同步计数行。
- **行号全库唯一，新号先算再写**：三本册子共用一套行号。查下一个可用号：
  `grep -o "^| [0-9]\+ " 投递台账*.md | tr -d '| ' | sort -n | tail -1` → +1。
  **只看当册最大值一定撞号**（他刚占的号可能落在另一册，或已被「不投」条目占用）；「投出就搬行」＝从待投册**删掉**、在已投册新增，不是两处都留。
- **改表格行：`old_string` 只锚「短唯一片段」**（单元格内容，或行首那段 `\| NN \| 日期 \| 公司名`）。
  ⚠️ **绝不要把「多行整块」当 old_string、却拿更少的行当 new_string** —— 中间那几行会被**静默删掉**，工具不报错、聊天里看不见，一次事故删掉了一条完整的企业记录，只靠当天日志与展板原图才补回来；
  同理，**别把「要保留的行」当 old_string 换成「另一条新行」**（会把原行的 ⏰/待办信息顶掉）。新增行要锚**上一行末尾的片段**再追加 `\n新行`。
  改完必核：`grep -o "^| [0-9]\+ " 投递台账*.md | tr -d '| ' | sort -n | tr '\n' ' '` —— 行号连续、无缺号、没出现两次才算过。
  第二种失败模式是**静默不写**：patch 返回 `no_change / File already contains the target text` ＝ **一个字都没改**（new_string 或它的锚点已是文件里存在的文本，搬行时最容易撞：删掉的那行与相邻行前缀相同）。这时**别原样重发**，换成让 new_string 含**文件里尚不存在**的文本——最省事是把删掉的位置换成一行 HTML 注释 `<!-- #NN 已移至 <册名> -->` 当搬行标记，然后回读行号列确认。
  每批表格改动落地后都核一次行号列；**发现缺号立刻从 `每日进度-YYYY-MM.md` 同日段落把那条企业信息补回**，不要等他自己发现少了一家（他核对得很快）。
- **现场企业的「投递通道」有三态，入库时必须问清并写进「投递方式」列**：
  ① 现场投递即止（无需网申）② 现场投递 **+ 必须再网申**（两条都要做）③ **只收网申**（现场递简历无效）。
  三态判断错要么让他白做一遍网申、要么漏掉网申直接失去资格；不确定就在备注挂 `⏰ 是否需网申待确认`，别默认「投过就算」。
- **学校/第三方就业平台的投递算「低置信通道」，入库时必须显式标注**：91job（南邮就业信息网）上投了≠企业 HR 会看。状态列写「已投（91job，⚠️ 渠道存疑：HR 是否查看未证实）」，并在「八」挂一条：**并行二次触达**（企业官网招聘页 / 微信公众号 / HR 邮箱，邮件标题「姓名+学校+专业+岗位」），把平台那次当「投过」而非「投到」。他本人主动提出过这条并要求特殊标注——不等他提就该做；同时区分「平台状态＝待处理」与「企业已读」，别把平台状态当企业反馈。
- **查企业官网 / 投递入口：HTTP 200 不代表是这家公司**（parked domain 也回 200）→ 抓回页面 `grep '<title>'` 并搜公司名确认，别把 200 当成了。
  企业投递入口的第一顺位永远是**现场问 HR**（顺手要姓名/电话），其次**学校就业信息网**（南邮入口 `http://njupt.91job.org.cn/`，从校主页「就业信息网」链接取得；它是 JS 单页应用抓不到内容，让他登录后按企业名搜）。
- ⏰ 行的生命周期：未完成标 ⏰（写清截止 / 现状态 / **具体怎么做**：入口、通行证号、找谁）
  → 办完改成 `✅ …（已销账）`，**不删行**（留痕）→ 同时把上游备注（未投本 / 主表）里的 ⏰ 一起改掉。
  → **因前提变了而作废的（第三种收尾）**：面试改期使「点邮件接受」不再需要、临时待定时间被正式时间取代、岗位本人决定不投 ——
  改成 `~~时机~~ | ✅ **动作**（已失效） | **无需操作** | 原因`。理由：08:30 晨报会把「八」里所有未销账的 ⏰ 行当成「今日必做」，
  留一条失效动作，他第二天会被催一件根本不用做的事。
  → 岗位/公司名一拿到官方证据（邀约短信、邮件、官网入口）就**回改全库**并注明纠正来源：手记名常与官方名差一两个字，
  同一家公司挂两个名字会让条数/家数计数与去重全错。
- **定时推送失败是静默的**（聊天里什么都不出现，所以他会主动来问「晨报呢」）：先查 `cron/executions.db` 最近几行的
  `status` / `delivery_outcome`，再查 `gateway_state.json` 的 `platforms.qqbot.state`；**立即手动补一份当天内容并说清哪一环失败了**（偶发 vs 通道坏了）。
  完整的排查顺序见 `hermes-qqbot-channel` 的 `references/qqbot-reconnect-recovery.md`。
- 「五、人脉与线下记录」也记**面试邀约邮件/短信里的 HR**（姓名 + 电话 + 邮箱）与“改时间 / 改期要找谁”。
- 有硬日程的日子写 `3-面试\2-投递与计划\明日行程-MMDD.md`：时间表 + 出门清单 + 考前要点，比只在聊天里说一遍可靠。
- 要复用的材料（成绩单、证书）复制一份到工作目录根并起清楚名字；PDF 同时转一份 JPG 到 `2-简历\_render\`
  （打印店 / 只收图的上传框应急用）。
- **秋招之外的事项进同一套提醒**：非秋招事项（毕设/综测/资助认定/学校表单）归 `5-重要事项\重要事项-台账.md`，行号 `M#`；⚠️ **晨报要同时扫两本台账**（秋招「八、待办决策」+ 本文件的 ⏰ 行）并按紧迫度**混排**进「今日必做」——学校硬节点（上报汇总表、系统注册截止）排在赛事跟进之前。新事项落盘时顺手挂一个**一次性提醒 cron**（`schedule` 写 ISO 时间，prompt 只写「直接输出提醒内容」）兜硬截止。
- **推送口径：敏感信息不外扩**：家庭经济困难认定这类只写「还差 N 项待补」，**不写金额、不写病情、不写家庭成员细节**（私聊也可能被截图）；原件留在各自源目录（`D:\大四上\…`、`D:\AI+教育毕设毕设\`），台账只汇总节点与动作。
- **「N 个工作日内」必须换算成具体日期并给阶梯**：先扣掉假期（中秋 9/25–27、国庆 10/1–7 这类），再数工作日 → 「最迟 X 日 → 未果则节后第一个工作日主动催 → 再一周收尾」，写进已投本「下次跟进」列 + 总入口「八」的 ⏰ 行。**把假期当工作日**会让他提前空催或晚一天才发现被晾着。跟 HR 催进度的话术要带上「面试岗位 + 面试日期 + 提醒对方自己说过的时间」。面试后等结果期间**该投的照投**：面试完成 ≠ 落袋。
- **一天里多场招聘会撞车时，回执要带「几点脱身、几点回」的时序**，不能只列场次。判据：本校/零通勤 > 能现场面试或发直通卡 > 方向对口 > 距离；并**避开当晚已有的硬时间**（如 19:00 线上集中测评、20:30 前必须登录），让他下午就把校外场收掉。
- **本校场次优先汇总**：学校就业办公众号与学院群的**同日多场**信息常散在不同消息里；处理一批消息时顺手把当天与次日**所有校内场次**并成一行，别只处理他正在看的那条 —— 漏一场本校招聘会的代价远大于漏一条推文。

## Pitfalls

- **一次只给 `vision_analyze` 加载 1–2 张图**。一个回合批量丢 4 张，会有图在进上下文前被丢弃（提示 removed to save context），表现为"图我读过却想不起来"。长图/海报单独一次调用，先看整体，再按 `region` 放大看小字。
- **读图里的门槛条件必须实读，不能猜**：学历层次、专业目录限制常藏在小字里，猜错会把他导向投不进去的岗位。
- **不吹规模、不替他编经历**。写题库可以给话术模板，但凡"他做过的"必须有细节支撑，"别人的活"要写清是谁做的——他上次压力面就是靠"我读的"这种诚实度拿分的。
- **产品/市场岗不要一刀切否掉**：同一位同学在"AI 产品/解决方案/售前"这条线的匹配度往往比算法岗高，要作为正经方向列出来让他自己选。
- **同一集团可能「一省一岗」互斥**：中国移动实测**一个省只能报一个岗位**，投了江苏（镇江）就覆盖掉苏州。集团类（运营商/银行/央企）多城市多岗位时**先问清申报规则再录**，已作废的标 `❌ 已由 #NN 覆盖` 并从待投队列里拿掉。
  中国联通实测**最多 2 家单位、每家最多 2 个方向；网申＝1 份统一申请 + N 个志愿，志愿顺序＝优先级**。拿到规则就写进总入口「七、硬门槛自查」+ 回改相关行号备注，并当场判断**是否已占满额度**（占满后看到更好的单位也不能投）；提醒他**现场交的纸质简历不占额度**，但顺序一旦随网申提交就不可改，填前先让他拍板。
- **他说「不投」要联动两处**：未投本移进「不投」清单**并且**把总入口「九、日程」对应场次划掉 —— 否则晨报和日程会继续推荐它，他得再纠正你一次。
- **聊天里的图片/通知截图带 `rkey`，几小时后失效**（下载成功但文件只有几十字节 = 空壳）→ 要留档就第一时间下载；拿不到就让他从群里重新保存后**单张直发**，不要用合并转发的聊天记录卡片（`attachments=None`、正文空）。
- **招聘会展板照片的固定处理流程**（他现场拍一张发一张）：`cp` 到 `1-情报\群消息与招聘会-MMDD\原图\MMDD-公司-展板.jpg` → 解析入台账（已投就进已投本、否则未投本；**行号全库接续**，别只看当册最大值，否则撞号）→ 同日 `每日进度` 的「新情报」段补一条 → 回执固定给四件：**本科可投的岗位 / 学历硬门槛 / 投递通道（现场即止 · 现场+网申 · 只收网申）/ 与他方向的对口点与风险**。⚠️ 展板「学历要求」列必须逐字读，但**写的学历不等于实际门槛**：实测同一场里既有 AI/大模型岗标「硕士」而本科递了也收、也有标本科实际只能投市场岗的 —— 读到的写进备注，**拿不准就让他现场问一句再定优先级**。
    - **展板印的邮箱/网址先做 DNS 校验再用**：`socket.gethostbyname(域名)` 一秒钟的事 —— 实测两家展板印的邮箱域名（`beyondcent.com`、`miwel.cc`）**解析失败（域名根本不存在）**，照抄发信＝寄给空气；`.com` 能解析也不代表是这家（可能只是 parked 页；`bocloud.cn` 实测是**另一家公司**的站）。探不通就让他走现场扫码/官方公众号，别让他照抄印刷品上的邮箱。
  - **现场 HR 口径 > 展板口径**：冲突时以现场为准，并在备注里写明「以现场为准」。实测博云展板写 AI 开发在苏州/深圳/南京，HR 现场说的是 **AI 开发主要在杭州、FDE 主要在南京** —— 按错口径排优先级，他会跑去一个没有坑位的城市。
  - **展板的「年份」字样也要读**：写「**2026** 校园招聘」而非「2027 届」的，很可能是**上一届遗留的旧展板** → 挂「是否面向 2027 届待确认」，别默认有效。
  - **现场面试被问到的题当场落盘**（公司未确认也照落）：`3-面试\1-面试准备\面试真题-MMDD-<主题>.md`，标「公司待确认」，并按他的规矩出 **1 原题 + 2 延伸**；带一条「本人当时怎么答的（原话）」待补项，用于判分与改写。
  ⚠️ **来源里没有的字段一律写「待确认」，绝不用岗位名/行业去推断补齐**：一条「学历要求」列没显示的岗位被补成「标硕士」，会直接把这条排到低优先级、还会让他按错的信息去问 HR。学到的口径是：**只写自己真读到的字段**（他也会替你抓这个错）。
