# Bullet 改写对照表

每条的判断标准：**读者能不能从中看出「解决了什么问题、指标动了多少」**。只有「我做了什么」的一律重写。

## 1. 弱化词 → 强动词

| 弱（删） | 强（改） |
|---|---|
| 参与、协助、负责、帮忙 | 设计、实现、搭建、独立完成 |
| 组员、成员、开发人员 | 项目名 + 技术栈写在标题上 |
| 使用 X 完成了 Y | 基于 X 实现 Y，[量化收益] |
| 学习并使用了 X | 在真实系统里落地 X（有产出才写） |

**头衔本身就是权重**。写「组员」等于主动降权。

## 2. 空话清单（直接删，不加分只占版面）

学习能力强、抗压能力好、团队协作、有责任心、对技术有热情、喜欢看书/打羽毛球/听音乐。

自我评价只保留 **1–3 行能力结论 + 一条差异化事实**，例如「已独立完成并开源一套 RAG 系统，习惯用消融实验
而非感觉驱动调优」。

## 3. 「做了什么」→「解决了什么问题、指标动了多少」

原文：
> 实现了文档切分与检索功能

改写：
> 针对「小切块语义不全、大切块检索不准」的矛盾，设计偏移映射双层切分方案：child 块（512 字符 / 128 重叠）
> 全文连续滑窗用于向量检索，parent 块（2000 字符语义段落）送入 LLM。相较按父块切子块的朴素方案消除尾部废块，
> 块总数由 7,600 降至 4,269（**-44%**），入库由超时变为稳定。

模式：**矛盾/约束 → 方案 → 可验证的数字**。数字可以来自块数、耗时、条数、体积、轮次、延迟——不一定是精度。

## 4. 排序：亮点提前

功能条目躺在第 6、7 条会被跳过。按**目标岗位的必看项**重排，不是按开发顺序：

- 投 Agent 岗：把「自适应检索决策（省调用）」「多轮记忆管理（8 轮 FIFO）」「双模式意图路由」提到第 2–4 条。
- 投后端岗：把「后端服务搭建」「表结构设计与索引优化」提到前面，RAG 项目压到 3–4 条。
- 「已开源」「有消融开关」「全链路日志可回溯」这类工程素养证据，永远比功能列表有效。

## 5. 数字从哪来（不许编）

可安全量化的自有指标：文件数 / 字数、切块数、入库耗时、检索延迟、用户感知等待、日志条数、索引条数、
清洗前后体积、消融开关个数、对话轮次窗口。

### 5.1 先分清：过程指标 vs 结果指标

| | 例子 | 它能证明什么 | 能不能当亮点写 |
|---|---|---|---|
| **过程指标** | 块数 7,600→4,269、清洗压缩 24%、文件数、耗时 | 「我的流程/代码改过了」 | 只能作为**做法描述**，不能挨着质量宣称写 |
| **结果指标** | Top-5 命中率、准确率、召回率、延迟、错误率、重试率 | 「效果/体验变好了」 | 可以，且是简历上最值钱的数字 |

**这是简历里最常见、也最容易被问穿的一类错**：把过程指标排在技术栈旁边，读者的眼睛会自动把它读成
「质量提升了 X%」。面试官一追「你做过对照吗」，没有就是夸大定性——**不是用户想说谎，是他的数字说了
他没打算说的话**。发现时**当场点破**，并给下面的处理办法。

### 5.2 每个数字配一张「自证三栏卡」

写进简历前逐条填满，填不出就不留：

1. **怎么测的**——分子是什么、分母是什么、样本从哪来、谁判定
2. **对照是什么**——跟哪个版本/方案比，还是只有改后值
3. **结论是什么**——数字动了多少、方向对不对

三栏齐 → 留，且面试时主动说测法。任一栏空 → 走 5.3。

### 5.3 没测过的数字：三选一，别硬留

按优先级：

1. **花 30–60 分钟补最小对照实验，升级成结果指标**（性价比最高，首选）；
2. **降级成动作描述**——把「块数 -44%」改成「把碎块合并成语义更完整的块」；
3. **删掉**。

**撤一个数字的成本，远低于被问穿的代价。**

### 5.4 最小对照实验配方（把过程指标变成结果指标）

适用场景：改了检索/切分/清洗逻辑，只有过程指标，没有质量指标。

1. 从项目自己的语料里出 **20–30 个问题**，每题**人工写好标准出处**（哪一段是正确答案）；
2. **改动前的旧索引 / 改动后的新索引各跑一遍**，同一批问题、同一套参数；
3. 判定 **Top-5 里有没有命中标准出处**，算命中率；
4. 结果写成 **「Top-5 命中率 68% → 82%，块数 7,600 → 4,269」**——过程指标与结果指标并列才成立。

同法可套：切分方案前后、重排开/关、查询改写开/关、清洗规则前后。

### 5.5 无法定义分子分母的指标，一律不留

凡答不出「分子是什么、分母是什么、样本怎么来的」的百分比（典型：`边界误差 <1%`），**不能留在简历上**。
两种处理：

- **要留 → 必须能定义**：分子＝边界归属错误的块数、分母＝抽检的边界样本总数、样本＝人工抽检 N 处跨段边界。
- **要删 → 换成可验证的做法描述**：如「跨段边界采用偏移映射对齐，已人工抽检 N 处」——**从结果宣称降级为
  做法描述，风险归零**。

### 5.6 要用但还没测的（命中率、准确率、QPS）

**先别写数字**，写「自建 N 题评测集」这种可交付的说法，并列入待补清单。

### 5.7 真实但规模小的数字，同样是负债

判定标准不是「是不是真的」，而是「**它会不会引出候选人答不上的追问**」。

典型：「最大表几万条记录」——真、可考，但招两刀：

1. 「几万条？那这套 SQL 面对百万级还行吗？」——没做过大数据量，答不上；
2. 「这个量级连索引优劣都感觉不出来，你写的'索引定义'是怎么验的？」——于是「索引」两个字变空话。

处理：**只写动作，不写规模**——「设计 10 余张表并完成表结构与索引定义」。规模问题留到面试口答，
老实说「数据量不大，几万条量级，索引是按查询路径按需建的，没做过大数据量压测」——**这是加分（知边界）**，
写进简历再被追着问才是失分。

### 5.8 没有 bug、没有难点的经历怎么写

用户答「整体顺利，没有明显 bug」时：

- **简历里不要出现「针对 X 问题…」**——没有这个 X 就不要造，属于 5.1 同源风险（自证不了的宣称）。
- 改写成**纯交付叙述**：独立承担的范围 + 接口/表的规模（数量级可写，规模量级不写，见 5.7）+ 交付动作
  （联调、以真值基准比对校验、提测）。
- 「这段实习里最难的点是什么？」是必问题，答不出会被读成「只会按部就班写 CRUD」。**不要编 bug**，从真实
  摩擦里挑一个：前后端字段格式约定、多表关联分页 SQL 返工、导出字段名映射易漏、页面与库里数值对不上是取数口径差异。
  一个都对不上就说「确实没有难点，更多是按迭代稳定交付」——也比硬编强。
- **这类补偿内容只用于面试口答，不进简历。** 写进去就变成又一个自证不了的宣称。

## 6. 落差表述模板

当用户的经历只到「读懂 / 复现」时：

> 这一栏现在的作用是让面试官知道**你看得懂源码**——这已经超过多数候选人。但它撑不起「独立做过 X」。
> 面试官必问：「所以你改了什么？」
>
> 最小可行解法：在 baseline 上做**任意一处真实改动**（半天 ~ 几天），然后据实写进简历。

据实写「复现 / 精读」+ 给补强方案，比拔高成「自研」安全得多，而且用户会照做。
