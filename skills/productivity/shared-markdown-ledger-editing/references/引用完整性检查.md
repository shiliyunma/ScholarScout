# 引用完整性检查（工作台体检）

触发：对方说「检查链接」；刚搬动/改名过文件；或例行体检。
交付是一份**报告**（真断链 / 假阳性 / 设计上已失效 分开列），不是一句「都正常」。

## 一、外链可达性

```bash
: > "$LOCALAPPDATA/Temp/urlout.txt"
for u in $URLS; do
  code=$(curl -sS -o "$LOCALAPPDATA/Temp/urlout.txt" -w "%{http_code}" -L --max-time 15 \
    -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/124 Safari/537.36" "$u")
  printf "%-5s %s\n" "$code" "$u"
done
```

- **MSYS git-bash 下 `-o /dev/null` 会报 `curl: (23) client returned ERROR on write of N bytes`** → 输出一律写临时文件，否则满屏假失败。
- **抓 URL 的正则会吞进 markdown 粗体 `**` 与中文括号** → 把尾随字符剥掉裸测一遍再下结论（实测过半「故障」是这么来的）。
- 跟随重定向（`-L`）后再判码；很多校招/招聘链接常态就是 302。
- 交付时**点明对方当下要用的那几条**（笔试入口 / 面试入口 / 网申入口）是什么状态 —— 这才是他问「检查链接」时真正想看的东西。

## 二、文档内部路径引用

解析顺序（必须按这个顺序，否则假阳性淹没真问题）：

1. 抽反引号里的**路径型 token**；
2. 先按**相对各根目录的精确路径**匹配；
3. 不中就按 **basename 在 `os.walk` 索引里找唯一命中**；
4. 多命中 → 判歧义；零命中 → 才判断链。

**判「文件不存在」前先排除这些非路径**：纯文件名（`analyze.ts`）、光扩展名（`.ts`）、URL 路由（`/llms.txt`、`/feed.xml`）、glob（`rules-*.md`）、占位符（`<当月>`）、shell 命令（`python check.py`）。不排除一次能刷出上百条假阳性（实测 145 条里只有 4 条真断）。

- 带 `:行号` 的锚点做**双重校验**：文件存在 **且** 行号 ≤ 该文件实际行数。行号最难维护，任何改动后都要复核。
- **归档目录里的备份会让 basename 重名** → 歧义时优先取非归档的那份。
- **行数用脚本累加，不要 `find | xargs wc -l | tail -1`**：xargs 会分批，`tail -1` 只看到最后一批（实测得到 5923，真实值 52501）。
- **`wc -l` 返回换行符数**：无尾换行的单行文件返回 0（要用字节数描述）；一份 6 个换行的长文本 prompt 也不是「只有 6 行」。

## 三、cron 任务与推送链路

| 字段 | 校验 |
|---|---|
| `script` | 相对 `~/AppData/Local/hermes/scripts/`，必须存在 |
| `workdir` | 必须是存在的目录 |
| `prompt` | 把所有写死的文件路径抽出来逐个 `os.path.exists` |

- **月份文件名是头号杀手**：prompt 写死 `YYYY-MM`，跨月那天就会把当月内容写进上个月的文件。改法是让 prompt 第 0 步跑 `date +%Y-%m` 再拼文件名；改完**复扫一遍确认无旧月份残留**（残留出现在「说明这条坑」的句子里是预期的）。
- 用 `cronjob_manage action=list` 看 `last_status` / `last_error` / `last_delivery_error` —— 任务「跑过」不等于「成功」；失败要区分是**模型不可达**还是**投递失败**。
- 查 `hermes gateway status`：gateway 停着时 cron **一个都不会触发**，这是「推送链路断了」的最高优先级信号。
- 代理/网关类进程从 agent 的 shell 里启动会在宿主 Job Object 退出时被一并杀掉 → 让**本人在普通终端**里启动（或双击启动项）。

## 修复纪律

- 改前 `cp` 到 `_归档\备份-<MMDD>-断链修复\`；改后**复扫一遍**确认正文零残留（备份文件里当然还有旧串，属预期）。
- **同音字是断链主因**：改名前先 `ls` 确认真实文件名，别凭记忆（中文公司名尤其容易错）。
- **发现重复落盘时先逐字比对再删**：误放的小节若与正确文件里的同名小节**去掉空白后完全一致**，才可以删；不一致就保留并报告差异，不擅自合并。
- 批量修复用「脚本 + 每处断言」：`assert t.count(old) == 1`，比连续 `patch` 安全。
