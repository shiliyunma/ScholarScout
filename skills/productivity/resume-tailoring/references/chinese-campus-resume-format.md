# 应届生中文简历：格式与投递规范

适用：在校生 / 应届生投校招或实习的中文简历。

## 篇幅

- 本科生 **严格 1 页**。内容压不进 1 页时，砍项目 bullet 数量（保留：架构/开源、最有技术含量的取舍、量化指标最好的、工程化可验证性），不要缩字号。
- 实习简历同样 1 页；工作 3 年以上才考虑 2 页。

## 版式

- 正文字体：宋体 / 思源宋体 **10.5pt**；板块标题加粗、可略大；行距 **1.15**
- 强调色 **只用一种**（深蓝或深灰）。全文不要彩色标题块、不要渐变。
- 一律左对齐；模块之间用留白分隔，不要横向分割线花样、不要图标装饰。
- 不用表格边框（技能表尤其容易变成格子，视觉噪音大）；用「标签：内容」的行式写法。
- 不贴照片、不写籍贯/政治面貌/期望薪资/兴趣爱好。

## 文件命名

HR 批量下载后会靠文件名认人，这是实打实的加分项：

- ✅ `姓名-学校-岗位.pdf`（如 `张思浩-南京邮电大学-AI Agent开发.pdf`）
- ❌ `简历.pdf`、`最终版.pdf`、`简历-改-3.docx`、纯学号命名的文件
- 学校名对本科生是加分项（对本地 HR 有辨识度的校名），一定带上。

## 各板块写法

| 板块 | 要点 |
|---|---|
| 个人信息 | 姓名 + **求职意向**（方向要具体到岗，不写「软件工程师」这种泛称）+ 出生年月 + 现居 + 电话 + 邮箱 + GitHub |
| 个人简介 | 3 行以内，一句话把**差异化**钉住（「会 X 的 Y 专业本科生」）。HR 初筛约 6 秒/份，这一栏决定他读不读下去 |
| 教育背景 | 学校 + 专业 + 起止时间 + 核心课程（分组、只留硬课）+ GPA/排名。**有排名优先写排名**；GPA 低于 3.0 就别写 |
| 项目经历 | 技术栈单独一行；bullet 用「问题→方案→量化结果」；最强的项目放第一个 |
| 实习经历 | 动词用搭建/设计/实现，不用「参与」「协助」；能提指标就提（QPS、耗时、覆盖率） |
| 专业技能 | **按目标岗位相关度排序**，第一行就是你的定位。技能写具体（库名/模型名/机制名），不写「熟悉计算机基础知识」 |
| 荣誉证书 | 只写有级别的（省/国家/校级）；重复记录合并 |
| 自我评价 | ≤3 行，只写能力结论 + 工程习惯。可以用「用数据/消融实验验证方案，而不是凭感觉调参」这类可验证的表态代替形容词 |

## 投递时的三种变体

同一份素材要能快速切三个版本，切换点如下：

| 目标方向 | 项目配比 | 技能栏首位 |
|---|---|---|
| 大模型应用 / Agent | 项目为主，后端经历压到 2–3 行 | LLM Agent / RAG |
| 纯后端 | 实习/后端项目展开为完整项目，算法类项目压到 3–4 条 | 语言 + 框架 |
| 算法岗 | 需要模型训练/评估指标的经历，纯工程项目不够 | 框架 + 模型 |

**先说方向再出稿。** 方向没定就出稿，等于三个方向都不及格。

## 面试预判问题（写简历时同步生成）

按板块生成，写进附件给用户提前准备。三类必出：

1. **项目深挖类** —— 每个量化数字都会被追：「这个指标怎么来的？」「为什么选 A 不选 B？」「换方案会怎样？」「做过消融对比吗？」
   简历里写了数字，就必须在附件里给对应的答案要点。
2. **取舍 / 被否方案类** —— 「为什么不用现成框架 X？」如果项目有决策日志（decision-log 之类），把「被否掉的方案 + 原因」单独列出来，这是最容易加分的回答。
3. **诚实兜底类** —— 「哪部分没落地？」「这个功能在生产上跑过吗？」
   在附件里明确列出「哪些别吹」（在路线图上但未实现的、只是复现 baseline 的），并给出据实回答的措辞。

## 投递渠道备注

- 内推 > 官网 > 招聘平台（平台 HR 初筛最容易卡学校/专业关键词，所以简历里的关键词要覆盖 JD 原词）
- 简历里的技术名词尽量与目标岗位 JD 的用词一致（JD 写「工具调用」就别只写「函数调用」），这是关键词匹配，不是虚饰
- 开源项目：把仓库链接放首行个人信息处 + 项目栏各出现一次；仓库本身的质量（README 截图、LICENSE、wiki）决定这行的价值
