# 高校学生资助 / 家庭经济困难认定材料办理

每年秋季学校下发一批附件（江苏省口径）：附件1 家庭经济信息采集表、附件2 可提供证件材料说明、
附件3 认定暨国家教育资助申请表、附件4 系统操作指南、附件5 学院录入的特殊困难学生名单、
附件6 民主评议表。通知正文常在群里，zip 里往往只有附件。

## 触发

- 学校下发“家庭经济困难认定”“学生资助”通知及附件，要求填表。
- 要申请国家助学金、减免学费、生源地助学贷款，需要先拿认定等级。

## 第一原则：先抬高认定等级的依据，再谈填表

认定等级（特别困难 / 比较困难 / 一般困难）来自两条路：

1. **系统可比对的特殊困难类型**（低保、建档立卡/脱贫、残疾、孤儿/困境儿童、特困救助供养、优抚对象子女）。
2. **民主评议加分**。民主评议表里“申请平台未识别出的特殊困难类型，凭证明”最多加 100 分，而“在校生活困难”“家庭经济状况复杂”两项各自上限只有 20 分。

所以：家里有大病致残、长期治疗致贫的，先推动去办**低保证、残疾人证**（民政、残联），这比在“其他类 / 家庭遭受突发意外事件”里反复写说明有效得多。每学年开头先问清这两证是否有、能否拍照片。

但**不要打包票**：若家里只有“残疾人子女 + 大病致残”这类平台比对不上的依据，能走的是民主评议那 100 分栏，
现实区间是“比较困难基本有把握、特别困难要争”，如实说明，别承诺等级。

**家庭类型一律按官方栏目名确认，不要采信口语概括**。用户说“家里办了那个补助”，实际可能是低保，
也可能是**病退/退休**，也可能是残疾两项补贴（困难残疾人生活补贴、重度残疾人护理补贴）。
“病退”（因病丧失劳动能力、经人社部门审批提前退休）**不是**家庭类型，但病退金/养老金**是收入**，
必须填进“平均月收入 / 年收入”栏；写了“无工作”就顺手写“无收入”是填报硬伤（系统与往年数据一比就露）。
确认时把官方栏目名念给他勾选，据此落笔，别等他事后纠正——本类表一旦按错类型生成，附件1、附件3、
情况说明三份都要重做。

## 流程

1. **通读目录全部附件**：`ls -la` + `read_file` 直接读 docx/doc/pdf/xlsx（自动抽取文本）；表格结构问题另按
   `references/docx-form-filling.md` 用 python-docx dump。
2. **找去年的归档当“数据基线”**：往年目录通常在同盘另一学年目录下（例如 `D:/Junior/经济困难认定/`）。
   若往年附件1/附件3 文件明显比空模板大，说明是已填版——里面有全家的身份证号、年龄、收入、户籍、既往填报口径，
   是最高价值的上下文，也顺带给出每个字段在表里的准确坐标（省掉一轮试写）。
   **但它是数据来源，不是交付底稿**：交付文件必须从本学年空白模板复制副本再填（见第 5 步）。
   直接交去年那份改出来的文件，会残留上一学年的勾选、年级、日期，用户看不出错。
3. **用 clarify 批量问 5 个以内的关键事实**（编号选项，用户常单字回）：父亲当前状态（住院/已出院卧床）、母亲有无收入、
   家庭人口数、手上已有哪些证明材料、本学年申请哪些资助项目。只问会改变填写的字段，能沿用往年的一律沿用并告知。
4. **定材料清单**：按附件2 说明逐条对齐——大病→疾病诊断证明/病历；伤残→残疾人证/伤残鉴定书；低保→低保证或低保金银行流水；
   建档立卡→扶贫手册；收入→家庭主要成员收入情况说明；确实无法提供证件→学生本人与家长共同书面承诺。
   系统比对一致的证件可免交，但仍让用户先拍好备用。
   补两类往年漏掉的高价值材料：**病退→劳动能力鉴定结论通知书、退休审批表或退休证**（“完全丧失劳动能力”的
   官方结论，比病历更有力）；**住院→住院记录、出院小结**（才能证明已出院在家卧床、需常年照料，单纯诊断证明
   说明不了照料负担）。
5. **产出并给路径**，形态与顺序固定（用户明确要求过，别换花样）：
   (a) 先写《认定信息汇总》md：学生信息、家庭成员表、致困原因、量化信息、家庭类型判定、材料清单、待核实事项。
       网上填报照它录，也是他自己核对的口径；
   (b) 从**本学年空白模板**各复制一份副本再填，命名 `副本—附件1：…（姓名·已填写）.docx`，原始空白模板不动；
   (c) 一页《家庭经济困难情况说明》（客观、可核验、不煽情）；
   (d) 一份《办理清单》md；被替代的中间稿一律移到 `_tools/旧稿-…/`，
       保证交付目录里每个表只有一个候选文件——留两份草稿他就会交错。
   附件5 是学院填的（含 建档立卡 / 低收入 / 残疾 / 困境儿童 / 特困救助供养 / 其他 六个工作表），用户的动作是提醒辅导员按真实困难类型上报：
   低保家庭走“低收入”表，**父母残疾的“残疾人子女”走“其他”表**（“残疾”表只放学生本人残疾，放错等于白报），
   并让辅导员在名单上写明父亲病退、完全丧失劳动能力等情况；不要沿用往年的“其他类”。
   生成《家庭经济困难情况说明》时用 `templates/情况说明-框架.md` 的分节骨架；文件里留下的空（养老金、负债数额）
   必须同时写进办理清单的“提交前必须自己补”一栏，不能只留在文档里。
6. **说清“交给谁、什么时候”**：不要只回“填好了”。同时提醒：认定表内不勾助学贷款，贷款另走生源地助学贷款系统续贷；
   助学金在省资助申请平台申请；认定等级和资助项目是两件事，先拿等级再分别申请。

## 一致性核对（必做，逐字段比对去年）

- 逐年填报前，把去年同一字段拉出来对比：**负债区间、人均年收入、赡养老人勾选、私家车、家庭人口**。
  数据在系统里留痕，前后矛盾会被辅导员追问。发现不一致时回问用户哪版属实，不要自己挑一个。
- “赡养老人生活费支出”必须与家庭人口自洽：勾了赡养支出就要有祖辈计入人口（或去掉勾选）。
- 人均年收入要能和成员收入自洽：家里有人打零工，就不能同一张表上又写“无收入”又写固定人均数。
- 采集表的“残疾”指**学生本人**（系统比对残疾人库）；父母的残疾填在“其他情况”和认定表的“残疾人子女”栏，勾错比对不上。

## 交付偏好（该用户）

- **先讲流程，再抠细节**。他要的是“我要交什么、交给谁、卡在哪”。字体、符号编码、渲染这类技术细节自己后台
  解决，不要拉着过程讲，他会直接打断要求“讲流程”。拿到能用的结论即止，不要为同一个细节换几个工具反复验证。
- 凡是能改变他要去办的事的判断（能否从“比较困难”升到“特别困难”、要不要去办残疾证/低保），第一时间单独抛出来。
- 提问给编号或字母选项；表格与网申文本用纯字符，不用下划线、emoji、①②、→、｜、「」。
- 重要产出落成文件给路径（docx 供打印，md 供他自己操作）。
