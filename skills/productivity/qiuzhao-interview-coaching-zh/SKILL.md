# 求职面试训练与 HR 沟通（大浩）

为大浩（南邮软件工程，2027 届本科，目标 AI 应用/大模型应用开发）编面试材料、抽背验收、准备向 HR 提问。
只覆盖面试与沟通这一半；消息入库与排期在 `qiuzhao-ledger-zh`。

## When to Use

- “java 校招常见问题”“帮我快速了解 X”“抽背”“开始吧”
- 从招聘会/宣讲会回来要整理现场信息、准备给 HR/老师发问题
- 要为某家公司/某个方向做面试准备或技能差距清单

## 铁律一：难度分层（最重要）

他的池子是「**南京 ＋ 苏州 ＋ 杭州 ＋ 上海**（本人 2026-10-15 明确放宽，**不再只限南京与苏南**）＋ 国企/运营商 ＋ 外包，加 AI 应用方向的公司（含大厂与游戏公司）」，
技术面**停在校园招聘基础难度**。所以：

- ⚠️ **城市放宽会改岗位优先级**：此前因「base 不在南京」被压下去的岗位要**升回可投**（实测两家：宇视科技研发全在杭州、远光软件工作地含杭州/上海但**无南京**）。反过来「无南京」不再是排除理由，**只有落在这四城之外才是**。排序、待投队列、宣讲会取舍都按四城范围重算。

- 默认先给基础层：`D:\找工作找工作\4-刷题\Java校招面试题库-0-基础版.md`（84 题，校园面主体考察范围；**三册题库都在 `4-刷题\` 根目录**，不在 `1-面试准备\`）。
- ⚠️ **工作台已改成五模块**（`1-情报` / `2-简历` / `3-面试` / `4-刷题` / **`5-重要事项`**＝非秋招事项：毕设、综测、资助认定、学校表单），本 skill 里凡是 `D:\找工作找工作\面试准备\…`
  或根目录台账的**老路径都是过期的**，按此映射读：题库/问答稿/问HR清单/压力面记录 → `3-面试\1-面试准备\`；
  三本投递台账与每日进度 → `3-面试\` 根目录；机试真题与错题重练 → `4-刷题\机试-MMDD\`。
- 进阶内容（锁升级、AQS、MVCC ReadView、三级缓存为什么是三级、GC 收集器选型、深分页优化这类）**必须先标注「大厂/进阶，不用背」再给**，并且放在单独文件里。
- 基础题的口述答案控在 **15–30 秒**；超过就是社招口径。
- 他明确反对把社招深度的题当校招题交付（“我要的是校招常见问题，应该是在基础难度”）。
  自作主张上深水区 = 一次白做的交付。先问“面试方是什么级别”再定深浅。

| 层 | 文件 | 何时给 |

| 基础 | `Java校招面试题库-0-基础版.md` | 默认 |
| 进阶 | `-1-语言与并发.md` / `-2-框架与中间件.md`（头部已标“不用背”） | 明确要大厂深度时 |

## 铁律二：抽背协议

- **一轮 5–6 题**，分模块推进：Java 基础 → 集合 → 并发+JVM → Spring/MySQL → Redis/网络/HR。绝不一欠抛完几十题。
- 出题时写明规则：**答不出写「不会」，别编**——抽背的价值是暴露漏洞，不是背答案。
  ⚠️ **但规则只说一次**：同一场考试／同一轮系列在第一轮讲清即可，**之后每条出题消息只留干净题面**（判分那几条＝判分＋机制＋追打题），别每轮复读「按编号短答 / 不会就写不会 / 我逐题判分 / 错的考点追打 3 题，全对才进下一轮」，也别把落盘路径、备选玩法（要不要改做整套自测卷）这类旁白挂在每条题目后面——他为此直接制止过：「答题机制你可以不用每次都讲，最好每次只留下干净的题目」。**下一轮原题预告属于有用信息，保留**。
- 判分三档：✅ 满分 / ⚠️ 半对（先肯定答对的部分，再点名缺的那半）/ ❌ 不会。
- 每题补：**口述版标准答案**（15–30 秒）+ **1–2 个追问坑**。
  例：`Integer` 缓存 -128~127；`equals` 的“默认就是 ==，String/包装类重写后比内容”；
  `sleep` 不释放锁而 `wait` 释放；`@Transactional` 失效三条。
- 他答完就**继续下一题**，不要替他把剩下的题一道答完；一轮结束再开新一轮。
- 弱项累记：哪个模块反复半对，下轮先抽那个模块。
- **抽背对象也可以是“他自己简历上的句子”**：他说「帮我熟悉熟悉简历」「抽一下简历」时，**不要讲简历**，直接拿最新版简历的 bullet 原文当题干（“你写‘由模型返回驱动工具调用与结果回填’，讲清这个循环怎么转、靠什么信号分岔、什么条件下停”），一轮仍 1 原题 + 2 延伸（机制 → 边界/剪裁 → 兜底与闭环）。考的是**能不能幂住三层追问**，不是背得出来。优先抽那种“简历上写了但代码里可能没有”的句子，它会当场暴露需降级的措辞。

## 铁律三：向 HR 提问分三个时机

| 时机 | 只问这类 |
|---|---|
| 初筛（现场/微信/电话） | 合同主体与是否外包驻场、工作地点会不会变、定岗还是按需分配、后续流程与时间节点、薪资范围 |
| 面试反复 | 团队人数、技术负责人背景、技术栈、有没有 mentor、日常与忙季节奏 |
| Offer 阶段 | 薪资结构明细（底薪/绩效/年终奖各占多少）、五险一金基数与比例、试用期时长与折扣、培训服务期与违约金、调薪晋升 |

**主观问题 → 客观问题（不转就只拿到官话）**

| 别问 | 改问 |
|---|---|
| 加班多吗 | 上个月平均每周加班几次？加班有调休还是加班费？忙季是哪几个月？ |
| 有没有试用期 | 试用期几个月？薪资打几折？转正率多少？ |
| 出差多吗 | 频率多少？长期驻客户现场算不算出差？有补贴吗？ |
| 能学到东西吗 | 团队几个人？技术负责人什么背景？前三个月具体做什么？ |

**别问**：要不要加班 / 能不能不加班·远程·少出差 / 公司稳不稳定 / 我多久能涨薪。
初筛只问薪资**范围**，明细留到 offer；过早问细节会把话题从“你合不合适”变成“你贵不贵”。

**他目标公司的两个高发坑**

1. **人力外包公司**（人服合资类）→ 必问“自研项目组还是外包驻场、劳动合同签哪个主体”；JD 写得再对口也可能是驻客户现场。
2. **带脱产培训的岗位**（如对日外包）→ 必问“培训期间薪资怎么算、有没有服务期或违约金”；口头承诺不算，要书面条款。

**中小公司 / 「实习转正」岗的尽调五问**（拿到面试或口头意向就要问，别等 offer）

1. **实习时长、实习期是否计入试用期**；
2. **转正考核的具体标准与通过率**（实习表现与转正是否强绑定）；
3. **转正后薪资** ＋ **五险一金基数与比例**（这类岗位往往只谈实习期、不谈转正后）；
4. **劳动合同签哪个主体**、公司工商全称；
5. 技术团队规模、**有没有人带**、算法/应用/交付怎么分工。

判据：**实习日薪 × 21.75 换算月薪**再与市场区间对照（南京/上海常规实习 150–300 元/天）；明显偏低＝公司在做**低成本长周期考察**，说明**offer 条款还没成型**，别当成承诺。
小公司先查工商：**参保人数**与它宣称的规模对不上（宣称 40 人、社保只交十几个）＝大量外包/派遣；成立年份、注册资本、有无母公司一起看。
谈的时候争取两件：**写明转正条件的实习协议/意向书**（口头不算）＋ **期限别一次签到底**（先 8–12 周，双向确认后再续）；同时评估它会不会挤掉秋招硬日程（笔试备考、集中测评、面试档期）。

## 铁律四：现场信息当日内落库 + 招聘会/宣讲会现场作战

- 现场拍的展板/传单/名片/易拉宝在聊天里只以 Hermes 图片缓存路径存在（`…\hermes\cache\images\img_*.jpg`），**会被清理** → 先 `cp` 到 `3-面试\4-附件截图\MMDD\`（按用途命名，如 `1015-远光软件-易拉宝.jpg`）再解析，台账备注直接写这条路径。
- 现场联系人（HR/老师姓名+电话/企业微信）写进 `投递台账.md` 的「五、人脉与线下记录」，岗位进主表，决策点进「八、待办与决策记录」。
- 现场资料比群消息值钱（有直接联系人），优先级高于线上岗位。
- **易拉宝/展板上的信息优先于官网调研**：现场版常含官网没有的东西（实测：易拉宝上写着「提前批」与「国家电网统一招聘」两条独立通道，前者自有测评、后者要国网统考 → 结论直接变成「走提前批」）。拿到现场图先抽取字段（投递入口/二维码、岗位清单、工作地、投递纪律提醒），再回写台账与清单。

**招聘会 / 宣讲会现场作战（名单 xlsx＋展位图＋台账去重＋现场话术）**：

他会在会前丢来「参会单位名单 xlsx」＋「展位图截图」，或一句「明天的招聘会，新增一家招聘单位：展位号 Axxx」。完整配方见 `references/campus-fair-playbook.md`（名单解析、展位分区、去重脚本、清单结构、子 agent 批量调研指令模板、装备与话术）。四条不能省：

1. **投之前必须与台账三本全量去重**（他明确要求过：「去重，搜索台账，已投递简历的不要再投」）。输出三档：**已投 → 只问进度不再投** ／ **未投待投 → 可投** ／ **不在册 → 可投**；并**剔除同名不同家的假匹配**（实测：名单里「兴业银行杭州分行／宁波银行南京分行／杭州银行南京分行」与台账里的招行上海、工行江苏、江苏银行苏州不是同一家）。产物两份：`3-面试\2-投递与计划\招聘会作战清单-MMDD.md` ＋ `招聘会-台账去重对照-MMDD.md`，前者的抬头要写一句「**照去重对照投，别照原始表投**」。
2. **已投过的公司里，岗位不同仍可再投**：岗位卡学历／岗位已关闭时不等于这家没机会（实测：某公司 Agent 岗不招本科，但同公司后端/算法/测试岗本科可投、薪资公开）—— 判定去重时按「**同一家公司 × 同一个岗位**」去重，不是按公司名一刀切。
3. **每家只给 3–5 分钟，问到三件**：有没有对口岗（本科可投吗）／怎么投（现场收还是官网网申，要二维码或网址）／后续流程与时间点；收尾一句「**方便加个微信吗**」——拿到 HR 姓名 + 微信才算有效拜访。
4. **现场情报按序号回指**：他在展位现场会发一句话（如「1. agent 不招本科」「7. 晚上有宣讲会」），序号对应的是你上一条清单/排名的第 N 项。**归属不确定时先标「归属待确认」并在聊天里给 A/B/C 选项让他一个字确认**，确认后回写三处：台账备注、清单对应行、清单的现场情报节。**别猜公司名硬写**——猜错要回头改三个文件。

## 铁律五：真题驱动的错题回炉（他指定的刷题法）

他做完机试/笔试后会说「这些是我刚才机试的题目，你全部转化为文字存储起来，并解析，然后寻找与之类似的题目锻炼我」，
并且**明确指定了练习形式：「一个问题你掰开了问，一道原题加两道延伸题」**。按这个形式出题，别退回「一轮 5–6 道散题」。

同一触发模式也用在**面试基础题**上：他会说「帮我补足一下 Java 基础，一会给你发一些题目，你先解析这些题目，然后再去调研与之相似的题目」→ 一样是**先落盘、再逐题解析**，交付固定四件套：**① 考点定位　② 校招口述版标准答案（15–30 秒）　③ 坑 + 追问方向　④ 相似题 1–3 道**（同考点换问法，标清是校招还是大厂）。
某题若 `Java校招面试题库-0-基础版.md` 已收录，直接给编号让他翻回去，别重复写。他通常在**出门前把一批题丢过来就去跑线下**（宣讲会/面试），回来才看——所以落盘比聊天重要。

- 一轮 = **1 道原题**（他真做错的那道真题）+ **2 道延伸题**（同考点、浅→深：先确认概念，再上陷阱或应用）。一轮就这三问。
- 真题转录与判分落 `D:\找工作找工作\4-刷题\机试-MMDD\机试真题-MMDD.md`（逐题：原题 / 他的选择 / 正确答案 / 一句话机制解析）；
  按考点归拢的**同类新题**落 `错题重练-MMDD.md`，**答案放文件最后一节**，不要贴在题面旁边。
- **拿到考试入口页 / 邀请邮件后，先出一份「题型结构与命题方向预测」再出准备卡**：入口页上有题型清单（如「单选题 5 ＋ 不定项 5 ＋ 问答 1 ＋ 编程 1 ＋ AI-coding 1」）、时长与总分 —— **这三样是硬信息，抄进台账；分值分配则是推测，必须标注为推测**。交付物落 `4-刷题\<考试名>-MMDD\题型结构与命题方向预测-MMDD.md`，只给方向**不出题**（他明确要求过：「帮我想一下可能是什么方向的题目，不要出题」）：① 题型拆解表（题量 / 推测分值 / 考察本质，结尾点出“哪一题最重”）② 逐题型方向 + 概率 ③ 由公司业务反推命题素材（官网产品线、邮件里的产品矩阵就是问答题的语境）④ 时段分配表（按分值给时间，并写死「最重的那题必须在还剩 N 分钟时开始」）⑤ **缺口对照表**（哪种题型练过 / 哪种空白）。
- **他问「把 X 的笔试链接以及相关信息给我」＝要一张可直接复制粘贴的信息卡**：链接（先 curl 实探一次可达性，连 HTTP 码与耗时一起报）、平台与设备要求（必须电脑端／浏览器）、截止或场次（含两处口径冲突时的取严结论）、登录账号（报名手机号）、联系人（姓名/电话/邮箱）、当前状态（已接受考试／待作答）、原始截图与备考文件路径 —— 给结构化清单，不要写建议段落。
- **有效期取严，不赌宽限**：同一场笔试的链接有效期可能在**邮件正文**与**考试系统页**上不一致（实测：邮件写「通知发送之日起 7 日内」，系统页写 14 天后失效）。两处取**更严**的那个当自我截止，并在台账备注里把两个口径都写清楚 —— 万一严的那个才是真规则，赌宽限就是直接丢掉这场考试。
- **启动一场考试的备考时**，顺手在当日 `3-面试\每日进度-YYYY-MM.md` 小节追加一行——cron 的 22:00 记录早于他回话，常写「本人全天无互动」：**追加更正行，不要重写已有小节**（每日进度只追加、不重排）。
- **「文件」与「聊天」是两套形式，别混**：同类重练/自测**文件**可以一次写十几题（答案放最后一节，供他自测）；但**聊天里的提问永远是一轮 1 道原题 + 2 道延伸、一轮只一个考点**。交付完文件要在回执里说清「这份是自测题库，抽背我按 1+2 逐轮来」，否则他会以为你要一次批阅十六道。
- **他考完只记得考点、没有原题是常态**（在线测评不能截图）：按**考点级**转录——每题：考点定位 / 机制 / 易错点 / 2 道延伸；**原题原文没留存就不写原文**，绝不用自己的话补造题干与选项。文末加一张**「备考预判 vs 实测」偏差表**（哪些预判的重灾区没考、哪些被推翻、下一场按什么口径备），它比题目本身更能改下一轮的备考优先级。
- **判分逐题来**：他按编号短答（`1.ad 2.a 3.对`），按编号一条条判（✅/⚠️/❌），判完**必须讲机制**，不能只宣布对错——
  他会接着追问「为什么」。
- **答错就不推进新考点**：当轮追加 3 道同考点追打题，**三题尽量三形式**（单选场景 / 多选 / 判断各一），全对才进下一轮——同一形式重问只是让他复述刚听到的答案。
  归类配对（把 N 个场景归到状态/分类池）对「记混概念」的考点最有效；**「状态/语义分不清」的考点用交叉场景题**（两个线程放进同一个锁场景，问其中一个处于什么状态）比列举式提问更能锁死区分。
- **他说「继续准备」「我打算突击一下」时，先接上没答完的那一轮，不要另起一份新文档**：翻 `4\刷题\<考试名>-MMDD\` 里最新的轮次文件，找**判分表还空着或追打仍待答**的那一轮（配合下面「文件里没有判分记录＝他还没练」那条判据），先把那三题发出去；同时给三行「今晚突击顺序」（本轮收口 → 下一轮考点 → 收尾自测卷）。突击场景下他要的是**题目**，不是又一份材料。
- **他答对之后常反过来追问某一个选项**（“C 和 E 跟我解释一下”）→ 追问与解说**也要落盘进当轮文件**（单独开一节「追问解说」），不能只在聊天里答完就丢：考前他只会翻文件。
- **他自己标「不确定」而答对的题＝蒙对，不算真会**：判 ✅ 但加注（“标不确定 → 待加固”），并在该轮追打里**换一种形式**再验一次 —— 按他自己定的规矩，猜对也算错。
- **一轮里的简答题可以带 2–3 个小问**（默对照表 / 三小问 / 手写两条 SQL），只要整轮**仍是一个考点**：「一轮一个考点」约束的是考点数，不是小问数。
- **下一轮的考点从历史实测错题里选**：翻 `4\刷题\` 下旧考试的真题文件，把当时「答错 / 答不会 / 只配对 2/8」的考点排成序列逐个回炉（他做题的弱项比章节顺序更能定优先级），并在轮次文件末尾预告下一个。
- **同一弱点最多点破一次**：他的多选题扣分是「**仔细看过、仍不确定才不选**」，不是没看见 —— 反复提醒答题习惯会被直接制止（原话：「不要再点了，我知道了」）。正确补法是把那个**不确定的知识点**用换形式追打锁死；点破一次就够，第二次出现时直接进追打题，不要在聊天里重提习惯。
- **追打可以连续两轮**（错 → 追 3 题 → 仍错 1 项 → 再追 3 题），全对才推进下一考点；所有考点通过后给一份**收尾清单**（剩余错题一句话补完 + 考前 5 分钟速记 + 当天时间线 + 纪律红线），**不要再加题量** —— 考前当天他只剩有限时间，增量是负收益。
- **出题前先确认这份卷子他做过没有**：判分只落在文件里，**文件里没有作答与判分记录＝他还没做**——别因为「卷子早就写好了」就当他练过，也别重复出他刚答过的题。查法：`grep -rn "判分|抽背" 4-刷题\` 并翻 `3-面试\每日进度-YYYY-MM.md` 最近几日条目。
- **笔试/在线测评（客观题）另备弹药**：多选漏选模式、判断题绝对化词的判法、题库覆盖空洞（数据结构）、高频概念边界清单 → `references/written-test-prep.md`。
- **他的短答会漏字/打错**（四个选项答成 `acse`）。选项歧义时**先问一句确认**（“是 A、C、E 还是 A、C、D、E？”），别猜着判分，也别把猜测写在判分里。他确认完那一轮再统一判。
- **出题前把前提写全（初始值、环境、假设）——前提缺失时他答“错”不算错。** 题干漏前提（例：
  「两个线程各 ++ 一次」没写 `count` 初值）时，他会按自己默认的值算，然后反驳「是你出题不清晰」——
  这类反驳**通常成立**。处理三步：① 当场认错并给规范版题干（补上初值/环境）；② 把判据换成**相对**
  形式再问一遗（“最终值会不会**小于理论值**”＝“少加了”，而不是“小于某个数字”），确保纠正的是概念
  而不是被表述问题绕过去；③ 在复盘文件里单开一节「题目歧义更正」，免得下次再犯同一个坑。
- **讲完被纠正的概念，用「复述探针」验收再走。** 让他**用自己的话把机制复述一遗**（“初值 0、两线程各 +1，
  最终可能是几？为什么？”），答对了才进下一轮，并在复盘文件里标上「✅ 概念已掌握」；不复述
  就往下走，下一轮他会带着同一个错前提继续错。
- **他常在一轮没答完时突然切任务**（发“处理一下”+ 另一批材料）。处理完新任务要**回到原轮**：报出还没答的题号让他续上，不要把切话题当成“这轮作废”。
- 下一轮的「原题」在上一轮回复里**预告**（「下一轮的原题是题8 单例」），保持连贯——他会顺着这条线走。
- **出题消息里绝不剧透答案**，哪怕是为了消歧义、哪怕用括号顺带一提；剧透一次这轮就废了。
- 同一考点**第二次**还错，判定为概念混淆（不是粗心）：从底层机制重讲 + 换形式锁死，不要重复同一道题。
- 机试真题图带「保密资料，请勿外传」水印 → **只在本机留存，不外传、不上传**；原图按 `qNN.jpg` 归档到 `4-刷题\机试-MMDD\原图\`。

## 铁律六：面试前定向突击（“明天就面，帮我准备” → 今晚这一场）

**收到面试邀约（邮件/短信/HR 微信）时，第一步不是备内容，是把通知拆成五项落进台账**，缺一项当天就出问题：

1. **绝对到点** —— 通知写「14:05 前 15 分钟签到」时要换算成 **13:50 到**，把绝对时间写进状态格，别把相对描述原样抄进去。
2. **地点 + 最近出口** —— 楼栋 + 层 + 厅，补一句「地铁 X 号线 <站> <出口> 对面」，他当天只看得懂这个。
3. **必带材料** —— 证件类型、纸质简历份数，以及**现场能否打印**（写「现场无法打印」＝必须前一天备好）。
4. **能不能改期 / 当天几轮 / 面完能否离场** —— 通知里常有「日期不可更改」「仅一轮」这类硬约束，原样记下。
5. **下次跟进日改成面试前一天**（打印、备证件、走一遍路线），不是面试当天。

并把岗位全称照抄进「岗位」格 —— 岗位名常直接点明考什么（「AI Coding / Agent 方向」⇒ 备考落在 Agent 架构、工具调用、AI Coding 场景，而不是泛泛的 Java 基础）。

交付两步，缺一不可：

1. **写一份定点突击稿**，落 `3-面试\1-面试准备\<公司>-面试突击-<项目>-MMDD.md`，骨架固定：
   - 进门前 5 分钟看的一页：三句话自我介绍 + “今天必须守住的三条”
   - **面经实证表**（这场大概会问什么）：按「观察 / 面经原话摘要 / 对本场的含义」三栏写，并标来源档位（A 考生原话 / 官方 JD / 我的推断）。华为系（华为、荣耀）的共性：**无手撕、项目拷打 20–30 分钟、会翻机考卷子让你复盘、少量八股、必问“用过 AI 工具吗”与 base 意愿／加班看法** —— 这类场次别花时间背八股，把时长全押在项目与机考复盘上。
   - 每个项目一节：三档表达（一句话 / 三句话 / 一段话）+ 链路与参数表 + **「必被追问 N 题 + 怎么答」** + ❌ 不能说的话
   - **简历逐条自检表**（他说「帮我熟悉熟悉简历上的内容」时，这一节就是主交付，比三档表达更要紧）：按**最新版简历的实文本逐句**拆三栏——「一句话口径 / 会被追问什么 / ❌ 不能说」，抬头、教育背景、每条 bullet、实习都要各占一行；同一事实在简历／口径稿／自我介绍三处说法打架的，当场摊开给统一口径。写之前先读那一版 docx 的实文本，别照旧稿写（版本迭代常已把措辞降级过，写回去等于又吹了一遍）。
   - **笔试/机考复盘口径**（这家考过笔试就必须写）：三段——① 我做了什么 ② 做得不好的地方（主动认：需求拆解没做透、没设硬性时间切点）③ 下次怎么做（给动作＋分钟数）。华为系/荣耀系面试**真会翻出那套卷子问**（“机考题复盘”是面经里的固定一问），答案必须面试前写死；顺带把编程题的**第二种、第三种解法与各自的扣分点**一并写好，别只说一种。
   - **“换我写会怎么补”**那一节（他最大的失分点：只发现问题、不给方案）
   - 目标公司的业务落地想法（把他的项目映到对方业务：游戏公司 → 知识库问答 / 策划数据助手）
   - 反问面试官 2–3 条（团队在做什么、技术栈、我进来碰什么），别问“发展前景”
   - 当晚行动清单 + 边界自查表
2. **按 `3-面试\1-面试准备\压力面记录.md` 的实际评分定点写**，不要泛泛复习：那份记录逐题标了给分/扣分与根因，突击稿每一节都应能对到某个扣分点。

- **岗位方向没确认时必须写「双预案 + 开场先问清方向」，不要停下来问他方向。** 同一场招聘会的批次常是同一类岗（如芯片公司的展板 8 个岗位全是嵌入式），而他的简历是 AI 应用方向 —— 方向错则整场错。突击稿第一节固定写**开场确认话术**（“开始之前想先确认一下，这个岗位具体是哪条线？我是现场招聘会投的，当时看到的岗位都是芯片/嵌入式方向，我想确认平时主要做什么，这样我好把项目里最相关的部分讲给您听。”），再按两条分支各给一套口径：
  - **A 档 · 方向不匹配（嵌入式 / 固件 / 驱动 / 芯片验证）＝轻准备 + 诚实收口**：正面讲能迁移的三样（**C++ 真做过的项目**、计算机基础分数、**读源码并把陌生代码库剥层再实现的能力**），主动认领缺口（“没做过裸机 / RTOS / 驱动 / 硬件联调”），争的是「基础扎实 + 愿意学」的印象；反问落在“这岗位具体在哪一层”。
  - **B 档 · 方向匹配（AI 应用 / 平台 / 上位机工具链 / 研发效能）＝全力打**：项目三档表达 + 速记表 + 红线表全套上。
- **短面试（≤30 分钟）要写时间盒**：开场确认方向 2′ → 自我介绍 **90 秒**（别用 3 分钟版）→ 项目深挖 10′ → 技术/岗位问 10′ → 他反问 + 确认后续流程 5′。写进突击稿，让他知道哪一段必须压缩。
- **HR 说「提前了解一下公司」＝自己抓官网出情报，别只回一句“你去看官网”**：curl 官网首页 → 剥标签取正文 → 抽成一张表（成立年份 / 定位 / 主产品线 / 生态伙伴 / 办公地址），再补**两句能直接出口的接话** —— 把他的能力映到对方业务（边缘设备算力与成本受限 ↔ 他做的是“模型外面那层”；对方有开源 SDK / 开发者生态 ↔ 他的 RAG 与 Agent 能落文档问答、选型推荐、报错诊断）。
- 他说「重新开始」＝**重置轮次从第 1 轮重来**，不要接着没答完的那轮续。
- 突击稿按方向复用：同方向的其他公司面试，技术内容直接用同一份。

## 铁律七：讲项目先划责任边界，简历数字先核实

**责任边界**（他反复出错）：第三方工具 / 自己写的代码 / 借鉴的类库必须分清，并且**主动说出来**。
例：教材解析项目里 MinerU 只负责 PDF→Markdown（版面 + 书签），
“知识点 / 习题 / 答案”的分段、父子块切分与偏移映射都是他自己的代码。
把工具的能力说成自己的，一追就穿；主动划清边界反而显得真做过。

**简历数字先核实再上场**：要准备面试、或某个数字可能被追问时，
**去他的项目仓库读历史**，不要凭印象、不要让他“回忆”：

```bash
# bundle 备份在 2-简历\_repo备份\<项目>-完整历史备份-*.bundle
git clone "D:/找工作找工作/2-简历/_repo备份/<项目>-完整历史备份-*.bundle" C:/Users/Lenovo/AppData/Local/Temp/rl
cd C:/Users/Lenovo/AppData/Local/Temp/rl     # git 是原生程序，用正斜杠原生路径
git log --oneline        # commit message 里常直接写指标（如「块数回归 4269」）
grep -rn "<可疑数字>" .   # 定位这个数字第一次出现的出处
```

再读仓库里的 `CHANGELOG.md` 与 `references/decision-log.md` —— 他自己的项目文档通常写着
**背景 / 根因 / 方案对比 / 效果**，这是最可靠的事实来源。
典型收获：一句「提升 X%」的简历claim，真相是**修掉自己中间版本的缺陷后指标回归正常**，
还外带一个**静默失效的 bug**（上游没把字段传下来、调用方判空吞掉）——后者比任何百分比都有说服力。
把真相写进突击稿，细节落 `2-简历\<项目>-技术详解.md` 供速查。
配方见 `references/project-claim-verification.md`。

**三类 claim 都要核，不只数字**：
① 量化指标 → 找它的来历（往往是对比了错误基准，或修 bug 前后对比）；
② **功能名词** → 逐条 `grep -rn "<名词>" .` 加 `git log --all --grep="<名词>"`；**代码与全部历史里都搜不到的功能，必须从简历和口述里删掉，或换成真实存在的功能名**（被问一句「这块代码在哪」就当场崩）；
③ 具体参数值（如「8 轮窗口」）→ 若 config 未随仓库提交就**不可确认**：要么让他去本机 `config.py` 看一眼真实值，要么把措辞降级成范围描述，绝不上场报一个没依据的精确值。

**性能数字去运行期埋点里拿，不要重跑流水线**：他自己的项目把每段耗时落进了数据库（连法与 SQL 见 `references/project-claim-verification.md`），分组统计就能得出“前后对比”，比重跑一遍快、可复现，而且**他明确不接受为核对一个数字把整条流水线重跑一遍**（“不要你跑这么详细，让你去查数据库的日志就行了”）。

**诚实红线表**：每个项目列一张「不能说 → 改说」对照（未测的百分比、没做过的规模、没用过的框架、
不是自己写的东西），放进突击稿，出门前扫一眼。

**他转发社媒/别人的「追问 N 问」清单**（“帮我回答一下关于 X 的这几个问题”）→ 交付一份逐题口径稿，落 `3-面试\1-面试准备\面试真题-<主题>N问-口径.md`：

- 抬头写清**来源**（谁的推文/哪篇文章）+ 那篇文章的**原话框架**，他的原话问题**逐字保留**。
- **每题四段固定**：(a) 考点定位（面试官在验什么）→ (b) **他的真实实现（源码级，报得出参数）** → (c) **口述版 35–45 秒** → (d) **必须自认的缺口 + 补法**。
- **社媒给的答案是通用套话，必须全部换掉**：写成他自己仓库里的文件名、函数名、参数值、埋点数字。换不掉的题，就是他要补的缺口，按 (d) 写。
- **几题合起来映射到下一步动作**（评测集 / 降级兜底 / 切分边界…），别只给答案不给路线。
- 文末两张表：**红线表**（简历上写了但 `grep` 不到的功能名、像“块数变化”被误当质量提升的百分比、未随仓库提交因而不可确认的参数值 → 各配一句替换说法）；**「面试前你自己动手看一眼的 3 件事」**（如 `grep -rn "threshold" query.py`、本机 `config.py` 里的真实轮数）——不确定项交回他验证，不要替他拍板。

### 项目问答口径稿（他说「把有关 X 项目的提问都准备一下」时）

- 落 `2-简历\<项目>-技术详解与面试问答-MMDD.md`（项目真相＋问答合一，**跨公司复用，不要一家公司一份**）。
- 结构固定六块：**① 项目本体 Q**（动机 / 边界 / 架构 / 主循环 / 工具 / 上下文 / 成本 / 与其它项目的关系 / 进度）**② 逐套评测集各一节**（E1/E2/E3 各占一节 —— 这里最容易被深挖）**③ 方法论专问**（为什么不报显著性、口径先写死还是先跑、你怎么知道指标本身是对的）**④ 红线表**（不能说 → 改说）**⑤ 缺口清单**（如实说＋补法要能说出时间）**⑥ 追问链演练**。
- **每个数字先实测再写进稿**：同一批数字在**简历 / 口径文件 / 评测报告**三处常打架（实测：提交数 154 vs 162、行数 8,066 vs src 2.01 万、E2 条数 12 vs 13）。一条命令就能定案：`git rev-list --count HEAD`、`find src -name "*.py" -exec cat {} + | wc -l`、`wc -l eval/sets/*.jsonl`；**发现打架就在稿里单列「文档打架」并给统一口径**，别让他上场说错（说小了也是亏）。
- **把「最容易被追穿的一问」标 ⚠️ 单独给答法**：典型是**自证循环**（题面期望值本身由被测规则推出 → 一致率 100% 只能当回归护栏，要主动承认，再转出真有外部效度的数字：误升率 / 如实报低的另一类指标 / 下一步人工标注）与**指标名与分母**（覆盖率＝可归属率 ≠ 语义支持度；action 类条目不进分母）。答法固定三拍：**承认局限 → 给反例或边界 → 转到下一步动作**。
- **追问链演练写成「面试官连追两层」的三条链**（每条三拍），比单题清单更能救场。

## 铁律八：HR 面 ≠ 技术面

- HR 面**别讲技术细节**（他会把整条 RAG 链路讲给 HR 听）：HR 问的是动机、稳定性、地点意愿、薪资期望、职业规划。
- HR 面必备六题，提前定口径：1 分钟自我介绍 / 为什么选这家与这个城市 / 薪资期望（**报一个数，不要报区间**——区间只会被读成下限；也别答“按公司规定”：先反问定档规则，再报薪资带上部的一个点）/
  3 年规划 / **是否考研** / 反问 2 条。谈薪的完整规则与演练协议见铁律十。
- **考研口径三档，只对外说第一档**：
  1. ✅ 对外唯一说法：「**我的主线是就业，考研是另一条我只做最低限度准备的路**」（真话，且不给 HR 想象空间）。
  2. ⚠️ 「考研是我的最后选项」——心里可以有，**嘴上不说**：它会把话题从“他考察你”变成“你暴露这是我唯一在意的机会”，自削议价空间。
  3. 🚫 禁用「保底」「找不到理想 offer 就去考研」——等于当面说“你在拿我兜底”，一句话能结束面试。
  追问“两边都成了选哪个” → 一句「**工作优先**」，不解释不犹豫（犹豫比选择本身更杀伤）；**不要主动提考试日期**。
- **口径与事实先查 `D:\个人画像\个人画像-张思浩.md`**（个人信息/学业/项目/荣誉/面试口径 12 节，多处标明“不能这么说 → 改说”）：HR 面或填表前先读它，不要在聊天里现编。
- 提问话术沿用铁律三。
- **线上面试**：提前测摄像头麦克风、定安静房间（宿舍吵就借空教室）、稳网 + 手机热点备用、
  提前 10 分钟进、手边放简历 PDF 与要点小抄、手机静音、别切到聊天软件（屏幕共享会露）。

## 铁律九：他反过来请教时的讲法（“轮到我对你请教了”）

抽背进行到一半，他会切成**反向提问**（“轮到我请教了”“继续挖”），而且**连问多层**（存哪 → 为什么不能那样 → 参数怎么定的 → 为什么单独一层）。
这时按五段讲，别只给结论：

1. **先纠正问题里的误解**：他的提问常带着错误前提（“为什么不能按 parent_id 找父块”→ 实际就是按 id 找，只是不需要第二次查询）。
   先澄清再回答，否则整段都建在歪地基上。
2. **机制**：讲清数据流与结构，能画成代码块 / 层级表就画（他看结构比看散文快）。
3. **替代方案对比表**：把“还有别的做法吗”列成 3–4 行，每行写做法 / 优点 / 代价，收尾给**取舍判据**（什么场景选哪个）——
   这正是他面试被追问时最缺的部分。
4. **有依据 vs 老实说**：参数与做法分两半 —— 哪些有硬约束支撑（如嵌入模型 512 token 输入上限）、
   哪些是经验值 / 没做过实验。明确标出来并给一句“面试这么答”的话术；承认没调优不丢分，吹“调过最优参数”才会被追到崩。
5. **顺手纠正他记错的事实**：归属边界（第三方工具 vs 自己写的）、简历上写了但代码里没有的功能、记混的数值 —— 当场指出并给替换话术。

讲完给一个“面试怎么用”的收尾句 + 1–2 个可执行的下一步（去跑一次命令拿真实数字、去看本机 `config.py` 确认真实参数）。
要真实性能数字时**查已有埋点，不要现场重跑流水线**（配方见 `references/project-claim-verification.md`）。

## 铁律十：谈薪演练（他说“帮我锻炼一下谈薪技巧”）

**交付物固定**：`3-面试\1-面试准备\谈薪演练-<公司>-<岗位>-<届>.md`，四块顺序不变：
① 能说/不能说速查　② 高频问题→怎么答表　③ 判分标准　④ 演练记录。
演练记录每题一条：**情境原题 + 他的原话 + 判分表 + 参考答案 + 状态行（⏳ 待答 / ✅ 已判）**；
他每答一题就**追加**进同一文件（他常在出门前答题、回来才看，落盘比聊天重要），不要新建文件。

**节奏沿用铁律五**：一轮 = 1 道原题 + 2 道延伸题，**一轮只放一个问题**等他答，答完先判分再讲透，然后才放延伸题。
题目自带情境（“HR 在电话里说…你现在怎么回”），要求他写**原话**。

**判分 5 维、每维 0–2**：锚点（报一个点且在带上部）/ 先问后答（反问定档规则）/ 依据（项目 + 薪数结构）/ 不暴露底价 / 换条款（被压价时转向非薪资项）。
**分数直给，并把这一步的代价换算成年薪差额**——他会立刻记住“这一句话值 4.4 万/年”，而“这样不太好”等于没说。

**先讲机制，再给话术**：他中途会追问“公积金这也能谈吗”“这有规定吧”——先给**规则边界表**（哪一层能谈、哪一层不能、为什么），再给话术；只给话术他会一路追到底。
他常给出“对一半”的判断（如“压力在我这边”）→ 明确说「对了一半」，先肯定对的部分，再把错的那半单独纠正。
他说「不会」是正常信号 → **直接给答案 + 讲解**，不反复引导、不让他猜。

**边界**：公司薪资带本身来自 `china-campus-recruiting-research` 的调研文件（含 `scripts/takehome_calc.py`），
**不要在本轮重做公司调研**；谈薪规则本体、应急话术、公积金三层、期限处理与止损线见 `references/offer-negotiation-drill.md`。

## 铁律十一：面试后真题复盘（“这是我面试被问到的问题” → 调研稿）

触发：他面完发来一串问题（常带自己的编号与括号备注）。交付是一份**文档**，不是聊天里的答案列表。

1. **原题逐字先落盘**：`3-面试\1-面试准备\<公司>-面试真题与调研-MMDD.md` 顶部放「原题清单」段，**保留他的编号与备注原文**，不改写他的话。
2. 每题固定七段：**(a) 这题在考什么 →(b) 他的诚实口径 →(c) 网上主流观点（带链接）→(d) 一手来源原句 →(e) 关键词 →(f) 追问 + 应对表 →(g) 口述版答案（40–60 秒）**。
3. **调研要真检索，来源分两档标注**：`✅已核对`（检索里真见到页面/摘要）/`⚠️ 待你点开核对`；数字与预测类**报出来前自己再核一遍**，别把二手转述带上台。
4. **诚实口径优先于漂亮答案**：他主动降级说明（“项目里仅仅是简单的表格转化”）时照实写进 (b)，再补「生产上正确的做法」对照 —— **替他拔高一次，就会被追穿一次**。
5. 文末加一节**本场复盘**：这一轮问的是深水区还是基本功、暴露了什么、下一步补哪块（对到题库/口径文件的具体动作），并挂上关联文件（突击稿、压力面记录、台账行号）。

**⚠️ 「关键词」段不能只是名词表**。本人明确要求过：「**我想要知道的是认知论和方法论，而不仅仅是一些具体的数字**」——
真题稿的 (e) 关键词 + (g) 口述版若靠名词罗列与数字堆砌撑着，另建一份**同目录 `AI应用与Agent面试题库\00A-AI认知论与方法论总纲.md`**（该目录已存在，编号插在 `00` 之后，属前置框架不是某一方向册）：

- **认知论**＝四个通用框架：① **分层定位**（模型 / 循环 / 知识 / 协议 / 流程 / 评测六层，用层判定「谁取代谁」）② **张力对**（能力↔可靠性、标称容量↔有效容量、常驻成本↔按需成本、确定性↔自主性、自动化↔可验收）③ **边界优先**（「X 的收益来自 A；A 不成立时收益转负」）④ **证据分层**（A 官方原句 / B 论文 / C 调查与机构报告 / D 厂商自述，四档各配引用纪律）。
- **方法论**＝三套可执行动作：「遇到没准备过的新概念」5 步、「你怎么看 X」四拍、"你会怎么做 X"四步。
- **数字一律降级为佐证**，放在判断**之后**：它的作用是证明「不是凭感觉」，不是替代判断。
- 原真题稿**不改结构**（他认七段），只在抬头加一行「★ 认知论/方法论升级版」指针 + 一句「本文件保留为证据库」，两文件互链、不互相抄。
- 建完**同步三处计数**：该目录 `00-索引与用法.md`（文件数 + 分工表 + 使用路线第 0 步）、`00-索引-面试准备.md`、根 `00-总索引.md` 的目录树注释。漏一处就会出现「10 份 / 11 份」打架。

**不写 `每日进度-YYYY-MM.md` 的新日期小节**：当天小节由 21:30 的 cron 创建，手动新建会与它撞出两个同日 `##` 标题——要留痕就等 cron 写入后追加一行更正。

**他一次只报一道题时**（常在校招现场、只记得一个考点）→ 单独立文件 `3-面试\1-面试准备\面试真题-MMDD-<考点>.md`，同上七段可简化，但另加两样：

- **开篇一张「分档表」**：只背定义＝不及格 / 答出实现机制＝良好 / 能补上系统认知（这一层的关键争点）＝优秀。他真正想知道的是**自己在哪一档**，不是知识点本身；表后再给 40–60 秒口述版。
- **文末「由这道题反推该公司的考察面」**：一道基础题就能定调（初面问数据库 ACID 而不是算法 ⇒ 这家不考纯算法，走「基础功＋落地能力」）→ 据此给出下一轮的准备双线，并同时回写那家公司的台账备注（面试流程列：几轮、有无笔试机试）。这一步比答案本身更能改他的备考优先级。
- 文件末尾留「待补」勾选（公司名 / 他当时的原话，用于判分并改写成下一版）。
- ⚠️ **归属不确定时不要硬写公司名**：他常说「刚才那家问的」而不点名。先按上下文记入并标「归属待确认」，同时在聊天里给 A/B 选项让他一个字确认；猜错要回头改三个地方（真题文件抬头 + 台账备注 + 每日进度）。

## 铁律十二：个人简介 / 自我评价段落（网申与表单用）

他说「把我的简历概括为一段话，包括优势特长、项目经验、未来规划」时：

- **一次给三档字数**，落 `2-简历\个人简介-一段话-<届>.md`，并标明各档用途：约 380 字（网申详情字段）/ 约 190 字（有字数上限的表单）/ 约 90 字（宣讲会签到表、一句话介绍）。只给一档，他填别处的表单时还得再问一次。
- **纯字符**：剔除下划线、编号符号（①）、箭头、「」、竖线、emoji —— 他要直接粘进表单（引用一律用「」或【】）。
- **数字口径必须与简历完全一致**（教材字数、本数、排名、评测任务步数）；简介是被追问的入口，口径漂了就等于自曝。
- **不引用无法自证的量化数字**：简历/项目里那些缺来源的“提升 X%”“Top-N”“N 轮窗口”在简介里一个都不用（依据 `2-简历\附-核心优势总结.md` 的边界表），只留可验证的规模类事实。
- **不含考研**（求职文本）；也不用「保底」「兜底」这类措辞（见铁律八）。
- 同方向还可顺手给一版**面向方案/交付类岗位**的改写（同一套经历翻译成「需求理解 + 方案沟通 + 交付」语言）——他手上有运营商解决方案经理类岗位在池子里，会用到。

  —— ②③ 是补他「只发现问题、不给方案」那个缺点的标准动作，**不能省**。

**把产物交到他手上（交付通路）**：

- 桌面会话：直接 `MEDIA:<绝对路径>`，卡片可下载/预览。
- 他说「**发到微信/QQ 上**」时用 CLI：`hermes send --list` 看可用目标（`weixin:<id>` / `qqbot:<id>` / `feishu:<id>`），再 `hermes send --to weixin:<id> --file "<md 路径>"` 发正文（要发附件就把 `MEDIA:<路径>` 写进消息体）。
- ⚠️ **发完必须让他确认收到的是文件还是只有文字**，并把 `message_id` 一起报给他：附件通道会静默失败，这时改**纯文本正文**重发兜底（md 表格在微信里会变平，可接受），同时照旧给一份桌面 `MEDIA:`。
- 报状态时把「接口返回成功」与「他实际看到什么」分开说 —— 只报接口成功等于把验证责任丢回给他。

## Pitfalls

- **通用题库与真题复盘分开存，别互相污染**：`<公司>-面试真题与调研-MMDD.md` 一场一份（原题逐字保留）；通用题库一个方向一份（可追加）。新被问到的题**追加进方向册末尾**开一节「MMDD 新增」，不要另起文件。
- **整理工作台的铁律：动文件之前先 grep 全库引用**。`1-面试准备\` 下那 10 份平铺文件被 10+ 个文件按文件名引用，**移动/改名会静默破坏交叉引用** → 正确做法是不动它们，另建 `00-索引-*.md` 做导航分层；`cron` 写入的 `每日进度-YYYY-MM.md` **只追加、不重排结构**。无引用的备份/重复件才移进 `_归档\`，并写一份 `_整理记录-MMDD.md`（含回滚命令）。
- **被 WPS/Office 打开的文件移动不了**：`mv`/`rm` 报 `Device or resource busy` / `Permission denied`。⚠️ **不要 `taskkill` 进程**（可能丢用户未保存的内容）→ 留在原处、在整理记录里写清「关掉 WPS 后执行这两行」，并核实内容是否与正本重复（重复即可安全删）。
- **`新建 文本文档.txt` 这类文件按内容重命名**，同时检查「目录名与内容不符」的错放文件（实测：`公司调研-0915\烽火网络\` 里装的是**炎魂网络**宣讲信息）→ **只在文件名里标注、不擅移目录**，把归属判断交回本人。
- **文件名里的全角冒号**（如 `内推码：XXX.txt`）在 Windows 上是非法字符，顺手换成 `-`。

- **别给他“标准答案”**：口径类问题（绩点低、考研、为什么选这个方向）由助手代写一段“更安全的标准答案”会被他直接打回（「你给我的标准答案，让我觉得很别扭」）。先问清他**自己的说法**，再按他的原话重写：只改会引发误读的措辞，不改他的叙事（真实原因是“兴趣驱动：编程相关课程投入更多 → 后来意识到不能只挑感兴趣的”，就照这个写）。
  - **“误读点”有固定模式：把“取舍”说出口**。只要把**考核指标**（绩点 / KPI / deadline）与他在意的东西（能力 / 兴趣）并列成“我当时做了取舍”，HR 就会外推成“他可能牺牲本职”。改成“我一开始以为它们是两件事，后来发现是一件事”（认知升级叙事），结论就从“会权衡掉你”变成“他更成熟了”。
  - **忌语**：不说“偏科”（主动贴标签），改说“投入不均衡”；不说“为了找到一份好工作”这类功利动机，改说“想走工程这条路”。
  - **结尾必须落到“规矩已经改了 + 有证据”**：只说原因不说改进，面试官记住的是“这人没有复盘习惯”；给一个可追问的证据（非编程类课程成绩一起上来了 / 实习里不感兴趣的部分也做到提测交付）。
- **别另建平行文件**：题库/清单都追加进上面这几个既有文件，不新建“某某题库-校招版.md”之类。**例外**：一场考试专属的**备考卷**可以新建，落 `4-刷题\<考试名>-MMDD\`——它绑的是一场考试的范围，不属于任何一本题库。
- **在线测评（银行/北森类）备考必须带一条设备纪律**：测评时段让他退掉桌面版 QQ / 微信 / 企业微信 —— 我们自己 cron 的定时推送（晨报 / 18:00 提醒 / 21:30 摘要）会弹窗抢焦点，被测评系统计成一次「页面跳出」，而多数测评只给 5 次跳出额度。
- **了解新框架/新方向先看 PyPI 项目页**：版本号、发布日期、官方一句话定位一次拿齐（如 LangGraph=“low-level orchestration for long-running, stateful agents”），比翻文档快。讲给时要落到“他手上哪个项目能对接、秋招哪类岗位要”。
- **方向类问题必须收敏到投递动作**：把岗位搜索词从“Agent”扩到 `大模型应用开发 / AI应用开发 / RAG / AI平台开发 / AI测试开发 / 行业AI`，否则只是一堆概念。
- **面试陪同不要抢答**：抽背时要等他答完再判，不要自问自答把答案预支了。
- **写任何带日期的文件名/内容之前先跑 `date`**。长会话会跳天，上下文里的「今天」只是上一次重建时的快照：靠它推日期会直接错到 `-MMDD` 文件名、`每日进度-YYYY-MM.md` 的小节、以及一次性提醒的触发时间上（重写一整天或漏写一整天都是这么来的）。排一次性提醒时若被 `cronjob_manage` 以 `is more than 120s in the past` 驳回，那就是日期已经跳了的信号 —— 先 `date`，再决定「一点半」指的是今天下午还是明天凌晨，并把这个假设写在回执里让他一句话就能推翻。
- **他说「今天没收到晨报 / 日报」时，先查 gateway 再查台账。** 两个 cron 任务（09:00 晨报 / 22:00 进度）**只在 gateway 运行时才触发**：`hermes gateway status` 报 `✗ No gateway process detected` 就是全部原因（`cronjob_manage action=list` 会同时给出 `gateway_running: false` 和上一次的 `last_status: error`，典型报错是 `RuntimeError: Hermes can't reach the model provider` 与推送侧 `getaddrinfo failed`）。**拉起的正确姿势是用登录启动项 detached 启动**：`wscript "C:\Users\Lenovo\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\Hermes_Gateway.vbs"`，隔几秒再用 `hermes gateway status` 确认 `✓ Gateway process running (PID: …)`；**不要从 agent 的 shell 直接 `hermes gateway start`** —— 那样起的进程活在 shell 的 Windows Job Object 里，shell 一退就被杀。
- **交叉核对他的多份稿子，互斥声明当场摊开让他二选一**：自我介绍稿、压力面记录、简历、问答稿各自成文，同一件事容易出现两种相反的说法（例：自我介绍稿写「用消融开关对比过各模块的贡献」，压力面里他亲口说「没做过对比命中率」）。**自我介绍是要背到脱口而出的**，带着这种雷上台，面试官接一句「消融实验的数据呢」就当场穿。发现后给两条出路：删掉改成做法描述（“把各模块做成可开关的配置，便于逐块排查”），或真跑一遍把数字补上 —— 不要替他选，但必须让他知道。

## Verification

- 基础层材料先于进阶层给出，且进阶文件头部有“不用背”标注。
- 抽背：每题有明确判分（✅/⚠️/❌）+ 标准答案 + 追问坑；一轮不超 6 题。
- 面试材料/方向图/HR 清单都有实际落盘路径，不是只在聊天里说完。
