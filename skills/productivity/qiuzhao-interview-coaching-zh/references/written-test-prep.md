# 笔试与在线测评备考

面向银行 / 国企 / 运营商的在线技术测评（北森 `ceping.com` 一类），以及 **AI 应用 / Agent 岗的牛客笔试卷**（多了编程题与 AI-coding）。
主观面试题仍走 SKILL.md 铁律二 / 五；本文件只管「考什么、怎么答、错哪了」。
客观题部分见 §一–六；**编程题与 AI-coding 等实操题见 §七**。

## 一、先定范围与试卷

- 银行系技术测评的范围基本固定：**Java 基础与并发 + MySQL + 计算机网络 + 数据结构**；题型＝单选 + 多选 + 判断（可能追加编程题）。**数据结构是最容易漏的一块，见第二节。**
- 通知里出现「多份试卷」「笔试方向将决定后续面试及录用方向」时：**选卷＝选岗，选完不可换**。原则——选与他所投岗位同名的那份、且与他八股准备的语言（Java）一致的那份；算法 / 前端 / 运维卷除非他真有对应经历，一律不选。这个决策要在**考前一晚**就定下来，写进准备卡。
- 备考范围只映射到 `4-刷题\Java校招面试题库-0-基础版.md` 的题号，逐条标「明天必看」；第 1、2 册标「大厂/进阶，不用背」。

## 一·附　按公司分卷形状（实测记录，备考先查这个再定复习重心）

| 卷型 | 判据 / 形状 | 复习重心 |
|---|---|---|
| **华为 / 荣耀系研发**（通软、算法） | **纯编程卷：2 小时 2 道编程题 ＋ 1 道 AI Coding**（ACM 模式）——**实测无选择题 / 判断题 / 简答题**（早年口径是 3 道纯编程）；难度低于华为，算法考察少，**重字符串处理与输入输出格式细节** | 手写 ACM 模式的**字符串解析 + 表格/逗号输出 + 矩阵（秩/迹，禁 numpy）+ 贪心子序列 + 背包/DP 最少个数型**；**AI Coding 那题按 §7.3 打**。⚠️ **别按「选择＋判断＋简答」给这类公司出备考卷** —— 题配比要贴实测形状，否则整卷练错（选择题只作兜底，且只在测开方向出现：20 单选＋10 不定项、60min、5G/协议多） |
| **北森 / 牛客综合技术卷**（如云帐房「AI 笔试题卷 3」） | 单选5＋不定项5＋问答1＋编程1＋**AI-coding 1**，90min/120 分；编程题直接上经典 hard DP（编辑距离） | AI/LLM 概念 + **语言工程性 + Java 并发** + DB（事务/索引）；简答准备「流式 + ToolCall Agent 全链路」 |
| **AI-coding 题（2027 届起普遍新增，携程已加）** | 给极简三层骨架（data/service/http）＋复杂业务需求，**采分看「测试用例」＋「与 AI 助手的对话过程」** | 标准动作：先喂上下文 → 一次只做一层 → 每轮指出 AI 产出的问题 → 自己补测试跑通 → 收尾说明取舍 |

**取形状的方法**：牛客搜索页是 SSR —— `https://www.nowcoder.com/search?query=<urlencode>` ＋ Chrome UA，curl 直出**考生原话**（含真题描述、反例、难度对比）；**加 `&type=post` 会返回 0 字节空页**。想拿整题原文再抓 `/discuss/<id>`（部分帖需登录，返回 40 字节壳页）。

**编写备考卷的固定结构**：考试信息与卷面预判（来源分档 ✅已核对 / ⚠️推断）→ 题面（编程题在前，ACM 模式，**含样例与反例**）→ 答案与解析放**最后一节** → 独立「易错点清单」＝**他自己的历史错点**（查 `4-刷题\<上一场>-*\备考-抽背第N轮-*.md`）＋ 该卷型高频坑 → 时间分配与考场纪律。

**自编卷的参考代码必须脚本对拍，不能凭眼验**：把每道编程题的参考解写成独立文件，用 runner 逐条跑「样例输入 → 期望输出」并 assert（含边界：无解 / 包含区间 / 多位数字重复 / 输入按行或按空白）。**题面里印的样例输出必须与参考实现逐字符一致** —— 不一致时改题面或改实现，绝不把印错的样例交给他（实测对拍 8 题 14 个用例即抓出 1 处「列宽补齐多一个空格」的样例与实现不符）。同一形状出 6–8 道即够覆盖，编程题是这类卷子唯一的拉分区。

## 二、题库覆盖空洞（考前必补）

题库 0 的板块题号：Java 基础 1–17、集合 18–28、并发 29–38、JVM 39–43、Spring 44–55、MySQL 56–67、Redis 68–72、网络 73–77、项目+HR 78–84。

**数据结构只有 76（排序复杂度）、77（数组 vs 链表）两条，不够考试用**——每次考前补下列 8 条：

1. 栈 LIFO / 队列 FIFO / Deque 双端；栈用于递归、括号匹配、表达式求值，队列用于 BFS、任务调度
2. 二叉树四种遍历；**BST 中序遍历＝升序**；BST 平均 O(log n)，退化成链表为 O(n)
3. 哈希表平均 O(1)；冲突解决＝链地址法 / 开放寻址；Java HashMap＝链地址 + 链表过长转红黑树
4. 排序：冒泡/插入/选择 O(n²)；快排/归并/堆排 O(n log n)；**快排最坏 O(n²)**；**稳定的是冒泡、插入、归并**
5. 二分查找 O(log n)，前提有序；写法 `mid = lo + (hi - lo) / 2`
6. 复杂度序：O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)
7. 图：BFS 用队列（无权图最短路），DFS 用栈/递归（连通性、拓扑排序）
8. 递归过深 → **StackOverflowError**（不是 OOM）；朴素斐波那契 O(2ⁿ)，记忆化后 O(n)

## 三、客观题答题策略

- **多选题：每个选项单独判一次真假**（逐个问「这一项字面上符合题干吗」），不要整体凭感觉。典型漏选模式是只挑两个最像的，漏掉**边界概念**（`CountDownLatch`/`ReentrantLock` 是 JUC 招牌、`RuntimeException` 属非受检、`locate`/`whereis` 也是按名字找文件）。排除法要防两类：**听过但不属于这一类**（`ArrayList` 不在 JUC）、**对但答非所问**（`grep` 能搜东西，但不是按名字找文件）。
- **判断题：出现「一定 / 都 / 必须 / 绝对 / 全部」先默认它错，再找反例**（`git merge` 不一定产生合并提交；`finally` 不是一定执行；`volatile` 不保证原子性）。
- **「只有 X」型判断按语法与语义分别核**：如 `try` 后面没有 catch、只有 finally 是完全合法的。
- 时间分配：单选 ≤60 秒、多选 ≤90 秒、判断 ≤30 秒；先扫全卷再回头攻难题。没有倒扣分时**不留空**，猜也要填。

## 四、高频概念边界清单（考试反复错的就是这些「一对」）

| 边界 | 一句话 |
|---|---|
| volatile vs synchronized | volatile＝可见性 + 禁重排，**不保证原子性**；要原子性用 synchronized / AtomicInteger |
| BLOCKED / WAITING / TIMED_WAITING / yield | 等**锁**→BLOCKED（唯一入口是 synchronized）；等**被唤醒**→WAITING（wait / join / park）；等**时间到**→TIMED_WAITING（sleep(ms) / wait(ms) / join(ms)）；**yield 仍是 RUNNABLE**（只是回到就绪队列） |
| sleep vs wait 的锁语义 | sleep **不释放锁**，wait **释放锁**且必须在 synchronized 内 —— 这一个差别决定了「另一个线程是卡在 BLOCKED 还是能直接进来」 |
| finally | 只有 `System.exit()` / JVM 被杀 / 线程被强制中断时**不**执行；try 后至少跟 catch 或 finally 之一即可 |
| StackOverflowError vs OOM | 递归 / 栈过深 → StackOverflowError，不是 OutOfMemoryError |
| 快进合并 vs merge commit | 快进合并只移指针、**不产生提交**；`--no-ff` 才强制生成 |
| HTTP 无状态 | HTTP 本身无状态，所谓「有状态」是 Cookie / Session / Token 在应用层补的 |
| MyISAM vs InnoDB | MyISAM 无事务、只表级锁、无外键；InnoDB 事务 + 行锁 + 外键 |
| equals vs == | equals 默认就是 ==，String / 包装类重写后才比内容；包装类缓存只有 -128~127 |
| 索引失效四条 | 索引列做函数/运算、前导 `like '%x'`、隐式类型转换、`or` 一侧无索引 |

## 五、考后动作（固定）

- 当晚把题型 / 题量 / 考点 / 自我感觉报回来 → 逐题转录 + 判分落 `4-刷题\机试-MMDD\机试真题-MMDD.md`，同类新题落 `错题重练-MMDD.md`（**答案放最后一节**）。
- 无论考得怎样都记住题型：同一类单位（银行 / 国企 / 运营商）的笔试互相参考价值很高。

## 六、抽背轮次文件的结构与判分细则

轮次文件 `4\刷题\<考试名>-MMDD\备考-抽背第N轮-MMDD.md` 固定四节，**先只写题面**：

- `§1 题面` —— 本轮 1 原题 + 2 延伸题（题面原文）
- `§2 判分记录` —— 表头固定 `| 题 | 他的答案 | 判分 | 病灶 |`，追打那行留空待答
- `§3 答案与机制` —— 等他答完这一轮再补进去
- `§4 追打 3 题` —— 题面 + 答案（答案放节末、标「答完再看」）

**「病灶」列是本表最有价值的一列：写「缺哪一环」，不写「答错」。**
反例：`❌`。正例：`强缓存 vs 协商缓存的两级先后关系未建立`。
下一轮的题面**直接照病灶来出** —— 病灶写不清楚，题目就打不准，一整轮就白做。

**追打通过后，在 §2 表下补一条「本轮结论」行**，格式：

```
> 本轮结论：原题 ✅ / 延伸 1 ⚠️ / 延伸 2 ❌ → 追打 3/3 全对 → <考点块> 通过 ✅
> 下一轮开始前需复述：<当场补讲但未验收的那几条机制，一句话一条>
```

下一个会话靠这一行就能接手，不用重读整份聊天记录。

**被追问的选项要单独落一节「追问解说」**（他常问「X 和 Y 跟我解释一下」）：把两个易混的指令/概念做成对照表 + 指出「名字骗人」的那个（如 `no-cache` 不等于不缓存），落进当轮文件。

**追打仍错时不要跳考点**：再做一轮同考点的 3 题，形式必须换（上一轮单选就问场景、上一轮判断就问反例），全对才推进。

## 七、AI 岗笔试的新题型：编程题与 AI-coding（实操题）

AI 应用 / Agent 岗的牛客笔试卷除了客观题，还会出**一道编程题 ＋ 一道 AI-coding**。别按客观题的路子备考。

### 7.1 题型结构与时间分配（先出这一张表）

入口页会写明题型清单 / 时长 / 总分 —— **题型是硬信息**（拄进台账），**分值分配是推测**（必须标注）。
实测样本：单选 5 ＋ 不定项 5 ＋ 问答 1 ＋ 编程 1 ＋ **AI-coding 1**，90 分钟 / 120 分，其中 **AI-coding 一题约占全卷 1/4，是最重的一题**。
交付物与「不出题只要方向」的要求见 SKILL.md 铁律五。

| 段 | 时长 | 铁律 |
|---|---|---|
| 单选 | 6–8 min | 卡住超 3 分钟就跳过、标记后回头 |
| 不定项 | 12–15 min | 逐项判对错；不确定的先按“确定的项”选，末尾回头 |
| 问答（1 题） | 15–18 min | 先列提纲再写；结论先行 → 分层 → 每层给**机制** → 主动说局限 |
| 编程（1 题） | 20–25 min | 先写暴力解拿分，再谈优化；边界用例写进注释 |
| **AI-coding** | 20–25 min | **绝不压到最后 10 分钟**，写死一个「还剩 N 分钟时必须开始」 |

### 7.2 编程题

- 难度可以**不止 easy**：实测出现过**编辑距离**（经典 hard 级 DP）—— 字符串 DP 是高频区，别只备滑动窗口与哈希。
- 财税 / 金融背景会把题裹一层业务皮（金额、发票、账期），**隐性考点是金额不能用 float 算**（整数分或 `Decimal`，四舍五入规则要说清）。
- 把**复杂度与边界用例**写进注释 —— 评分常看过程。

### 7.3 AI-coding（评分标准比题面更值钱）

题面通常是「用 AI 编码助手完成一个复杂业务需求」，框架给得极简（实测：三个文件分别代表三层 —— `data.py` / `service.py` / `http.py`）。
**评分标准实测包含「测试用例 ＋ 与 AI 助手的对话过程」** —— 这一条决定了打法：

| 采分点 | 含义 |
|---|---|
| 测试用例 | 要**自证正确**。只有实现、没有测试＝丢分 |
| 与 AI 的对话过程 | 考会不会**审查** AI 产出；无脑采纳是负分 |
| 三层骨架 | 考**分层不越界**（业务逻辑不写进 http 层、SQL 不写进 service 层） |
| 「复杂需求」 | 考**把需求拆给 AI** 的能力，不是自己硬写 |

**标准动作（照做即可复用）**：

1. **先喂上下文再让它写**：三层职责 + 现有代码 + 接口契约 + 业务规则 + **边界条件**一次讲清。上下文给不够是 AI 产出不可用的第一原因。
2. **一次只让它做一层**（data → service → http），改一处验证一处。
3. **每轮产出后主动指出问题**：「AI 给的 X 有隐患，因为 Y，改成 Z」—— **这就是“对话过程”的采分点**。
4. **自己补测试并跑通**：正常用例 + 边界（空 / 超长 / 非法参数 / 重复调用）+ 失败路径（下游超时、DB 报错）。
5. **收尾说清哪些 AI 建议没采纳、为什么**。

**采分是分档递进的，按档锁分**：实测评分分四档 —— **冒烟测试 → 基础业务测试 → 进阶业务测试 → 高难度业务测试**，自下而上给分。策略：**先保冒烟不挂（能跑通、主流程走得通），再逐档往上加**。最大失分点不是不会写，而是**「高级特性」没抓全、需求没读明白就开写** —— 读完题先拆两栏：「必须有的骨架」＋「题面点到的高级特性清单」，照着清单逐条对，再动手。时间不够时宁可高档特性写一半，也不要为了高档把冒烟跑挂。

**可复用到面试的说法**：这套「分层 + 边界 + 测试自证」正是“我怎么保证 AI 写的代码没越界”的现成答案（同源做法见 `ai-collab-project-gates`）。

### 7.4 问答题的通用骨架

**结论先行 → 分层展开**（数据 / 检索 / 生成 / 评测 / 合规，每层给一个具体机制）**→ 主动说局限**。
忌讳“用大模型做智能问答、效果好”这种没机制的空话。
要结合公司业务时，**官网产品矩阵 + 邀约邮件里的原话就是命题语境**（先读一遗再动笔）。

### 7.5 考后：笔试真题复盘

落 `4-刷题\<考试名>-MMDD\真题复盘-MMDD.md`（**与面试真题复盘分开**：那份是“我经历过什么”，这份是“这场卷子考了什么”），固定内容：

① 元信息（平台 / 时长 / 总分 / 题型） ② 各题型实际考点（对照预测，点出**漏押**的）
③ **简答题写“完整口径”，要能当场讲 5 分钟**（考完就写成可复用的面试资产）
④ 编程题题解 + 同族题 ⑤ **AI-coding 的评分解读与应试动作** ⑥ **「备考预判 vs 实测」偏差表**
⑦ 可直接复用到面试的 3 条资产 ⑧ 下一步清单。

⚠️ 他**只记得考点、没有原题是常态**（在线笔试不能截图）：按**考点级**转录，**没留原文就不写原文**，绝不用自己的话补造题干与选项。
考点与判分继续回写进当轮的 `备考-抽背第N轮-*.md`（结构见 §六）—— 两套文件互链，不互相抄。
