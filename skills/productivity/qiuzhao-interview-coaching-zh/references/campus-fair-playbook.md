# 招聘会 / 宣讲会现场作战配方

配套 SKILL.md 铁律四。适用：他丢来「参会单位名单 xlsx」「展位图截图」「第七周校园招聘活动汇总」这类链接，或会前一天/当天问「明天带哪版简历、印几份」。

---

## 1. 三种输入的解析法

### 1.1 参会单位名单 xlsx

- 结构通常是三列：**类别（组团） / 展位号 / 单位名称**，末尾附一张按类别的计数表。
- **解析用 terminal 里的 `python` 跑脚本**（`openpyxl` 已装；`execute_code` 的沙箱解释器没有该包，直接 import 会 ModuleNotFoundError）→ 先 `write_file` 落一个解析脚本，再 `python parse_zp.py` 跑，**不要手抄几百家**。
- 脚本顺手做两件事：① 打印「表头 + 前 6 行 + 全部行（截断）」让人眼扫一遍；② **把全量 dump 到临时 txt**，后续所有筛选（按城市、按关键词、按展位区）都用 `grep` 打这个 txt，不再重复解析 xlsx。
- 单位名带括号注释（城市/性质）时不要丢掉括号——里面的城市信息常常是排序的唯一依据。

### 1.2 展位图截图

读图取**分区结构与编号范围**，不逐格抄。常见分区的性质（可用于优先级判断）：

| 区 | 性质 |
|---|---|
| A 区 | 自行报名企业 + 团省委/就管中心等组团 —— **主力区，对口公司最密；新增展位常挂在 A 区最末端** |
| 软件谷组团 / 校友企业组团 | **命中率最高的两片**（前者全软件企业，后者愿意当场聊） |
| 央企/行业组团（铁塔、邮政快递、通信服务类） | 中；在册单位多、可当场问进度 |
| 地方人才组团（扬州、昆山、南陵等） | 低——机械/汽车/材料/光电成片，标「不去，别占时间」 |

### 1.3 公众号长图流（「第 N 周校园招聘活动汇总」）

原文是图片流，**必须重排成「日期 → 场次（公司/地点/时间）」清单**才可用：`curl -A "<Chrome UA>"` 取 HTML → 剥 script/style → `<br>`/`</p>`/`</li>` 转换行 → 去标签 → unescape。重排后按「**与他相关 / 中等 / 基本不对口**」三档分流，并在文末单列「本周只有这 N 场值得去」。

## 2. 去重：与台账全量比对（动手投之前必做）

他明确要求：**「去重，搜索台账，已投递简历的不要再投」**。

**配方**：

1. 读三本台账的行：`re.match(r'\|\s*\**(\d+)\**\s*\|', line)` 取行号，`line.split('|')` 取公司列（第 4 格）/状态列（第 10 格）。
2. **名称归一化**：剥 `**`、`（…）`、`~~…~~`；去掉通用后缀与地域词（有限公司/股份/集团/科技/技术/信息/软件/网络/智能/研究院/分公司/子公司/南京/江苏/杭州/苏州/上海/中国/省/市…）；取前 4 字当匹配键，**双向 contains** 匹配。
3. **假匹配必须人工剔一遍**：银行分行（兴业/宁波/杭州银行 ≠ 台账里的招行上海、工行江苏、江苏银行苏州）、同集团不同主体（中国通信服务系就有多个主体）、名称相似的子公司。误合并会让某家被当成「已投」而不投。
4. 输出三档并落两份文件：
   - `3-面试\2-投递与计划\招聘会作战清单-MMDD.md`（现场照着走的那份）
   - `3-面试\2-投递与计划\招聘会-台账去重对照-MMDD.md`（去重结果）
   - 清单**顶部写一句指路**：「照去重对照投，别照本文件的原始表投」，以后改动只改对照表。
5. **去重粒度是「同一家公司 × 同一个岗位」**，不是公司名：岗位关闭/卡学历时，同公司的其他岗位仍可投（并把它写进台账备注）。

## 3. 现场清单该长什么样

固定骨架（照这个顺序写，他只会在现场翻前两屏）：

1. **抬头**：时间地点 + 规模（多少家/几个组团）+ 名单与展位图的本地路径 + 指路句。
2. **展区结构表**：区 / 展位号范围 / 组团性质 / 值不值得走。
3. **优先表**：`优先 | 展位 | 公司 | 对口岗位（原文） | 本科可投? | 城市 | 薪资 | 证据链接`；每一行必须是**可核对的岗位名**，查不到就写「未查到，建议现场问（展位 X）」，**绝不编岗位名/薪资/届次**。
4. **未查到的那几家单独一表**，每行给「现场问什么」（几句话）。
5. **路线建议**：按展位区连扫，给出时间预算（A 区 ≈ 60′、软件谷+校友 ≈ 45′、其余 ≈ 30′，留 20′ 缓冲）。
6. **装备 + 开场三句 + 必问三件 + 回执动作**。
7. **现场情报节（§N）**：他现场反馈逐条追加，带「归属」与「处置」。

**装备**：纸质简历（按方向分两叠，AI 方向多带）+ 成绩单复印件 + 笔与本子（记展位/岗位/联系人/微信）+ 满电手机与充电宝。
**开场三句**：学校专业届别 + 方向 + 一个可验证的项目 + 「想了解有没有对口技术岗、该走哪个通道投」。
**回执动作**：当天把谈到的每条写进台账（新公司按行号追加；现场投出的搬进已投本）、加微信的当天发自我介绍、现场照片/传单归档到 `3-面试\4-附件截图\MMDD\`。

## 4. 写入台账（行级改写，比字符串 patch 稳）

- **改单元格**：`cells = line.split('|')` → 改某个下标 → `'|'.join(cells)`。12 列的行切出来是 **14 段**（首尾各一个空段），**插入新行后核一遍 `len(cells) == 14`**，少一段就是漏了个空列。
- **每处替换先断言命中**：`assert text.count(old) == 1`；插入新行前先 `cp` 备份。
- **插入前重扫锚点行与最大行号，不要复用上一轮读到的值**：台账由多个会话/cron 并发维护，上一轮的 `| 106 |` 可能已经被搬进另一册（实测据此直接 `max()` 空序列崩）。行号 `#` 全库唯一，号从**三本的最大值 +1** 起。
- 已投过的公司若有**新岗位**要投 → **不新建行**，在该公司在册行的备注里追加（现场投出后才整行搬册）。

## 5. 批量公司/岗位调研：用子 agent 并行（3 路 × 8 家）

会前一天 24 家以内的岗位细查，用 `delegate_task` 并行 3 路最省时。**指令里必须写死这几条，否则子 agent 会在一家官网上死磕到超时**：

- **每家最多 3 分钟**，查不到就写「未查到公开岗位信息，建议现场问（展位 X）」＋ 给出该公司官网首页链接，立刻进入下一家；8 家必须全部过完，宁粗不细。
- **优先 `curl` + Python 去标签**；**不要开浏览器**（本机 browser_exec 会在一次 420s 超时上白耗 7 分钟）。
- **每家至少一个可点开的证据链接**；**不许编岗位名、薪资、届次、学历要求**，拿不准标「待现场确认」。
- 输出统一模板：`### 公司全名（展位号）` → 一句话画像（行业/规模/是否外包驻场）→ 校招入口 URL → 对口岗位逐条（岗位名｜学历｜城市｜薪资｜链接）→ 对本人判断（能投哪 1–3 个岗位 + 优先级 + 现场该问什么）。
- 并发跑起来后可以用 `action='steer'` 中途纠偏（实测有效：一路陷在浏览器里，steer 后改成 curl 立即推进）。
- **子 agent 给的“补量化数字”类建议要拦一道**：它们常建议给简历/项目补“提升 X%”——这与他的口径红线冲突（没有评测集支撑的数字一个都不报），在回执里明确写「这条不要照抄」。

## 6. 交付通路

- 桌面会话直接 `MEDIA:<绝对路径>`；他要「发到微信/QQ」时用 `hermes send --list` 取目标，再 `hermes send --to weixin:<id> --file "<md 路径>"`（要附件则把 `MEDIA:<路径>` 写进消息体）。
- **发完必须让他确认收到的是文件还是只有文字**，并把 `message_id` 报给他：附件通道会静默失败，这时改**纯文本正文**重发兜底。只报「接口返回成功」＝把验证责任丢回给他。
