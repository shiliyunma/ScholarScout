# 秋招台账维护 Skill

把大浩（南邮软工，2027届，目标 AI Agent/大模型应用开发）从 QQ 群转发来的秋招消息解析成结构化岗位/日程记录，写进既有台账，并据此更新当天与本周的时间规划。

## When to Use

- 他一次性转发一批群消息（招聘会通知、宣讲会、招聘贴、HR 联系方式）并说"帮我处理一下"
- 需要更新投递台账 / 当天行动清单 / 本周排期
- 他汇报投递进度（"我投了 XX 公司"）

不适合：单条闲聊、与求职无关的校园通知。

台账本章节固定（**09-16 起拆两本，章节号沿用原编号，两册编号一致，跨文件引用不会错位**）：

| 章节 | 在哪册 |
|---|---|
| 一 投递主表 | 已投本（已投的）/ 未投本（待投的 + 一·附不投的） |
| 二 待投队列 | 未投本 |
| 三 每日计数 / 四 笔面进展 | 已投本 |
| 五 人脉线下 / 六 已挂归档 / 七 硬门槛自查 / 八 待办决策 / 九 校内日程 | 总入口 `投递台账.md` |

投出去一家的动作：改状态为 `已投` → **整行搬到已投本** → 在未投本删掉 → 已投本的计数、进展表同步补。行号 `#` 全库唯一，不许重号。

## Procedure

1. **先读台账**（总入口 `投递台账.md` + `投递台账-已投.md` + `投递台账-未投.md` + 最新 `投递执行清单-*.md`），确认现有行号（# 全库唯一）、状态码、已排日程，避免重复录入或另建文件。
2. **下载消息里的图片**：QQ 多媒体链接带 `rkey`，**有效期很短，必须先落地**。用 `urllib` + 浏览器 UA 下载到 `1-情报\群消息与招聘会-MMDD\群消息原图\msgNN-<用途>.png`，逐张 `vision_analyze` 识读（海报类要按区域放大看小字，如报名时间、学历门槛）。
3. **抽取字段**：公司 / 岗位（照抄 JD 名）/ 城市 / 投递入口或邮箱 / 截止时间 / 学历硬门槛 / 宣讲时间地点 / HR 联系方式。
4. **归档原文**：写 `1-情报\群消息与招聘会-MMDD\群消息原文-MMDD.md`（消息清单表 + 今日日程 + 本周关键日）。
5. **更新台账**：新岗位进 `投递台账-未投.md` 的待投主表（状态 `待投`）；他报「已投/已网申」的 → 按上表搬进已投本并改状态；他明确说不投的 → 挪进未投本的「一·附 不投」；新宣讲会写进「九」；学历/专业不达标的写进「七、硬门槛自查」并标注 ❌（不要塞进主表）。
6. **排时间规划**：把事件落到「投递执行清单」的时间盒里；**同一天同一时段多场宣讲会必须做冲突取舍并说明理由**（判据：能否现场面试/免筛选 > 岗位方向是否对口 > 校区距离）。
7. **回执**：给一段简短汇报——新增几个岗位、今天最高价值场次、需要他决策的点（截止日临近的、方向冲突的）。

## Pitfalls

- **台账是「一主两册」，别再拆也不能合成一本**。总入口存共享章节；已投/未投各一本；不投的单独留档在未投本「一·附」，避免来回纠结。
- **目录分层约定（本人要求）**：`3-面试\` 下**台账类文件一律留根目录**（投递台账三本 + 每日进度），其余**按类进编号子目录**（1-面试准备 / 2-投递与计划 / 3-公司资料 / 4-附件截图\MMDD）。新建文件先想好归哪类；搬动文件后**必须全项目扫一遍旧路径并修引用**，包括两个 cron 任务的 prompt —— 它们写死了绝对路径，漏改第二天早上就报「读不到台账」。
- **cron prompt 里绝不要写死 `YYYY-MM` 的月份文件名**。09 月转 10 月时就因为这个，10-01 的晨报被写进了 `晨报存档-2026-09.md`（与 10 月存档完全重复）、而 10-03 的晨报哪边都没落盘。正确写法：prompt 第 0 步先跑 `date +%Y-%m` 拿当月年月，再拼 `每日进度-<当月>.md` / `晨报存档-<当月>.md`；读的时候允许退回目录里最新的 `每日进度-*.md`，**写的时候只准写当月文件**。改完必须扫一遍 prompt 里所有 `20\d\d-\d\d` 形式的路径并逐个核对。
- **文件名里的同音字是最隐蔽的断链源**。公司的正确写法是「云帐房」，但某个会话把准备卡引用写成了「云账房-笔试准备卡-1007.md」，三份文档跟着错、全部指向不存在的文件。新增/改名后必须 `grep -rn "<文件名片段>" --include="*.md" .` 全库扫一遍，并 `ls` 确认每一处都能命中真实文件。
- **搬动前先列引用**：`grep -rn "3-面试" --include="*.md" --include="*.py" .`，改完后复扫一遍确认无残留。
- **新增投递条目前必须先扫三本的最大行号**。行号 `#` 全库唯一，但**最大号可能在任一册**（09-30 实测：已投本最大 #94、未投本最大 #100）→ 随手按已投本给号会立刻撞号。先跑：`for f in 投递台账*.md; do grep -oE "^\| +[0-9]+ +\|" "$f" | grep -oE "[0-9]+" | sort -n | tail -1; done`。
- **本人直接发的截图先落地再识读**。微信直发的图在 `C:\Users\Lenovo\AppData\Local\hermes\cache\images\img_*.jpg`，与业务无关的随机文件名 → 按用途重命名 `cp` 到 `3-面试\4-附件截图\MMDD\`（如 `0930-荣耀-AI软件开发工程师-笔试邀约短信.jpg`），台账备注里直接写这条路径。
- **批量改写台账用「脚本 + 每处断言」**，不要连续 patch：每处 `assert text.count(old) == 1`，开头先 `cp` 三本 + 每日进度到 `_归档\备份-MMDD\`，改完核对「主表数字行数 = 本册合计条数」。patch 一次只改一处，9 张图对应十几处改动时极易半途失配。
- **绝不用 `split("---")` 切 markdown 章节**。表格分隔行 `|---|---|` 里含 `---`，会被当成章节边界、把表格截断并且**静默丢数据**（本次就这么丢了两张表）。正确做法：按 `re.split(r"\n(?=## )", t)` 切章节，只剥**行尾**的 `---`：`re.sub(r"\n[ \t]*-{3,}[ \t]*$", "", s.rstrip())`。
- **每日进度当日小节是「一天一节」**：`每日进度-YYYY-MM.md` 同一天**绝不允许出现两个小节**。若当天小节已存在（白天会话可能已写过一段），22:00 的任务要**整段替换**它：读全文 → `s.index("\n## MM-DD")` 截断 → 追加新小节（当天通常是最后一节）。**不要用大段 `patch` 去匹配旧全文**（80+ 行、含 emoji 与反斜杠路径，极易失配），也**不要**用 `write_file` 重写整份文件（要把前几天的内容重打一遍，一有闪失就丢历史）。小节固定四段：`- 已完成：` / `- 新情报：` / `- 决定：` / `- 卡点/未完成 → 明天：`；日期简写要与文件里既有写法一致（如 `## 09-22 周二`）。
- **改写已有文件前先留副本**。拆册脚本第一版直接覆盖了源文件；规范动作＝先 `cp` 到 `_归档\`（或先写临时文件、比对行数与字节数无误再替换），别指望内容还在上下文里。
- **校验文件大小用 `os.path.getsize()`**，不是 `len(text)` —— 中文一个字符 3 字节，`len()` 只有字节数的 1/3（本次据此误报过 `assert`）。
- **合并转发的聊天记录**：QQ 官方机器人有时只给截断预览（`[群聊的聊天记录]` + `attachments=None`），图片 URL 拿不到 → 让他"单张图片直接发"或"复制成纯文本"；本次成功到达的是完整纯文本形态，图片以 URL 形式内嵌，可下载。
- **图片里的学历/专业门槛必须实读，不能猜**。军队类海报常见"本科以上岗位专业限电子信息类"这种坑——计算机/软件工程可能不在列。
- **工作地点是硬取舍**（如军队路线=河南洛阳），必须显式提出来让他决定，不要默默录进队列。
- 状态码只用台账定义的那套：`待投 → 已投 → 已查看 → 笔试待考 → 笔试完成 → 面试邀约 → 面试完成 → 已挂 / Offer / 无回复（7天跟进）`。

## 主动消息（推送）

- **群主动消息没开**：`POST /v2/groups/<openid>/messages` 报 `40034105 主动消息失败, 无权限`（沙箱 / 未上线机器人不发主动消息）。群里只能被动回复（@ 一次，5 分钟内最多回 5 条）。
- **私聊主动消息可用**：`POST /v2/users/<openid>/messages` 返回 200。
- 所以任何定时推送（cron）的 `deliver` 必须写 `qqbot:CF5E45E3965A23041DA9C8278AAE7ACC`（大浩私聊 openid）；写 `origin` 在群里会 `delivery_outcome: failed`，日志报 `Send failed: ... 主动消息失败, 无权限`。
- 已排任务（时间 09-20 已后移）：`秋招早报-0830`（`c5a5d86a45ef`，每天 **09:00**）、`秋招进度记录-2200`（`18fdd693f76b`，每天 **22:00**）。散文里的 08:30 / 21:30 是历史表述，别按它改任务。

## Verification

- 三本都读一遍：总入口有共享章节；已投本行数 = 已投条数、未投本行数 = 待投条数 + 不投条数；`grep -c "^| "` 确认表格行数没被截断。
- `search_files` 搜公司名能在正确的册里找到，列数与表头对齐（12 列）。
- 主表每个新行都有「截止/宣讲时间」和「下次跟进」日期。
- 时间盒里每个时段都有地点与产出，冲突场次给出了明确取舍。
