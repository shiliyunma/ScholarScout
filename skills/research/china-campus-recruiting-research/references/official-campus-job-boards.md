# 官方 ATS 岗位板：怎么读、拓什么、怎么定投不投

公司级结论在岗位级是错的。这个文件是怎么读雇主自己的校园招聘系统——唯一能逐岗说明
用工形式、学历门槛、职位ID 与实习转正措辞的来源。

## 1. 岗位板长什么样（实测形态）

| 形态 | 例子 | 要点 |
|---|---|---|
| 集团校招门户 | `campus.<corp>.com/campus` | 宣传壳；投递按钮会跳到 ATS 登录 |
| 公司校招 hub | `hr.<corp>.com/campus` | 落地页把**批次**列成独立入口，批次 ID 就在按钮 href 里 |
| ATS 岗位列表 | `wecruit.hotjob.cn/SU.../`（北森）、`hr-jobs.<corp>.com/edu/` | 真岗位在这层；列表由 query 参数控制 |
| 运营商统一招聘 | `job.10086.cn` | 一个账号覆盖集团 + 省公司 + 专业公司 |

批次级查询（真正干活的那一下）：

```
https://hr-jobs.<corp>.com/edu/?keywords=<关键词>&category=&location=
  &project=<批次ID>&type=&job_hot_flag=&current=1&limit=10&functionCategory=&tag=
```

- `project=<id>` 隔离一个批次（校招正式批次 vs 实习生批次），两个批次要分别查。
- `keywords=` 收窄方向（`Agent`、`大模型`），会带出别批次的同名岗位便于对比。
- 列表行自带决定性标签；详情锚点形如 `/edu/position/<id>/detail`，点进去读 JD 正文。

## 2. 逐岗要拓的字段

| 字段 | 出现在哪 | 为什么它决定投不投 |
|---|---|---|
| 批次 / 用工形式 | 标签行 `...校招正式研发 - 后端开发27届校园招聘` / `...校招实习研发 - 后端开发实习生` | 正式 HC 与转正赌注的区别 |
| 职位ID | 同一行 `职位 ID：AXXXXX` | 就是台账里的「岗位编号」 |
| 学历 | 职位要求第一条 | 会静默筛掉申请的门槛 |
| 经验年限 | 职位要求 | 校招板上写「2 年以上」＝实质社招，应届跳过 |
| 框架/工具点名 | 职位要求 | 直接列出定制话术里要诚实交底的缺口 |
| 转正措辞 | 正文 `实习表现优异，有实习转正机会` | 有 = 可能；无 = 未承诺 |
| 驻场/出差 | 备注行（`⚠️该职位需要前往…驻场开发`） | 投递前用户得先接受的通勤约束 |

## 3. 判断表

| 信号 | 结论 | 动作 |
|---|---|---|
| 名称带【XX届校招】+ 标签「校招正式」 | 正式校招 HC | 优先投，精力花在这 |
| 标签「校招实习」，批次面向毕业时间窗口的本硕博 | 校招实习（非散招） | 备选；JD 未写转正＝未承诺 |
| 同批次他岗明写转正机会 | 该批次有转正通道，但不统一 | 逐个岗位问 HR，别推广到用户投的那个 |
| 硕士/博士 或 N 年经验 | 硬门槛 | 不投，记进硬门槛自查免得重算 |
| 聚合站写「公司正式岗要硕士」 | 只是部分岗位的总结 | 逐岗去官方板核实再采信 |

## 4. 侦察卫生与交还

- 每家公司的页面正文存到工作区的 `_recon/` 下：后面再被问「这个实习岗能转正吗」时，
  证据还能重读，不必重新跑一遍浏览器。
- 打印 scraper DOM 前过滤 `data:image/...;base64`：二维码图会把工具结果撑爆。
- 官方入口两三次打不开、或联系方式藏在登录后面时，停手并把找链接交还用户：在待办里写
  `由自己找`，同时把已知信息（截止、办公地、流程、强制邮件标题格式）全部附上，不要用猜的网址填空。
