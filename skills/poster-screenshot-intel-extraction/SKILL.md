# 超长截图 / 海报情报提取

用户转发的通知、招聘会海报、公众号长图常是一张**超高截图**（实测 1200×10205 px）。整图丢给视觉模型必然糊，必须**分区放大**读。本 skill 是这类“从图里取结构化情报”的作业流程与判读规则。

## When to Use

- 用户发来一张很长的海报/通知截图（招聘会、宣讲会、政策通知、报名须知）
- **用户发来一段视频/动图**并期待你实际看过它（房型、场地、演示、录屏）→ 抽帧拼联图一次读完，
  配方与「未见≠没有」的措辞纪律见 `references/video-frame-inspection.md`
- 已经有一份 OCR 文字，但需要核对关键字段（日期、地点、家数、金额）
- 同一件事有多个来源且细节对不上

## Procedure

1. **整图先定性，不要指望读字**：不带 `region` 跑一次 `vision_analyze`，只回答“这是什么、有哪几块、各块大致纵向位置”。长图会被等比压缩（1200×10205 → 150×1275），小字一定不可读。
2. **按 `region=[x1,y1,x2,y2]` 逐块取字，坐标用原图像素**。换算关系：`原图坐标 ≈ 预览坐标 × 缩放倍数`（工具会在返回里给出该倍数，如 ×8.00）。每块给足纵向重叠，别卡太紧留缝；一次读一块，读完打印位置再推下一块。
3. **表格逐行读全**：region 卡住表头到下缘，读完后**再往下确认一屏**有没有漏行。
4. **关键数字二次放大单独确认**：日期、金额、人数、截止时间。日期行用**一行高**的窄 region 高倍放大读（例：`region=[150, 3280, 1100, 3560]` 读「2026年9月21日14:00-16:30」）——读错一个数字的代价是排错整天的日程。
5. **读到边角信息**：主办/指导/承办单位、报名二维码说明、备案号。它们用来判真伪与找官方渠道。
6. **对账**：海报声明的「N 家企业 / N 个岗位」要和表格实际行数对账，不一致就把差额写出来（可能发布后有企业补入），不要按其中一个数字下结论。
7. **归档**：原图先下载再归档（QQ 多媒体链接带 `rkey`、时效很短，过期只剩几十字节空壳）；深加工结果写成单独 md，带时间地点 + 按优先级排序的目标清单 + 行动项。
   **归档目录名与回写哪一天的进度小节，都按「图片到达日」定 —— 不是事件日、也不是你以为的今天。**
   用户直接发的图在 `$HOME/AppData/Local/hermes/cache/images/img_*.jpg`，那个文件的 **mtime 就是真实到达时间**：
   `ls -la "$HOME/AppData/Local/hermes/cache/images/" | tail`。实测一张被当成前一天的展板照片其实是**两天后**才收到的 →
   情报写进了错的小节、归档目录也起错了名。落笔前先跑 `date` ＋ 看一眼缓存 mtime，两个对上了再写。
8. **图里的二维码单独裁切并解码**：板面/PPT 上的码常常就是唯一投递入口（还可能把内推码嵌在 `?referralCode=` 参数里）→ 用 `cv2.QRCodeDetector` 裁成单码图 + 取出 URL，保存前用 vision 复核定位环完整。配方与坑见 `references/qr-code-extraction-from-photos.md`。

## 一次十几张：并发会让前面的图被挤掉，改用子智能体

现场招聘会一天能发来十几到几十张展板照片。**同一轮里并发多个 `vision_analyze` 时，靠后的图会把靠前的顶掉** —— 返回里出现「[screenshot removed to save context]」**不是「没加载成功」，而是那张图已被丢弃、你根本没看到**（实测：一轮 4 张，只有最后 1 张留得下来）。三条纪律：

- **要自己逐张核字段时：一轮只加载一张。** 图数 ≥8 张时不要串行走完整流程。
- **≥8 张就分批交子智能体并行**（每个 ≤8 张，一批一个子智能体）：
  - 提示词里写死输出模板（公司全名 / 对口岗位 / 学历 / 薪资 / 网申入口 / 工作地点 / 其他要点）＋ 两句硬要求：**「看不清或图上没写就写「未标注」，绝对不要编造」**、**「同一公司的多张图合并成一条并注明」**。
  - 要求它**把完整结果写进工作区的 `_wip/海报批量-批N-MMDD.md`**，**最终答复只回一份短清单**（公司名 ＋ 对口岗位一行）。长内容留在文件里，别灌回主上下文。
  - **子智能体看不到台账 → 去重与入册必须由主会话做**：拿回清单后逐个公司名跑一遍「投前必查」，已存在的老公司**只补信息不新建**。
  - **关键词命中不等于重复**：命中可能落在**别行的备注**里（顺带被提一句的公司名）。判据＝这一行是否以 `| <编号> |` 开头；否则当新实体处理。
- **展位号（他口中的「现场的号码」）优先查文本映射表，不要靠读图**：招聘会前通常已有一份「展位号 → 公司」的作战清单／展位分区表（A 区 A001–A208、B 区 B001–B050、F 区 F001–F013、K 区 K001–K013 这类贴片编号）。**先用 grep 按公司名在这份清单里查** —— 它是文本、准且快；照片只作补充。回执里把**展位号与台账行号两个号都写上**（例「润和 #127 → 展位 K003」），他下次说哪一个都不用再问。
- **照片上读不到展位号就说读不到，绝不据邻位编号推断**：现场拍的展板照片里，正主的展位贴纸常被**易拉宝整块挡住**，画面上只留下左右邻位的号（实测两家的照片里只读到「A101 无锡…」与「A104 中天电…」，正主那两个号一个都没露）。此时正确动作是回一句「号被易拉宝挡住了，你记得的是多少」＋保留已确认的邻位信息；**不要写「大概在 A102/A103」这种推算值** —— 它会以「已核实」的样子进台账。
- **大批入册后回头扫一遍「格数」**：几十行连续插入最容易出现少一格 / 多一格，报数前先校 `行.count("|") - 1 == 表头列数`。

## 落地前的字段核验（照片读出来的值不能直接入册）

照片上的小字极易读错一个字符，而下游动作是「照抄去投递 / 发信」，错的代价直接落在用户头上。落库前按字段类型过一遍：

- **邮箱 / 网址**：写进台账前先做 DNS 解析（Python `socket.gethostbyname`）。解析失败几乎一定是你读错了字符（`.cc` vs `.com`、p/v、单复数）→ 标「**⚠️ 域名解析失败，勿照抄发信**」，并给一条现场核验动作（当场核对板面 / 直接扫展位二维码）。**同名的其它后缀域名一律不要当成候选写进记录**（同名公司常有 `.cn` 属于另一家主体，写错比不写更坑）。
- **届别年份**：板面写「2026 校园招聘」而目标届是 2027 届时，多半是**上一届旧板** → 标「疑似旧板，待确认」，不要直接按当前届入册。
- **学历门槛**：「本科 / 硕士及以上 / 博士」逐条实读。**标「硕士及以上」不等于本科一定不能投** —— 存在展板标硕士、现场实际收本科的先例，所以用户在场就问一句「本科可投吗」，不在场就标「学历待确认」，不要替他判定。
- **多岗位板只录对口岗**：一块板常列 5–8 个岗位而只有少数对口 → 只把对口岗写成记录，其余在备注里一句「其余（电气/机械/结构…）均方向不符」，不要每岗一行。
- **「本科可投」≠「该投技术岗」——先分层再报**：板上的本科岗分两类：**技术开发**（软件 / 后端 / AI 开发 / 算法）与**驻场交付**（FAE / FDE / 实施 / 售前 / 解决方案经理）。本科门槛的板子大多数岗位落在后者：门槛低、招人多、易拿 offer，但**以出差为主、不写核心代码、技术纵深有限**。交付岗要写清性质与代价，并提醒“别让它占满志愿”——交付岗按 +3 天跟进、技术岗优先。
- **公司太新要点出来**：成立不足一年的公司（常带明星孵化方/集团背景）→ 机会多但流程、转正规则、薪资体系都不成型，标「稳定性与转正条件待观察」，并配一条现场追问（“转正考核标准与通过率？”）。
- **配套偷看旁边的展位**：现场拍的展板照片常带到**邻展位/背景板**，而邻展位可能比正主更对口（实测发生过：邻展位是 AI Infra 公司）。发现时在回执里指出并让他补拍一张，别只处理照片里占主体那一块。
- **反过来：并排的两块面板可能是同一家雇主，别拆成两家。** 招聘会一个展位常摆两块 ── 一块是**岗位总览**（分类 + 年薪区间 + 工作地点 + 二维码），另一块是**详细 JD**（岗位名 + 招聘人数 + 月薪 + 逐条任职要求）。
  判定同一雇主就看**公司简介段是否一致**（成立年份、员工数、战略口号），不要因为标题不同、薪资单位一个写年一个写月就当成两家去建两行。
  两块的字段还会**互补**：总览给「本科及以上明确可投」这类总口径，JD 页才写出某个岗位的硬门槛（实测：总览页不写学历的那个岗本科可投，JD 页里另一个岗第一条就要求硕士）—— **两页都要读到同一行上**，只读一页会给出错的建议。

## 多来源冲突：判定与动作

**优先级**：**现场 HR 口头**（面试轮次 / 有无笔试机试 / 城市 / 报销条件） > 活动自己发布的材料（海报 / 主办方公众号原文） > 转发汇总通知 > 群里转述。印刷展板常是往季模板或总部口径，与现场说法冲突时**按现场执行，并把「冲突」本身写进备注**（例：板面写苏州/深圳/南京，HR 口头说主要在杭州）—— 后续会话只看到文件、看不到「谁说的、凭什么」，不记冲突就会把作废的板面口径当真。
**裁判优选**：找**周度/期次汇总类原文**（学校就业办公众号的《第 N 周校园招聘活动汇总》）—— 它逐条列出每场的时间地点，能一次性判掉日期与场次归属的分歧。
**交叉验证**：**同一场馆、同一时段不可能有两场活动** —— 用已知的另一场反推哪份材料错了。
**冲突解除后要收尾**：把结论（哪份对、依据是哪篇文章）+ 解决时间写回**两个文件**，并**撤掉「日期存疑」标记**（台账里的存疑行也要一并改掉）；留着过期标记会让后续会话继续按错误的日期排日程。
**不一致时不要硬选一个**：
- 两个文件里都标「**日期存疑**（A 说 X 日、B 说 Y 日）」，不要静默采信其一；
- 给一条**零成本核验**动作（本校场馆走过去看一眼、看就业信息网详情页、看公众号最新一条）；
- 说明两种可能各自的时间代价，让用户 10 秒决定。

## Pitfalls

- **引导性提问会让 vision 编出图里没有的文字 —— 再放大也救不了，只有量像素能定案**：问「这里有没有 X？」这类**确认式/否定式**问题，它会把 X 念出来；**连续几次回答一致也不是事实**（实测：对一块空白区域，三次一致的回复都念出了同一条本机磁盘路径，细节具体到路径里的中文目录名）。因此：
  1. **提问一律中性**：「念出你看到的全部字符，不要补齐或推测；看不清就写『看不清』」。
  2. **任何「图里有 X」的结论，写进台账/动手改之前先做一次像素测量**（两种任选）：
     - **取值去重**：把目标区域的像素值 `Counter` 一遍 —— 真文字有**几十种**取值（含 ClearType 彩色边缘），空白只有 **1 种**；
     - **两版差分**：改动前后逐像素比，差异 0 = 你改的是空白（也说明它本来就没内容）。
  3. **「有墨/无墨」扫描要先量对背景基准**：页眉/表格的底边横线会让附近整行都算「有墨」，据此设的阈值全错。判据：若「最暗点」出现在**所有 x 的同一行**，那是线条，不是文字。
  4. 要读小字就把条带**裁出来放大 3–4 倍**（`pymupdf`：建同尺寸 page，`insert_image` 用负 y 偏移把目标条带顶进页面，`dpi=216` 渲染）—— 比整页缩略图可靠，但**放大与中性提问都不能替代像素复核**。
- **别把整图当可读的图**：整图识别出来的细节基本是幻觉，尤其是长数字与家数。任何写进台账的字段都应该来自分区放大后的读法。
- **别把「拿不到」直接当结论 —— 先换站点适配的 UA 再判**：政务/就业网站的详情页多为 SPA，`curl` 只得到 `<div id="app">` 空壳；但**微信公众号文章（`mp.weixin.qq.com/s/…`）用 MicroMessenger UA 的 `curl` 能直接抓到正文**（`curl -sS -L -A "Mozilla/5.0 (iPhone; …) MicroMessenger/8.0.42" <url>`，再去标签取文本）——学校就业办公众号的原文常是名单与日期的权威出处，值得先试一次。真的拿不到时给替代核验路径，绝不根据链接编造页面信息。
- **网址来源的搜索词要选对站点**：搜索引擎对**中文短词**（如公司名里的单字）会跑偏成字典释义页，返回一堆无关结果；查公司/岗位/笔面真题这类材料，**直接抓目标站的站内搜索更可靠**（见 `blocked-page-recovery` 的站点适配 UA 段）。
- **中文参数不要经 shell 直传**：把中文查询词/路径直接交给 `curl` 等原生程序时，git-bash 会按 GBK 送出，服务端收到乱码、返回一堆与前缀毫无关系的页面（症状看着像「搜索引擎坏了」）。凡要发出去的中文 URL/参数，一律先在 Python 里用 `urllib.parse.quote` / `quote_plus` 组好再请求；另外注意**同一条查询短时间内反复发会拿到同一批缓存结果**，看起来像「多组不同查询返回相同内容」——这本身就说明请求参数没生效，别再基于它下结论。
- **把情报写回共享台账时，先重读、再取号/取锚点**：这类台账会被多个会话与 cron 同时写，且行号是**全库唯一**。① 取新行号前先 grep 全库已用号（`grep -oE "^\| [0-9]+ \|" *.md | sort -u`）取最大号 +1，别信记忆里的空号；② 锚点必须与被改文件是同一册（行号唯一但行分居多文件），失配时先重读目标文件再取一段更短、更靠行尾的锚点；③ 自己刚写过的公司名/行号在下一轮可能已被别的写入者改动 —— 有冲突以文件现状为准，改完在当日进度留一句更正；④ **替换后立刻 `grep -n '<新内容关键片段>'` 复读整行** —— 台账备注单元格很长，`old_string` 只截半截会把相邻内容吃掉（实测两次：行首那半句消失了；另一份文档里下一道题的答案整段被挤掉）。发现被吃当场补回，并在当日进度留一句更正。
- **口头情报也要「一问一绑一行」**：他现场回来常连着报十几条情报，**大多不点名公司**（例：「不需要网上投递，等国庆后电话即可，预期年薪 20w」）。看不到展板的那些行最容易串家——先问一句「这条是哪家的？」再落库，绝不按上下文里最近讨论的那家猜；当场没确认的标「归属待确认」并给 A/B 选项让他一个字定。
- **发现情报串了公司：不是改一条，是改四处**：① 被误挂那行的备注删掉移出内容；② 它的**状态 / 流程 / 跟进日三格一起回退**（只改备注会把错日期留在状态列，后续提醒继续按错的催）；③ 移出的内容**建成新行**，带自己的状态与跟进日；④ 当日进度与当日汇总段里重复过该归属的句子都要改，并留一句更正（写明哪条实为哪家、已移到哪行），最后重算两册计数。
- **纯口述行要标出「无书面材料」**：没展板、没 JD、没 HR 联系方式的记录，在备注里列出待补字段（工商全称 / JD 原文 / HR 姓名电话 / 展板照片），并在回执里点出来——否则后续接电话时他手上没东西可对。
- **会话会跨天**：写当日进度、拖跟进日、报「明天有什么场次」之前先跑一次 `date`；上下文里的「今天」不可信（实测一轮对话里日期自己往前跳了一天）。
- **占位样式的备案号不等于假站点**：`苏ICP备2023000000号-1` 这类“全零/顺号”备案号常见于设计稿模板套用。发现时**提示走官方渠道核验**（从主办单位官网/官方公众号进入），不要直接断言诈骗。
- **顺手检查场次归属与场地冲突**：同一张海报上的“上午场 / 下午场”常分属不同主办、不同日期，落地到日程前要跟当地已知场次交叉核对一次。
- **敏感内容不上推**：涉及家庭经济、病情、金额的海报/表格，取字后只写动作与节点，细节留在本地文件，不写进推送给用户看的摘要或任何群消息。

## Verification
