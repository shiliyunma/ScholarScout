# 用户发来的视频：抽帧 → 联图 → 一次看完

用户转来一段手机视频（房型/场地/演示/录屏）并期待你"看到了"时，**不要请他描述**，也不要只看
第一帧。做法是把视频压成一张联图，交给视觉一次读完，再把规格写进落盘记录。

## 配方

```bash
V="<video.mp4>"
# 1) 先探规格：时长 / 分辨率 / 帧率 / 编码决定抽帧密度
ffprobe -v error -show_entries format=duration,size \
  -show_entries stream=codec_name,width,height,r_frame_rate \
  -of default=noprint_wrappers=1 "$V"

# 2) 抽帧（每 N 秒一帧）—— 留档供复核
ffmpeg -v error -y -i "$V" -vf "fps=1/2,scale=640:-1" "$OUT/f%02d.png"

# 3) 联图（一整段一次看完，一次 vision 调用搞定）
ffmpeg -v error -y -i "$V" -vf "fps=1,scale=460:-1,tile=4x4" -frames:v 1 "$OUT/sheet16.png"
ffmpeg -v error -y -i "$V" -vf "fps=1/2,scale=560:-1,tile=3x3" -frames:v 1 "$OUT/sheet9.png"
```

- **联图优于逐帧**：一次调用就看完时间轴；**关键帧再单独抽高分辨率复核细节**（角落小物件、
  门牌、铭牌、水印）——联图被降采样后正好会丢掉这些。
- 抽帧密度按内容定：一镜到底的看房/看场地用 1/2 秒一帧；有字幕/PPT 切换的录屏用 1 秒一帧。
- 竖屏手机视频常见 **720×1280 / 30fps**；`tile=4x4` 跟 `fps=1` 搭配时，超过 16 秒的视频
  只会有前 16 帧 —— 长视频要么提高抽帧间隔，要么分段拼多张。

## 判读纪律

- 🔴 **低码率手机视频里「没看到」≠「没有」**：结论一律写成「**未见 X**」并给一条核验动作
  （问对方 / 要一张照片 / 现场确认），绝不写成「没有 X」。手机拍摄会漏掉角落、暗处、
  被门挡住的物件，而这句话会被用户当事实去谈条件。
- **区分「物件」与「状态」**：裸床垫、空台面、无生活痕迹 → 说明「刚配齐、无人入住」，
  这是推断出来的一条**状态**结论，要和物件清单分开写。
- **只描述画面里能指认的东西**，「大致面积/采光好/装修新」这类判断要标明是感觉而非测量。
- 用户真正的用法往往不是「描述视频」，而是**据此做判断**（这套房能不能住 / 要问什么 / 值不值）
  —— 看完直接接上「因此要问清的 N 条」，并把它们写进对应的决策文件。

## 归档

- 原视频**复制进项目附件目录并按用途重命名**（`<日期>-<来源>-<用途>.mp4`），别留在 hermes 缓存里。
  缓存目录名形如 `<hermes>/cache/documents/doc_<hash>_<name>.mp4`，会被清理。
- 保存**帧目录 + 联图**，并在落盘记录里写清**视频规格**（时长 / 分辨率 / 帧率）与联图路径 ——
  后续会话要复算或复核时有据可依，不必再问用户要一次视频。
